### 1. Exchange Server hybrid: "Last Exchange Server" retirement operator (2016/2019/SE to Exchange Online) `closed`

**Why it's powerful:** A hybrid org spans on-prem AD, Exchange Online, Hybrid Configuration Wizard connectors, an organization relationship, OAuth or federation, Entra Connect or Cloud Sync, Autodiscover DNS and SMTP relays. Exchange 2016 and 2019 left support on 2025-10-14, so a large SMB and mid-market base is sitting on one last out-of-support server.

**Why people bounce off it:** Microsoft's retirement path is a 30-plus step, order-dependent runbook across two PowerShell sessions, Entra and DNS, and the traps are silent. Flipping `IsExchangeCloudManaged` before the sync cycle plus 24 hours can write stale recipient types back to AD. Enabling the tenant-wide flag early strands new on-prem users as plain Entra users with no MailUser. Arbitration, audit and public-folder mailboxes block uninstall. `Setup /m:Uninstall` deletes all receive connectors, so printer, scanner and app SMTP relay stops with no warning. Stale Autodiscover SCP and Centralized Mail Transport both break mail after cutover.

**AI operator:** Runs read-only first and produces a gated plan: inventories mailboxes by recipient type, finds anonymous-relay devices from receive connector logs, checks the sync clock, flags Exchange Management Tools users, and finds mailboxes pinned to system mailboxes. It then executes phase by phase, checks each gate, writes a receipt, and refuses to uninstall until every gate is green.

**Killer example:** User: 'We're all in Exchange Online, the 2019 box is just for managing recipients. Kill it safely.' The AI finds 3 mailboxes not yet cloud-managed and 2 printers relaying anonymously through a receive connector, and proposes moving the printers to Exchange Online SMTP relay. It waits out the 24-hour window, flips `IsExchangeCloudManaged`, clears the Autodiscover SCP, removes the hybrid objects, uninstalls, and cleans up the cloud side.

**Integration path:** Exchange Online PowerShell (`Set-Mailbox -IsExchangeCloudManaged`, `Set-OrganizationConfig`, `Set-OutboundConnector`, `Remove-InboundConnector`, `Remove-OrganizationRelationship`, `Remove-IntraOrganizationConnector`, `Remove-OnPremisesOrganization`) plus on-prem Exchange Management Shell (`Remove-HybridConfiguration`, `Set-ClientAccessService -AutoDiscoverServiceInternalUri`, `Remove-FederationTrust`, `Setup.exe /m:Uninstall`). Based on Microsoft's decommission-last-exchange-server and enable-exchange-attributes-cloud-management pages (2026-05 and 2026-08).

**Caveats and overlap:** The verifier found no first-party wizard, agent or Copilot tool for this retirement, only the manual Learn runbook. Community Exchange MCPs exist (for example a `Set-Mailbox` wrapper) but do routine mailbox admin, not a decommission workflow. Setting `IsExchangeCloudManaged` needs interactive delegated auth, because app-only auth is unsupported, so that one step needs a human sign-in. Whether the Entra Cloud Sync writeback config is creatable via the Graph synchronization API was not verified and may be a manual step. Adjacent to the 11-17 Windows Server 2016 exit and the Exchange public-folder cards, but the operator here is the hybrid decommission, with public folders only a prerequisite.

**Demand 4/5 · Buildability 4/5**

### 2. Yeastar P-Series PBX (with Grandstream UCM as a second connector): call-flow architect `closed`

**Why it's powerful:** A widely resold SMB and mid-size phone system (appliance, software and cloud editions) with IVRs, queues, ring groups, inbound and outbound routes, business hours, holidays, trunks and extensions. MSPs and resellers in India, the Middle East and Europe run it for small offices.

**Why people bounce off it:** Call flow is a chain of objects that must be wired in order: trunk, inbound route, business-hours check, IVR, queue or ring group, fail destination, each referenced by internal ID. Holidays and out-of-hours branches multiply the combinations. A missing holiday route or failover shows up only when a customer cannot get through. Office managers do this a few times a year and forget the model each time.

**AI operator:** A call-flow architect. The user describes the business in words, and the operator creates the leaf objects first (business hours, holidays, queue, ring group), then the IVR, then the inbound route. It simulates every caller path, flags dead ends and loops, and prints a plain-English call-flow map for sign-off before applying. Day-to-day changes ('closed Monday for the holiday') use the same path.

**Killer example:** User: 'New Kochi office: 9-6 Mon-Sat. Press 1 for sales (round-robin queue of Anu, Ravi, Joe), 2 for support (ring group), otherwise voicemail. Holidays go to the on-call mobile.' The AI creates the queue and ring group, creates the IVR with key-press destinations, creates the inbound route with business-hours and out-of-hours destinations, and prints a path diagram.

**Integration path:** Yeastar P-Series Open API (POST, `access_token` query parameter, User-Agent header): `queue/create`, `ivr/create`, `inbound_route/create` (with `time_condition` and `business_hours_destination` fields), plus ring group, extension and business-hours create and update endpoints. Grandstream UCM HTTPS API has `addIVR`, `addInboundRoute`, `addQueue` and `applyChanges`. FreePBX GraphQL is a third connector for ring groups and inbound routes.

**Caveats and overlap:** Found independently by two scouts (office/CRM-adjacent and dev-ops), which is a strong-signal pick. The verifier confirmed the IVR, queue and inbound-route create pages on the Software Edition docs and the business-hours page on the Cloud Edition. The exact business-hours path and its Software Edition availability are unconfirmed, and endpoint sets differ by edition. Yeastar's MCP support runs the other way (its AI Receptionist is an MCP client) and its AI page lists PBX management over MCP as "coming soon", so re-check before building. No community Yeastar MCP was found, though only one search covered it. 3CX, Five9, Dialpad and CUCM were already killed by their own MCPs.

**Demand 3/5 · Buildability 4/5**

### 3. Jamf Pro / Workspace ONE UEM to Microsoft Intune macOS migration mapper `closed`

**Why it's powerful:** Intune is the landing spot for Microsoft-centric shops moving Macs off Jamf, and for the Broadcom/Omnissa licence exodus off Workspace ONE. Configuration profiles, scripts, smart groups and app packages represent years of accumulated policy.

**Why people bounce off it:** No converter exists. Admins rebuild every profile, script, smart group and package by hand, and Microsoft's own docs say to reset and re-enrol devices. The mapping is lossy: Intune dynamic groups support roughly 17 criteria against 150-plus in Jamf smart groups, and Jamf extension attributes, FileVault escrow settings and Self Service policies have no one-to-one equivalent.

**AI operator:** A source-to-target migration operator. It reads the source inventory (profiles, scripts, smart groups, packages, extension attributes), passes `.mobileconfig` payloads straight through as Intune custom profiles, turns smart-group criteria into Entra dynamic-group rules, ports scripts, and emits a gap list of items with no equivalent. It then proposes pilot-wave assignments and tracks per-wave results.

**Killer example:** User: 'We have 400 Macs on Jamf and the renewal is in six weeks.' The AI exports 63 profiles, 21 scripts and 14 smart groups, builds 51 as Intune custom profiles or shell scripts assigned to a pilot group, flags 12 as manual (FileVault escrow, extension attributes, three Self Service policies) and proposes wave 1 of 25 devices.

**Integration path:** Read from the Jamf Pro API and Classic `/JSSResource/osxconfigurationprofiles` (or Workspace ONE UEM REST). Write via Graph `POST /deviceManagement/deviceConfigurations` with `macOSCustomConfiguration` (confirmed in v1.0 and beta, needs `DeviceManagementConfiguration.ReadWrite.All`) and `POST /deviceManagement/deviceShellScripts` (not confirmed). App packages need a content upload and the profile size limit is about 1 MB.

**Caveats and overlap:** The verifier found no Jamf-to-Intune converter anywhere: only consultancy guides, Microsoft's `shell-intune-samples` (enrolment only) and Jamf Migrator (Jamf-to-Jamf). No Intune first-party migration agent turned up. Position it as source-to-target migration, the same framing as the 11-18 Okta to Entra card, not as the 08-11 Intune policy-authoring card. SOTI MobiControl was folded in as a possible source rather than carded separately.

**Demand 4/5 · Buildability 3/5**

### 4. Power Platform data policies (formerly DLP): layered policy designer for Power Automate, Power Apps and Copilot Studio `closed`

**Why it's powerful:** Data policies are the only control that stops flows from moving SharePoint or Dataverse data to personal Gmail, Dropbox or arbitrary HTTP endpoints, and they now also gate Copilot Studio agents and MCP tools. They are present in nearly every Microsoft 365 tenant.

**Why people bounce off it:** Admins must classify more than 1,000 connectors into Business, Non-business or Blocked. Tenant and environment policies stack and the most restrictive combination wins. Custom connectors need URL-pattern rules, and a policy change can break running flows with no preview of which.

**AI operator:** Turns plain-English rules into a layered tenant and environment policy set, shows which existing flows and agents would be blocked before applying anything, handles per-environment exceptions, and audits connector drift as new connectors appear.

**Killer example:** User: 'Marketing flows must never touch HR data, block all consumer file-sharing connectors tenant-wide, except Dropbox in the Sandbox environment.' The AI creates a tenant policy blocking the consumer connectors, an HR/Business-group policy scoped to the HR environments and a Sandbox exception policy, lists the 9 flows that would break, and applies only after confirmation.

**Integration path:** PowerShell module `Microsoft.PowerApps.Administration.PowerShell` (the documented DLP SDK: `New-DlpPolicy`, `New-PowerAppPolicyUrlPatterns`, update and remove cmdlets) and the Power Platform for Admins connector. The newer `api.powerplatform.com` governance API is confirmed only for rule-based policies; its data-policy path is unconfirmed.

**Caveats and overlap:** The verifier found no natural-language data-policy creation from Microsoft, and no deprecation of the SDK cmdlets (a Pulumi `DlpPolicy` resource was updated May-June 2026). The closest first-party item is Power Shield in the Copilot Agent Kit, which is an approval workflow that creates policies, not an operator. Advanced Connector Policies went GA around June 2026 and overlap in scope, and Microsoft's 2026 wave 1 agent-governance work could narrow the Copilot Studio part. It was strong but cut from the top 12 earlier, not killed.

**Demand 3/5 · Buildability 4/5**

### 5. PostgreSQL native partitioning + pg_partman: big-table partitioning retrofit and retention (SQL Server and MySQL as sibling connectors) `open-source`

**Why it's powerful:** Partitioning is the standard answer for 500M-row event, audit and log tables: constant-time retention (detach or drop a partition instead of a day-long `DELETE`), partition pruning and cheap archiving.

**Why people bounce off it:** You cannot convert an existing table in place. The path is a new partitioned parent, a batched data move, primary and unique keys that must include the partition key, foreign keys pointing at the old table, a default partition at cutover, and indexes that child tables created earlier do not inherit. SQL Server has the equivalent with `NEXT USED` filegroups, RANGE LEFT vs RIGHT, aligned indexes and switch-compatible staging tables. Most shops never do it and run nightly batch deletes that bloat the table instead.

**AI operator:** Reads the table and its dependents (constraints, FKs, indexes, views, query patterns from `pg_stat_statements`), picks the partition key and granularity, and writes a staged plan: shadow partitioned table, batched backfill, count and checksum validation, a short-lock cutover, then scheduled retention. Everything runs dry-run first with a rollback script per step.

**Killer example:** User: 'events is 900M rows, deletes of 90-day-old data take all night and bloat the table. Partition it by month and keep 18 months.' The AI says created_at is not in the PK so it will make the PK (id, created_at), repoints 2 foreign keys, estimates the backfill at about 11 hours in 50k-row batches with a roughly 2-second cutover lock, and on approval runs it and schedules monthly maintenance with 18-month retention.

**Integration path:** Plain SQL over a normal connection: `CREATE TABLE ... PARTITION BY RANGE`, `ALTER TABLE ... ATTACH/DETACH PARTITION`, `partman.create_parent()`, `CALL partman.partition_data_proc()`, `partman.run_maintenance_proc()`, `UPDATE partman.part_config SET retention`. SQL Server: `CREATE PARTITION FUNCTION/SCHEME`, `ALTER PARTITION FUNCTION ... SPLIT/MERGE RANGE`, `ALTER TABLE ... SWITCH PARTITION`.

**Caveats and overlap:** The verifier found no MCP or agent product for the retrofit, only guides and a vendor-specific Alibaba RDS online-conversion tool. Individual vendors (pgEdge, Xata, Aiven, Neon, Crunchy) were not checked one by one. A general coding agent with psql can do much of this, so the value is dependency analysis, cutover planning and safety rails. It is structural work, distinct from the seen MySQL, Postgres and SQL Server tuning cards. The audience is engineers and DBAs, so demand is capped at 3.

**Demand 3/5 · Buildability 4/5**

### 6. Zimbra Collaboration (and Zextras Carbonio): effective-settings explainer and bulk provisioning `open-core`

**Why it's powerful:** A full mail and calendar server still run by ISPs, universities, governments and telcos across India, LatAm, Europe and Africa, with Class of Service inheritance, distribution lists, aliases, resource calendars and per-domain settings.

**Why people bounce off it:** Everything is `zmprov` and LDAP attributes. Account-level attributes silently override COS, quota and forwarding rules are scattered across attributes, nested distribution lists are invisible, and the admin UI does not expose most of it, so one sysadmin holds the knowledge.

**AI operator:** A provisioning and audit operator that explains the effective settings of any mailbox (account vs COS vs domain), applies policy in bulk, cleans up distribution lists and aliases, and exports the directory as a migration manifest for a Microsoft 365 or Google move.

**Killer example:** User: 'Give all of Finance 20 GB, block external auto-forwarding for them, add finance-alerts@ as an alias on the AP shared mailbox, and show me anyone whose quota is being overridden.' The operator finds the Finance members, sets the quota and forwarding attributes, adds the alias and returns the accounts that diverge from the COS.

**Integration path:** Admin SOAP at port 7071 `/service/admin/soap`, or `zmprov`. Operations confirmed in the Zextras admin API reference: CreateAccount, ModifyAccount, CreateCos, ModifyCos, CreateDistributionList, AddDistributionListMember, CreateDomain, ModifyDomain, SetPassword, RenameAccount, AddAccountAlias, CreateCalendarResource.

**Caveats and overlap:** The only Zimbra MCP found is an end-user mail, calendar and contacts one with no provisioning. The install base is shrinking toward Microsoft 365, so the migration-manifest angle carries part of the demand. Loosely adjacent to the Google Workspace admin and Exchange cards, but the job is effective-settings explanation plus bulk policy, not leaver handover or delegation.

**Demand 3/5 · Buildability 4/5**

### 7. VICIdial (open-source outbound/blended dialer): campaign tuner and compliance operator `open-source`

**Why it's powerful:** Predictive dialing, hopper, AMD, call-time rules, DNC lists, in-groups and recording. Heavily used by BPOs, telemarketing and collections teams in India, the Philippines and the US.

**Why people bounce off it:** One campaign has well over 100 interacting settings (dial method, auto dial level, hopper level, dial statuses, list order, call-time rules, caller ID groups, AMD, DID routing). Tuning and compliance changes are tribal knowledge in the admin UI, and wrong values cause abandon-rate or compliance problems.

**AI operator:** Reads live stats, then proposes and applies campaign changes in plain language, handles DIDs, lists and agent accounts, and keeps an audit log with before and after values.

**Killer example:** User: 'Abandon rate hit 4% on SALES_A. Drop the dial level and stop dialing lists older than 30 days.' The AI reads campaign and in-group status, calls `update_campaign` with a lower dial level, deactivates old lists via `update_list`, shows the diff, and applies it on confirmation.

**Integration path:** `/vicidial/non_agent_api.php` with `source`, `user`, `pass` and `function` parameters. Confirmed functions: `update_campaign`, `add_list`/`update_list`, `add_did`/`update_did`, `add_user`/`update_user`/`copy_user`, `add_phone`, `hopper_bulk_insert`. Per the ViciJS SDK page, `update_campaign` accepts dial method, auto dial level, adaptive maximum level, dial timeout, hopper level, list order and its secondary order, active flag, outbound caller ID, dial statuses, lead filter and transfer-conf fields.

**Caveats and overlap:** There is no `add_campaign` and no in-group or IVR create function, so the operator can only tune existing campaigns. Call-time and list-order-mix fields are not listed on `update_campaign`, so call-window changes may not be possible through the API; check the official NON-AGENT_API doc before promising them. VICIdial's own list loader is a built-in bulk tool, so lead upload is out of scope. VICIPanel, a commercial panel, ships an MCP that appears to be ops and reporting; its tool list was not confirmed, so check it for overlap.

**Demand 3/5 · Buildability 3/5**

### 8. Unity Gaming Services Economy (PlayFab Economy v2 stores as a second connector): live-ops economy operator `closed`

**Why it's powerful:** The live-ops back end for a large share of mobile, PC and console games: currencies, items, bundles, stores, per-currency prices, segment-gated stores and scheduled start and end dates.

**Why people bounce off it:** Draft-then-publish with hard limits (for PlayFab: 15 prices per item, 50 item references per bundle). Content types and tags must be defined in the catalog config before items can use them, store prices and item references are mutually exclusive, and items reference each other by ID, so one wrong ID breaks a bundle. Designers keep the economy in spreadsheets and re-key it by hand.

**AI operator:** Takes an economy design in plain language or a spreadsheet, resolves item IDs and dependencies, builds currencies, items, bundles and stores in the right order, validates, and shows a diff against the live config before publishing. It also audits for dangling references, bundles priced below their parts and stores with no segment gate.

**Killer example:** User: 'Make a Winter Event store: 3 bundles using the existing gems and coins, 20% cheaper than buying parts, visible Dec 1-31, only to the lapsed-player segment.' The AI creates the bundle drafts and the store with its date window and segment permission, prints the price math and the diff, and publishes after one confirmation.

**Integration path:** Unity Economy Admin v2: `POST /economy/v2/projects/{pid}/environments/{eid}/configs/draft/resources` to add a resource, `PUT .../configs/draft/resources/{resourceId}` to edit one, and `PUT .../configs/draft` with `isPublished` true to publish (publish limited to 2 requests per second). PlayFab: `POST /Catalog/CreateDraftItem` with `Item.Type` of currency, bundle or store, then publish.

**Caveats and overlap:** The Unity reference page documents only the CURRENCY schema, so inventory item, virtual purchase and real-money purchase schemas are unconfirmed. For PlayFab, the community `akiojin/playfab-mcp-server` (developer preview, 3 stars) already covers catalog item create, update and publish, so the PlayFab catalog is overlap. Its tools include no store management, so PlayFab stores and the economy-design layer (dependency ordering, diff, audit) remain the wedge. No official Unity UGS Economy MCP was found; a third-party Unity MCP lists Economy only under UGS LiveOps. Game dev rather than a classic creative-pro app, so demand is capped at 3.

**Demand 3/5 · Buildability 3/5**
