### 1. Apache Spark (Spark UI + History Server, on EMR/Dataproc/K8s/on-prem) `open-source`

**Why it's powerful:** It is the default distributed engine for ETL, SQL and ML pipelines. The Spark UI plus event logs record per-stage, per-task, per-executor and per-SQL-node metrics (shuffle bytes, spill, GC time, skew, AQE decisions) for every run.

**Why people bounce off it:** The Jobs/Stages/Executors/SQL tabs expose hundreds of numbers, and a slow job means reading task-quantile tables to spot one 22-minute straggler task among 4,000. Then you have to map it back to a plan node and pick from 100+ interacting configs (shuffle.partitions, AQE skewJoin, broadcast threshold, executor memory overhead). Most teams respond by doubling the cluster size.

**AI operator:** A 'Spark Performance Doctor'. It pulls event logs and the SQL plan through the History Server REST API and computes skew ratio, spill, GC share and small-file counts per stage. It diffs a slow run against the last good run, ties the hot stage to a plan node and source line, and proposes a minimal fix (null-key isolation, broadcast hint, AQE settings, repartition, memory overhead). It then re-runs on a sample partition and shows before/after metrics. Anything touching prod config goes through a PR.

**Killer example:** User: 'The nightly orders job went from 40 minutes to 3 hours since Tuesday. Fix it, and don't just add nodes.' AI diffs Tuesday's run against Monday's. Stage 14 has a max task of 22 min against a median of 8 s on the customer_id join. Since Tuesday's upstream change, 38% of rows carry the placeholder key 'unknown', and 180 GB spills at the default 200 shuffle partitions. It splits the placeholder key out of the join, enables AQE skewJoin, and re-runs yesterday's partition: 28 minutes, zero spill. It opens a PR with the code diff and a before/after metrics table, and notes that doubling the cluster would have cost about $310/night and fixed nothing.

**Integration path:** Spark History Server REST API (/api/v1/applications/{id}/stages/{sid}/taskSummary, /executors, /sql), event-log JSON from S3/HDFS/GCS, spark-submit, Livy, the EMR Steps API, Dataproc batches and the spark-on-k8s operator. Headless and scriptable, easy to expose as an MCP server. Solo MVP: read-only event-log diagnosis plus config-diff generation, then rerun orchestration. Caveat: AWS has a Spark troubleshooting agent for EMR/Glue and Databricks has its own assistant, so the gap is OSS, Kubernetes, Dataproc and on-prem Spark, plus verified cross-run regression diffs.

**Demand 5/5 · Buildability 4/5**

### 2. SELinux on RHEL/Rocky/Alma/Fedora/Amazon Linux (auditd, semanage, setroubleshoot) `open-source`

**Why it's powerful:** Mandatory access control confines every daemon to a minimal policy. It contains compromised services and is required for many compliance baselines (CIS, STIG, PCI), and it ships enabled on all RHEL-family distros.

**Why people bounce off it:** A denial surfaces as a mysterious 'Permission denied' with the real cause buried in /var/log/audit/audit.log AVC lines (scontext, tcontext, tclass). Fixes live in four different mechanisms (file contexts, port labels, booleans, custom modules). The top Stack Overflow answers are `setenforce 0` or blanket `audit2allow -M`, which silently weakens the system. So many teams set SELINUX=disabled and lose the hardening.

**AI operator:** An 'SELinux Fix Ladder' operator. It runs ausearch/sealert/audit2why on the failing service and clusters the AVCs. It walks the fix ladder in strict order: restorecon or semanage fcontext, then semanage port, then a boolean via setsebool -P, and only last a minimal reviewed custom module. It can put just the one domain in permissive (semanage permissive -a) to collect all follow-on denials and then flips it back. After each change it re-tests the service, and emits the same fix as an Ansible/Salt task so the fleet matches.

**Killer example:** User: 'nginx can't proxy to my app on port 8081 or read /srv/app/static. SELinux is on and I'm not turning it off.' AI finds two denials: httpd_t name_connect to unreserved_port_t, and httpd_t read on var_t files. It runs `semanage port -a -t http_port_t -p tcp 8081`, `semanage fcontext -a -t httpd_sys_content_t '/srv/app/static(/.*)?'` and `restorecon -Rv /srv/app/static`. A curl test passes with zero new AVCs and no custom module, and it explains why `setenforce 0` would have hidden both bugs. It then prints an Ansible snippet with the same two changes for the other 14 hosts.

**Integration path:** Pure CLI over SSH or locally (ausearch, aureport, sealert, audit2why, sesearch, seinfo, semanage, setsebool, restorecon, semodule) plus the ansible.posix selinux/seboolean/sefcontext modules. No GUI or API needed, so it is headless and testable in a container or VM. Solo MVP: an MCP server or CLI wrapper with an enforced ladder and a human-approved apply step. Caveat: Red Hat has a Lightspeed CLI assistant and generic coding agents can run these commands, so the differentiator is the guard-railed ladder, per-domain permissive trials and fleet-wide config-as-code output.

**Demand 4/5 · Buildability 5/5**

### 3. Meta Business Portfolio / Business Settings (Business Manager admin layer: ad accounts, Pages, pixels/datasets, catalogs, system users, partner access, domains) `closed`

**Why it's powerful:** It is the permission and ownership backbone of every Meta advertiser. Assets are either owned by a portfolio or shared with a partner. Each asset (ad account, Page, pixel, catalog, IG account) has its own per-person and per-partner permission grid. System users, admin system users and business-scoped IDs sit on top. Agencies, freelancers and ecom owners all depend on it.

**Why people bounce off it:** Access is spread across dozens of per-asset screens, and nobody can easily answer 'who can touch what' or 'which assets do we own versus merely share'. Offboarding a person or agency means clicking through every asset, and missing one leaves a live back door or a single-admin account.

**AI operator:** A natural-language access and asset-ownership operator. It reads the whole portfolio graph through the Business Management API (owned_ad_accounts, client_ad_accounts, system_users, assigned_users per ad account, pixel and catalog, and the clients and agencies edges). It answers who can touch what and what is owned versus shared. It produces a diff-style change plan and applies it only after approval. A scheduled mode flags orphaned assets, over-permissioned partners and unverified domains.

**Killer example:** User: 'Our freelancer Dana left. Remove her everywhere, make sure the agency we fired can't see the Shopify pixel or catalog anymore, and tell me which ad accounts only she had admin on.' AI lists every asset where Dana or the old agency has access and flags 3 ad accounts where Dana was the only admin. Plan: 17 unassign calls plus 2 admin grants to the owner. After approval it executes them and returns a before/after permission matrix. It then warns that the pixel is owned by the agency's portfolio, not the client's, so removing the agency's access would break ad tracking, and lays out the transfer steps first.

**Integration path:** Graph API (Business Management API under the Marketing API): GET and POST/DELETE /act_{id}/assigned_users, /{business}/owned_ad_accounts, /client_ad_accounts, /owned_pixels, /client_pixels, /system_users, /{system-user}/assigned_ad_accounts, /{business}/clients. Needs the business_management scope. A system-user token on the user's own portfolio avoids full app review; a multi-tenant SaaS needs Advanced Access review. Standard-access apps get one system user, and Meta has tightened pixel sharing, so some transfers fall back to guided UI steps. MVP: read-only audit plus write-with-approval, as a CLI, MCP server or small web app.

### 4. Salesforce Omni-Channel and skills-based routing (Service Cloud, Sales Engagement, and Messaging) `closed`

**Why it's powerful:** Omni-Channel is the engine that pushes cases, chats, messaging sessions, leads and custom objects to the right agent based on skills, capacity, presence status and priority. Every large Service Cloud org uses it, and as Agentforce handles first contact, it also decides what reaches a human.

**Why people bounce off it:** One routing rule requires about eight objects that must line up: a Service Channel, a Queue, a Queue Routing Configuration, Skills and Service Resource assignments, Presence Statuses, Presence User Configs, an Omni flow (Route Work), and fallback queues. A mistake produces silent non-routing: work sits in a queue and nothing says why. Capacity arithmetic across channels is a spreadsheet exercise.

**AI operator:** A routing architect that reads the current routing config from the org and then explains or changes it. It answers 'why did case 00123456 not route?' by walking the chain (queue, routing config, skills, capacity, presence). It converts a plain-language routing policy into Metadata API files, shows a diff before deploying, and simulates the result against the last 30 days of cases.

**Killer example:** Support manager: 'Spanish billing cases go to agents with Billing L2 and Spanish. After 10 minutes with no match, drop Billing L2 and send to anyone who speaks Spanish. Cap everyone at 5 open cases but only 2 chats. Last week 37 cases sat unrouted.' AI creates the skills, the skills-based QueueRoutingConfig with dropAdditionalSkillsTimeout 600, the channel capacities, the Presence User Config and the Route Work flow step. It shows the diff and replays last week's 37 cases: 31 would have routed, 6 would not because nobody holds the Spanish skill. It names the six agents it suggests adding the skill to.

**Integration path:** Salesforce Metadata API and sf CLI (sf project deploy start): QueueRoutingConfig (API v44.0+, with isAttributeBased, QueueRoutingConfigSkill and dropAdditionalSkillsTimeout), ServiceChannel, PresenceUserConfig, Queue, Skill and Flow are documented types. Skills and ServiceResource/ServiceResourceSkill are data records via REST. The replay simulation is SOQL over history plus a local engine. Omni-Channel must be enabled, so sandbox testing needs a Service Cloud licence. One search found no first-party AI setup agent for routing, but that is unconfirmed. Dynamics 365 Unified Routing is the analogous Microsoft product.

**Demand 4/5 · Buildability 4/5**

### 5. Excel + Google Sheets version history (OneDrive/SharePoint versions, Excel 'Show Changes', Drive revisions): cell-level change forensics `closed`

**Why it's powerful:** OneDrive, SharePoint and Drive silently keep dozens to hundreds of full snapshots of every shared workbook, with author and timestamp. The full audit trail of who changed which input, formula or hardcode is already stored.

**Why people bounce off it:** The UI gives no usable diff. Version History only opens a snapshot beside the current file and you eyeball them. 'Show Changes' lists only recent edits. Spreadsheet Compare is Windows-only, Pro Plus-only and cell-by-cell, and can't answer 'which edit changed the Q3 total?'. Autosave splits one session into many versions, so people restore a backup and lose the good edits too.

**AI operator:** A read-only forensic agent. It lists every version through the API, exports each snapshot, and diffs values, formulas, named ranges, hidden sheets and row/column structure between consecutive versions. It collapses autosave noise into per-author editing sessions, traces the effect of a change (changed cell, precedents, affected outputs) and answers in plain English. Optionally it builds a repaired copy that reverts only the bad edits, leaving the original untouched.

**Killer example:** User: 'The FY27 budget total dropped 340k since Friday and nobody admits touching it. What happened?' AI scans 61 versions and replies: 'On Monday at 09:12, Priya Nair overwrote the formula in Inputs!C14 (=Headcount!F20*Rates!B3) with the hardcoded value 118,000. That flowed through to Summary!D9 and caused the -340,200 swing. Nothing else changed since Friday. Want a copy with only that cell reverted, and a one-line note for Priya?'

**Integration path:** Microsoft Graph: GET /drives/{id}/items/{id}/versions and /versions/{vid}/content return each snapshot with lastModifiedBy and timestamp. Parse the .xlsx with openpyxl (formulas, plus data_only=True for cached values), diff the sheet XML, and use an LLM to narrate and cluster. Google Drive revisions.list/get with export links is a best-effort Sheets path (old revisions get pruned). Output is a Markdown/HTML report or a revert patch applied to a copy. Limits: granularity is per saved version, and the sync client must have kept versions on.

**Demand 3/5 · Buildability 4/5**

### 6. Cloud Custodian (c7n, CNCF incubating; AWS/Azure/GCP/Kubernetes governance engine) `open-source`

**Why it's powerful:** One YAML policy language can find and act on any cloud resource. It has filters (value, JMESPath, event, offhours, age, unused) and actions (tag, mark-for-op, stop, delete, notify, remediate). It runs pull-mode or serverless on a schedule or on CloudTrail/Config events, and c7n-org fans it out across hundreds of accounts.

**Why people bounce off it:** You must learn the exact resource-type names (aws.ec2 vs aws.ebs-snapshot), the filter and value_type grammar, per-resource action lists and the mode and IAM-role setup. The schema is browsed through `custodian schema` in a terminal. Policies are destructive, so people fear a typo stopping production and write only report-only policies.

**AI operator:** A 'Policy Author with a safety harness'. It turns a sentence into policy YAML using the live schema, runs `custodian validate`, then `--dryrun` across the target accounts and shows the matched-resource table with an estimated monthly cost. It stages rollout as notify only, then mark-for-op with a grace period, then the real action, and auto-adds guard filters (exclude tag:keep, prod accounts, resources younger than N days). Deployment needs explicit approval.

**Killer example:** User: 'Anything in our dev accounts without an Owner tag should get a warning email, and be stopped after 7 days. Never touch prod or anything tagged keep.' AI writes a two-policy set (mark-for-op plus notify, then stop-when-marked) scoped through c7n-org to the 6 dev accounts with the exclusions. The dry run matches 212 instances (31 excluded as keep or too new, about $9.4k/month at stake). After approval it deploys in periodic Lambda mode and posts a weekly report of what was marked and stopped.

**Integration path:** `custodian schema|validate|run --dryrun|report` CLI with resources.json outputs, c7n-org for multi-account runs, the c7n Python library, and Lambda/Azure Functions modes. Fully headless, and dry-run is a built-in safety rail. Solo MVP: schema-grounded YAML generation, validation and a dry-run summarizer, with deploy later. Partial overlap with AWS Config/Org tag policies, which cannot take actions.

**Demand 3/5 · Buildability 4/5**

### 7. Temporal (open-source durable-execution server; Temporal Cloud) `open-source`

**Why it's powerful:** It gives code-defined workflows durable state, automatic retries, timers, signals and exactly-once-style semantics that survive crashes and deploys. It has full event history per workflow, a visibility query language and batch operations.

**Why people bounce off it:** A stuck workflow shows up as a raw JSON event-history timeline. Non-determinism errors after a deploy, patched()/getVersion and Worker Versioning rules, reset points, retry-policy interactions and task-queue backlogs are poorly explained by the Web UI. Mass remediation means hand-writing visibility queries and CLI batch jobs, and one wrong reset can replay a payment activity.

**AI operator:** A 'Workflow Doctor'. It groups stuck or failed executions by failure signature through the visibility API, replays exported histories against the current worker code with the SDK replayer to find the first mismatching command, and drafts the patched()/versioning fix plus a replay regression test. After approval it runs batch reset, signal or terminate in canary waves, always with a dry-run count and an idempotency warning for non-idempotent activities.

**Killer example:** User: 'After this morning's deploy about 3,200 order workflows are stuck with nondeterminism errors. Fix it without losing in-flight orders.' AI lists them and replays 20 sampled histories. The divergence is at event 41, where the diff reordered reserveInventory and chargeCard. It proposes a patched() guard and a replay test that passes on all 20. After you deploy, it resets workflows to the last WorkflowTaskCompleted before event 41 in batches of 100 (canary of 10 first). Result: 3,187 recovered, 13 flagged for manual review because chargeCard already ran.

**Integration path:** temporal CLI (workflow list/show/describe/reset/batch with --output json), the gRPC WorkflowService API (ListWorkflowExecutions, ResetWorkflowExecution, batch operations), and the replayer in the Go/Java/TS/Python SDKs. Works against self-hosted and Cloud via API keys. Solo MVP: an MCP server wrapping the CLI plus a replay-diff script. No first-party AI exists today.

**Demand 3/5 · Buildability 4/5**

### 8. PowerPoint / Word decks and memos tied to Excel models: number tie-out and internal-consistency checker `closed`

**Why it's powerful:** The Office stack is where every board deck, banker's pitch, audit memo and consulting report gets assembled. Numbers are pasted or linked from Excel into slides and Word text, and one wrong figure can be embarrassing or legally costly.

**Why people bounce off it:** Tie-out is a manual ritual: an analyst opens the deck beside the model and ticks off every figure with a highlighter at midnight. Nothing in Office does this. Linked charts go stale, pasted images can't be checked, and rounding, units ($M vs $K) and period labels drift between summary, body and appendix. Existing tools compare Excel to Excel, not Excel to prose and slides.

**AI operator:** A tie-out agent that takes a deck or doc plus its source workbook(s). It extracts every number with its label, unit and period, fuzzy-matches each to a source cell or a derivable one (sum, delta, margin, CAGR), and produces a log marking each tied, tied-with-rounding, mismatched, source-not-found or unverifiable (image). It flags internal contradictions inside the deck and writes the log back as a colour-coded workbook and PowerPoint comments on the offending shapes.

**Killer example:** User: 'Tie out the board deck against Q3_Model_v12.xlsx before it goes at 8am.' AI: 'Checked 412 figures. 396 tie, 9 tie with rounding, 4 mismatch: slide 6 EBITDA margin 18.2% vs model 17.9% (stale linked chart); slide 9 shows ARR $41.3M but the model's Units row says $41.3K; slides 3 and 12 give customer counts of 1,204 vs 1,240 (model: 1,240). 3 figures are in pasted images and could not be verified. I commented on each offending shape. Want me to fix the stale link and re-export the PDF?'

**Integration path:** Headless: python-pptx and python-docx read text frames, tables and chart parts (series values from the embedded workbook or numCache); openpyxl with data_only=True reads cached model values (Graph Excel API calculation as fallback). Write-back via PowerPoint comments or Graph/Office.js. Delivery: CLI, a SharePoint/OneDrive Graph app, or an Office.js task pane. Hard parts: label-to-cell matching, units/sign conventions, deciding when two numbers are the same fact, so expect a human-review UI.

**Demand 4/5 · Buildability 3/5**

### 9. Walmart Connect Advertising (Sponsored Search / Sponsored Brands / Sponsored Videos for Walmart.com) `closed`

**Why it's powerful:** Walmart.com is the number-two US e-commerce channel and its ad platform is growing fast. It needs a different playbook from Amazon: SKU-level ad groups, auto versus manual campaigns, keyword bids, placement multipliers and negative keywords.

**Why people bounce off it:** The UI is thin, bulk spreadsheet workflows are clunky, and keyword harvesting between auto and manual campaigns is manual. Most Walmart marketplace sellers pay for ads they cannot tune.

**AI operator:** A conversational ads operator. It reads search-term and keyword performance, promotes winning auto-campaign queries to exact-match manual keywords with sensible bids, adds negatives for wasteful terms, applies ROAS/ACOS targets, rebalances budgets across SKUs and pauses campaigns when an item goes out of stock. It cross-references Marketplace inventory and the Buy Box. Writes happen in guarded batches with spend caps and a change log.

**Killer example:** User: 'My ACOS on the Walmart pet-supplies campaigns is 38% and I want 22%. Fix it without killing volume.' AI pulls 30 days of keyword and search-term reports, lists 41 terms with 120+ clicks and no orders to add as negatives, and moves 12 converting auto-campaign queries to exact keywords. It cuts bids on 18 keywords outside the target band and shows the projected spend change. After approval it applies the changes in batches under hourly API limits and posts a day-7 check.

**Integration path:** Walmart Connect Sponsored Search REST APIs on developer.walmart.com: campaigns, ad groups, keywords (PUT /api/v1/keywords, suggested-keyword and bid-recommendation endpoints), snapshot reports, negative keywords. Advertiser enables access through Streamlined Activation. Hourly rate limits and ~50 keywords per call mean a queue and snapshot-reader are needed. MCP server plus thin chat UI. Partner approval takes time; sellers can use their own credentials.

**Demand 4/5 · Buildability 3/5**

### 10. Celonis Execution Management System (process mining: Data Pools, Data Models, Transformations, PQL, Studio analyses) `closed`

**Why it's powerful:** Celonis reconstructs how work really flows (order-to-cash, procure-to-pay, ticket handling) from ERP/CRM tables. It finds bottlenecks, rework loops and late payments, and can trigger automations. Fortune-500 ops and finance teams own licences, but only a small CoE can use it.

**Why people bounce off it:** Before any chart appears, someone must write SQL transformations that build an event log, define the data model joins, and write PQL for every KPI, filter and variance. Business users who ask 'why are invoices late?' hit this wall.

**AI operator:** A 'Process Analyst Operator' that inspects data pools, drafts event-log transformations, authors and validates PQL (runs it against the model and checks results) and assembles Studio analyses. It proposes the case/activity/timestamp mapping and always shows the PQL it ran so a CoE reviewer can audit it.

**Killer example:** AP manager: 'Why are 18% of our supplier invoices paid late, and which vendors and plants drive it?' AI inspects the P2P data model, writes PQL for throughput time and late-payment rate, and breaks it down by vendor, plant and payment-block reason. It finds 60% of late cases pass through a manual 'price variance' block, saves a Studio analysis with a weekly KPI, and posts the top 10 vendors with example case IDs and the PQL used.

**Integration path:** PyCelonis (Python SDK) and Celonis public REST APIs cover data pools, data models, transformations, PQL execution and Studio package import/export. Headless with an application key. Risk: not every Studio widget layout is writable via API, so the MVP targets PQL, data-model and transformation authoring plus Studio package files. PM4Py + OCEL is a self-hostable fallback.

**Demand 4/5 · Buildability 3/5**

### 11. Conga Composer for Salesforce (the AppExchange document-generation standard; Nintex DocGen and Salesforce Document Generation as later connectors) `closed`

**Why it's powerful:** Conga Composer merges any Salesforce record, related lists and SOQL results into Word, Excel, PowerPoint and PDF templates with conditional blocks and multi-object merges. It generates proposals, quotes, contracts and renewal letters, and sales ops treats it as the final step of the deal flow.

**Why people bounce off it:** Every output depends on a Merge Query (SOQL plus alias), a Word template with TableStart/TableEnd merge fields, and a Solution record binding both to a button. Common failures are mismatched aliases, empty tables in Lightning, wrong sharing context, and Classic-to-OAuth button conversion. Admins debug by launching and retrying, and most orgs have one person who understands it.

**AI operator:** A Composer builder agent. It reads the object schema with describe calls, writes the Merge Query with correct aliases and field API names, generates the .docx template with python-docx, creates the Solution record and launch button, then runs a test merge against a named sample record and checks whether tables came out empty. If so, it fixes the alias and re-runs.

**Killer example:** Admin: 'Build a quote PDF for Opportunities with the account billing address, a table of Opportunity Products (qty, list price, discount, total), a payment-terms paragraph only if Terms = Net 60, and our logo in the header. Add a button and test it on Acme - Renewal.' Agent writes the queries and template, registers the Solution and button, merges Acme, and reports: 'Product table has 6 rows, Net 60 paragraph shown, total matches the Opportunity amount of $48,200.'

**Integration path:** Salesforce REST/SOQL describe calls to read schema and existing Conga Solution/Query/Template records. Conga's Ingress API has POST /v1/queries; Composer merge launch (API/background mode) is the generation path. GATES TO CHECK FIRST: whether Solution and Template objects (APXTConga4__) are createable (fallback: Playwright UI setup); a Composer sandbox licence; whether Ingress API covers Composer; whether Conga's own AI doc-generation already covers this. Conga is steering customers to newer products, so pitch at the installed base facing migration.

**Demand 4/5 · Buildability 3/5**

### 12. Teamwork.com (project management / professional services automation for agencies and client-service firms) `closed`

**Why it's powerful:** Teamwork is more capable than most PM tools for agencies: templates with relative-date task lists and dependencies, billable and cost rates, retainer and fixed-fee budgets, custom fields, workload planning, time approvals, invoicing and automations.

**Why people bounce off it:** Setup is spread over several settings areas that depend on each other (rates, budgets, templates, project-level overrides), so the first month of rollout is mostly misconfiguration. Agencies often discover months later that a retainer was never tied to a rate card.

**AI operator:** An 'Agency Ops Operator' that holds the agency's playbook (rate cards, project types, naming and tagging rules). It creates projects from templates with the right dates, rates and budget, audits running projects for drift (no budget, wrong rate, missing milestones, unbillable time) and bulk-fixes after showing a diff.

**Killer example:** User: 'Kick off the Acme website rebuild. Fixed fee 48k, launch Feb 27, use our web-build template, Priya as PM, 15% internal margin. Then tell me which running projects are burning budget faster than their timeline.' AI instantiates the template with dates back-calculated from Feb 27, assigns the team, sets budget and rate card, tags the project, then ranks at-risk projects by burn vs schedule with the offending task lists.

**Integration path:** Teamwork.com REST API v3 (/projects/api/v3/, token or basic auth), sparse fieldsets, paging and custom fields; some v1/v2 endpoints still back templates. Webhooks for triggers. Free trial gives a sandbox. Unconfirmed: whether automation rules and rate/budget settings are fully writable, so the first step is an endpoint coverage check.

**Demand 3/5 · Buildability 4/5**
