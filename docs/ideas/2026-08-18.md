### 1. Zoom (Zoom Workplace: admin portal, Webinars, Zoom Phone) `closed`

**Why it's powerful:** Zoom is far more than a video window. The web portal runs a three-tier settings hierarchy — Account > Group > User — with per-setting lock icons, SSO/SAML attribute mapping with domain-verified auto-provisioning, role-based admin delegation and granular license assignment. Webinars add registration with approval workflows, custom registration questions, source-tracking links, panelists vs attendees, practice session, Q&A, polls/quizzes, live streaming and post-event attendance reports. Meetings add pre-assigned breakout rooms, waiting-room customisation, meeting authentication profiles, alternative hosts, and cloud recording with audio transcript and separate participant audio files. Zoom Phone is a full cloud PBX (auto receptionists, call queues, shared line groups, dial plans, SMS campaigns). Nearly every one of these is reachable through the Zoom REST API v2 plus webhooks, which is unusually deep for a product this consumer-known.

**Why people bounce off it:** The most-reported wall is "Locked by Admin": a user — often even the account owner — toggles a setting on their own page and nothing happens, because the effective value is set and locked at account or group level, and no screen anywhere shows you the effective value and where it came from. Webinar setup is a chain of ordering dependencies: you cannot add registrants until registration is set to Required, and the API answers with a 404 `Registration has not been enabled for this meeting`; bulk-adding attendees trips error code 3000, `You have reached the limit for the number of attendees you can add`. Breakout-room pre-assignment silently fails unless each participant signs in with the exact Zoom-account email in the CSV, so hosts arrive to empty rooms with no error at all — and breakout rooms are not a native webinar feature, so people build the wrong event type and discover it live. License hygiene is the classic trap: deactivating a user does not reclaim the license, and the confirmation dialog never says so, so seats stay billed; the default Users view has no last-login column, so finding dead seats needs a separate Active Hosts report. Recording and security settings are scattered across Meeting/Recording/Telephony tabs with independent lock states, and "require authentication to join" plus authentication profiles routinely locks out the exact external guests a meeting was created for.

**AI operator:** Four skill packs. **Settings governance** fetches account, group and per-user settings, computes the effective value and lock source for any setting, and can enforce a policy across groups. **Webinar production** clones a past webinar's full configuration, creates registration questions and source-tracking links, adds panelists, polls and Q&A settings, then pulls the post-event participant and registrant reports. **License and seat hygiene** reconciles Active Hosts reports against assigned licenses and produces a reclaim plan. **Zoom Phone routing** reads and edits call queues, auto receptionists and business hours in plain language. Safety model: GET-before-PATCH with the prior JSON stored as a rollback snapshot, the literal request bodies presented as a diff, explicit confirmation for anything affecting more than one user or touching billing, and typed confirmation for user deletion, license removal and recording deletion. It runs on a Server-to-Server OAuth app carrying only the scopes the enabled skills need, so a marketing-only deployment never gets `user:write:admin`. What makes it more than a chat wrapper is the inheritance simulator: it models account/group/user precedence and lock state, so it can answer "why can't Priya turn on cloud recording" with the actual originating group and setting name, then fix it at the right level rather than the level the user was clicking on.

**Killer example:** User says: *"Set up next Thursday's customer webinar exactly like the Q2 one, but cap it at 800, require registration with approval, and add Dana and Raj as panelists."* → AI calls `GET /v2/users/{userId}/webinars` to locate the Q2 webinar, `GET /v2/webinars/{webinarId}` to read its full settings object, checks the account-level lock on "require registration" via `GET /v2/accounts/{accountId}/lock_settings` before promising anything, `POST /v2/users/{userId}/webinars` with the copied settings (`approval_type=1`, registration_type, `practice_session=true`, `registrants_confirmation_email=true`), `POST /v2/webinars/{id}/panelists` for Dana and Raj, `POST /v2/webinars/{id}/polls` to recreate the polls, creates the registration source-tracking links, and schedules a post-event `GET /v2/report/webinars/{id}/participants` export.

**Integration path:** Zoom REST API v2 at `api.zoom.us/v2` with Server-to-Server OAuth (`account_credentials`) or user-level OAuth; granular scopes such as `meeting:write:admin`, `webinar:write:admin`, `user:write:admin`, `report:read:admin`, `phone:write:admin`. Verified endpoint families: `/users/{id}/settings`, `/accounts/{id}/settings`, `/accounts/{id}/lock_settings` (PATCH), `/users/{id}/webinars` and `/webinars/{id}/registrants|panelists|polls`, `/report/webinars/{id}/participants`, plus the Zoom Phone and Zoom Rooms API families and event webhooks. Breakout pre-assignment rides inside the meeting settings object (`settings.breakout_room` with named rooms and participant emails) rather than a standalone endpoint. Honest gaps: an app must be created and admin-approved inside the customer's account (internal apps are fine; a published Marketplace app needs Zoom review), a handful of portal toggles have no API equivalent, and API-created objects still obey account-level locks — so the operator must read lock state before it can promise a change.

### 2. Azure Data Factory `closed`

**Why it's powerful:** ADF is the default enterprise integration engine in the Microsoft estate, with 90-plus native connectors, a Copy activity handling binary/tabular/hierarchical formats with staged copy and PolyBase/COPY-INTO acceleration into Synapse, and Mapping Data Flows that compile a visual design into Spark jobs so users get real transformation power without writing Scala. Control flow is genuinely expressive: Lookup, ForEach with parallelism, Until, If Condition, Switch, Web/Webhook, Execute Pipeline, and a full expression language over activity outputs. Integration Runtimes let one factory reach Azure services, on-prem SQL Server behind a firewall (self-hosted IR), and lift-and-shifted SSIS packages (Azure-SSIS IR). Triggers include schedule, tumbling window with dependency chains and backfill, storage events, and custom events via Event Grid. Everything is JSON in Git with ARM-template deployment, and it plugs directly into Key Vault, Managed Identity, Purview lineage and Log Analytics.

**Why people bounce off it:** The Integration Runtime concept is where most people fall off — `UserErrorJreNotFound` because 64-bit self-hosted IR needs a 64-bit JRE, and *"The Integration Runtime (Self-hosted) node has encountered an error during registration"* when a proxy or firewall blocks the service-bus endpoints. Both require server-admin work in a product that looks like a drag-and-drop designer. Copy failures surface as `ErrorCode=UserErrorSourceBlobNotExist` or wrapped connector exceptions where the real cause is a wildcard path or a missing folder. The expression language is the second wall: `@concat`, `@activity('Lookup1').output.value`, `@item().tableName` and `@pipeline().parameters.x` must all agree with the dataset parameters, and a single mismatched quote or an unbound dataset parameter produces a run that copies nothing without failing. Lookup activity silently caps at 5000 rows and about 4 MB, which quietly truncates metadata-driven loops. Mapping Data Flows add a second mental model entirely: debug sessions must be started and warmed (cluster startup in minutes, billed), the Azure IR's TTL setting is what makes iteration bearable, schema drift and "sink has no mapping" errors appear when the source shape changes, and the data-flow script DSL under the canvas is invisible until something breaks. Publish-versus-debug and the ARM-template parameterisation needed to move linked services across environments defeat most teams' first CI/CD attempt. Tumbling-window trigger dependencies and backfill semantics are a third distinct concept nobody reads about until a reprocess goes wrong.

**AI operator:** An operator that owns the factory JSON. **build-metadata-driven-pipeline** generates the control table, parameterised dataset, Lookup → ForEach → Copy pattern with `@item()` bindings and a watermark update, all as valid pipeline JSON. **diagnose-run-failure** walks the run and activity-run history, classifies the error code, and explains the real cause including IR-level issues. **fix-self-hosted-IR** checks node status, JRE presence and proxy reachability and produces the exact remediation or PowerShell. **design-data-flow** emits the data-flow definition and script, starts a debug session, runs a preview on sampled data, and iterates until the output matches the described shape. **parameterise-for-cicd** rewrites ARM-template parameterisation so linked services resolve per environment. Safety model: all authoring happens in a feature branch of the factory's Git integration, never against the live published factory; data-flow validation uses debug sessions with row limits so nothing writes to a sink; publishing requires explicit approval and always shows the JSON diff plus an estimated Data Integration Unit and Spark-cluster cost. The differentiator over chat is the debug-session loop — create the session, execute a command against it, read the actual preview rows, and self-correct the transformation before a human ever sees it.

**Killer example:** User says: *"Land these 40 on-prem SQL Server tables into ADLS as Parquet every night, incremental by modified date, and alert me if any table is late."* → AI verifies the self-hosted IR node status via the Integration Runtimes API, creates a Key Vault-backed linked service and a fully parameterised dataset, writes a Lookup-over-control-table → `ForEach(@activity('GetTables').output.value)` → Copy pipeline with `@item().schema`/`@item().table` and a dynamic WHERE on the watermark, adds a Stored Procedure activity to update the watermark, deploys into the Git branch, creates a tumbling-window trigger with a one-hour dependency, kicks a validation run through `pipelines/{name}/createRun`, polls Pipeline Runs - Get and Activity Runs - Query By Pipeline Run until completion, and wires a Log Analytics alert rule on failed runs.

**Integration path:** Azure Resource Manager REST at `management.azure.com/subscriptions/{sub}/resourceGroups/{rg}/providers/Microsoft.DataFactory/factories/{factory}/...` covering pipelines (including `pipelines/{name}/createRun`), datasets, linkedServices, dataflows, triggers, integrationRuntimes, `pipelineruns/queryByFactory`, activityruns, and the data-flow debug session endpoints (`createDataFlowDebugSession`, `executeCommand`, `queryDataFlowDebugSessions`). Also `az datafactory` CLI, PowerShell `Az.DataFactory`, official SDKs, ARM templates, and the Git-integrated JSON files themselves, which are the cleanest authoring surface. Auth is Microsoft Entra ID (service principal or managed identity) with the Data Factory Contributor role. Honest gaps: self-hosted IR host-level fixes (JRE install, proxy config) require action on the VM outside the ADF API, and a few newer preview connectors have properties not yet reflected in the published schema.

**Demand 5/5 · Buildability 5/5**

### 3. Autodesk Fusion (Fusion 360) `closed`

**Why it's powerful:** Fusion puts parametric CAD, direct modelling, assemblies, simulation, generative design, sheet metal, PCB and 2.5- to 5-axis CAM in one cloud-versioned document. The Timeline records every feature, so any early sketch or dimension can be edited and the whole model recomputes. Joints (Rigid, Revolute, Slider, Cylindrical, Pin-Slot, Planar, Ball) plus Motion Links and contact sets give real kinematics rather than static assemblies. User Parameters with units and expressions let a whole design be driven from a table of values. The Manufacture workspace produces real machine code through post processors, with stock/WCS setup, adaptive clearing strategies, tool libraries and simulation. Drawings, sheet-metal flat patterns and derived/linked components tie it into an actual production workflow — and it is priced so that millions of hobbyists, makerspaces and small shops use it daily.

**Why people bounce off it:** The central confusion is Component vs Body. Users model everything as bodies in one component, then discover joints don't work and assemblies can't be exploded, and the fix — Create Components from Bodies, or ticking the New Component operation in Extrude — is invisible until someone tells you. The Timeline is the second wall: change one dimension and a row of features turns into red exclamation markers, usually because a sketch used Project geometry referencing an edge that no longer exists, and the recovery ritual is right-click → Edit → re-pick references, feature by feature. Autodesk's own guidance is blunt that most parametric failures trace to sketches that are not fully constrained, but the only signal is line colour — blue for under-constrained, black for fixed — plus a small status text that beginners never read. CAM multiplies the pain: a Setup with a wrongly oriented WCS or mis-defined stock produces toolpaths that look right on screen and crash the machine, and Post Process fails with post-processor `.cps` errors that mean nothing to a hobbyist. Drawings go "Out of Date" silently after a model change. Derived components from other files show update-available badges and break links entirely when a source file is renamed in the cloud. The result is a huge population of users who can make one part but cannot maintain a parametric model.

**AI operator:** A Fusion Python add-in driving `adsk.core`/`adsk.fusion`/`adsk.cam`. Skills: **model repair** (locate failing timeline features, identify the broken projected reference, re-attach to a stable face or edge), **constraint completion** (find remaining degrees of freedom and propose the missing dimensions and constraints), **parametric refactor** (promote hard-coded numbers into named User Parameters), **component/joint restructuring**, **CAM setup from a plain-language job description**, and **drawing generation**. Safety: before mutating, it saves a named cloud version and records the timeline marker position, so rollback is a single restore; changes are presented as a timeline diff listing exactly which features will be edited and which downstream features are at risk. It never silently changes geometry — under-constrained sketches are shown with the specific degrees of freedom named, and the user approves the proposed dimensions. It reads the actual failure state from the API rather than guessing, so instead of "try re-selecting the reference" it says *"Extrude7 fails because Sketch4 projected an edge deleted by Fillet3; re-project onto Face 12 or move Fillet3 after Extrude7."* That diagnose-explain-fix loop over a real dependency graph is what makes it a tool rather than a chatbot.

**Killer example:** User says: *"Make this bracket take an M5 bolt instead of M4 and re-cut the toolpaths."* → AI edits the `hole_dia` User Parameter — creating it from the hard-coded 4.5 mm value first if it doesn't exist — runs Compute All, detects that a fillet and a projected sketch now fail, re-attaches the projection to a stable face, verifies wall thickness against a minimum, then updates the CAM Setup's tool selection and drill operation, regenerates the toolpaths and re-posts NC code with the existing `.cps` post.

**Integration path:** The Autodesk Fusion API is a first-class documented Python and C++ API (`adsk.core`, `adsk.fusion`, `adsk.cam`) with the in-app Scripts and Add-Ins manager, custom features, command inputs and event handlers; add-in samples and the official API help are published by Autodesk alongside a dedicated Fusion API forum. Cloud-side data (projects, versions, references) is reachable via the Autodesk Platform Services Fusion Data API (GraphQL) using standard 3-legged OAuth. Post processors are readable `.cps` JavaScript files. Honest gaps: the desktop API is in-process only — no external RPC, no headless Fusion — so the operator must ship as an add-in hosting its own local socket; the API is effectively single-threaded with documented Python-specific constraints; some CAM and simulation functionality is only partially exposed; and cloud/desktop state can diverge when a design has unsaved changes.

**Demand 5/5 · Buildability 4/5**

### 4. Oracle Fusion Cloud ERP (Financials) `closed`

**Why it's powerful:** Fusion Financials ships a rules-driven accounting engine — Subledger Accounting — where you define journal line rules, account derivation rules and mapping sets that translate any subledger event into GL entries without code. It supports primary, secondary and reporting-currency ledgers for parallel GAAP, account hierarchies as versioned Trees, cross-validation rules, and Intercompany Balancing rules that auto-generate due-to/due-from lines. AutoInvoice, Payment Process Requests, invoice holds and release rules, Revenue Management for ASC 606, and Joint Venture Management all run off the same ledger. Reporting is three stacks in one: Financial Reporting Studio against the GL balances cube, OTBI against subject areas, and BI Publisher for pixel-perfect output. Approval routing is a full BPM rules engine with attribute-driven, parallel and serial approvers.

**Why people bounce off it:** Setup lives in Functional Setup Manager as Offerings → Functional Areas → Setup Tasks, and finding the one task that controls a behaviour is genuinely a search problem. Journal Import is the canonical trauma: it completes "with errors" and hands you terse codes — `EF04` *Invalid Accounting Flexfield* (which really means a cross-validation rule or a disabled segment value), `EU01`/`EU02` for unbalanced journals where EU02 means suspense posting isn't allowed, `EF01` for an invalid ledger — and the fix path is the Correct Import Errors spreadsheet against `GL_INTERFACE`, which most accountants have never opened. Bulk loading via FBDI means downloading an XLSM template, generating CSVs, zipping them, uploading to the correct UCM account (`fin$/generalLedger$/import$` — get the path wrong and the ESS job simply finds nothing) and then submitting the right scheduled process. The Scheduled Processes UI lists hundreds of near-identical job names — Import Journals, Create Accounting, Post Journals, Transfer Transactions from Receivables to General Ledger, Validate Payables Invoices — with ordering dependencies nobody documents for you. Security is a second maze: Data Access Sets, Security Console job roles, data role provisioning and segment value security together produce "you do not have access to this ledger" with no hint which of the four layers blocked you. Approval changes require the BPM Worklist with its own rule syntax, a different UI from everything else.

**AI operator:** An **FBDI skill** takes a plain CSV or a description, maps it onto the correct FBDI template columns, zips it, uploads via the `erpintegrations` REST resource with `OperationName=importBulkData`, submits the ESS job with `submitESSJobRequest`, polls `getESSJobStatus` and downloads the execution details. An **error decoder** reads the Journal Import output and translates EF04/EU01/EF01 into the specific offending segment value, cross-validation rule or ledger. A **reporting skill** authors OTBI analyses and BI Publisher data models from a question. A **setup skill** uses FSM's Export/Import Setup Data CSV business objects to propose configuration changes as reviewable diffs. Safety: everything is dry-run first against a test ledger or a validate-only pass, and any journal is previewed as full line detail plus total debits/credits/net before submission. Hard blocks on posting into a closed or Close Pending period, on any FBDI touching more than a configured line threshold without a second approver, and on changes to cross-validation rules or Data Access Sets. Every call is logged with the literal REST payload so an auditor can reproduce it. It is more than a chat wrapper because it owns the whole asynchronous chain — build file, upload to the right UCM account, submit, poll, read the log, fix, resubmit — which is exactly the part humans get wrong.

**Killer example:** User says: *"Load last month's payroll accrual from this spreadsheet into the US ledger and post it."* → AI maps the columns onto the GlInterface FBDI template, validates every account combination against the chart of accounts and active cross-validation rules first, zips the CSV, POSTs to `/fscmRestApi/resources/11.13.18.05/erpintegrations` with `OperationName=importBulkData` targeting the `fin$/generalLedger$/import$` UCM account, calls `submitESSJobRequest` for Import Journals, polls `getESSJobStatus`, finds 3 lines rejected with EF04, identifies the exact disabled cost-centre segment value causing it, shows the fix, and after approval resubmits and then runs Post Journals.

**Integration path:** REST at `/fscmRestApi/resources/11.13.18.05/*` (invoices, suppliers, receivables, journals via the `erpintegrations` resource), with documented erpintegrations operations `importBulkData`, `submitESSJobRequest`, `getESSJobStatus`, `downloadESSJobExecutionDetails`, `exportBulkData`. BI Publisher via the `ExternalReportWSSService` SOAP endpoint (`runReport`) for anything not in REST. FBDI as XLSM → CSV → ZIP over UCM. FSM Export/Import Setup Data CSV packages give a real, supported path for configuration-as-data. Auth: Basic auth for an integration user, or OAuth/JWT via OCI IAM. Honest gaps: FBDI is batch-only and fully asynchronous with a recommended 250 MB ZIP cap, so nothing is real-time; there is no REST for editing BPM approval rules; and many setup tasks are only reachable through FSM CSV round-trips rather than a proper API.

**Demand 5/5 · Buildability 4/5**

### 5. Jamf Pro `closed`

**Why it's powerful:** Jamf Pro is the de-facto Apple fleet management platform (Jamf reports 76,000+ customers) and it is far deeper than generic MDM. Smart Computer and Mobile Device Groups build live-recalculating cohorts from dozens of inventory criteria including script-generated Extension Attributes. Configuration Profiles cover the full Apple payload surface — Restrictions, PPPC, Managed Login Items, Software Update deferrals, Content Caching — and can be authored as raw plist. Policies fire on triggers (Enrollment Complete, Recurring Check-in, Login, Self Service) to run scripts, install packages, bind directories and set FileVault escrow. Patch Management ties software title definitions to patch policies for versioned rollouts, PreStage Enrollments drive zero-touch Automated Device Enrollment, Self Service turns any policy into an on-demand app portal, and Declarative Device Management support keeps it current with Apple's newer management model.

**Why people bounce off it:** The Scope tab's three-part Targets / Limitations / Exclusions model is the single biggest trap — Jamf Nation is full of threads like *"targeting groups excluded smartgroups are not being excluded from scope"* and *"restricted software policy for exclusion does not seem to work."* The accepted community answer for scoping to an LDAP group is to set Targets to All Computers and All Users and then put the LDAP group under Limitations; one admin's exact wording was that "the wording on it is garbage but that is how it works." Jamf Pro also cannot query LDAP *computer* groups at all, only user groups. Smart Group membership only recalculates on inventory update or recurring check-in, so admins conclude a policy is broken when it is merely stale. Failures surface as a wall of opaque MDM errors under the computer record's Management → Management Commands → Failed Commands, and profiles sit in Pending indefinitely when User-Approved MDM was never granted. The folk remedy passed around the community — add the machine to a static group used as an Exclusion, save the profile, then remove it to force a re-push — is a ritual nobody can derive from the UI. Extension Attributes require writing a shell script that echoes a `<result></result>` block. Patch policies silently do nothing unless a matching software title definition *and* a correctly named package both exist. PPPC config profile payloads need Apple identifiers and code requirements copied from the binary, which is not something a school IT generalist can produce.

**AI operator:** Pre-loaded skills for smart-group criteria authoring, scope resolution and diffing, configuration-profile payload generation (including PPPC identifier and code-requirement lookup), policy and script authoring, Extension Attribute generation, patch-policy assembly, and failed-command triage. The safety model is scope-simulation-first: before any write the operator resolves the proposed Targets/Limitations/Exclusions into an explicit device list, shows the before/after membership delta and counts, and requires typed confirmation for anything touching more than a threshold of devices or any FileVault/Restrictions/erase payload. All writes go through a dedicated Jamf API Role with least-privilege endpoint grants, and every change is journalled so the operator can replay or roll back its own edits. What lifts it above a chat wrapper is the effective-policy resolver: it mirrors the Jamf object graph — groups, profiles, policies, packages, EAs, patch titles — locally so it can answer "what actually applies to this Mac and why," a question Jamf Pro itself cannot answer in one place. It also reads the live OpenAPI spec the server publishes so it never calls endpoints that moved between releases, and it correlates Failed Commands against UAMDM state to explain failures in plain language instead of echoing MDM error codes.

**Killer example:** User says: *"Every Finance Mac still on macOS 14 or older should get the FileVault escrow profile, but skip the three loaner laptops."* → AI creates a Smart Computer Group via `POST /JSSResource/computergroups` with criteria Department is Finance AND Operating System Version less-than 15, creates a Static Computer Group holding the three serial numbers, posts the FileVault Recovery Key Redirection profile to `/JSSResource/osxconfigurationprofiles` with Scope Targets = the smart group and Exclusions = the static group, pulls the resolved membership from `/api/v1/computers-inventory` to show the operator the exact 214 machines affected before committing, then polls each device's management-command status and reports back that 9 devices are stuck Pending because they never granted User-Approved MDM.

**Integration path:** Two documented REST surfaces on the same server — the Classic API (`/JSSResource/...`, XML and JSON, covering computergroups, policies, osxconfigurationprofiles, computerextensionattributes) and the modern Jamf Pro API (`/api/v1/...`, `/api/v2/...`, JSON, with an OpenAPI/Swagger spec served by the instance itself). Auth is clean: since Jamf Pro 10.49 you create an API Client with API Roles in the console and do OAuth 2.0 client_credentials against `/api/oauth/token`, or take a bearer token from `/api/v1/auth/token`. No partner program, no marketplace review, works on Jamf Cloud and on-prem alike. Honest gaps: object coverage is split unevenly across the two APIs so an operator must speak both, the Classic API is XML-first with quirky schemas, and Jamf Pro API endpoints migrate between `/v1` and `/v2` across releases — so endpoint discovery should be done at runtime from the published spec rather than hardcoded. Some newer Declarative Device Management objects lag behind the UI.

**Demand 4/5 · Buildability 5/5**

### 6. Microsoft Advertising (Bing Ads) `closed`

**Why it's powerful:** Microsoft Advertising is the second search ad platform almost every performance marketer runs, spanning Bing, Edge, Yahoo, DuckDuckGo and syndication partners, with near-parity campaign types: Search, Shopping backed by Microsoft Merchant Center, Performance Max, Audience Ads across the Microsoft Audience Network, App Install and CTV/display. Its genuinely unique asset is LinkedIn Profile Targeting — targeting and bid-modifying by company, industry and job function, which no other search platform offers. It has full bid strategy coverage (Manual CPC, Enhanced CPC, Maximize Clicks, Maximize Conversions, Target CPA, Target ROAS), the UET tag with conversion goals including view-through, in-market/custom/remarketing/Customer Match audiences, shared budgets, negative keyword lists, website exclusion lists, experiments, automated rules and Clarity integration. Programmatically it is unusually rich: a Bulk service that round-trips the entire account as TSV/CSV, an async Reporting service, and Microsoft Advertising Scripts, a JavaScript host inside the product that can rewrite bids, budgets, keywords and ads.

**Why people bounce off it:** The wall here is a set of concrete, expensive footguns rather than abstract complexity. The Import from Google Ads feature — how most accounts are created — installs a recurring sync under Tools → Import → Import schedule & history, and on every run it can overwrite the changes the advertiser made natively in Microsoft Advertising; people discover this only after a week of tuning silently reverts. The Microsoft Audience Network is the other classic: there is no single switch to turn it off for a Search campaign, so advertisers hunting wasted spend must discover ad-group-level Ad distribution settings and then build website exclusion lists, which are hard-capped at 10,000 URLs per list, 5,000 per upload and 3 lists per account — a limit nobody finds until an upload silently truncates. Conversion tracking fails quietly: a UET tag shows Inactive or Tag unverified and the conversion goal records nothing, and diagnosis requires understanding the split between the UET tag, the conversion goal, and goal-level attribution and count settings. Shopping campaigns need a Merchant Center store ID and an attribute-mapped feed, and feed disapprovals surface in a different product surface than the campaign. On the API side it is SOAP-first across many separate services, and the Bulk file schema has ~100 record types where a blank column means "leave unchanged" but the literal string `delete_value` means "clear it" — a distinction that turns a careless bulk upload into an account-wide wipe. Microsoft's own docs note Scripts have no undo.

**AI operator:** Build the operator around the Bulk service as the primary write path, because bulk TSV is reviewable in a way a stream of SOAP mutations is not. Skills: account structure (campaigns, ad groups, keywords, RSAs with pinning), audience and targeting (LinkedIn Profile Targeting, in-market and remarketing association, geo and device bid modifiers), Audience Network hygiene (ad distribution settings plus website exclusion list management with the 10,000/5,000/3 limits enforced client-side), conversion setup (UET tag verification, conversion goal creation, attribution and counting settings), Shopping/Merchant Center feed diagnosis, negative keyword and search-term mining, budget and bid strategy changes, and Import-from-Google conflict management. The spend-safety model *is* the product: every proposed change is materialised as a Bulk download-modify-upload diff shown as a human-readable table, gated by hard guardrails the user sets once (max daily budget delta, max total account budget, max % bid change per run, never enable a paused campaign without confirmation), plus typed confirmation for anything that increases spend, plus a mandatory sandbox dry-run using the universal sandbox developer token before touching production. It records the pre-change Bulk snapshot so "revert everything you did in the last hour" restores exact prior values. It also proactively surfaces the import-overwrite risk: before writing, it checks the import schedule and warns that the next sync will clobber the edit, and offers to pause or scope the sync.

Output is captured structurally via OMS to XML/SAV, and `.sav` files are readable outside SPSS with `pyreadstat`. Auth is a desktop licence or Statistics Server / subscription. Honest gaps: there is no cloud REST API for desktop SPSS, so the product must ship as a local companion or an add-in driving the installed copy, and the Python plug-in version is tied to the SPSS release, so the operator needs a version-detection layer.
