### 1. Windows Server 2016 end-of-support exit planner (in-place upgrade vs Storage Migration Service vs Arc ESU, per server) `closed`

**Why it's powerful:** Windows Server 2016 still runs a large share of on-prem domain controllers, file servers, IIS and line-of-business boxes. Microsoft ships every exit path at no extra tooling cost: in-place upgrade, Storage Migration Service (SMS), which moves shares, permissions and server identity, a new domain controller with FSMO role moves, and paid Extended Security Updates through Azure Arc.

**Why people bounce off it:** Extended support ends 2027-01-12 (Microsoft Lifecycle page). Each server needs its own decision, and each path has its own procedure: SMS inventory, transfer and cutover jobs, DC promotion and FSMO transfer (SMS can't move a DC), and Arc ESU licensing with edition, pCore vs vCore, core counts and a per-machine license link. Arc ESU for 2016 could be configured from 2026-08-03 and bills from 2027-01-13. Small IT teams have about two months and no planner across the paths.

**AI operator:** It inventories the 2016 fleet from AD and the roles on each server, then proposes a path per server with a cost line: upgrade, SMS move, DC replacement, or ESU for the boxes that can't be touched yet. It runs the chosen path with a checkpoint after each step.

**Killer example:** 'Get FS01 and DC01 off 2016 before January, and put the three line-of-business boxes we can't upgrade yet on ESU as cheaply as possible.' The AI finds the 2016 machines with `Get-ADComputer` and reads their roles with `Get-WindowsFeature`. For FS01 it runs `New-SmsInventory`, `Test-SmsMigration`, `New-SmsTransfer` and a Saturday-night `New-SmsCutover`. For DC01 it promotes the new server with `Install-ADDSDomainController`, moves the roles with `Move-ADDirectoryServerOperationMasterRole`, and checks replication before demoting the old one. For the other three it first onboards each box to Azure Arc by installing the Connected Machine agent (`azcmagent connect`, from memory), then creates one Arc ESU license with `PUT .../Microsoft.HybridCompute/licenses/{name}` (`target: "Windows Server 2016"`, edition, `pCore` or `vCore`, core count) and links each machine with `PUT .../machines/{m}/licenseProfiles/default` (`esuProfile.assignedLicense`).

**Integration path:** The Arc ESU license PUT and the `licenseProfiles` link are confirmed on Microsoft Learn ("Manage ESU licenses programmatically", api-version `2023-06-20-preview`, page updated 2026-10-05), with `Windows Server 2016` as a supported target. The StorageMigrationService module's inventory, transfer and cutover cmdlets are confirmed in the module reference. The AD DS cmdlets and Arc onboarding (`azcmagent`) are from memory; the `licenseProfiles` link only works once a server is Arc-onboarded. Everything runs over PowerShell remoting and Azure Resource Manager, so the product is a local agent plus an ARM client.

Overlap: The Azure Copilot migration agent lists out-of-support servers and builds plans for moving to Azure, but it can't replicate servers and doesn't plan on-prem upgrade vs SMS vs ESU. No Windows Admin Center agent was found. o365hq sells Arc ESU enrollment as a consultancy. This card differs from the 2026-11-07 SQL Server 2016 card (a database instance move with dbatools) and the 2026-10-28 file server and DNS/DHCP cards (day-to-day permissions and scopes, not an OS exit). Re-check how far the Azure Copilot migration agent has grown before building.

**Demand 5/5 · Buildability 4/5**

### 2. Twitch channel modes (AutoMod level, blocked terms, Channel Points rewards, stream schedule) `closed`

**Why it's powerful:** Millions of streamers tune AutoMod by category, blocked and permitted terms, custom Channel Points rewards with cooldowns, per-stream limits and input prompts, and a public schedule with segments.

**Why people bounce off it:** These settings live on separate dashboard pages and have to be redone for every special event: a charity stream, a subathon, a sponsor segment. Most streamers never leave the default AutoMod level or build a rewards economy, and nobody remembers to put things back afterwards.

**AI operator:** It saves "channel modes" described in plain language (family-friendly charity stream, late-night 18+, sponsor hour). It applies a mode across moderation, rewards and schedule in one step, snapshots the previous state first, and reverts when the stream ends.

**Killer example:** 'Tonight is a charity stream at 8pm: strict AutoMod, block these scam phrases, add a 500-point "pick the next song" reward with a two-minute cooldown, and put it on my schedule. Put everything back tomorrow.' The AI snapshots the current settings, then calls `PUT /moderation/automod/settings`, `POST /moderation/blocked_terms` for each phrase, `POST /channel_points/custom_rewards`, and `POST /schedule/segment`. The next day it restores the snapshot and disables the reward.

**Integration path:** All four Helix endpoints are confirmed in Twitch's API reference, with the scopes `moderator:manage:automod_settings`, `moderator:manage:blocked_terms`, `channel:manage:redemptions` and `channel:manage:schedule`. OAuth is a normal user token, so access is open.

Overlap: Twitch ships no AI configurator. StreamChat AI runs its own AI chat and rewards, not Twitch's native settings, and Streamer.bot is a scripting tool. The 2026-10-22 Discord card covers roles, permission overwrites and AutoMod keyword rules on a different platform. This card's job is time-boxed event presets across rewards and schedule, so keep the pitch there and not on moderation alone.

**Demand 3/5 · Buildability 5/5**

### 3. Zendesk Guide help-center restructuring (sections, article placement, user segments, translation gaps) `closed`

**Why it's powerful:** Guide is the self-service help center for most Zendesk customers, and the content that Zendesk AI agents answer from. It has brands, categories and sections, per-locale translations, and user segments that decide who sees each article. Since March 2026 it also supports flexible hierarchies and placing one article in several sections.

**Why people bounce off it:** A product rename or a support reorg means moving hundreds of articles, changing their visibility and finding which locales are now missing. There is no bulk move or bulk visibility change, so admins open articles one at a time.

**AI operator:** It reads the whole help-center tree, proposes a new structure as a diff, then creates sections, moves articles, sets user segments and reports translation gaps. It keeps a change log so the move can be undone.

**Killer example:** 'Split Billing into Invoices and Payments, make anything about refunds agents-only, and tell me which German articles are missing.' The AI creates the two sections and an "Agents only" segment with `POST /api/v2/help_center/user_segments`. It updates each article's `section_id` and `user_segment_id`, then calls `GET /api/v2/help_center/articles/{id}/translations/missing` and lists the German gaps.

**Integration path:** User-segment create, translations, missing translations, and the Redirect Rules API (`/api/v2/guide/redirect_rules`) are confirmed in Zendesk's Help Center API reference. `section_id` and `user_segment_id` are writable article fields, but the Update Article page doesn't show a move in its example, so test the move first: since multiplacement launched, writing `section_id` may only change the primary placement. Section create is from memory. A moved article keeps its ID and translations, so moves need no redirects. Redirect rules only fire on 404s, for deleted or archived articles. There is no bulk article endpoint, so expect one call per article.

Overlap: Zendesk's built-in AI translation is now in Suite and Knowledge plans, and the Knowledge copilot early-access program offers bulk translation, Article builder and Procedure builder. None of them restructures sections or bulk-moves articles. So the card doesn't pitch translating, only the gap report. Risk: Knowledge copilot could expand into restructuring. This card differs from the 2026-08-03 Zendesk Support card (triggers, macros, SLAs) and the 2026-10-23 Zendesk data-model card (ticket forms and custom objects).

**Demand 3/5 · Buildability 4/5**

### 4. SAP Business Network supplier operator (PO-flip invoices, order confirmations, ship notices across customers) `closed`

**Why it's powerful:** Millions of small and mid-size suppliers have to transact with large customers through SAP Business Network (formerly Ariba). Getting confirmations, ship notices and invoices right per customer decides whether they get paid on time.

**Why people bounce off it:** Each buyer has its own rules, such as one customer only accepting network invoices for POs with a given prefix, plus tax, attachment and line-matching rules. Rejections are hard to read. Small receivables teams re-key every confirmation, ship notice and invoice by hand in the PO-flip screens.

**AI operator:** It reads the supplier's own shipments and invoices from QuickBooks, Xero or the ERP, matches them to open network POs, and builds a correct confirmation, ship notice and invoice per customer's rules. It explains rejections and resubmits after fixing them.

**Killer example:** 'Confirm and bill everything we shipped to Cummins last week.' The AI matches last week's QuickBooks invoices to the open network POs. It sends a cXML `ConfirmationRequest` and a `ShipNoticeRequest` per PO, then an `InvoiceDetailRequest` that follows that customer's rules. When an invoice is rejected, it reads the reason, corrects the line and resubmits.

**Integration path:** SAP Managed Gateway for Spend Management and SAP Business Network (formerly CIG) carries `InvoiceDetailRequest`, per SAP Learning's Managed Gateway courses. cXML and EDI integration needs an **Enterprise** supplier account, which can carry fees; Standard accounts are excluded (SAP Learning and the Ariba support FAQ). Whether a third party can submit on a supplier's behalf is unconfirmed, so the MVP runs inside each supplier's own Enterprise account setup. The `ConfirmationRequest` and `ShipNoticeRequest` names are from memory. sap.com blocked direct fetches, so SAP-side claims rest partly on search excerpts.

Overlap: SAP lists generative-AI PDF-to-network-invoice conversion for Q4 2026 ("not a commitment"), invoice only. Intelligent Invoice Error Classification explains rejections but doesn't create documents. The only Business Network Joule agent found is buyer-side supplier onboarding. So this card leaves PDF conversion to SAP and pitches confirmations, ship notices and per-customer rules. The 2026-09-04 Coupa card is the buyer's AP side; this is the supplier's.

**Demand 4/5 · Buildability 3/5**

### 5. Windows Task Scheduler (with macOS launchd as a second connector) `closed`

**Why it's powerful:** It's on every Windows PC and server. Tasks can run on a schedule, at logon, when idle, on a specific event-log entry or on workstation unlock, with up to 32 actions and 48 triggers, power and network conditions, retries and a run-as identity.

**Why people bounce off it:** One task is spread over five dialog tabs. Event triggers need hand-written XPath. "Run whether user is logged on or not" and run-level settings make tasks fail silently, and the last-run result is a hex code. launchd plists are harder still for ordinary users.

**AI operator:** The user describes the job and when it should run. The AI writes the task, registers it, and later explains failures by reading the last-run result and the task history.

**Killer example:** 'Every weekday at 6pm, if the laptop is plugged in, copy D:\Projects to the NAS, retry twice, and tell me if it fails.' The AI builds a robocopy action with `New-ScheduledTaskAction`, a weekly trigger with `New-ScheduledTaskTrigger`, and settings with `New-ScheduledTaskSettingsSet` (no start on battery, two restarts). It registers the task with `Register-ScheduledTask`, then a second task whose event trigger (XPath written by the AI) watches the Task Scheduler log for that task's failure and posts a notification. It checks `Get-ScheduledTaskInfo` after the first run.

**Integration path:** `Register-ScheduledTask` with its XML, Principal and Settings parameter sets, `-CimSession` for remote machines, and the 32-action/48-trigger limits are confirmed on Microsoft Learn. The other ScheduledTasks cmdlets, the failure event IDs and `launchctl bootstrap`/`bootout` are from memory.

Overlap: No Microsoft agent writes Task Scheduler tasks. Copilot Tasks (moving to Copilot Cowork) schedules prompts in Microsoft's cloud, not on the PC. The 2026-10-04 AutoHotkey card writes macros, not scheduled jobs, and the 2026-09-18 Apple Shortcuts card already covers many Mac automations, so launchd stays secondary. Risk: low price point, and Copilot Cowork could reach the local scheduler later.

**Demand 3/5 · Buildability 4/5**

### 6. Asana custom-field consolidation (merge duplicate fields and remap values) `closed`

**Why it's powerful:** Custom fields drive Asana reporting, portfolios, rules and workload views across an organization.

**Why people bounce off it:** Teams create duplicate fields ("Priority", "priority", "Prio") with different options. Asana has no merge, and its forum confirms values must be moved by hand. Deleting a user-created field removes its values from every task, so cleanup risks losing data.

**AI operator:** It finds near-duplicate fields and their options and proposes one canonical field with an option mapping. It attaches the canonical field to every affected project, copies values task by task, verifies them, and only then detaches the old fields.

**Killer example:** 'Merge our six Priority fields into the library one and map P0 to Urgent.' The AI lists the workspace's fields and where each is used. It calls `POST /projects/{project_gid}/addCustomFieldSetting` on each affected project, then `PUT /tasks/{task_gid}` with the mapped `custom_fields` value for every task. After a value-by-value check it removes the old field settings and lists any values it couldn't map.

**Integration path:** `addCustomFieldSetting` and the task update with `custom_fields` are confirmed in Asana's official OpenAPI spec (`Asana/openapi`). Removing a field setting and creating fields are from memory. Expect rate limits on large workspaces, so it needs to page and throttle.

Overlap: No native merge and no Asana AI Studio feature for it was found. One forum post mentions a community field-consolidation app, status unverified. The moat is thin, since a one-off utility could cover it, so it fits best as one skill inside a wider Asana admin operator. The 2026-08-06 Asana card is about automation rules, not field cleanup. The Jira custom-field merge was dropped on 2026-11-05 because the Doctor Pro wizard already does it, and nothing similar was found for Asana.

**Demand 3/5 · Buildability 4/5**
