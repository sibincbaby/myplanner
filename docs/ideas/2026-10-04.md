### 1. Amazon S3 (bucket policies, Block Public Access, lifecycle, replication, Object Lock, access points, Storage Lens) `closed`

**Why it's powerful:** S3 sits under almost every AWS workload: app assets, data lakes, logs, backups and ML datasets. Each bucket has deep controls: resource policies, ACL and Object Ownership, Block Public Access at account and bucket level, lifecycle transitions across 7+ storage classes, same- and cross-region replication with RTC, Object Lock/WORM, access points, SSE-KMS/DSSE, Intelligent-Tiering archive tiers, Inventory and Storage Lens analytics.

**Why people bounce off it:** Whether a request is allowed depends on IAM policies, the bucket policy, ACLs, Block Public Access, the KMS key policy, the VPC endpoint policy and SCPs together, and the console shows each one on a different tab. Lifecycle rules have cost traps: Glacier transitions on tiny objects cost more than they save, and some classes have 30-day minimums. Replication needs its own IAM role, versioning on both sides and KMS grants. Storage Lens shows waste but doesn't fix it. Teams end up granting 's3:*' or leaving thousands of buckets on STANDARD forever, and most orgs have hundreds to thousands of buckets nobody has audited.

**AI operator:** An 'S3 Steward' agent that inventories every bucket across the AWS Organization and works in plain language. It explains effective access for a given principal and object using the IAM policy simulator and Access Analyzer. It writes least-privilege bucket and KMS policies and checks them with ValidatePolicy and CheckNoPublicAccess before applying anything. It designs lifecycle rules from Inventory object-size histograms and Storage Lens metrics, with a projected dollar saving. It sets up replication or Object Lock end to end (role, versioning, KMS grants). Every change is a reviewable diff and can also be emitted as Terraform or CloudFormation.

**Killer example:** A platform lead asks: 'Across all 14 accounts, which buckets could leak data, and where are we wasting money?' The AI works through 1,812 buckets. It finds 3 that are effectively public: one through a legacy AllUsers ACL in a sandbox account with BPA off, one through a bucket policy with Principal:* and a condition key that never matches, and one through an access point policy. It also finds 41 roles with s3:* on prod data buckets that have used only GetObject and PutObject in 90 days. On cost, it reads Inventory for the CloudTrail and ALB log buckets and finds 92% of objects are under 128KB, so a Glacier transition would raise the bill. It proposes Intelligent-Tiering plus 400-day expiry instead, saving about $4.1k a month. The user says 'fix the public ones, tighten those roles, and apply the lifecycle plan'. The AI validates every policy with Access Analyzer, applies the changes account by account after a single approval, and opens a Terraform PR so the IaC matches.

**Integration path:** AWS SDK/boto3 S3 control-plane APIs (Put/GetBucketPolicy, Lifecycle, Replication, PublicAccessBlock, ObjectLockConfiguration), the S3 Control API (access points, Storage Lens, Batch Operations), IAM Access Analyzer (ValidatePolicy, CheckNoPublicAccess, unused-access findings), the IAM policy simulator, S3 Inventory queried through Athena, and Cost Explorer for dollar figures. Cross-account access uses Organizations plus AssumeRole. Fully headless: it can ship as a CLI, MCP server or Slack bot, and read-only mode alone is a strong MVP.

**Demand 5/5 · Buildability 4/5**

### 2. Microsoft Excel spreadsheet-model auditing layer (Trace Precedents/Dependents, Inquire add-in, Spreadsheet Compare, Evaluate Formula, Error Checking); Google Sheets as a second connector `closed`

**Why it's powerful:** Excel already ships forensic tools for financial and operational models. It can walk precedent and dependent chains across sheets. Inquire maps workbook, sheet and cell relationships and flags hidden or very-hidden sheets, external links and formula inconsistencies. Spreadsheet Compare diffs two versions cell by cell, and Evaluate Formula steps through nested calculations. Billions of dollars of decisions rest on spreadsheets that have never been audited.

**Why people bounce off it:** The tools are scattered. Formula Auditing is on the Formulas ribbon, Inquire is a COM add-in that is off by default and only in Pro Plus/E3+, and Spreadsheet Compare is a separate Windows-only app. Trace arrows are useless on a 5,000-row model. People also don't know what to look for: hard-coded plugs inside formulas, one cell that breaks a copied pattern, SUM ranges that stop a row short, mixed absolute and relative references, circular references hidden by iterative calculation. Professional tools such as PerfectXL and Operis OAK are expensive, so most finance staff skip auditing.

**AI operator:** 'Model Auditor' is an Office.js task-pane add-in backed by a headless Python engine. It builds the full cell dependency graph and runs a library of risk detectors: hard-coded constants inside formulas, R1C1 pattern breaks, SUM ranges that miss adjacent data, orphan inputs, circular references, volatile functions, external links, hidden sheets and numbers stored as text. It explains each finding in plain language, and the user can reply 'fix it' or 'show me why'. It can also diff two versions of a model and describe the changes in business terms.

**Killer example:** A user says: 'Before I send this budget to the CFO, check it for anything sketchy, and tell me what changed since v6.' The AI walks the dependency graph and reports 3 issues. (1) Summary!F14 is =SUM(F2:F12) but the data runs to F13, so Marketing is left out and the total is $41,200 low. (2) Forecast!K22 is =J22*1.05+15000, a $15k plug that no other row has. (3) 11 Opex cells link to C:\Users\dan\old_rates.xlsx, which no longer exists. On the version diff it says: 'v7 cut the churn assumption from 3% to 2.5%, which adds $380k to FY revenue, and someone typed over Q3 revenue with a constant.' The user says 'fix 1, comment on 2 and 3, and replace the links with current values.' The AI makes all the edits in one batch, colors the changed cells, and adds an 'Audit log' sheet the CFO can read.

**Integration path:** Office.js Excel API: Range.getDirectPrecedents (ExcelApi 1.12), getPrecedents and getDirectDependents (1.14), getDependents (1.15), plus formulas, formulasR1C1, comments and worksheet APIs for in-place fixes and notes. Headless/CI path: openpyxl plus the 'formulas' or pycel libraries rebuild the graph and recalculate without Excel. R1C1 turns pattern-break detection into string comparison. Google Sheets: values.get with valueRenderOption=FORMULA. The read and audit pass needs no Excel automation, so a solo developer can ship the Python engine first as an upload web app or CLI.

**Demand 4/5 · Buildability 4/5**

### 3. Amazon RDS / Aurora fleet operations (engine upgrades, Extended Support, parameter groups, Blue/Green deployments, snapshots, Database Insights) `closed`

**Why it's powerful:** RDS and Aurora run the production Postgres and MySQL for a large share of AWS companies. They provide Multi-AZ, read replicas, Global Database, Blue/Green deployments for near-zero-downtime upgrades, automated backups with point-in-time restore, cross-region snapshot copy, IAM auth, RDS Proxy and CloudWatch Database Insights.

**Why people bounce off it:** Fleet hygiene never ends, and the console handles it one instance at a time. Engines keep leaving standard support (RDS for PostgreSQL 13 in early 2026, MySQL 8.0 around mid-2026), after which Extended Support adds per-vCPU-hour charges without much warning. Major upgrades need compatible parameter groups, extension and plugin checks, and a Blue/Green rehearsal. Parameter groups drift between environments and there is no diff view. Pending maintenance, CA certificate rotations and instance-class deprecations pile up across accounts and regions, and teams usually learn about them from the bill.

**AI operator:** A 'DB Fleet Operator' that scans every account and region and keeps a live risk board: engine versions against EOL dates, Extended Support exposure in dollars, pending maintenance, CA expiry, unencrypted snapshots, missing backups and parameter-group drift. In plain language it can (1) plan and run major upgrades: diff the parameter groups, check extension compatibility, create a Blue/Green deployment, watch replica lag and switch over in a maintenance window; (2) diff parameter groups across environments and explain each setting; (3) run restore drills (PITR to a scratch instance, row-count check, teardown). Destructive steps always need explicit approval.

**Killer example:** A user says: 'Which databases are about to start paying Extended Support, what will it cost, and upgrade the staging ones to Postgres 17 this weekend.' The AI replies: '23 instances across 9 accounts start Extended Support on the 1st, about $11,800/month combined. The 4 largest prod clusters are 71% of that.' It flags 3 instances using an extension version with no PG17 build and suggests replacements. For the 6 staging instances it clones the custom parameter group to the pg17 family, carrying over all 11 non-default settings, and notes that one (a deprecated vacuum setting) no longer exists. It creates Blue/Green deployments and schedules switchover for Saturday 02:00 with a replica-lag gate under 5 seconds. Sunday morning it posts in Slack: '6/6 switched over, 38s max write pause, old blue instances kept 48h for rollback.'

**Integration path:** boto3 RDS APIs: DescribeDBInstances/Clusters, DescribeDBEngineVersions (ValidUpgradeTarget), DescribeDBParameters, Create/ModifyDBParameterGroup, CreateBlueGreenDeployment/SwitchoverBlueGreenDeployment, DescribePendingMaintenanceActions, RestoreDBInstanceToPointInTime. The AWS Health API supplies EOL and maintenance notices, the Pricing API and Cost Explorer supply Extended Support costs, and CloudWatch/Database Insights supply lag and load. Multi-account access uses Organizations plus AssumeRole. Fully headless. A read-only fleet report is a one-week MVP and also works as the sales wedge.

**Demand 4/5 · Buildability 4/5**

### 4. Apple Ads (formerly Apple Search Ads), Advanced tier: App Store search, Today tab, Search tab and product-page placements `closed`

**Why it's powerful:** It is the only paid channel inside App Store search at the moment someone intends to install. Advanced offers keyword-level CPT bids, Exact vs Broad match, Search Match discovery, negative keywords, CPA goals, demographic, device and location targeting, ad variations tied to Custom Product Pages, and per-keyword reporting. Every App Store developer can use it, so the addressable base (indie devs, studios, agencies) is very large.

**Why people bounce off it:** The UI handles one-off edits well and strategy badly. A sound account needs a Brand / Category / Competitor / Discovery campaign split with cross-negatives so campaigns don't bid against each other. Converting search terms have to be promoted from Discovery into Exact and negated back, week after week. Bid tuning means reading TTR, CR and CPA keyword by keyword across storefronts. There is no rules engine, and third-party tools charge agency prices. As a result indie developers either settle for Basic or overspend on Advanced and quit after a bad first month.

**AI operator:** An 'ASA Pilot' agent built on Campaign Management API v5. It (1) builds the standard 4-campaign structure per storefront with correct cross-negatives; (2) runs a weekly search-term harvest that promotes converting terms to Exact, negates them in Discovery and flags waste; (3) moves bids toward a target CPA within guardrails, with a dry-run diff; (4) maps Custom Product Pages to ad groups; (5) answers plain-English questions such as 'why did installs drop in DE?'. Every change is shown as a plan before it is applied, and an audit log allows rollback.

**Killer example:** A user says: 'Launch my habit tracker in the US, UK and Canada at $40/day, keep CPA under $2.50, and never bid on Streaks or Habitify by name except in a competitor campaign.' The AI creates 12 campaigns (Brand, Category, Competitor and Discovery for each storefront) with a 15/45/20/20 budget split. It seeds Category keywords from the app's subtitle and metadata, puts competitor names only in the Competitor campaigns as Exact and negates them everywhere else, and turns on Search Match only in Discovery. Seven days later it posts: '14 Discovery search terms converted under $2. Promoted to Exact and negated in Discovery. Paused 6 keywords that spent over $15 with 0 installs. UK Competitor CPA is $4.80, so I propose cutting it to 5% of budget and moving the rest to UK Category, which runs at $1.70. Approve?'

**Integration path:** Apple Ads Campaign Management API v5 (REST/JSON). Auth is OAuth2 client credentials using an ES256-signed client-secret JWT with a key pair uploaded in the Apple Ads UI. Endpoints cover campaigns, ad groups, targeting keywords, campaign and ad-group negatives, ads (CPP variations), and reports at campaign, ad-group, keyword and search-term level. Build it as a TypeScript or Python MCP server plus a cron worker for the harvest and bid loops. No scraping needed.

**Demand 4/5 · Buildability 4/5**

### 5. AutoHotkey v2 (with COM automation of Excel/Outlook/Word and UI Automation) as the cross-app macro layer for office workers `open-source`

**Why it's powerful:** AutoHotkey is a free GPL-2.0 Windows automation runtime. It offers system-wide hotkeys, hotstrings with logic, window and clipboard control, GUI building, and full COM access to Office (ComObjActive('Excel.Application'), Outlook.Application). Community UIA-v2 libraries can drive almost any app, including legacy line-of-business systems with no API. One script can move data from an ERP screen into Excel and on to Outlook, which VBA cannot do because it stays inside one app.

**Why people bounce off it:** AHK is a real programming language. v1 and v2 syntax differ, and most forum answers are v1 code that fails on v2. The Outlook MAPI and Excel Range/ListObject COM models are deep. Window targeting, WinWait timing, UIA element paths and clipboard races are fragile. The office workers who would gain the most open a blank .ahk file and stop, and IT has no visibility into what scripts do.

**AI operator:** 'Desk Pilot' is a tray app that turns plain-English workflow descriptions into tested AHK v2 scripts. It covers hotstrings and templates, Excel and Outlook COM recipes, window and UIA element capture (the user clicks a field and it records a robust selector), and safe clipboard handling. Every script is linted, dry-run in a sandbox that logs intended actions, explained in plain language and turned on with a single toggle. The user's automations live in a library that can be edited by conversation, for example 'also CC my manager'.

**Killer example:** A user says: 'When I press Ctrl+Alt+P on an order in our ERP screen, grab the order number, find that row in Orders.xlsx on the shared drive, and draft an Outlook email to the customer in column E saying it shipped, with the tracking number from column H.' The AI asks the user to click the order-number field once to capture its UIA path. It then generates an AHK v2 script that reads the field through UIA, opens the workbook read-only through Excel COM and finds the row, and creates an Outlook draft (not a sent email). The dry run shows: 'would draft to jane@acme.com with tracking 1Z...'. It then installs the hotkey. Later the user says 'also CC my manager and attach the packing slip PDF from the order folder', and the script is updated and re-tested.

**Integration path:** Generate .ahk v2 source and run it with AutoHotkey64.exe, which is portable and needs no admin rights. Use /ErrorStdOut and /validate for syntax checks before activation. Use Descolada's open-source UIA-v2 library for element capture, and native ComObject/ComObjActive for Office. A small AHK host exposes a named-pipe or stdio bridge so the LLM can inspect live windows (WinGetList, UIA tree dump) while writing selectors. Everything is local files with no vendor API dependency. Windows only.

**Demand 4/5 · Buildability 4/5**

### 6. Azure networking: Virtual Network + Private Link/Private Endpoints + Private DNS Zones + NSGs/Azure Firewall (with Network Watcher) `closed`

**Why it's powerful:** This stack is how every enterprise Azure estate isolates PaaS services. It covers hub-spoke VNets, peering and Virtual WAN, Private Endpoints for Storage, SQL, Key Vault and App Service, Private DNS zones, NSGs and ASGs, UDRs that force traffic through Azure Firewall, and Network Watcher (connectivity check, next hop, IP flow verify, VNet flow logs). Almost every regulated customer requires it.

**Why people bounce off it:** Private Endpoint DNS is one of the most-complained-about problems in Azure. Each service needs the right privatelink.* zone linked to the right VNets, plus on-prem conditional forwarders and Private DNS Resolver. Miss one link and the app quietly resolves the public IP and hits a firewall deny. Whether traffic flows also depends on priority-ordered NSG rules at subnet and NIC level, UDRs, firewall policy rule collections, peering flags and each service's public-network-access setting, all on different blades. NSG flow logs are being retired in favour of VNet flow logs. Developers file tickets with the network team and wait days.

**AI operator:** A 'why can't X reach Y' network operator. Given two endpoints in plain language, it builds the full path model from Azure Resource Graph (VNets, peerings, route tables, NSGs, firewall policies, private endpoints, DNS zone links). It confirms the model with Network Watcher connectivity check, next-hop and IP-flow-verify, then names the exact object that blocks the traffic. It proposes the smallest fix as a diff and as Bicep/Terraform. It can also build private-endpoint wiring end to end from a one-line request, and audit the estate for PaaS resources that are still publicly reachable.

**Killer example:** A developer says: 'orders-api in spoke-prod can't reach stordersprod since we turned off public access. Fix it properly.' Within a minute the AI reports three separate causes. (1) The private endpoint exists, but privatelink.blob.core.windows.net is linked only to the hub VNet, so spoke-prod still resolves the public IP. (2) The App Service has no VNet integration, so its traffic never enters the VNet. (3) An NSG on the integration subnet denies outbound 443 to the hub at priority 200. It proposes enabling regional VNet integration, linking the DNS zone to spoke-prod, and adding an NSG allow at priority 190, shown as one diff. After approval it applies the changes and reruns connectivity check (Reachable, resolves to 10.20.4.5). It then opens a Bicep PR and adds: 'Four other spokes have the same missing zone link. Want me to fix them too?'

**Integration path:** Azure Resource Manager REST and SDKs (azure-mgmt-network, privatedns, web), Azure Resource Graph KQL for fast estate-wide inventory, and the Network Watcher APIs (connectivityCheck, nextHop, ipFlowVerify, VNet flow logs in Log Analytics), with az CLI as a fallback. Auth is an Entra service principal or managed identity: Reader for diagnosis, Network Contributor for fixes. Output Bicep or Terraform. Headless. A read-only path-diagnosis MVP is feasible for a solo developer, with writes added later.

**Demand 4/5 · Buildability 3/5**

### 7. Microsoft Word: long-document structure engine (multilevel list numbering linked to heading styles, captions and cross-references, section breaks with per-section headers/footers and page numbering, TOC/TOF fields) `closed`

**Why it's powerful:** Word can produce a 300-page thesis, tender response, SOP manual or contract that numbers itself ('Section 4.2.1', 'Figure 3-7'). It keeps every 'see Table 12' live, uses roman-numeral page numbers for front matter, mixes in landscape pages, varies headers per chapter and rebuilds the TOC and list of figures on demand. All of this runs on the field-code and section model that every Word install already has.

**Why people bounce off it:** This is the most frustrating part of Word. Multilevel numbering only works when the list is linked to Heading 1-9 through 'Define New Multilevel List > More >>'. Pasted content brings in rogue list definitions, which produces '1.1.1' after '3.2' or numbering that restarts at random. Deleted bookmarks turn cross-references into 'Error! Reference source not found.' 'Link to Previous' quietly overwrites chapter headers, and page-number restarts have to be set per section. Students, paralegals and proposal writers lose days to this and fall back on typing numbers by hand, which breaks on the next edit.

**AI operator:** 'Doc Surgeon' is a Word add-in plus an OOXML engine. It (1) diagnoses structure: numId/abstractNumId conflicts, fake headings made with direct bold formatting, dead bookmarks, wrongly linked headers; (2) rebuilds one clean multilevel list bound to the heading styles and remaps every heading to it; (3) turns typed 'Figure 3' and 'see Section 2.4' text into real SEQ captions and REF fields; (4) sets up sections from plain requests; (5) refreshes all fields and reports what changed.

**Killer example:** A PhD student two days from submission says: 'My numbering is broken. Chapter 3's subsections show 1.1, 1.2. Fix it, number my figures by chapter, make every "see Figure X" update itself, roman numerals until Chapter 1, and put the chapter title in the header.' The AI finds 4 competing list definitions left over from pasted drafts and merges them into one Heading-linked 1 / 1.1 / 1.1.1 scheme. It converts 62 typed captions into chapter-numbered SEQ captions (Figure 3-4). It matches 118 in-text mentions to those captions and turns them into REF fields, and lists 3 ambiguous mentions for the student to confirm. It inserts the section breaks, sets up the roman/arabic page restarts and STYLEREF chapter headers, then rebuilds the TOC and List of Figures. It finishes with before/after page thumbnails and a note: 'Figure 2-6 is referenced as Figure 2-5 on p.41. The old text pointed to the wrong figure. Please check.'

**Integration path:** Main path is direct OOXML manipulation: python-docx plus raw lxml on numbering.xml, document.xml, sectPr, header/footer parts, bookmarks and simple/complex fields. It runs headless, is deterministic and its output can be diffed. Field refresh and PDF preview use LibreOffice headless, or Word COM on Windows (Fields.Update, TablesOfContents.Update). The in-Word version uses Office.js: WordApi 1.5 for fields (including TOC insertion), styles and lists, plus desktop-only sets for sections and headers/footers. The MVP can be a web app where users upload a .docx and download a repaired one.

**Demand 4/5 · Buildability 3/5**

### 8. Linnworks (multichannel order and inventory management: Rules Engine, Listings, Macros, Dashboards) `closed`

**Why it's powerful:** It is the back office for thousands of UK, EU and US sellers on Amazon, eBay, Shopify, Etsy, TikTok Shop and more. It provides real-time stock sync, composite and kit SKUs, multi-warehouse and FBA stock, an order Rules Engine (assign shipping service, warehouse and tags; split or merge orders by condition), per-channel listing templates, C# Macros and custom SQL dashboards.

**Why people bounce off it:** The Rules Engine is a nested IF/ELSE tree over dozens of order fields, with evaluation-order and 'stop processing' semantics that sellers often get wrong. The result is orders shipped with the wrong courier or not shipped at all. Listing templates, variation groups and composite stock each have their own screens. Macros need C#, and dashboards need SQL against a poorly documented schema. Sellers pay consultants just to set up shipping rules.

**AI operator:** An 'Ops Clerk' that turns plain business policy into Rules Engine trees and checks them before activation. It reads every existing rule and explains in plain English what will happen to a given order. It replays proposed rules against the last 30 days of processed orders and shows exactly which orders would change. It writes SQL dashboard queries on demand and bulk-edits inventory and listings from natural-language filters.

**Killer example:** A seller says: 'From Monday, anything to Northern Ireland or the Highlands over 2 kg goes DPD, not Royal Mail. Amazon Prime orders with 3+ items get Next Day. Don't touch eBay Global Shipping orders.' The AI reads the current tree and warns: 'Your existing "Amazon Prime → Royal Mail Tracked 24" rule runs first with stop-processing on, so it would silently override the new Prime rule.' It drafts a reordered rule set: BT postcode prefixes plus the Highlands IV/KW/PH/HS/ZE prefixes, a weight > 2000 g branch, a Prime item-count branch and a GSP exclusion. It replays 30 days of orders and reports: '412 orders would change service. 0 GSP orders affected. 9 orders would have no rule match at all because they are Prime orders to Jersey and Guernsey, so I added a fallback. Estimated cost +£186/week.' The draft is activated only after the seller confirms.

**Integration path:** Linnworks public REST API: apps are registered in the Developer portal and installed per account with a token, using a server-specific base URL. Relevant controllers are Orders/ProcessedOrders for history, Inventory and Stock, Listings, RulesEngine (read and edit condition trees and actions, draft and activate), ShippingService, and Dashboards ExecuteCustomScriptQuery for read-only SQL. Ship it as an embedded Linnworks marketplace app or a standalone MCP server.

**Demand 4/5 · Buildability 3/5**

### 10. Siemens Polarion ALM (Jama Connect and PTC Codebeamer as secondary connectors) `closed`

**Why it's powerful:** It is the system of record for requirements, risks, tests and the traceability between them in safety-critical engineering. It has LiveDocs, typed link roles, document baselines and branching, workflows with e-signatures (21 CFR Part 11), Lucene queries, Velocity/LiveReport pages, variants, and test runs linked to requirements. Auditors sign off on its trace matrices.

**Why people bounce off it:** Engineers don't want to learn Lucene syntax, link-role semantics, LiveDoc vs work-item behavior, baseline mechanics or Velocity widget configuration. Admin config is buried. Teams export to Excel and re-import through ReqIF or Word, which breaks traceability. Answering 'which safety requirements lack a verifying test in this baseline?' usually takes a Polarion specialist.

**AI operator:** A 'Traceability Copilot' that reads the project's types, link roles and workflow config. It turns questions into Lucene queries, runs coverage, gap and impact analysis by walking the link graph, and drafts bulk changes as a reviewable change set. Every write runs under the user's own token so the audit trail stays intact. Actions that need a signature stop at 'ready for signature', and the agent never signs.

**Killer example:** A user says: 'For the brake-controller SRS in baseline R2.3, show every ASIL C/D requirement with no verifying test or with a failed last run. Then create placeholder test cases for the uncovered ones in the HIL spec, link them as verifies, and assign them to Priya.' The AI runs the query at the baseline revision, walks the verifies back-links and test-run records, and returns a gap table: 14 uncovered, 3 failing.
