### 1. Excel / Google Sheets CSV and text-import layer (Text Import Wizard, Data > From Text/CSV, automatic data conversion). The 'CSV Rescue' operator. `closed`

**Why it's powerful:** Excel can ingest nearly any delimited export (ERP, CRM, lab, bank, e-commerce) and its import layer can set per-column types, locale, delimiter, encoding and decimal/thousands separators. Almost every business workflow starts with a CSV landing in a spreadsheet.

**Why people bounce off it:** Double-clicking a CSV silently corrupts data. Leading zeros on ZIPs and SKUs vanish, 16+ digit IDs collapse to 1.23E+15 and lose digits permanently, gene symbols become dates, DD/MM and MM/DD flip by locale, UTF-8 shows mojibake without a BOM, and semicolon CSVs collapse into one column. The fixes are buried in a legacy wizard and an options page nobody finds, and the damage is invisible until saved, then irreversible.

**AI operator:** An agent reads the raw bytes before Excel touches them: it sniffs encoding, BOM, delimiter, quoting, decimal convention and per-column value patterns, and infers each column's intended type with cited evidence. It writes an .xlsx with explicit Text/Date/Number formats, then runs a lossless round-trip check of every cell against the raw file. It also audits existing workbooks for earlier damage (E+ notation on 15+ digit values, 4-digit ZIPs, gene-symbol dates) and labels each damaged column recoverable or lost.

**Killer example:** User: 'Finance opened the Shopify + warehouse export and half the order IDs look weird, and the German supplier file is all in one column.' AI: finds column C holds 18-digit order IDs already truncated to 1.2345E+17 in the saved xlsx, so 4,212 rows are unrecoverable from that file but fully intact in the original CSV. It re-imports the original with IDs as text, parses the supplier file as cp1252 with ';' delimiter and ',' decimals, confirms DD/MM from rows where day > 12, writes a clean workbook plus a one-page 'what changed and why' sheet, and proves 100% cell parity against the raw files in under a minute.

**Integration path:** Headless and file-based: Python (charset-normalizer, csv, pandas dtype=str, openpyxl/XlsxWriter with explicit number formats), no Excel install needed. Optional Excel COM / Office Scripts, or Sheets API with RAW vs USER_ENTERED. Ships as CLI, drag-and-drop web page or MCP tool. No vendor API needed.

**Demand 5/5 · Buildability 5/5**

### 2. Excel financial-model construction layer (three-statement / DCF / LBO / debt-schedule models built to FAST-style standards) `closed`

**Why it's powerful:** Excel is the universal medium for integrated financial models used for fundraising, lending, M&A and budgeting. Plain .xlsx files, no vendor approval needed.

**Why people bounce off it:** A correct integrated model is a structure problem, not a formula problem: consistent time axis, sign conventions, working-capital, PP&E, debt and revolver schedules with cash sweep, circular interest handled with a toggle, scenario switches, and a balance sheet that balances in every period. Founders ship models that are off by cents, circularity blows up, and the scenario toggle half works.

**AI operator:** Model Wright builds the workbook from a fixed Inputs/Calcs/Outputs layout via openpyxl or XlsxWriter (or Office.js/COM). It ingests 2-3 years of actuals, generates drivers and all schedules, adds a circularity breaker, scenario selector and Checks sheet, then recalculates headless in LibreOffice and fails the build unless balance, cash tie-out and schedule-sum checks are zero in every period. Change requests are applied as layout-preserving incremental edits.

**Killer example:** User: 'Here is our 2023-2025 P&L and balance sheet. Build a 5-year three-statement model, a $4M term loan at SOFR+450 with 1% mandatory amortization and a 50% excess cash sweep, plus base/downside/upside switching on revenue growth and gross margin.' AI delivers the workbook, recalculates in LibreOffice, reports 'balance check 0.00 in all 60 months, cash ties to the CF statement', and flags that the downside case trips the revolver limit in Q3 of year 2. Then: 'add a second term loan' is applied without breaking a single existing reference.

**Integration path:** File-level: openpyxl/XlsxWriter writes formulas; headless LibreOffice (soffice --convert-to) recalculates and reads values back for verification. Live editing via Office.js/Office Scripts or xlwings/COM. Differentiation must come from verified-checks discipline since AI-for-finance tools are crowded.

**Demand 5/5 · Buildability 4/5**

### 3. ISO 20022 bank files (pain.001, camt.053/054, pain.002) plus legacy MT940 / BAI2 / NACHA, as used by ERP bank-integration modules. 'Bankfile Doctor'. `open-source`

**Why it's powerful:** Every ERP (D365, SAP, NetSuite, Sage, Odoo) generates or imports these files, and they are the only path to bulk payments and automated reconciliation. Schemas are free and open.

**Why people bounce off it:** Banks layer their own implementation guidelines on the schema, so finance teams get 'file rejected, group header invalid' with no line number. Culprits: structured vs unstructured addresses (CBPR+), wrong BIC/IBAN, unaccepted charge-bearer or service-level codes, decimal/date format mismatches. Fixing means opening 40 MB of XML in a text editor or waiting days for a consultant; camt.053 formats differ per bank and silently break reconciliation.

**AI operator:** Validates against official XSDs (lxml) plus per-bank/scheme rule packs, parses pain.002 rejections and maps each error to the exact element path, explains it in plain English, repairs batches (normalize addresses, strip illegal characters, fix codes, split by date), converts MT940 to camt.053/CSV, and writes an ERP-specific fix note.

**Killer example:** User drops a rejected pain.001 (1,240 payments): 'Bank bounced this with AM04/FF01 and payroll cutoff is in two hours.' AI validates, finds 37 payments missing creditor country in structured addresses and 4 non-SEPA currency payments under a SEPA service level, writes a repaired file for the 1,199 clean payments plus a quarantine file for the 41 with exact reasons, and names the vendor master records to fix in the ERP. Payroll goes out with 90 minutes to spare.

**Integration path:** File-in/file-out with XSD validation (lxml/xmlschema) plus a rules layer; MCP server or CLI; optional SFTP/ERP export hooks and later ERP APIs (D365 DMF, NetSuite SuiteTalk, Odoo JSON-RPC). Value grows with the bank rule-pack library.

**Demand 4/5 · Buildability 4/5**

### 4. Semgrep (OSS CLI + AppSec Platform): custom rule authoring, autofix and findings triage `open-source`

**Why it's powerful:** Semgrep is a fast, language-aware pattern engine covering 30+ languages that can enforce any in-house convention, banned API or migration pattern in CI, with autofix. The platform adds findings dashboards, triage states and policies.

**Why people bounce off it:** Rules are a YAML DSL with metavariables, ellipsis, pattern-inside/not, taint-mode sources/sinks/sanitizers and per-language quirks, plus test fixtures with ruleid/ok annotations. Most teams run stock rulesets and never encode their own conventions. On the platform side, thousands of findings pile up with nobody able to say which matter.

**AI operator:** A rule-smith agent: the user describes a convention or bug class (optionally pointing at a bad commit), the agent writes rule YAML and positive/negative fixtures, runs semgrep --test and a real scan against the repo to measure false positives, iterates until precision is acceptable, adds autofix, and opens a PR wiring the rule into CI. For triage it clusters findings, explains reachability and bulk-ignores with recorded reasons via the API.

**Killer example:** User: 'We keep getting bitten by requests.get without a timeout, and by Django views missing our @require_scope decorator. Warn on the first, block on the second, and fix the existing ones.' AI writes both rules with fixtures, runs them over all 40 repos ('212 hits, 9 false positives, rule tightened to 0'), runs --autofix for the timeout rule on a branch, and opens a PR adding both rules to the shared CI config with the requested severities.

**Integration path:** Fully headless: semgrep --test/--validate/--json/--autofix/--dryrun, Semgrep Platform REST API for triage, GitHub/GitLab API for PRs. MVP is a CLI wrapper plus an LLM loop with semgrep output as the feedback signal; no platform account needed.

**Demand 4/5 · Buildability 5/5**

### 5. Gradle (Build Tool + Build Scans / Develocity): build performance, dependency conflicts and build-logic migration `open-source`

**Why it's powerful:** Gradle underlies nearly all Android and much JVM/Kotlin work, with incremental builds, build cache, configuration cache, composite builds, version catalogs and convention plugins. Build Scans record per-task timings, cache-miss reasons, dependency resolution and flaky-test history.

**Why people bounce off it:** A scan has hundreds of dense panels and the answer to 'why is CI 14 minutes now' is buried across them. Cache misses come from nondeterministic inputs or absolute paths, dependency conflicts need dependencyInsight and constraint knowledge, and migrations (Groovy to Kotlin DSL, buildSrc to convention plugins, version catalogs, configuration cache) break silently. Teams give up and buy bigger runners.

**AI operator:** A build doctor ingesting a scan URL or local --scan/--profile/--info output. It diagnoses with evidence (critical-path tasks, cache-miss root causes via Develocity cache-key comparison, flaky tests), proposes concrete build-logic patches, applies them on a branch, re-runs the build and shows a before/after scan comparison.

**Killer example:** User: 'Our PR builds went from 6 to 15 minutes since October and I have no idea why.' AI pulls the last 60 scans, finds :app:kaptReleaseKotlin stopped hitting the remote cache on 14 Oct, compares cache keys, and discovers a new plugin writes a timestamp into a task input. It patches the plugin config on a branch, re-runs two builds, and reports 'cache hit restored, median 6m10s, PR opened, 3 other tasks flagged with similar non-reproducible inputs'.

**Integration path:** CLI (--scan, --profile, dependencyInsight, --configuration-cache), Gradle Tooling API, Develocity REST API (licensed; local --profile/--info plus free scans.gradle.com suffice for an MVP). Build files are plain text in git, so changes ship as PRs.

**Demand 4/5 · Buildability 4/5**

### 6. Microsoft Word / Excel / PowerPoint right-to-left and multilingual layout (OOXML bidi, w:rtl, w:lang, Arabic-Indic/Hebrew numbering). 'Office Bidi Fixer'. `closed`

**Why it's powerful:** Office has full bidirectional support (paragraph/run/table/section direction, language-specific numbering, complex-script fonts, per-run proofing language, mirrored layouts) on an open ECMA-376/ISO format, used daily by hundreds of millions of people in MENA, Iran, Pakistan and Israel.

**Why people bounce off it:** Bidi bugs are hard to see and hard to fix: numbered clauses flip to '.1', brackets and percent signs jump sides in mixed text, tables stay LTR, TOC uses the wrong digits, spellcheck flags correct Arabic because runs carry the wrong language tag, and pasted content scrambles direction. Controls are scattered across ribbon buttons, Paragraph dialogs and the language bar, so users retype through Notepad.

**AI operator:** A skills-loaded agent edits OOXML directly: audits every paragraph, run, table, section, list definition and header/footer for direction, language and script mismatches, applies plain-language rules (base direction by dominant script, numbering style per language, mirrored tables, w:lang per run, complex-script font mapping), and renders before/after pages via headless LibreOffice. It also builds clean bilingual templates.

**Killer example:** User: 'This 40-page bilingual tender is a mess: Arabic clauses numbered backwards, brackets on the wrong side, tables left-to-right, and Word flags correct Arabic as misspelled.' AI finds 212 paragraphs whose base direction disagrees with their dominant script, 3 LTR list definitions, 14 tables without bidiVisual and 1,900 runs tagged en-US containing Arabic. It fixes all, switches numbering to Arabic-Indic digits, inserts LRM/RLM only where needed, sets ar-SA proofing, and returns a change log plus before/after screenshots of the three worst pages.

**Integration path:** File-level and headless: python-docx/docx4j, lxml on document.xml/numbering.xml/styles.xml, python-pptx, openpyxl (sheetView rightToLeft), LibreOffice headless for visual diffs. Optional Office.js add-in. Rules are deterministic enough to test with golden documents.

**Demand 4/5 · Buildability 4/5**

### 7. Kit (formerly ConvertKit): creator email marketing with tags, segments, sequences, forms and automations `closed`

**Why it's powerful:** Kit runs the email businesses of a huge number of creators, with tags, forms, sequences, broadcasts, custom fields, commerce and a v4 API covering most of it.

**Why people bounce off it:** Kit scales by accretion: every landing page and product adds a tag, form, sequence and automation. After 2-3 years there are 300+ tags, overlapping segments and visual automations nobody dares touch, and no place answers 'why did this subscriber get that email?'. Bulk fixes (merge tags, rebuild segments) are click-by-click.

**AI operator:** A chat operator over the v4 API that inventories tags, forms, sequences, segments and fields, maps who is in what, proposes merges and renames with a dry-run diff, builds segments from plain English, drafts and schedules broadcasts with a test send, and explains a subscriber's history. Visual automations are read-and-advise only (no write API).

**Killer example:** User: 'I have 412 tags and half are dupes like webinar-oct, Webinar_Oct24, oct-webinar-attended. Collapse them, then send a broadcast about the new course to everyone who attended any webinar in the last 90 days but hasn't bought.' AI clusters the tags, proposes 38 canonical ones, shows affected subscriber counts in a dry run, applies merges after approval, builds the segment excluding purchasers, drafts the broadcast in the user's past tone, sends a test, and schedules it after approval.

**Integration path:** Kit REST API v4 (OAuth2/API key): subscribers, tags, forms, sequences, broadcasts, custom fields, purchases, webhooks. Gaps: no automation write API and limited segment creation, so those need browser fallback or advice-only. Verify the current v4 endpoint list first.

**Demand 4/5 · Buildability 4/5**

### 8. Airbyte (open-source core; Fivetran as second connector): connection, sync-mode and schema configuration `open-source`

**Why it's powerful:** Self-hostable ELT with hundreds of connectors, a public REST API, Terraform provider and PyAirbyte; everything the UI does can be written.

**Why people bounce off it:** Per-connection wall: pick streams, then a sync mode per stream (full refresh vs incremental append vs dedupe), with a valid cursor and primary key the UI does not always reveal, plus schema drift, resets and column selection. Mistakes surface later as duplicates, missed updates or runaway warehouse cost.

**AI operator:** A Pipeline Operator that inspects each source's discovered catalog, picks sync mode, primary key and cursor per stream, deselects PII and huge log tables, sets the schedule, creates source/destination/connection via API, runs a test sync, diagnoses failures and can emit Terraform so changes land in Git.

**Killer example:** User: 'Pull Stripe charges, customers and subscriptions plus HubSpot deals and contacts into Snowflake RAW nightly. No card details or email columns, and deals history without duplicates.' AI discovers both catalogs, configures incremental dedupe on id with the right cursor, deselects the sensitive fields, schedules 02:00, runs a test sync, reports row counts, and warns that HubSpot contacts has no reliable cursor so it is set to full refresh.

**Integration path:** Airbyte public REST API (sources, destinations, connections, jobs, discover schema, refresh/reset), Terraform provider, PyAirbyte. Fivetran REST API has equally broad coverage.

**Demand 3/5 · Buildability 4/5**

### 9. Kustomize + Flux CD (GitOps repo structure, overlays, reconciliation) `open-source`

**Why it's powerful:** Kustomize is built into kubectl and Flux is CNCF graduated; together they run GitOps for a large share of Kubernetes shops, with dependency ordering, health checks and multi-tenancy.

**Why people bounce off it:** Overlay logic is hard to predict (strategic-merge vs JSON6902, selectors, components, replacements) and Flux failures show as cryptic conditions spread across Kustomization, HelmRelease, GitRepository and ImagePolicy objects. Repo layout is a design choice most teams get wrong and dare not refactor.

**AI operator:** Runs kustomize build and flux diff to explain what an overlay renders, walks the Flux object graph to name the single root cause of a stuck reconciliation, writes patches and Flux Kustomizations from intent, and refactors layouts with a before/after rendered-manifest diff proving nothing changed.

**Killer example:** User: 'Staging payments has been stuck two hours.' AI runs flux get all and events, finds payments waits on infra-controllers, which fails on CRD ordering after yesterday's cert-manager bump, explains the dependsOn chain in two sentences, and proposes a PR splitting CRDs into their own Kustomization with wait: true, with flux diff showing only that change.

**Integration path:** CLI and git only: kustomize, kubectl, flux (get, diff, trace, events, build), kubeconform; PRs via GitHub/GitLab API. MVP runs against a kind cluster or local repo.

**Demand 3/5 · Buildability 4/5**

### 10. TouchDesigner (Derivative; free non-commercial tier) `closed`

**Why it's powerful:** The standard for media artists, projection mapping, interactive installations and audio-reactive shows, with real-time GPU rendering, DMX/OSC/MIDI/NDI I/O, and a full Python td module that can create, connect and parameterize operators.

**Why people bounce off it:** Node networks (TOPs, CHOPs, SOPs, DATs, COMPs) have a brutal learning curve: cooks, operator families, expressions vs Python vs CHOP exports. Networks turn to spaghetti, performance mysteriously tanks, and every tutorial is a 2-hour video of someone wiring 40 nodes by hand.

**AI operator:** A Network Builder and Doctor: instantiates networks via Python in a running TD session from a described visual, reads the Performance Monitor and per-operator cook times to diagnose slowdowns, and packages results as clean .tox components with exposed custom parameters.

**Killer example:** User: 'Make the LED wall react to the kick drum: pulsing particle tunnel, hue shifts on the snare, 1080p, output to 3 projectors with edge blending.' AI builds the audio chain, bands kick and snare, drives an instanced tunnel from CHOP-bound parameters, sets up three windows with edge blend, wraps it in a COMP with Sensitivity and Hue Range sliders, and reports measured cook time and GPU usage.

**Integration path:** Python td module in a Script DAT or Textport, with a Web Server/WebSocket DAT as the bridge for an external agent; OSC/MIDI for runtime control; .tox recipe library. MVP is a TD component hosting a WebSocket bridge plus chat UI.

**Demand 3/5 · Buildability 4/5**
