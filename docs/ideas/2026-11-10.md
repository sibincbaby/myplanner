### 1. Windows power management: overnight sleep-drain diagnosis and repair (powercfg) `closed`

**Why it's powerful:** `powercfg` ships on every Windows laptop and is a complete power toolkit: sleep study, battery and energy reports, last-wake source, wake timers, active power requests, per-device wake arming, request overrides, and every power-plan setting by GUID or alias.

**Why people bounce off it:** "My laptop is dead every morning" is one of the most common Windows complaints. Finding the cause means an elevated shell, reading a sleep-study report, linking a wake or active-time entry to the device or app behind it, and then writing GUID-addressed settings. Settings > Power & battery exposes only a few of these switches, so most people just turn sleep off or live with it.

**AI operator:** It gathers the evidence, names the device or process keeping the machine awake, applies the narrowest fix (one device or one process, not "disable sleep"), and reads the next sleep study to confirm the drain is gone.

**Killer example:** 'My laptop loses 40% overnight with the lid closed.' The AI runs `powercfg /sleepstudy /duration 7 /xml`, `/lastwake`, `/waketimers`, `/requests` and `/devicequery wake_armed`, and pulls Power-Troubleshooter events with `Get-WinEvent`. It finds that the HID mouse keeps waking the machine and a vendor updater holds a SYSTEM power request. It runs `powercfg /devicedisablewake "HID-compliant mouse"` and `/requestsoverride process updater.exe system`, turns "Allow wake timers" off on battery with `/setdcvalueindex SCHEME_CURRENT`, and sets `/change hibernate-timeout-dc 120`. A scheduled task with "wake to run" is flagged but left alone. Tasks belong to the 11-08 Task Scheduler card.

**Integration path:** Local CLI. Every write option used here (`/devicedisablewake`, `/requestsoverride`, `/setacvalueindex`, `/setdcvalueindex`, `/change`, `/hibernate`) and every read option is on Microsoft's "Powercfg command-line options" page. Some reports need elevation. The exact alias for the wake-timer setting was not checked, so use the GUID from `powercfg /q`. macOS `pmset` is a natural second connector.

Overlap: The verifier found no Copilot+ Settings agent, Copilot app, Get Help troubleshooter or OEM assistant (HP AI Companion, Lenovo AI Now, MyASUS) that diagnoses overnight drain and applies these fixes. Guides still describe a manual `/sleepstudy` walkthrough. Community Windows diagnostics MCPs (emyk windows-debug-mcp, Windows Diagnostics MCP) are read-only and block powercfg writes.

**Demand 4/5 · Buildability 4/5**

### 2. Active Directory account-lockout root-cause investigator (on-prem DCs and endpoints) `closed`

**Why it's powerful:** The Security event log on domain controllers and member machines records every failed logon and lockout. With the right audit policy it can answer who locked out whom, from where and with which stale credential, at no cost.

**Why people bounce off it:** Tracing a lockout means finding event 4740 on the PDC emulator, jumping to the caller computer, reading 4625 and 4771 events there, and then finding the stale credential: a service, a scheduled task, a mapped drive, saved credentials or a phone. Audit subcategories are often off and logs roll over within hours. Small IT teams repeat this by hand every week or buy a rule-based auditing suite that only gets them as far as the caller computer.

**AI operator:** The admin names a user or a symptom. The AI hunts across the DCs and the source machine, names the process or stored credential that is causing the lockouts, fixes it after approval, and turns on the auditing that was missing so the next lockout can be traced.

**Killer example:** 'Why does Ravi keep getting locked out?' The AI finds the PDC emulator with `Get-ADDomain`, reads 4740 events there with `Get-WinEvent` to get the caller computer, then reads 4625/4771 events on that host. It lists `Get-ScheduledTask` and `Get-CimInstance Win32_Service` entries that run as ravi and finds a nightly report task still holding his old password. After approval it runs `Unlock-ADAccount ravi` and `Set-ScheduledTask -User ravi -Password ...`, enables lockout auditing with `auditpol /set /subcategory:"Account Lockout" /failure:enable`, and raises the Security log size with `Limit-EventLog` so the trail survives next time.

**Integration path:** PowerShell remoting with the ActiveDirectory and ScheduledTasks modules, plus `auditpol`. `Unlock-ADAccount`, `Set-ScheduledTask` and `auditpol /set` are standard documented commands. The doc pages were not fetched this run.

Overlap: Security Copilot's Defender for Identity integration summarizes identities but has no lockout-source agent (verified). Netwrix Account Lockout Examiner, ADAudit Plus and Lepide already name the caller computer without AI. The wedge is therefore the endpoint step: finding the stale credential on the machine and fixing it. The only community AD MCP found (Skills-MCP-AD) has no lockout tools. This is distinct from the 10-24 AD account-hygiene card (stale and privileged accounts).

**Demand 4/5 · Buildability 4/5**

### 3. Windows Server Network Policy Server (NPS): RADIUS for 802.1X Wi-Fi, VPN and network devices `closed`

**Why it's powerful:** NPS comes free with every Windows Server licence and is the default RADIUS server in small and mid-size AD shops. It gates Wi-Fi, VPN, RD Gateway and switch or AP logins on AD groups, assigns VLANs and enforces EAP methods.

**Why people bounce off it:** Network policies and connection request policies are built in an old wizard as nested conditions, constraints and vendor attributes (Tunnel-Type, Tunnel-Pvt-Group-ID). Policy order matters and fails silently. Failures appear only as event 6273 reason codes that admins have to look up. Most teams copy a blog post once and never touch the config again.

**AI operator:** The admin says who should get onto which network and how. The AI backs up the config, writes the RADIUS clients and the ordered policies, and explains failed logins from the NPS events in plain language.

**Killer example:** 'Let only Staff-WiFi onto CORP Wi-Fi from the 12 new APs on 10.20.0.0/24, put contractors on VLAN 30, and tell me why Anil can't connect.' The AI runs `Export-NpsConfiguration` as a backup and then `New-NpsRadiusClient` for each AP. It looks up attribute IDs with `netsh nps show npconditionattributes` and creates ordered policies with `netsh nps add np` (Windows-Groups condition, Tunnel-Pvt-Group-ID 30 for contractors). It then decodes Anil's 6273 event, reason code 48 ("did not match any network policy"): Anil isn't in Staff-WiFi, and no lower-order policy catches him. The AI asks whether he should be added to the group or covered by the contractor policy.

**Integration path:** The PowerShell NPS module (`New-NpsRadiusClient`, `Set-NpsRadiusClient`, `Export-/Import-NpsConfiguration`) plus `netsh nps`. Microsoft's NPS admin-tools page still documents `netsh nps` for Server 2016 and later (verified). `Import-NpsConfiguration` replaces the whole config and cannot merge, so complex EAP edits go through the exported XML with a full backup. Test on Server 2025, where some netsh RRAS commands are reported to fail with "binding handle is invalid".

Overlap: No MCP server or AI tool for NPS was found. Within NPS only NAP was deprecated, in 2012 R2. The 09-24 AD CS card issues the 802.1X certificates and the 08-13 Meraki card drives the AP side. Neither one writes RADIUS policy.

**Demand 4/5 · Buildability 3/5**

### 4. Sage Intacct Dynamic Allocations (allocation definitions and runs) `closed`

**Why it's powerful:** Dynamic Allocations takes source balances and spreads them across dimensions (department, location, entity, project) on a basis such as headcount, square footage or revenue. It then posts to a chosen book and journal, replacing the allocation spreadsheet that mid-market and nonprofit controllers rebuild every month.

**Why people bounce off it:** A single definition ties together the source pool, the basis, the target and offset entries, how each dimension is treated in each of those, and the book and journal. Controllers often keep a side workbook anyway, and partners sell allocation setup as a paid service.

**AI operator:** "Allocation Architect" turns a plain-English cost-sharing policy into Intacct allocation definitions. It previews the journal lines the definition would generate against last month's actuals before saving, then runs the allocation each close.

**Killer example:** 'Split rent and utilities across every department by FTE count each month, and IT costs across entities by revenue, posted to the Allocations journal.' The AI reads GL balances and the FTE statistical account, then POSTs one definition per policy to `/objects/general-ledger/account-allocation` with source pool, basis, target and offset. It dry-runs the definitions against the prior period and shows the lines per department. After approval it runs the allocation for the current period.

**Integration path:** Intacct REST with OAuth2: `POST https://api.intacct.com/ia/api/v1/objects/general-ledger/account-allocation` (Sage developer portal, "Account allocation definitions", verified). The legacy XML API also documents account allocations and an allocation-run operation. Requires the Dynamic Allocations subscription.

Overlap: Sage's first-party Intacct AI Gateway MCP is described as read-only, and no source shows Sage Copilot creating allocation definitions (verified). The 08-20 Sage Intacct card covers closing, Smart Rules and dimension reclasses, not allocation definitions. NetSuite allocation schedules would be a second connector (unchecked).

**Demand 3/5 · Buildability 4/5**

### 5. Salesforce PRM channel programs, partner tiers and MDF allocation `closed`

**Why it's powerful:** Salesforce PRM on Experience Cloud runs a vendor's whole channel: tiered programs, partner membership by level, deal registration, and market development funds (MDF) with budgets, allocations, requests and claims.

**Why people bounce off it:** Each piece lives on a different Setup page or tab. A yearly tier redesign means re-ranking levels, moving hundreds of partners to new levels, and recutting MDF allocations per partner under a budget cap. Channel-ops teams model it in spreadsheets and then re-key it record by record.

**AI operator:** The user describes the new program. The AI creates or re-ranks levels, reassigns each partner's level from the stated rules (bookings, certifications), and splits MDF budgets into per-partner allocations. It shows a diff and a budget-cap check before writing.

**Killer example:** 'Collapse Silver/Gold/Platinum into Registered/Advanced/Elite; anyone with over $2M bookings last FY goes Elite; give Elite 60% of the Q1 MDF budget, split by bookings.' The AI creates the three `ChannelProgramLevel` records with rank, then bulk-updates `ChannelProgramMember` to the new levels. It reads Opportunity bookings by `PartnerAccountId` and creates `PartnerFundAllocation` records (Amount, BudgetId) against the Q1 `PartnerMarketingBudget`, staying under its total.

**Integration path:** Salesforce REST sObject API. The object reference lists create/update/upsert for `ChannelProgramLevel` (API 41.0+) and `PartnerFundAllocation`, with Amount and BudgetId settable on create, and `PartnerMarketingBudget` fields settable on create. `ChannelProgramMember.LevelId` is listed with Create and Update properties (API 224.0 reference). Another page for the same version mislabels it as the partner ID. All of this evidence comes from search excerpts of older API-version pages, because developer.salesforce.com returned 403. Confirm with `describeSObjects` before building.

Overlap: The only Salesforce partner agent found is the Partner Community support agent, which does not handle tiering or MDF (verified). Separate PRM vendors (ZINFI, Zift) replace Salesforce PRM instead of driving it. The 10-19 Experience Cloud card covers portal access and sharing, not programs or funds.

**Demand 3/5 · Buildability 4/5**

### 6. Salesforce Action Plan templates (Industries clouds) from an SOP `closed`

**Why it's powerful:** An Action Plan template turns a repeatable process into a reusable task set, such as commercial-loan onboarding, an annual client review or care-coordination intake. It sets due-date offsets, owners, priorities and required items, and can be applied to records in bulk or from a Flow.

**Why people bounce off it:** You build templates by hand, one item at a time, setting each item's field values through separate value rows. You then publish a version, which freezes it, so every change means cloning a new version. Banks and clinics usually keep the real 30-step process in a Word SOP that never reaches Salesforce.

**AI operator:** The user pastes the SOP or describes the process. The AI drafts the template item by item, with offsets, owners and required flags, shows it for approval, and saves it. It can also clone an existing template into a revised version.

**Killer example:** 'Turn our 22-step commercial loan onboarding checklist into an action plan on Opportunity; KYC tasks go to the compliance queue and are due within 3 business days.' The AI creates an `ActionPlanTemplate` (TargetEntityType=Opportunity) and an `ActionPlanTemplateVersion`. It then creates 22 `ActionPlanTemplateItem` records (IsRequired, DisplayOrder) and their `ActionPlanTemplateItemValue` rows (Subject, Priority, due-date offset, owner). Finally it publishes the version by setting Status to Final. If that API update doesn't publish, it falls back to a Metadata API deploy of `ActionPlanTemplate`.

**Integration path:** REST sObject API. Template, Version, Item and ItemValue are createable from API 44.0, and Version Status can be set on create and update, with Final meaning Published (Industries API object reference, from search excerpts because the pages returned 403). No excerpt explicitly confirms that an API update to Final publishes the template. The Metadata API `ActionPlanTemplate` type is the fallback write path. Requires the Industries Action Plans licence, so the market is Financial Services, Health, Public Sector, Manufacturing and other Industries clouds, not plain Sales Cloud.

Overlap: No Agentforce feature that generates action plan templates was found (verified). Trailhead teaches setting them up by hand.

**Demand 3/5 · Buildability 4/5**

### 7. SAP Business One pricing engine (special prices, period and volume discounts) `closed`

**Why it's powerful:** Business One works out a line price through a precedence chain: business-partner special prices, then period and volume discounts, then discount groups, then price lists, with quantity breaks and date windows. That chain is how SME distributors run contract pricing.

**Why people bounce off it:** Users don't know which layer won on a given line. Setting up date- and quantity-tiered contract prices means filling in grid after grid, and expired or overlapping specials pile up. The Service Layer can't update period and volume discounts (SAP Note 3006734 calls it a system limitation), so support points customers to the DI API.

**AI operator:** A pricing operator turns contract terms into Business One price records, explains why a given line got a given price, and cleans up expired or overlapping specials.

**Killer example:** 'Give Acme 12% off all Bosch tools for Q1 2027, 15% above 100 units, and tell me why order 4512 priced the drill at list.' The AI builds `SpecialPrices` records with a date line and a quantity line for each item through the DI API (`SpecialPrices.Add`), or through a Service Layer POST for new records. It then reads the price layers for order 4512's drill and shows which rule applied and why the special didn't.

**Integration path:** DI API `SpecialPrices` (OSPP, with SPP1 date and SPP2 quantity lines; SAP B1 SDK help). The DI API is a Windows COM component, so a small on-prem agent is needed. A Service Layer `POST /b1s/v2/SpecialPrices` exists but is reported slow for business partners with many existing prices, and period/volume updates must go through the DI API.

Overlap: No official SAP B1 MCP server was found, and the CData B1 MCP is read-only (verified). No SAP Business AI feature for B1 writes prices. CompuTec and Boyum were not checked. The 08-30 Business One card covers journal entries and reporting, not pricing.

**Demand 3/5 · Buildability 3/5**

### 8. Microsoft Purview Information Barriers + Slack Enterprise Grid barriers (one ethical-wall model for both) `closed`

**Why it's powerful:** Information barriers let a regulated firm stop research and investment banking (or two sides of a legal matter) from chatting, calling or sharing files. Broker-dealers and law firms need this for compliance.

**Why people bounce off it:** In Purview, admins build segments from Entra attribute filters, write pairwise block/allow policies, and then run a separate application job before anything takes effect. Users in more than one segment need an IB mode change first. Slack repeats the whole job with IdP user groups and per-barrier restricted subjects, and Slack Support has to turn the feature on. Firms on both platforms keep two ethical-wall models in sync by hand. A mistake either breaks collaboration or breaches compliance.

**AI operator:** The compliance admin describes the wall once. The AI turns it into Purview segments and policies plus Slack barriers, shows a who-can-talk-to-whom matrix for approval, applies it to both platforms, and reports any drift between them.

**Killer example:** 'Equity Research must not message or call Investment Banking, Compliance can talk to both, same rule in Slack.' The AI runs `New-OrganizationSegment` for each department filter and `New-InformationBarrierPolicy` (SegmentsBlocked / SegmentsAllowed) for each pair. It starts `Start-InformationBarrierPoliciesApplication` and polls its status. On Slack it calls `admin.barriers.create` with the Research user group barriered from the Banking group (restricted subjects im, mpim, call).

**Integration path:** Security & Compliance PowerShell cmdlets for segments, policies and application (Microsoft Learn "information-barriers-policies"). Slack Web API `admin.barriers.create/update/delete/list` (Enterprise Grid, `admin.barriers:write` user token; v1 requires all three restricted subjects).

Overlap: Intapp Walls already manages exclusionary access for Microsoft Teams from its own wall model, which covers law firms on the Microsoft side (verified). No Intapp connector for Slack barriers was found, so this card is pitched at the cross-platform gap, and at broker-dealers without Intapp. The 08-23 Purview card covers DLP and lifecycle, not IB.

**Demand 3/5 · Buildability 3/5**

### 9. Microsoft PowerToys configuration (Keyboard Manager remaps and module settings via PowerToys DSC) `open-source`

**Why it's powerful:** PowerToys is Microsoft's own Windows power-user kit. It includes key and shortcut remapping (per app, launch a program, open a URL), the FancyZones window manager, a launcher, a global mic and camera mute, and keep-awake. Since v0.95 every module can be set from a config file through `PowerToys.DSC.exe` or `winget configure`.

**Why people bounce off it:** Each utility has its own page of opaque toggles (FancyZones alone has about 35). The Keyboard Manager editor is a click-heavy grid. Applying a remap profile replaces the whole remap set, so a naive script wipes existing remaps. Most users never get past "enable it".

**AI operator:** The user describes the setup they want. The AI reads each module's current state, merges in the change, shows a diff, applies it, and emits one `.winget` file that rebuilds the setup on a new PC.

**Killer example:** 'Make Caps Lock Escape, Ctrl+Alt+N save in Notepad only, Win+Shift+T open Terminal, and only snap windows to zones when I hold Shift, without losing my existing remaps.' The AI exports the current Keyboard Manager profile with `PowerToys.DSC.exe export --resource profile --module KeyboardManager`. It merges `{from: CapsLock, to: Esc}`, a Notepad-only `targetApp` remap and a `runProgram` remap for `wt.exe`, then applies the merged profile with `set`. It sets FancyZones `fancyzones_shiftDrag: true` through `set --resource settings --module FancyZones`, runs `test`, and writes the `.winget` file. It doesn't create FancyZones custom layouts, because DSC can't write them yet.

**Integration path:** CLI/declarative: `PowerToys.DSC.exe` get/set/test/export, the `Microsoft.PowerToys/KeyboardManagerProfile` resource and the per-module `Settings` resources (Microsoft Learn "PowerToys Microsoft DSC"). That page documents `targetApp`, `runProgram`, `openUri` and the replace-whole-profile behaviour.

Overlap: No MCP server or Command Palette extension that edits PowerToys settings was found (verified). The WinGet MCP only finds and installs packages. Unlike the AutoHotkey card, this approach is declarative and needs no script. Willingness to pay is the weak point, so it may fit better as a free wedge into a wider Windows-setup operator.

**Demand 2/5 · Buildability 5/5**
