### 1. Clover POS (Fiserv) `closed`

**Why it's powerful:** One of the largest merchant POS estates in North America — hundreds of thousands of restaurants and retailers on Station/Flex/Mini. The Inventory back office supports item groups with attributes and variants, modifier groups with min/max-required semantics, per-item tax rates and exemptions, revenue classes, item-level printer and order-type routing, employee roles with shift permissions, and scheduled discounts/promos.

**Why people bounce off it:** The Modifier Groups screen and the Item Groups → Attributes → Variants flow. Attributes must be defined on the group *before* variants exist, so merchants routinely create 12 duplicate items instead of one item with variants. Modifier groups are created on a separate screen and then attached per item with `minRequired`/`maxAllowed` — set those wrong and the register prompts the server for the wrong thing all day. The Tax Rates screen compounds it: per-item overrides interact invisibly with the default rate.

**AI operator:** A "talk to your menu" layer holding Clover's `/v3/merchants/{mId}/...` object graph (items, item_groups, attributes, options, modifier_groups, modifiers, tax_rates, categories) and doing bulk menu surgery, seasonal repricing, and 86-ing from natural language — including straight from a photo or PDF of a printed menu.

**Killer example:** User: 'Add the new brunch menu — eggs any style at 12.99 with a choice of one bread and up to three sides at a dollar each, and put 8 percent off everything on Tuesdays.' AI POSTs the item to `/v3/merchants/{mId}/items`, creates two modifier groups with `minRequired:1,maxAllowed:1` (bread) and `minRequired:0,maxAllowed:3` (sides), POSTs the `modifiers` at `price:100`, associates them via `item_modifier_groups`, files the item under the Brunch `category`, and creates the scheduled percentage discount — an afternoon of tablet-tapping done in one sentence.

**Integration path:** Clover REST API `https://api.clover.com/v3/merchants/{mId}/...`, Bearer token — merchant API token for single-merchant use, full OAuth 2.0 app flow for multi-merchant, scopes granted per app in the Clover Developer Dashboard. Optional Android SDK for on-device. No scraping.

**Demand 5/5 · Buildability 4/5**

### 2. MikroTik RouterOS `closed`

**Why it's powerful:** Carrier-grade routing on cheap hardware — full BGP/OSPF/MPLS, CAPsMAN centralized wireless, bridge VLAN filtering, queue trees with HTB shaping, IPsec/WireGuard, and a built-in scripting/scheduler engine, all in a $50–$500 box that ISPs, WISPs and SMBs deploy by the million. Every menu in the CLI tree is also a configuration object, so anything the GUI can do is expressible as data.

**Why people bounce off it:** The firewall/NAT chain model plus `bridge vlan-filtering`. Users must hand-order rules across input/forward/output chains, understand where connection-state (`established,related,untracked`) belongs, and separately keep `/interface/bridge/vlan` tagged/untagged member lists in sync with `/interface/bridge/port` pvid. Get one wrong and the router locks them out of Winbox entirely. Add `/ip/firewall/mangle` marking for queue trees and most SMB admins end up copy-pasting forum scripts they do not understand.

**AI operator:** An operator holding a live model of the device's menu tree that reads current `/ip/firewall/filter`, `/interface/bridge/vlan` and `/ip/address` state, computes the minimal ordered change, dry-runs it, and applies it alongside a safety `/system/scheduler` rollback job — so a bad rule auto-reverts after 60 seconds instead of bricking remote access.

**Killer example:** User: 'Put the guest WiFi on VLAN 30, give it 20 Mbps total, and make sure it cannot reach my 192.168.1.0/24 LAN or the router admin ports.' AI POSTs `/rest/interface/bridge/vlan` (vlan-ids=30, tagged/untagged members), sets pvid on the guest port, creates the address/pool/dhcp-server trio, *inserts* two drop rules above the existing accept rule in `/rest/ip/firewall/filter`, adds `/rest/queue/simple` at 20M/20M — and schedules the auto-revert. The rule-ordering and the lockout-safety net are exactly what non-experts get wrong.

**Integration path:** Official RouterOS REST API (`https://<host>/rest/...`, RouterOS ≥ 7.1beta4, HTTP Basic over www-ssl), with the legacy binary API (8728/8729) and SSH `/export` as fallbacks for pre-v7 devices. Every console menu path maps 1:1 to a REST path. No scraping.

**Demand 5/5 · Buildability 4/5**

### 3. Adobe Workfront `closed`

**Why it's powerful:** Enterprise work management for marketing, creative and IT orgs with a Fortune 500 install base: request queues with routed queue topics, multi-step approval processes, custom forms with calculated fields, resource and scenario planners for capacity modeling, proofing with e-signature, and portfolio-level prioritization. Everything is one object graph (Project → Task → Issue → Assignment → Hour) that can be searched and reported on.

**Why people bounce off it:** The report/filter builder and the Setup area. Building a report means choosing a Report Type and then hand-writing filter rules in Workfront's text-mode syntax — `task:project:portfolio:ID=...`, `_Mod=cicontains`, `EXISTS:A:...` sub-filters — which almost no admin gets past. Standing up a Request Queue is worse: Queue Details → Topic Groups → Queue Topics → Routing Rules → Custom Form → Approval Process across five screens, and one misconfigured routing rule silently sends requests nowhere at all.

**AI operator:** A chat layer preloaded with the object model and the text-mode filter grammar. The user describes intake flows, approval policies and portfolio rollups in English; the AI composes the underlying objects, validates by running the resulting search, and previews matched records before saving anything.

**Killer example:** User: 'Any creative request over $50k budget tagged paid-social should need brand review, then land in the Creative Ops queue — and give me a weekly report of everything stuck in review more than 5 days.' AI creates a Queue Topic under the Creative topic group, a Route Rule to the Creative Ops team, an approvalProcess with a Brand Review step, attaches the custom form via `categoryID`, then creates a Report whose text-mode filter reads `status=AWR&status_Mod=in&lastUpdateDate=$$TODAY-5d&lastUpdateDate_Mod=lte` — via `POST /attask/api/v15.0/queuetopic`, `/approvalprocess` and `/report`.

**Integration path:** Workfront REST API `/attask/api/v15.0/<objCode>` with full GET/POST/PUT/DELETE on every object type; auth is Adobe IMS OAuth2 (JWT server-to-server or authorization-code user flow — the legacy `/login` + API key path is deprecated). Optional Workfront Fusion for scheduled automations. No scraping.

**Demand 5/5 · Buildability 4/5**

### 4. REDCap (Vanderbilt) `closed`

**Why it's powerful:** The de facto clinical-research data platform, free-licensed to 7,000+ academic and non-profit institutions and powering hundreds of thousands of studies. Instrument designer, longitudinal events with an arm/event-to-instrument grid, branching logic, calculated fields, data quality rules, Data Access Groups, randomization, e-Consent, and a 21 CFR Part 11 audit trail.

**Why people bounce off it:** The Data Dictionary CSV and REDCap's own logic syntax. Coordinators hand-write branching logic like `[age] > 18 and [consent(2)] = '1'` — with a `[event_1_arm_1][field]` prefix once the project is longitudinal — plus `@CALCTEXT`/`@HIDDEN`/`@DEFAULT` action tags and per-row validation min/max columns, then upload the CSV and try to decode row-level import errors. The 'Define My Events / Designate Instruments for My Events' grid is where most researchers quit and go back to Excel, which is exactly the compliance failure REDCap exists to prevent.

**AI operator:** An operator that owns the whole project-build loop: read the protocol or CRF document the researcher uploads, draft the entire Data Dictionary (fields, types, choice strings, validation, branching, action tags), push it via metadata import, wire up events and instrument designations, create DQ rules and reports — and then repair the specific rows REDCap rejects. The user never opens the Online Designer.

**Killer example:** User: 'Add a follow-up visit at 6 months that only shows the adverse-event form for patients who were on the drug arm, and flag any BP over 180.' AI does `POST content=metadata` to append the `ae_*` fields with branching logic `[baseline_arm_1][treatment_arm] = '1'`, `POST content=event` to add `visit_6mo_arm_1`, `POST content=instrumentEventMappings` to designate the AE instrument to that event only, then adds a Data Quality rule on `[sbp] > 180` — a week of coordinator-and-biostatistician back-and-forth in one turn.

**Integration path:** REDCap API — a single POST endpoint at `https://<host>/redcap/api/` with a form-encoded `content=` verb (metadata, record, project, event, instrumentEventMappings, report, file, userRole). Auth is a per-project-per-user 32-char API token, plus a 64-char Super API Token for `content=project` to create new projects. Official `REDCapR`/`redcapAPI` (R) and `PyCap` (Python) wrappers. No scraping.

**Demand 5/5 · Buildability 4/5**

### 5. Zuora (Billing + Revenue / Workflow) `closed`

**Why it's powerful:** Runs the subscription revenue stack for a large share of enterprise SaaS, telco and media — a product catalog with per-charge pricing models (tiered, volume, overage, discount-percentage), order actions (AddProduct / UpdateProduct / RemoveProduct / RenewSubscription) carrying full mid-term amendment and proration math, and a Workflow engine that reacts to events like failed payments. Object Query and Data Query give SQL-ish access to every subscription, rate plan charge, invoice item and revenue schedule.

**Why people bounce off it:** The Product Catalog and the Orders/amendment model. One plan means stacking Product → Product Rate Plan → Product Rate Plan Charge with `charge_model`, `trigger_event`, `end_date_condition`, bill cycle and pricing tiers all interlocking; any pricing change then becomes a multi-order-action Orders payload with effective dates the UI never explains. Billing ops teams routinely open a Zuora support ticket just to run a plan migration.

**AI operator:** A chat layer over the catalog, Orders and Workflow. It reads current state via Object Query, composes the Orders JSON (including charge overrides and effective dates), runs it through the order *preview* endpoint first, shows a plain-English delta of who gets charged what and when, and only then commits.

**Killer example:** User: 'Move everyone on Pro Monthly to Pro 2026 at their next renewal, but grandfather anyone paying over $10k a year.' AI queries `GET /v1/object-queries/rateplans` plus subscriptions, splits the population by ARR, builds a `POST /v1/orders` payload pairing `RemoveProduct` and `AddProduct` actions triggered at `TermStartDate` with `chargeOverrides` carrying the grandfathered prices, dry-runs it through `POST /v1/orders/preview`, commits, then drops a dunning Workflow in via `POST /workflows/import`.

**Integration path:** Zuora REST API v1 — OAuth 2.0 client credentials → bearer token. Orders API, Product Rate Plan / Charge CRUD, Object Query + Data Query, and the Workflows API (`GET /workflows`, `POST /workflows/import`, `PUT /workflows/tasks/update`). No scraping.

**Demand 5/5 · Buildability 4/5**

### 6. Esri ArcGIS Pro + ArcGIS Online `closed`

**Why it's powerful:** ~2,000 geoprocessing tools (spatial joins, network analysis, suitability modeling, raster algebra), a full cartography engine with CIM-level symbology, ModelBuilder, hosted feature services, and Web Maps/Dashboards/Experience Builder for publishing. It is the dominant platform for municipal government, utilities, environmental agencies and retail siting.

**Why people bounce off it:** Doing anything real means chaining the right geoprocessing tools with correct projections. Users bounce off Project vs Define Projection confusion, the Symbology pane's graduated-colors classification and unique-values setup, and the three separate places you can filter data (Definition Queries, Select By Attributes, Select By Location) — plus joins and relates that fail silently on a field-type mismatch. ModelBuilder is supposed to be the no-code escape hatch and is itself a wall.

**AI operator:** A GIS-analyst-in-a-box spanning both surfaces: the user states a spatial question in plain language, the operator picks and sequences the geoprocessing tools, handles reprojection, builds the layer renderer, and publishes a shareable Web Map or Dashboard to the org's ArcGIS Online.

**Killer example:** User: 'Show me which of our fire hydrants are more than 300 m from any hydrant that was inspected this year, and put it on a map I can send the council.' AI runs `arcpy.analysis.Select` on `inspect_date`, `arcpy.analysis.Buffer` at 300 Meters, `SelectLayerByLocation` with INVERT, applies a `UniqueValueRenderer` through `arcpy.mp` CIM, then uses the ArcGIS API for Python `gis.content.add()` + `Map.save()` to publish a hosted feature layer and Web Map shared to the council group — the classic request that today takes a trained analyst half a day.

**Integration path:** Two official surfaces, no scraping — (1) `arcpy` / `arcpy.mp` Python 3 site package shipped with ArcGIS Pro (needs a local agent and a Pro license), plus the ArcGIS Pro SDK for .NET for add-ins; (2) the ArcGIS API for Python (`arcgis`) and ArcGIS REST API against ArcGIS Online/Enterprise, auth via OAuth 2.0 (app credentials or named-user token) or API keys.

**Demand 5/5 · Buildability 4/5**

### 7. cPanel & WHM `closed`

**Why it's powerful:** cPanel/WHM runs a huge share of the world's shared and reseller hosting. It bundles account provisioning with packages and quotas, Exim mail routing and filters, DNS zone editing, MySQL/Postgres users and grants, cron, AutoSSL, ModSecurity vendor rules, backups, and per-domain PHP version and extension selection — and every one of those is exposed as a callable API function.

**Why people bounce off it:** The gap between 'I own a website' and the WHM/cPanel surface area. Zone Editor is where users mangle MX/SPF/DKIM/CNAME records and silently break their own mail; Email Routing's Local vs Remote vs Backup mail exchanger choice is invisible until mail vanishes; MultiPHP Manager and the Domains/Addon/Subdomain/Alias document-root model confuse everyone. Small-business owners and agency staff open a support ticket rather than touch any of it — which is the hosting industry's single largest ticket category.

**AI operator:** A hosting operator a non-sysadmin can talk to. It resolves intent across UAPI (per-account) and WHM API 1 (server-wide), validates the DNS and mail side-effects *before* writing, and explains what it changed. Doubles as a first-line-support deflector that hosts can bolt into their client area.

**Killer example:** User: 'Move mail for clientco.com to Google Workspace but keep the website here, and set up SPF and DKIM so we stop landing in spam.' AI calls WHM API 1 `setemailrouting` to Remote Mail Exchanger, removes the existing MX records, adds Google's five MX records via `addzonerecord`, rewrites the SPF TXT to `v=spf1 include:_spf.google.com ~all`, adds the DKIM record — then calls UAPI `Email::list_pops` to report which local mailboxes will *stop* receiving mail and need migrating first, which is the step that burns people.

**Integration path:** UAPI (`https://host:2083/execute/<Module>/<function>`) and WHM API 1 (`https://host:2087/json-api/<function>`), both documented at api.docs.cpanel.net; auth via `Authorization: cpanel user:TOKEN` / `Authorization: WHM root:TOKEN` API tokens (cPanel ≥ 76), plus local `uapi`/`whmapi1` CLI binaries. No scraping.

**Demand 4/5 · Buildability 5/5**

### 8. Box (Content Cloud) `closed`

**Why it's powerful:** Far beyond file sync — Box carries a full enterprise content-governance engine: custom metadata templates with cascade policies that auto-stamp every file in a folder tree, retention policies with disposition actions and legal holds, Box Shield classification labels driving access rules, and Box Sign e-signature in the same repository. Roughly 115k companies including most of the Fortune 500 already pay for it.

**Why people bounce off it:** The Admin Console's Metadata → Templates and cascade-policy flow. To get automatic classification and retention you must build the metadata template, then apply a metadata *instance* to the parent folder, *then* create a cascade policy with a conflict-resolution mode, *then* bind a retention policy to that template with the right disposition action. Miss the second step and the cascade silently does nothing — no error, no warning. Almost every customer ends up using Box as an expensive dumb dropbox.

**AI operator:** A governance operator that turns plain-English records-management intent into the full metadata template + cascade + retention + Shield + collaboration stack — and, just as valuably, audits an existing tenant ('show me every folder where retention is not actually applying'), because these misconfigurations are all machine-detectable.

**Killer example:** User: 'Every signed customer contract in /Legal/Contracts should be tagged with counterparty, effective date and renewal date, locked for 7 years after signing, and only Legal can download it.' AI does `POST /metadata_templates/schema`, applies the instance to the folder, `POST /metadata_cascade_policies` with `conflict_resolution: overwrite`, `POST /retention_policies` (`retention_length: 2555`, `disposition_action: remove_retention`), `POST /retention_policy_assignments` scoped to the template, sets a Shield classification, and downgrades external collaborators via `PUT /collaborations/{id}`.

**Integration path:** Box Platform REST API — OAuth 2.0, JWT server auth, or Client Credentials Grant with an enterprise-scoped service account; official Node/Python/Java/.NET SDKs plus the `box` CLI. No scraping. Verified constraint: Box Relay workflows are trigger-only via the Workflow Trigger API (`WORKFLOW_MANUAL_START`) — you cannot author a Relay flow programmatically, so the product must be built on metadata/retention/Shield/Sign/collaboration primitives, not Relay authoring.

**Demand 4/5 · Buildability 5/5**

### 9. vMix `closed`

**Why it's powerful:** A full software live-production switcher used by churches, esports, corporate AV and small broadcasters — unlimited inputs, NDI/SRT/SDI capture, instant replay with slow-motion, multi-bitrate streaming, virtual sets, GT Titles with data sources, and a multi-bus audio mixer. It ships an official HTTP Web API on port 8088 that both returns full XML state and executes every switcher function.

**Why people bounce off it:** Shortcuts/Triggers and GT Title data sources. Wiring a lower-third to a Google Sheet or XML feed means manually mapping `SetText` against `SelectedName` for every text field, and the Triggers dialog (input change → run script → activator) is where volunteer operators give up outright. Replay and multi-bus audio routing are the other two abandonment points — and the people running this software on a Sunday morning are usually unpaid volunteers, not broadcast engineers.

**AI operator:** A voice/chat operator sitting beside the switcher that reads the live XML state and issues API functions — building show presets, wiring title data sources, generating shortcut and trigger sets, and then running the show hands-free ('cut to camera 2, bring up the lower third, start recording').

**Killer example:** User: 'Set up our Sunday service: three cameras, lyrics from that Planning Center CSV as a full-screen title, and a trigger that mutes the pulpit mic whenever camera 3 is live.' AI POSTs `AddInput&Value=Title|Lyrics.gtzip`, loops `SetText&Input=Lyrics&SelectedName=Line1.Text&Value=...` over the CSV rows, then writes a VB.NET script bound via `ScriptStart` and registers it under Input 3's Triggers — a whole volunteer training session replaced by one sentence.

**Integration path:** Official vMix HTTP Web API (`/api/?Function=...` on port 8088) returning full XML state, plus the TCP API and internal VB.NET/Web scripting; auth is local-network or an optional Web Controller password. Runs alongside vMix on the same Windows box. No scraping.

**Demand 4/5 · Buildability 5/5**

### 10. RingCentral (RingEX) `closed`

**Why it's powerful:** RingCentral runs the phone system for roughly 400k businesses and its routing engine is genuinely deep: multi-level IVR menus with recorded prompts, call queues with ring modes (rotating, simultaneous, longest-idle), per-extension and company-wide Answering Rules with business-hours/after-hours/holiday/custom-date conditions, forwarding chains, voicemail-to-email, and SMS/fax on the same extensions.

**Why people bounce off it:** The Admin Portal's Auto-Receptionist → Multi-level IVR tree combined with Answering Rules. Holiday coverage means creating a custom answering rule with explicit date ranges on *each* IVR extension and *each* queue separately, plus a matching after-hours rule, plus a recorded prompt — spread across three different screens with no single view of the resulting call flow. Small businesses pay a VAR for what should be a five-minute change, and the classic symptom is 'we forgot to turn the holiday greeting off' still playing in January.

**AI operator:** A phone-system operator: plain-English call flow in, provisioned IVR + queues + answering rules out, including TTS-generated prompts. It also does continuous ops — 'we're closed Dec 24–26' becomes correctly scoped custom rules on every affected extension — and can diff the live routing tree against what the user *thinks* it is.

**Killer example:** User: 'After 6pm and on weekends, send sales calls to voicemail but keep support ringing the on-call queue, and set a holiday greeting for December 24 to 26.' AI POSTs a TTS prompt to `/restapi/v1.0/account/~/ivr-prompts`, wires `/ivr-menus`, PUTs the sales queue's `after-hours-rule` with `callHandlingAction: TakeMessagesOnly`, POSTs a `type: Custom` answering rule on the support queue with `schedule.ranges` for the holiday dates and `queue.transferMode: Rotating`, then GETs the rules back to show the resulting flow in English.

**Integration path:** RingCentral Platform REST API (`platform.ringcentral.com/restapi/v1.0`) — OAuth 2.0, JWT bearer flow for server-side apps, with `ReadAccounts`/`EditExtensions`/`AutoReceptionist` scopes; official Node/Python/PHP/.NET SDKs and a free sandbox tier. No scraping.

**Demand 4/5 · Buildability 4/5**

### 11. Coupa (Spend Management / Procure-to-Pay) `closed`

**Why it's powerful:** A full source-to-pay suite — requisitions, POs, catalogs and punchout, supplier information management, invoice OCR with 2/3-way match, contracts, sourcing events, expenses and spend analytics — with a policy engine that enforces budget checks, commodity-based routing and multi-level approval chains on every dollar. Thousands of mid-to-large enterprises run it as the system of record for indirect spend.

**Why people bounce off it:** Approval Chains and Chain Links (approval groups, dynamic approvers, custom approval rules) combined with Content Groups, Account Groups and chart-of-accounts Lookup Values, all of which must line up before a requisition will even route. Meanwhile AP clerks drown in an invoice exception queue where `Requires Approval` vs `On Hold` vs `Disputed` give no clue which lever unblocks a stuck invoice — so month-end close becomes a manual scavenger hunt.

**AI operator:** A chat layer over the Coupa Core API preloaded with AP/procurement operator skills: triage the exception queue, mass-approve within policy, chase suppliers, re-code GL strings, and answer 'where is my PO' without anyone learning the object model.

**Killer example:** User: 'Clear the September AP backlog — approve every invoice under $5k that is PO-matched with no exceptions, and push everything else back to the buyer with a note.' AI runs `GET /api/invoices?status=pending_approval&total[lt]=5000`, checks `po-number` and match status per invoice, fires `PUT /api/invoices/{id}/approve` on the clean ones, and reassigns the remainder through `/api/approvals` with a comment — two days of clerk clicking done before lunch.

**Integration path:** Coupa Core API (REST, JSON/XML) at `https://<instance>/api/*` — `/requisitions`, `/purchase_orders`, `/invoices`, `/suppliers`, `/approvals`, `/users`. Auth is OAuth 2.0 client credentials with scopes (Setup → Integrations → OAuth2/OIDC Clients); the legacy `X-COUPA-API-KEY` header still works. Separate Coupa Supplier Portal REST API for the supplier side. No scraping.

**Demand 4/5 · Buildability 4/5**

### 12. Drupal (core + Views UI + Layout Builder) `OSS`

**Why it's powerful:** Drupal runs roughly a million sites including most large government, university and enterprise publishing estates. It gives arbitrary content modeling (entity types, bundles, fields, taxonomy, Paragraphs), a query builder (Views) that produces any listing, feed or REST export without code, and a full config-as-code system where every structural change is exportable YAML. Layout Builder, Workspaces content staging, and per-role/per-field permission matrices put it well beyond WordPress for structured multi-site publishing.

**Why people bounce off it:** The Views UI — the Format / Fields / Filter criteria / Sort criteria / Relationships / Contextual filters panel where something as simple as 'articles by author in the last 30 days, excluding one term' requires knowing you must first add a *Relationship* to reach the field, then a *Contextual Filter* with the right 'when the filter value is NOT available' fallback. The field/bundle machine-name conventions and the form-display vs view-display split are the second wall; the permission grid with hundreds of checkboxes is the third.

**AI operator:** An operator preloaded with Drupal's entity, field and Views config schema that writes and applies config-entity YAML through Drush. A site builder describes a content type, listing page or permission change in English; the AI produces the correct bundle, fields, displays and view — and diffs the config export before applying anything.

**Killer example:** User: 'Make a Press Releases section — each one has a date, a PDF attachment, and a region; show the 10 newest for whatever region the visitor is browsing, and let the Comms team publish but not delete.' AI creates `node.type.press_release`, the field storage and instances, configures `core.entity_form_display` and `core.entity_view_display`, builds a `views.view.press_releases` config entity with a taxonomy-term contextual filter using the 'Taxonomy term ID from URL' default argument, adds `user.role.comms` with create/edit but not delete, then runs `drush config:import --partial` and `drush cr`.

**Integration path:** Drush 13 CLI (`config:export/import`, `entity:create`, `php:script`, `sql:query`) over SSH or Drush aliases; JSON:API (core, `/jsonapi/...`) with Simple OAuth or Basic Auth for content CRUD; the PHP Entity/Config API for anything Views-related. No scraping.

**Demand 4/5 · Buildability 4/5**

## Killed during verification (no usable programmatic surface for the actual wall)

- **Trello / Butler** — REST API exposes boards and cards, but there is no public endpoint to create or manage Butler rules, which *is* the usability wall.
- **Yotpo Loyalty & Referrals** — earning rules, VIP tiers and reward campaigns are UI-only; the API merely records customer actions against rules that already exist.
- **Gainsight** — CTA/Task/Playbook APIs exist, but the Rules Engine and Journey Orchestrator Programs (the real wall) have no create endpoint.
- **Amplitude** — the Dashboard API only queries saved charts; there is no POST to create a chart or dashboard.
- **Articulate Storyline 360** — no public authoring API or SDK; `.story` is a closed binary and only SCORM/xAPI output is programmatic.
- **Affinity (Photo / Designer / Publisher)** — still no scripting API or plugin SDK, unchanged after the Canva acquisition.
