### 1. Windows Server IIS (sites, bindings, app pools, URL Rewrite) `closed`

**Why it's powerful:** It is the built-in web server on Windows Server and hosts a large base of internal line-of-business and ASP.NET apps. It covers sites, app pools, rewrite rules, a central certificate store and shared configuration.

**Why people bounce off it:** Config is spread across nested `applicationHost.config` and `web.config` files, and IIS Manager hides which level a setting came from. Rewrite rules inherit parent-to-child and run in order, so a rule that looks harmless can change what later rules see. The people who inherit these servers are often general admins, and one wrong binding or rule takes an app down.

**AI operator:** The admin describes the outcome. The AI backs up the config, shows a diff, applies the change in one commit, then tests the URL. It can also explain which config level set a value and why a request was rewritten.

**Killer example:** 'Stand up the new build at shop.contoso.com, force HTTPS, and redirect the old /catalog URLs.' The AI runs `Export-IISConfiguration` for a backup and creates the pool with `New-WebAppPool`. It opens a batch with `Start-IISCommitDelay`, adds the site and HTTPS binding with `New-IISSite` and `New-IISSiteBinding`, then commits with `Stop-IISCommitDelay`. It adds the redirect rules to the site's rewrite `<rules>` collection and requests the old and new URLs to confirm the status codes.

**Integration path:** PowerShell over WinRM:
- The IISAdministration module: `Start-IISCommitDelay`, `Stop-IISCommitDelay`, `Export-IISConfiguration` (confirmed in the module list). It has `Get-IISAppPool` but no create cmdlet.
- The WebAdministration module: `New-WebAppPool` (doc page read).
- URL Rewrite distributed `<rules>` and global `<globalRules>` (confirmed in the configuration reference). The module is a separate install. Writing rules with `Add-WebConfigurationProperty` on `system.webServer/rewrite/rules` is from memory and needs a test. A pool made with WebAdministration won't necessarily join the IISAdministration commit batch, so create it first.

Overlap: Microsoft's April 2026 agentic IIS tooling, run from VS Code Copilot Chat, migrates IIS apps off to Azure App Service and is not for running IIS. Searches for chat management of IIS in Windows Admin Center, Azure Copilot and Arc found nothing, which doesn't prove none exists.

**Demand 4/5 · Buildability 4/5**

### 2. Outlook bulk attachment filing to SharePoint / OneDrive (historical backlog) `closed`

**Why it's powerful:** The mailbox is where many organizations' invoices, contracts and statements first arrive, and SharePoint is where those files are supposed to live.

**Why people bounce off it:** Outlook saves attachments message by message. Doing it across years of mail with sensible names and folders means VBA or a Power Automate flow, and the flows found handle new mail rather than the backlog. Signature images and duplicates pollute the result. The 2026-10-15 reclaim card frees mailbox space; it doesn't build a filed archive.

**AI operator:** The user states the criteria and filing convention in plain language. The AI previews the plan, skips inline images and duplicates, files everything and writes an index workbook.

**Killer example:** 'Save every invoice PDF from our suppliers since 2023 into Finance/Invoices/supplier/year, named by date and invoice number.' The AI finds the messages and calls `GET /me/messages/{id}/attachments`. It filters on `isInline` and `name`, decodes `contentBytes`, and reads invoice numbers from the PDFs. It shows the first 50 proposed paths, then uploads with `POST /sites/{siteId}/drive/items/{parentItemId}:/{fileName}:/createUploadSession`. It finishes with an index listing each file's source message and the 12 PDFs it couldn't parse.

**Integration path:** Graph message list attachments (confirmed) and driveItem `createUploadSession` (doc read; delegated `Files.ReadWrite` is supported). Fragments must be multiples of 320 KiB. Gmail plus Drive would be the second connector (unverified).

Overlap: not fully ruled out. Copilot Cowork's Email skill "manages attachments", but its docs don't describe filing history into named libraries, and Outlook Copilot and Agent Builder got no dedicated search. harmon.ie saves emails, attachments and whole Outlook folders through a UI, with Copilot features in beta. Test Cowork live before building.

**Demand 4/5 · Buildability 4/5**

### 3. OneDrive / SharePoint sync repair (conflict copies, illegal names) `closed`

**Why it's powerful:** OneDrive is the default file layer for Microsoft 365. Files On-Demand and per-device sync mean whole companies work out of it.

**Why people bounce off it:** Offline or two-device edits leave copies tagged with the PC name, and the user has to work out which one is current. Illegal characters, reserved names, and names such as `.lock` or `desktop.ini` block sync. Bulk-renaming before fixing the conflict can re-trigger duplicates. The seen SharePoint version-reclaim and Office Link Fixer cards cover different jobs.

**AI operator:** A local agent plus Graph scans the sync root and groups conflict copies. It compares their content and versions, proposes a keep, merge or archive plan, and applies it after approval. It never deletes: losing copies go to a dated folder.

**Killer example:** 'OneDrive has been complaining for weeks. Fix it and don't lose anything.' The AI scans locally and lists 214 conflict copies and 37 illegal names. It renames with `PATCH /me/drive/items/{item-id}` using `name` and moves losing copies to `_Conflicts/2026-11` using `parentReference`. The `if-match` header makes each call fail safely if the file changed in the meantime.

**Integration path:** Graph driveItem update and Microsoft's naming restrictions page (both confirmed). No documented API for sync-client error state was found, so the MVP infers problems from local file names and state. The delta and versions endpoints weren't checked. The conflict-copy behaviour comes from third-party sources.

Overlap: Copilot Cowork's FAQ says by design it can't access local files or delete in OneDrive or SharePoint, which leaves room here. Other vendors weren't checked.

**Demand 5/5 · Buildability 3/5**

### 4. TLS certificate renewal for the 200/100/47-day limits (Windows-first, CA-neutral) `mixed`

**Why it's powerful:** Certificates sit on every public endpoint, and ACME can automate issuance and renewal end to end.

**Why people bounce off it:** Public certificate lifetimes fell to 200 days on 2026-03-15, then drop to 100 days on 2027-03-15 and 47 days on 2029-03-15. The hard part isn't buying certificates. It's finding every one and installing renewals on each kind of target, and many small shops still track this in a spreadsheet. The seen nginx and AD CS cards cover one web server's config and internal PKI.

**AI operator:** It builds the inventory and sorts targets by whether they can auto-renew. It sets up ACME per target and flags the ones that still need a person. It isn't tied to any certificate authority.

**Killer example:** 'Find every public cert we still renew by hand, and put our Windows servers on auto-renew before the 100-day rule hits in March.' The AI inventories bindings with `Get-IISSiteBinding` and `Get-RDCertificate`, then compares them with Certificate Transparency logs to find what it missed. It sets up Posh-ACME with `New-PACertificate` and schedules `Submit-Renewal`. It installs with `New-IISSiteBinding` or `Set-RDCertificate`, and lists 6 appliance certificates that still need a person.

**Integration path:** The IIS and RDS install cmdlets are confirmed in their module lists. Posh-ACME is actively maintained (v4.35.0, October 2026) and `Submit-Renewal` is documented; `New-PACertificate` is from memory. win-acme is a real alternative, with its last stable release in May 2024. Certificate Transparency lookup and appliance targets weren't checked.

Overlap: Sectigo's MCP Server (GA June 2026, per a search result) offers issuance, renewal, revocation and search from Claude or Copilot. Keyfactor Command MCP was in preview in 2025. CyberArk, DigiCert and AppViewX got only one combined search with no hits. Stay away from enterprise CLM: the opening is small teams with no CLM product and more than one CA.

**Demand 5/5 · Buildability 3/5**

### 5. IRS IRIS 1099 e-filing after FIRE retirement (A2A, high-volume filers) `closed`

**Why it's powerful:** IRIS is the federal intake for the 1099 family and 1042-S, with bulk A2A XML, corrections and combined federal/state filing.

**Why people bounce off it:** FIRE's last filing is 2026-11-19 at 3 p.m. ET, FIRE transmitter code applications go read-only on 2026-11-09, and IRIS is the only system from January 2027. A2A needs an IRIS TCC, an API Client ID, a JWKS file with an X.509 certificate, and ATS testing before production. Schemas come only in a package that expires after 60 days. The IRS's own Q&A shows filers confused about issuer versus transmitter and about which Client ID to use.

**AI operator:** It turns AP or vendor exports into validated IRIS submissions, walks the filer through onboarding, and explains rejections in plain language.

**Killer example:** 'File our 1,400 1099-NECs from this AP export and fix the ones that bounce.' The AI maps rows to the IRIS schema and transmits with `POST https://api.www4.irs.gov/IRIntakeAcceptanceA2A/1.0/irisa2a/v1/intake-acceptance`. It polls `POST .../iris/transstatusorack` with the Receipt ID and explains 23 TIN rejections in plain language. A person approves the corrections before it submits them.

**Integration path:** Pub 5718 (A2A), Pub 5719 (ATS), Pub 5717 (portal) and Pub 5903 (TCC). The endpoints come from a Pub 5718 search excerpt, and a 2024 IRS Q&A spells the path `intakeacceptance`, so check the current PDF. A TCC can take 48 hours to 45 days, which makes January tight for anyone starting now. The portal route takes CSV and needs a person to upload it. Using an agent doesn't relieve the payer's penalty liability.

Overlap: Tax1099 AI Assist already files NEC and MISC in chat for up to 50 recipients and has an MCP server, per its own marketing. TaxBandits' BanditAI exists, with chat filing unconfirmed. So stay on in-house filers above that size who are leaving FIRE. Cheap filing vendors are the real competition.

**Demand 4/5 · Buildability 3/5**

### 6. Brazil NFS-e Nacional service invoices `closed`

**Why it's powerful:** It is a national service-invoice system with public APIs for issuing, municipal parameters and the national registry, which replaces a patchwork of city systems.

**Why people bounce off it:** Small service providers must get the DPS layout and each municipality's parameters right, and the layout spec is a technical annex spreadsheet. The timing is sharp: Simples Nacional ME and EPP companies moved to the national system on 2026-11-01 under CGSN 191/2026 (from a search excerpt, not the resolution itself).

**AI operator:** The user describes the sale. The AI checks the municipality's parameters, builds and signs the DPS, submits it and returns the result, explaining any rejection in plain Portuguese.

**Killer example:** 'Issue an R$ 8,000 consulting invoice to client X in Campinas.' The AI calls `GET /parametros_municipais/{codigoMunicipio}/convenio` and builds the DPS from Anexo I. It signs with XMLDSig and calls `POST /SefinNacional/nfse` over mTLS with the signed XML in `dpsXmlGZipB64`. It stores the returned NFS-e and sends the client a copy.

**Integration path:** The official API listing covers SEFIN, ADN, CNC, Parâmetros and DANFSe, each with a restricted-production environment, and there is a taxpayer API manual (v1.2). The JSON body, XMLDSig and A1 e-CNPJ over mTLS come from an ACBr forum thread and a PyPI package, not the manual, so verify them there. `dpsXmlGZipB64` was seen on the restricted-production host. NT 008 said the DANFSe API would be suspended on 2026-07-15, and its current status is unknown.

Overlap: two Portuguese searches found no named chat agent, but Focus NFe and NFE.io never surfaced, so check each vendor before building. Unlike the seen CFDI, GSTN and ZATCA cards, this is a brand-new mandate.

**Demand 4/5 · Buildability 3/5**

### 7. Windows Server Remote Desktop Services (on-prem RDS) `closed`

**Why it's powerful:** It delivers published apps and shared desktops with no cloud dependency, and it still ships in Windows Server 2025. The seen Azure Virtual Desktop and Windows 365 card covers only the cloud products.

**Why people bounce off it:** Connection Broker, Gateway, Web Access, Licensing, collections and per-role certificates all interlock. Routine jobs such as publishing an app or draining a host mean moving between consoles.

**AI operator:** The admin asks in plain language for publishing, session-policy and maintenance changes, and the AI runs them against the Connection Broker. It also catches settings that don't do what the admin assumes.

**Killer example:** 'Publish the payroll app to Accounting only, log idle sessions off after 2 hours, and drain RDSH02 for patching tonight.' The AI runs `New-RDRemoteApp -UserGroups Accounting` and warns that this controls who can see the app, so it also checks file permissions. It sets `Set-RDSessionCollectionConfiguration -IdleSessionLimitMin 120` with `-BrokenConnectionAction`. It runs `Set-RDSessionHost -NewConnectionAllowed NotUntilReboot`, then uses `Get-RDUserSession` and `Send-RDUserMessage` to warn the people still connected.

**Integration path:** The RemoteDesktop module. All three parameters above are confirmed on their doc pages; note the plural `-UserGroups` here against `-UserGroup` on the collection cmdlet. Deployment cmdlets such as `New-RDSessionDeployment` and `Set-RDLicenseConfiguration` are in the module list. CAL pack installation and Gateway CAP/RAP policies aren't in that module, so leave them out of the MVP.

Overlap: one search covering Windows Admin Center and Copilot found no chat management, which doesn't prove none exists.

**Demand 3/5 · Buildability 4/5**

### 8. Active Directory Sites and Services (replication topology) `closed`

**Why it's powerful:** Sites, subnets and site links control which domain controller clients use and how directory changes move across the WAN.

**Why people bounce off it:** Cost, frequency and schedule settings interact in ways few admins understand, and orphaned subnets quietly send clients to the wrong domain controller. The topology is rarely touched, so the knowledge fades. The seen account hygiene, Group Policy and DNS/DHCP cards don't cover it.

**AI operator:** It turns a description of the offices and WAN into a topology, previews it with `-WhatIf`, applies it, then checks replication health. It also audits for subnets with no site.

**Killer example:** 'We opened Pune on 10.40.0.0/16. Replicate with Kochi every 15 minutes, but only overnight.' The AI previews, then runs `New-ADReplicationSite -Name Pune` and `New-ADReplicationSubnet -Name 10.40.0.0/16 -Site Pune`. It builds an `ActiveDirectorySchedule` for the overnight window with `SetDailySchedule` and runs `New-ADReplicationSiteLink -SitesIncluded Pune,Kochi -ReplicationFrequencyInMinutes 15 -ReplicationSchedule $schedule`.

**Integration path:** The ActiveDirectory module. All three `New-` cmdlets and their `-WhatIf` support are confirmed on their doc pages, and the schedule pattern appears in the `New-ADReplicationSite` examples. Health checks with `repadmin` are from memory. No AD-specific agent search was run, so overlap is unchecked.

**Demand 3/5 · Buildability 4/5**

### 9. Shopify Plus expansion-store diff and promote `closed`

**Why it's powerful:** Plus allows one main store and nine expansion stores, so a brand can run separate storefronts per region or brand, each with its own currency, catalog and settings.

**Why people bounce off it:** Shopify's help says products, collections and inventory don't sync between stores, and import is offered only when a store is created. Every change is repeated per store or pushed through middleware, and the stores drift apart without anyone noticing. The seen Shopify Markets + B2B card works inside one store.

**AI operator:** It treats one store as the source, compares the others against it, and promotes approved changes while keeping local prices and translations.

**Killer example:** 'Copy the Autumn collection and its 40 products from US to UK and DE, keep local prices, and show me the differences first.' The AI reads each store through the Admin GraphQL API and shows a per-store diff. After approval it writes each product with `productSet`, merging in the local prices it read, and creates the collection with `collectionCreate`.

**Integration path:** `productSet` and `collectionCreate` are confirmed in the 2026-10 Admin GraphQL API, and both need `write_products`. A separate token per store is assumed from how Shopify apps normally work. Test how `productSet` treats fields left out of the payload before trusting it with live prices.

Overlap: two searches of Shopify's domains found no Sidekick or organization-admin cross-store sync or diff. Edition ($25–80/month) and Syncio are rule-based sync apps, and Shopify's own guidance pushes retailers toward one store with Markets. The edge has to be chat-driven diffing and one-off promotion, not continuous sync.

**Demand 3/5 · Buildability 4/5**

### 10. PowerPoint narrated video (speaker notes to voiceover, timings and video) `closed`

**Why it's powerful:** PowerPoint is the default authoring tool for corporate training, and it can record narration and export video.

**Why people bounce off it:** Getting a clean result means recording slide by slide, redoing takes after any edit, syncing animations and keeping timings aligned. One changed slide often means re-recording and re-exporting. The seen Slide Master and animation cards don't cover narration.

**AI operator:** It treats speaker notes as the script, generates audio per slide, sets timings to match, and regenerates only what changed.

**Killer example:** 'Turn this deck into a training video using my notes, and fix slide 12's narration since the policy changed.' The AI rewrites slide 12's notes and regenerates that audio with an external text-to-speech service. It embeds the audio, sets the slide timings and calls `Presentation.CreateVideo(FileName, UseTimingsAndNarrations, DefaultSlideDuration, VertResolution, FramesPerSecond, Quality)`.

**Integration path:** `CreateVideo` is confirmed in the VBA reference, so this is a desktop Windows COM path. `AddMediaObject2` and `SlideShowTransition.AdvanceTime` are from memory. MP4 output is confirmed only through the UI, and the `Quality` scale is undocumented, so test both first.

Overlap: Copilot's Agent mode writes speaker notes, and no Microsoft page was found for AI voiceover in the export flow; Clipchamp wasn't checked. Pictory's add-in reportedly exports MP4 with voiceover (secondary source), and avatar-video vendors import decks. The edge is keeping the deck as the source and re-rendering one slide.

**Demand 3/5 · Buildability 3/5**

### 11. Dynamics 365 / Dataverse server-side sync (mailbox rollout and repair) `closed`

**Why it's powerful:** It syncs email, appointments, contacts and tasks between Exchange and Dynamics at server level, per mailbox and queue. Every Dynamics activity timeline depends on it.

**Why people bounce off it:** Admins work through mailbox records one at a time: server profile, delivery methods, address approval, Test & Enable. Failures appear as per-mailbox alerts and codes such as 8005E274 / `MailboxNotEnabledForRESTAPI`, and the fix may be a different server profile.

**AI operator:** A rollout and triage operator. It configures mailboxes in bulk, schedules the tests, groups failures by cause and proposes the fix for each group.

**Killer example:** 'Get the 40 new sales reps syncing and tell me who failed, and why.' The AI finds their records with `GET /mailboxes`. It uses `PATCH /mailboxes(id)` to set the server profile and the incoming, outgoing and ACT delivery methods, then sets `testemailconfigurationscheduled` to true. It reads back `incomingemailstatus`, `outgoingemailstatus` and `actstatus`, reports 34 working, and groups the other 6 by cause.

**Integration path:** The Dataverse Web API `mailboxes` table, whose reference lists Create, Update, Upsert and SetState and these fields as writable. No `TestAndEnable` action is listed, so the path is to schedule the test and poll; this is inferred from the field description and hasn't been run. Microsoft 365 admin approval of the email address stays a human step. Writes to the `emailserverprofile` table weren't confirmed, so the MVP assigns existing profiles only.

Overlap: no named Copilot for this job was found, from one search. This isn't covered by the seen Dynamics 365 Sales card.

**Demand 3/5 · Buildability 3/5**
