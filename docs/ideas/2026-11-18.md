### 1. Okta → Microsoft Entra ID: SSO app-integration exit `closed`

**Why it's powerful:** Entra ID P1/P2 already ships inside Microsoft 365 E3/E5. For a company paying for both, every SAML/OIDC app moved off Okta is a step toward dropping a six- or seven-figure Okta renewal. Entra has a large app gallery, Conditional Access and group-based assignment, so most apps have a direct home.

**Why people bounce off it:** Every app must be rebuilt by hand: entity ID, ACS/reply URLs, NameID format, claims (Okta Expression Language has to become Entra claims mapping or transformations), signing certificate, and group assignments. After that, each app needs its own cutover with the SaaS vendor's admin. Microsoft's Okta-to-Entra tutorial is entirely manual: inventory Okta with Postman, then configure apps one at a time in the portal. The Entra migration wizard reads AD FS, not Okta. A 140-app estate turns into a months-long consultant project, and that is why so many companies keep paying for both.

**AI operator:** 'Okta Exit' skill pack. It inventories every Okta app with its assignments, sign-on mode, attribute statements and recent usage, then sorts apps into gallery match, custom SAML, OIDC and "unused, just retire". It translates Okta expressions into Entra claims, instantiates the Entra twin, copies or rotates certificates, and assigns the matching synced groups. It runs a test sign-in and produces a per-app cutover sheet (the new metadata URL, certificate and entity ID to give the SaaS vendor). Okta stays live as the fallback until each app is confirmed working.

**Killer example:** User: 'Move our 140 Okta apps to Entra. Start with the 30 that have no custom expressions, leave Salesforce and Workday for last, and retire anything nobody has signed into for 90 days.' The AI reads `/api/v1/apps` and the System Log and finds 22 apps with no sign-ins in 90 days, which it lists for retirement. It instantiates 30 Entra enterprise apps from gallery templates, sets SAML mode, uploads signing certificates, maps `user.department` and the `groups` claim filter, and assigns 41 groups. It then hands IT a cutover sheet with each vendor's new IdP metadata URL. One app (an internal Jira with `String.substringBefore(user.email, "@")` as NameID) gets a claims transformation and a flag for human review.

**Integration path:** Okta Management API (`GET /api/v1/apps`, `/api/v1/apps/{id}/groups`, System Log `/api/v1/logs`). Microsoft Graph: `POST /applicationTemplates/{id}/instantiate`, `PATCH /servicePrincipals/{id}` with `preferredSingleSignOnMode: "saml"`, `POST /servicePrincipals/{id}/addTokenSigningCertificate`, claims-mapping policies, `POST /servicePrincipals/{id}/appRoleAssignedTo`. Docs: learn.microsoft.com/graph/application-saml-sso-configure-api and learn.microsoft.com/entra/identity/enterprise-apps/migrate-applications-from-okta.

**Verification:** Verified 2026-11-18: the three Graph calls are documented, and Microsoft's Okta → Entra tutorial is manual, with no script or tool. The nearest first-party item is the Security Copilot App Lifecycle Management agent (roadmap RM536578), which covers discovered unmanaged apps, not Okta migration. Disclosure: Cyclotron's 'Beam' is a paid third-party migration service. Different from the 2026-08-14 Okta card, which operates Okta rather than leaving it.

### 2. Tableau Server / Cloud: connection re-pointer and embedded-credential rotator `closed`

**Why it's powerful:** Every published workbook and data source holds its own connection: server address, port, username and an embedded password. Those connections drive every extract refresh and live query in the deployment.

**Why people bounce off it:** A database server rename, a move to Azure SQL, a service-account password rotation or Snowflake's move off password users means editing hundreds of connections, one Edit Connection dialog at a time. There is no "find every connection to `sqlprod01` and change it" screen. One missed source shows up as silent refresh failures days later, usually in the CFO's dashboard. Teams either put off the rotation (a security finding) or schedule a weekend of clicking.

**AI operator:** 'Connection Cutover' skill pack. It inventories every workbook and data-source connection on a site and groups them by host, database and user. It proposes waves, rewrites server, port and credentials, and runs a test extract refresh for each changed item. Failures roll back to the stored previous values. It also answers ahead of time, for example 'what breaks if `svc_tableau` loses its password?'

**Killer example:** User: '`sqlprod01` moved to `sqlprod-az.database.windows.net`, and `svc_tableau` now has a new password in the vault. Fix everything, finance first.' The AI finds 312 connections (204 in workbooks, 108 in published data sources). It updates the 41 in the Finance project first, triggers the 37 affected extract refreshes, and finds 4 failures: 3 still pointing at an old database name and 1 needing `Encrypt=True`. It fixes those, then rolls out the remaining waves overnight and posts a before/after report.

**Integration path:** Tableau REST API: Query Data Source Connections / Query Workbook Connections, then `PUT /api/{v}/sites/{site}/datasources/{ds}/connections/{conn}` and the workbook equivalent with `serverAddress`, `serverPort`, `userName`, `password`, `embedPassword`. Run Extract Refresh Task to test. The Metadata GraphQL API gives lineage (which dashboards sit on each connection). Works for Tableau Server and Tableau Cloud with a PAT.

**Verification:** Verified 2026-11-18: both connection-update methods are documented (the field is `serverPort`, not `port`). The official `tableau/tableau-mcp` has no connection-update tool (checked `toolName.ts`). Disclosure: Tableau's paid Content Migration Tool can transform connections during a site-to-site migration. In-place rotation on a live site is the gap. Different from the 2026-10-18 Tableau permissions card and the Tableau Cloud delivery-layer card.

### 3. Poland KSeF 2.0: permissions and authorization manager `closed`

**Why it's powerful:** KSeF is Poland's mandatory national e-invoicing system. It has been live for large taxpayers since 1 February 2026 and for most others since 1 April 2026, and the smallest firms join in 2027. Every Polish B2B invoice passes through it, so KSeF permissions decide who can issue invoices for a company and who can read its invoices.

**Why people bounce off it:** The 2.0 permission model is complex:
- grants to persons (PESEL, NIP or certificate fingerprint) versus grants to entities by NIP
- indirect grants through an accounting office, which only work if the client set `canDelegate`
- selective targets (one client's NIP) versus general ones (`AllPartners`), which can't be mixed in one call
- subunit administrators identified by `InternalId` (NIP plus 5 digits)
- EU-entity representatives and self-billing authorizations
- two different revoke paths

Accounting offices with 100+ clients and companies offboarding staff get this wrong. A wrong grant either blocks invoicing on a deadline day or leaks every purchase invoice to an ex-employee.

**AI operator:** 'KSeF Access Steward' skill pack. It answers 'who can see or issue invoices for NIP X?' in plain Polish or English. It turns an onboarding, offboarding or new-accountant request into the right set of grant and revoke calls, and shows an accounting office which clients haven't delegated yet. It polls each operation reference until it completes. Every change is previewed, with the authenticated context (qualified signature or a token holding `CredentialsManage`) shown before anything is sent.

**Killer example:** User: 'Jan Kowalski leaves Friday, revoke everything he has. Give Biuro Rachunkowe Lex (NIP 5251234567) InvoiceRead and InvoiceWrite with delegation, and make Anna Nowak admin of the Kraków subunit.' The AI queries person grants and finds 3 for Jan, including an InvoiceRead nobody remembered granting. It schedules 3 `DELETE /permissions/common/grants/{id}` calls for Friday 17:00, sends 1 entity grant with `canDelegate=true` and 1 subunit grant, then confirms all 5 operation references as completed.

**Integration path:** KSeF 2.0 API, documented in the official CIRFMF `ksef-docs` (`uprawnienia.md`):
- grant: `POST /permissions/persons/grants`, `/permissions/entities/grants`, `/permissions/indirect/grants`, `/permissions/subunits/grants`, `/permissions/authorizations/grants`, `/permissions/eu-entities/grants`
- revoke: `DELETE /permissions/common/grants/{permissionId}` and `/permissions/authorizations/grants/{permissionId}`
- query: `/permissions/query/*`
- status: `/permissions/operations/{ref}`

**Verification:** Verified 2026-11-18: every endpoint above is in the official docs. Community KSeF MCPs were checked: `olegtyshcneko/ksef-mcp` has only an attachment-permission check, `cmendezs/mcp-ksef-pl` has 25 tools and none for permissions, and `gacabartosz/ksef-mcp` handles tokens only. A `flippico/ksef-mcp` named in a directory doesn't exist on GitHub. Note: the KSeF *reconciliation* idea was cut on an earlier run as the same operator as the 2026-09-25 GSTN card. The drop note said 'only a different job such as access and permissions setup would reopen it', and this is that job.

### 4. Microsoft 365 rebrand / domain change (UPN, primary SMTP, SharePoint tenant rename) `closed`

**Why it's powerful:** One Microsoft 365 tenant can take on a new identity after a rebrand, merger or divestiture without migrating any data. Users get new sign-in names and email addresses, old addresses keep receiving mail as aliases, and SharePoint and OneDrive URLs can move to a new `*.sharepoint.com` name.

**Why people bounce off it:** The change is spread across four tools, each with its own rules:
- **Entra:** UPN changes (made in on-prem AD instead when the tenant is hybrid).
- **Exchange:** primary SMTP swaps, done one mailbox at a time because email address policies only cover Groups.
- **SharePoint:** `Start-SPOTenantRename`, which only targets an onmicrosoft.com name, is blocked for multi-geo, can be used once or twice per tenant, and keeps redirects for one year.
- **Everything else:** Power Automate flows, documents and Teams tabs with hard-coded URLs, which break later.

Admins lose a weekend to scripts and then spend months on broken links.

**AI operator:** 'Rebrand Conductor'. It runs a readiness check (hybrid or cloud-only, multi-geo, site count, OneDrive sync clients, flows and documents with hard-coded URLs), then runs the change in waves. It adds and verifies the domain, swaps the primary SMTP and keeps the old address as an alias, changes UPNs, schedules the SharePoint rename for a quiet window, and produces a 'will break' report with suggested fixes.

**Killer example:** User: 'We're Acme now, not Zentra. Move 2,300 users to @acme.com, keep @zentra.com mail working, rename SharePoint to acme.sharepoint.com on a weekend.' The AI confirms the tenant is cloud-only and single-geo. It swaps SMTP for 2,300 mailboxes and 140 groups, updates UPNs in waves of 200 (excluding 12 service accounts used by scanners), and schedules `Start-SPOTenantRename` for Saturday 22:00. It lists 87 Power Automate flows and 1,204 documents that link to `zentra.sharepoint.com` and rewrites the flow URLs after the rename.

**Integration path:** Microsoft Graph `POST /domains` + verification, `PATCH /users/{id}` (userPrincipalName). Exchange Online PowerShell `Set-Mailbox -WindowsEmailAddress` / `-EmailAddresses`, `Set-UnifiedGroup -PrimarySmtpAddress`. SharePoint Online `Start-SPOTenantRename` / `Get-SPOTenantRenameStatus`. Power Automate flow definitions are read and written through the Dataverse `workflows` table.

**Verification:** Verified 2026-11-18 (medium confidence): the Microsoft 365 Admin agent's GA scope (MC1436831) lists users, licenses, groups, agent governance, service health and Message Center. Nothing in it covers domain, UPN or SMTP changes. `Start-SPOTenantRename` limits come from Microsoft Learn. Disclosure: non-AI bulk tools exist (ManageEngine), and some vendors sell SharePoint-only rename helpers. Different from the 2026-10-24 Entra cross-tenant access card (B2B access, not identity change).

**Demand 3/5 · Buildability 4/5**

### 5. Exchange Online public folders → Microsoft 365 Groups / shared mailboxes, before the EWS shutdown `closed`

**Why it's powerful:** Public folders are the shared mail, calendar and contact store behind many companies' info@ folders, shared calendars and CRM sync. Some of these hierarchies go back twenty years.

**Why people bounce off it:** Microsoft is blocking EWS in Exchange Online from October 2026 and fully on 1 April 2027. It has said it 'will not provide APIs for programmatically creating, reading, updating and deleting public folders after October 2026', so every third-party sync and backup of public folders breaks. The supported way out, batch migration to Microsoft 365 Groups, has three gaps:
- It copies only Mail and Calendar folders.
- The target groups must already exist.
- Mapping thousands of folders, their client permissions, their mail-enabled addresses and their Contacts folders is left to the admin, with CSV files and helper scripts.

**AI operator:** 'PF Exit' skill pack. It inventories the folder tree, item counts, last-modified dates, client permissions and mail-enabled addresses, and proposes a target for each subtree: a Group, a shared mailbox, or leave in place. It creates the targets, maps folder permissions to owners and members, moves the SMTP aliases, runs the batches, and reports what can't move.

**Killer example:** User: 'Move \Sales\Regions (412 folders) into one group per region, keep sales-north@ working, and tell me what won't move.' The AI creates 6 groups and adds 38 owners and 140 members derived from folder permissions. It moves 6 aliases with `Set-UnifiedGroup -EmailAddresses @{add=...}` and starts 6 `New-MigrationBatch -PublicFolderToUnifiedGroup` batches. It flags 23 Contacts folders for shared mailboxes instead and 51 folders untouched since 2019 for archive.

**Integration path:** Exchange Online PowerShell: `Get-PublicFolder -Recurse`, `Get-PublicFolderStatistics`, `Get-PublicFolderClientPermission`, `Get-MailPublicFolder`, `New-UnifiedGroup`, `Add-UnifiedGroupLinks`, `New-MigrationBatch -PublicFolderToUnifiedGroup`, `New-Mailbox -Shared`. Doc: learn.microsoft.com/exchange/collaboration-exo/public-folders/batch-migration-of-exchange-online-public-folders.

**Verification:** Verified 2026-11-18: the EWS post's 'no public folder APIs after October 2026' statement, and that the Groups path is batch cmdlets plus scripts with no wizard or AI mapping. Caveat: public folders keep working in Outlook, so the deadline only hits organizations whose integrations or backups read them through EWS. CodeTwo reports that Graph support for public folder migration is disabled until a fix planned for December 2026.

**Demand 3/5 · Buildability 3/5**

### 6. Tableau Catalog trust labels: data-quality warnings, certifications and labels `closed`

**Why it's powerful:** With Data Management (or Tableau+), a warning or certification on a database, table or data source shows up on every workbook downstream of it through lineage. These badges are Tableau's main trust signal, telling viewers whether a dashboard is safe to use.

**Why people bounce off it:** Labels are set one asset at a time in a buried Catalog panel. Nobody keeps them current when a source database is deprecated, a table goes stale or a system is under maintenance, so certified badges sit on dashboards that are actually broken. Governance teams pay for Data Management and then barely use the labels.

**AI operator:** 'Catalog Trust Steward' skill pack. It reads lineage and the jobs list, and applies, updates or clears warnings, certifications and custom labels by rule ('anything downstream of erp_legacy', 'certified sources whose refresh failed twice'). It runs nightly and posts a diff so labels stay accurate.

**Killer example:** User: 'The erp_legacy SQL Server retires on 31 January. Flag everything built on it as Deprecated with that date, certify the 12 finance sources under /Finance/Gold, and clear stale-data warnings where the last refresh succeeded.' The AI walks lineage from the database to 3 tables, 41 data sources and 188 workbooks. It batch-adds 41 Deprecated warnings with the retirement message, certifies the 12, removes 9 stale warnings and posts a report listing the 188 affected workbooks and their owners.

**Integration path:** Tableau REST metadata methods: Add / Update Data Quality Warning, Batch Add or Update Data Quality Warnings, Batch Add or Update Data Quality Certifications, Update Labels, batch delete. The Metadata GraphQL API gives lineage. Docs: help.tableau.com/current/api/rest_api/en-us/REST/rest_api_ref_metadata.htm.

**Verification:** Verified 2026-11-18: the methods exist (there is no single 'Add Data Quality Certification'; certifications go through the batch method and labels). No Tableau Agent, Pulse or other Tableau AI sets warnings or certifications, and tableau-mcp has no tool for them. The only automatic warnings are rule-based extract/flow-failure monitoring warnings. Requires the Data Management add-on or Tableau+.

### 7. Cross-CRM SLA holiday calendars: Salesforce Business Hours / Holidays and Zoho CRM holidays `closed`

**Why it's powerful:** Business hours and holidays drive every SLA timer, escalation rule, entitlement milestone and case-age report in a service org. Get them right and a 24-hour SLA pauses correctly for Diwali in Mumbai and Eid in Dubai.

**Why people bounce off it:** Holidays whose date moves each year (Diwali, Eid, Lunar New Year, Easter, Golden Week, Carnaval) can't be set to repeat. Admins re-key them every year for each region's business-hours set, and Zoho only accepts dates in the current or next financial year. Weekend changes (the UAE's move to Saturday–Sunday) leave old business-hours rows behind. When one region's holiday is missed, SLAs breach in that region without anyone noticing until the monthly report.

**AI operator:** 'Holiday Calendar Steward' skill pack. It takes a list of regions and support sites, computes next year's public and moveable holidays, compares them with each business-hours set, writes the missing holidays, and flags weekend definitions that no longer match the country. It also lists SLA records that would have been miscounted under the old calendar.

**Killer example:** User: 'Load 2027 holidays for our Mumbai, Dubai, São Paulo and Tokyo support hours, Diwali and Eid included.' The AI creates 52 Holiday rows, attaches each to the right one of 4 business-hours sets, and handles the Eid date uncertainty by adding both candidate dates as tentative entries. It flags that the Dubai business hours still treat Friday as a non-working day and that 2 Tokyo Golden Week days are missing from the current year as well.

**Integration path:** Salesforce: Metadata API `BusinessHoursSettings` (holidays with `businessHours`, `isRecurring`, `activityDate`), or the `Holiday` and `BusinessHours` sObjects through REST. Zoho CRM v8: `POST /settings/holidays` (scope `ZohoCRM.settings.business_hours.CREATE`) and business-hours settings. Dynamics 365 would be a later connector: holiday-schedule calendar rules are writable only through unsupported routes.

**Verification:** Verified 2026-11-18: the Salesforce metadata fields and the Zoho endpoint exist. The documented scope of Setup with Agentforce (objects, fields, users, permissions, flows, report types, pages, formulas) doesn't mention Business Hours or Holidays. Zoho's four pre-built CRM MCP servers have no holiday tools. Not confirmed: whether a custom mcp.zoho.com server can mirror the Add Holiday API. Different from the 2026-09-24 Salesforce Entitlements/SLA milestones card, which covers milestones, not the calendars under them.

### 8. AzuraCast: station programming (playlist rotation, schedules, DJ slots) `open-source`

**Why it's powerful:** AzuraCast is a self-hosted 'radio station in a box' (Liquidsoap, Icecast, AutoDJ, live DJ streaming, podcasts, listener stats). Thousands of community, college, church and internet stations run on it.

**Why people bounce off it:** A radio 'clock' is built by combining many playlists. Each one has a type (general rotation, once every N songs, once every N minutes, at a set minute of the hour), a weight, an order, and schedule entries with day and time windows. How these rules interact is opaque, so volunteers end up with dead air at 3 a.m., the same song five times an hour, or a jingle that never plays. Most stations use one shuffled playlist because programming a proper format is too hard.

**AI operator:** 'Station Programmer' skill pack. It turns a format described in plain words ('morning show, two currents an hour, ID every 15 minutes') into playlists, play-per rules, schedule entries and streamer (DJ) slots. It audits an existing station for gaps, overlaps and starved playlists, and simulates the next 24 hours of rotation before saving.

**Killer example:** User: 'Weekdays 6–10am morning show: 2 currents per hour, a station ID every 15 minutes, a jingle every 4 songs. DJ Maya live Fridays 8–10pm. Gold hour at noon.' The AI creates 5 playlists: currents (weight 5), IDs (`play_per_minutes` 15), jingles (`play_per_songs` 4), gold (scheduled 12:00–13:00) and morning bed. It adds the schedule items and a streamer account for Maya with a Friday 20:00–22:00 slot. Its 24-hour simulation shows the gold playlist starving the noon IDs, so it moves them to `play_per_hour_minute` 0/15/30/45.

**Integration path:** AzuraCast REST API (OpenAPI spec in the repo): `POST /station/{station_id}/playlists` and `PUT /station/{station_id}/playlist/{id}` with `play_per_songs`, `play_per_minutes`, `play_per_hour_minute` and `schedule_items`; `PUT …/playlist/{id}/order`; `POST /station/{station_id}/streamers`; `POST /station/{station_id}/webhooks`. Self-hosted, API key per user, so an MVP needs no vendor approval.

**Verification:** Verified 2026-11-18: the `StationPlaylist` schema in `openapi.yml` (and `StationPlaylist.php`) has the play-per fields and `schedule_items`. The only AzuraCast MCP found (`luisitoys12/azuracast-mcp-server`) has 0 stars; its tools were not inspected. The docs mention no built-in AI.

### 9. Azure Automation State Configuration (DSC) → Azure Machine Configuration (retires 2027-09-30) `closed`

**Why it's powerful:** Azure Automation DSC has been the desired-state engine behind years of Windows and Linux server baselines (IIS hardening, registry and service settings, file contents) for Azure VMs and on-prem servers.

**Why people bounce off it:** Azure Automation State Configuration retires on 2027-09-30, after which the configurations and node history are deleted. Microsoft's documented migration is 8 manual steps:
1. Export the configurations.
2. Work out the module versions, because modules and compiled MOFs can't be exported.
3. Recompile.
4. Package for Machine Configuration.
5. Publish to blob storage.
6. Generate and assign Azure Policy definitions.
7. Onboard on-prem nodes to Azure Arc.
8. Unregister the old nodes.

There is no migration button. Teams with dozens of configurations across several Automation accounts put it off.

**AI operator:** 'DSC Lift' skill pack. It inventories Automation accounts, nodes, configurations and compiled node configurations, and infers the module versions each configuration needs. It builds and tests Machine Configuration packages, then creates and assigns a policy per node group. It onboards hybrid nodes to Arc, and unregisters a node from Automation DSC only after Resource Graph compliance matches its last DSC report.

**Killer example:** User: 'Move all 3 Automation accounts off DSC, starting with the IIS baseline on 48 servers, 12 of them on-prem.' The AI exports `WindowsIISServerConfig` and pins `xWebAdministration` 1.19.0.0 from the node reports. It builds and publishes the package and assigns an `ApplyAndAutoCorrect` policy to the resource group. It generates the Arc onboarding script for the 12 on-prem servers, then compares compliance and finds 2 servers drifting on a TLS registry key that DSC had been silently correcting. It unregisters the other 46 from Automation DSC and leaves those 2 on DSC for review.

**Integration path:** Az.Automation (`Get-AzAutomationDscConfiguration`, `Export-AzAutomationDscConfiguration`, `Get-AzAutomationDscNode`, `Unregister-AzAutomationDscNode`). GuestConfiguration module (`New-GuestConfigurationPackage`, `Start-GuestConfigurationPackageRemediation`, `New-GuestConfigurationPolicy`). Az.Resources (`New-AzPolicyDefinition`, `New-AzPolicyAssignment`), Azure Resource Graph for compliance, Az.ConnectedMachine for Arc. Doc: learn.microsoft.com/azure/governance/machine-configuration/migrate-from-azure-automation.

**Verification:** Verified 2026-11-18: the 2027-09-30 retirement, the manual 8-step process, and that modules and MOFs can't be exported. Not checked: whether the Azure MCP server exposes Automation DSC or Machine Configuration packaging. Some overlap with general coding agents (recompiling configurations is code work); the value is in orchestrating nodes, Arc and policy. Different from the 2026-09-30 Azure Policy card, which writes policy guardrails, not DSC migration.

### 10. Dynamics 365 Unified Service Desk → Customer Service workspace rebuild `closed`

**Why it's powerful:** Unified Service Desk (USD) runs the agent desktop at many large and government contact centres. It provides multi-session tabs, hosted controls, action calls, window navigation rules and agent scripts on top of Dynamics 365.

Contact centres with hundreds of USD configuration records find out how much logic is hidden in action-call chains.

**AI operator:** 'USD Exit' skill pack. It reads the USD configuration tables and builds a parity map for each component: portable, needs a custom page, or has no equivalent. It writes the workspace configuration into a solution in a sandbox and generates a test script per agent persona.

**Killer example:** User: 'Rebuild our Billing Dispute USD agent configuration in workspace.' The AI reads 23 hosted controls, 41 action calls and 9 navigation rules. It creates 1 session template anchored on Case, 4 app tab templates (KB search, account timeline, a billing-system iframe, a refund custom page) and 1 app profile for the Billing Tier 2 team. It flags 3 UII-SDK hosted controls (a softphone and two legacy desktop apps) as needing a rebuild, with notes on why.

**Integration path:** Dataverse Web API: `POST /api/data/v9.2/msdyn_sessiontemplates` (with `msdyn_anchortab@odata.bind`), `POST /msdyn_applicationtabtemplates`, app profile and agent script tables, all packaged in a solution with `pac solution`. USD source configuration is read from its Dataverse tables (hosted controls, actions, action calls, window navigation rules).

**Verification:** Verified 2026-11-18: retirement dates; Microsoft ships only a migration playbook and component-mapping guide (no tool or assessment); no evidence that Copilot in the Customer Service admin center creates session or app tab templates. ### 11. UrbanPiper (India/MENA restaurant aggregator hub): per-channel availability, store toggles and channel pricing `closed`

**Why it's powerful:** UrbanPiper connects 40,000+ restaurants' POS systems to Swiggy, Zomato, Talabat, Uber Eats and their own ordering sites. Multi-outlet chains use one hub to push menus, prices and availability to every aggregator.

**Why people bounce off it:** Each aggregator has different rules for menus, options and timings. Snoozing items per channel and outlet, closing one outlet on one aggregator for a festival night, and adding channel-specific prices to offset 25–30% commissions mean clicking through Prime outlet by outlet. Chains with 15–50 outlets end up with stale stock-outs (cancelled orders and penalties) and identical prices everywhere because channel pricing is too much work.

**AI operator:** 'Aggregator Menu Ops' skill pack. It turns plain-language stock-outs, closures and channel price uplifts into per-location item/option toggles, store actions and catalogue pushes.
