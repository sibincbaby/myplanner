### 1. Vector (Datadog, MPL-2.0) + Fluent Bit as a second connector: observability/log pipeline configs (VRL transforms, routing, sampling, redaction) `open-source`

**Why it's powerful:** Vector is a very fast Rust pipeline that can replace several agents, route to any sink, and cut vendor ingest bills by 30-70%. Its built-in unit-test framework and `validate` command give the AI a hard verification loop, which most dev/ops UIs do not offer.

**Why people bounce off it:** Every org with a Datadog/Splunk/Elastic bill wants to filter, sample, redact PII and route logs before ingest, but the work lives in hand-written TOML/YAML topologies and VRL (Vector Remap Language) or Fluent Bit parsers and regex. VRL has its own type system where fallible functions must be handled, so people cannot predict what a transform does to real log lines. A bad drop rule silently loses incident evidence, and nobody can say what a rule saves until after deployment. Most teams run default shippers and overpay.

**AI operator:** A 'Log Pipeline Surgeon' that connects to a repo or running agent config. It samples live logs with `vector tap` or exported samples and clusters them by pattern and volume. It turns plain-language intent ('drop health checks, mask emails and card numbers, route 5xx to the hot index, send the rest to S3') into sources, transforms and sinks. It writes VRL and generates `vector test` unit tests from real sample events, runs `vector validate`, replays a sampled hour through the new pipeline, and reports bytes saved per rule and any would-be-dropped ERROR lines. It then opens a PR. A guardrail refuses rules that drop levels at or above WARN without explicit approval.

**Killer example:** User says: 'Our Datadog log bill doubled. Cut it by 40% without losing anything I'd need during an incident.' The AI pulls a 1-hour sample and finds 38% of volume is ELB health checks, debug lines from one chatty service and duplicate retries. It writes three VRL transforms (drop, 10% sample, dedupe-by-trace-id) plus `vector test` cases built from real lines, then replays the hour: volume down 41%, zero ERROR/WARN lines dropped, two near-misses flagged for review (a health-check path that also carried a 502 and a sampled retry that was the only copy of a stack trace). It opens a PR with a per-rule savings table and projected monthly cost: $14.2k to $8.5k.

**Integration path:** Fully headless and text-based. Config is TOML/YAML/JSON on disk. The `vector` CLI offers `validate`, `test`, `tap`, `top` and `generate`. The Vector GraphQL API and the Fluent Bit HTTP monitoring endpoint expose live component metrics. Delivery is via git PR (Helm values, Ansible, or ConfigMap). The solo MVP is an MCP server/CLI wrapping the Vector binary, a log-sample ingester, a replay harness and a cost estimator driven by a per-GB price table.

**Overlap check:** No Datadog or Vector AI assistant for VRL was found (only template autofill in the Custom Processor). Weak negative: Bits AI docs and the vectordotdev org were not checked.

**Demand 5/5 · Buildability 4/5**

### 2. Excel / Google Sheets: two-source reconciliation and tie-out (vendor statement vs ledger, HR roster vs payroll, stock count vs system, CRM export vs billing) `closed`

**Why it's powerful:** Excel and Sheets already hold every export that finance, HR, ops and audit teams deal with. Their live formulas, conditional formatting, filters and SUMIFS roll-ups are the format reviewers and auditors expect. Almost every close process ends in a hand-built tie-out workbook.

**Why people bounce off it:** A real tie-out needs fuzzy or composite keys (names, invoice numbers with prefixes or typos), one-to-many and many-to-one matching, amount tolerances, and a visible exceptions queue. In Excel that means stacking XLOOKUP, COUNTIFS, SUMIFS, helper columns and manual eyeballing. VLOOKUP returns #N/A on trailing spaces, text-vs-number IDs and 'INV-0042' vs '42'. People give up and tick rows by hand, or build a fragile lookup grid nobody else trusts or can audit.

**AI operator:** The AI inspects both sheets and proposes a match plan: normalised key, fuzzy threshold, tolerance and grouping rules. It builds a reconciliation workbook with live formulas: normalised-key helper columns, match status, difference columns, an exceptions tab and a summary tie-out. The user reviews the plan and the ambiguous pairs the AI flags, then corrects rules in chat ('treat anything under $1 as a rounding difference'). The AI rebuilds the sheet and keeps every cell a formula, so the logic stays inspectable.

**Killer example:** User says: 'Here is the supplier's March statement and our AP ledger export. Tell me what doesn't tie and why.' The AI strips prefixes and whitespace from invoice numbers, fuzzy-matches 14 typo rows, groups 3 split payments against 1 invoice, and flags $412.50 of unmatched credit notes. It delivers a Recon tab whose difference column sums to zero once the flagged items are explained, plus an Exceptions tab ranked by amount, each with a suggested reason (duplicate, timing, missing credit note). The user says 'treat under $1 as rounding'; the AI rebuilds in seconds and the auditor can click any cell to see the formula.

**Integration path:** Office Scripts or Microsoft Graph Excel REST API for cloud workbooks; Google Sheets API plus Apps Script for Sheets. Headless path: openpyxl or pandas with rapidfuzz to compute matches, then write formulas back, and LibreOffice headless to recalculate and verify totals. The solo-dev MVP is a CLI or web app that takes two uploaded files and returns a formula-driven .xlsx.

**Overlap check:** Microsoft's Financial Reconciliation agent (Copilot for Finance) already reconciles two tables on keys or tolerances into exception categories, and Power Query has a manual fuzzy merge (default threshold 0.80). Neither does fuzzy, split-payment and one-to-many matching with a formula-only workbook as output, which is the card's gap. Not checked: whether Excel Agent Mode covers this end to end.

**Demand 5/5 · Buildability 4/5**

### 3. ZoomInfo (Admin Portal + Enterprise API + CRM sync) - 'Credit-Aware Prospecting Operator' `closed`

**Why it's powerful:** The de facto B2B data layer for sales teams worldwide. The underlying API is rich (search, enrich, intent, org charts) and every outbound team pays heavily for credits it often wastes.

**Why people bounce off it:** ZoomInfo is the dominant B2B contact/company database, but the Admin Portal is a maze: a Search filter builder with 100+ nested filters (technographics, intent topics, scoops, hierarchy, management level vs job function), credit-metered exports, enrichment field-mapping into Salesforce/HubSpot/Dynamics, dedupe/overwrite rules, and Workflows with opaque triggers. Reps burn credits on duplicate exports or wrong filters, and RevOps admins dread the CRM-sync mapping screens.

**AI operator:** A chat operator with skills for ZoomInfo Search/Enrich/Intent/Scoops APIs plus the target CRM's API. It translates an ICP sentence into the right filter payload, previews the count and credit cost BEFORE spending anything, dedupes against CRM accounts/contacts, enriches only missing fields, and pushes net-new records with owner and source stamped. It also explains and diffs enrichment field mappings and overwrite rules in plain English.

**Killer example:** Rep says: 'Find VP-and-above in RevOps or Sales Ops at US SaaS companies with 200-1000 employees that use Salesforce and are researching CPQ this month. Skip anyone already in our CRM or owned by Dana, 150 contacts max.' The AI builds the Contact Search filter, shows 412 matches minus 97 CRM duplicates, and quotes about 150 credits. It asks 'go?', then enriches only missing fields, creates the 150 leads in Salesforce owned by the rep with Lead Source 'ZoomInfo-Intent-Nov26', and returns the list. Nothing was spent on duplicates, and the second run next week skips everyone from this one.

**Integration path:** ZoomInfo Enterprise API (OAuth2/PKI JWT auth; /search/contact, /search/company, /enrich/contact, /lookup/*, intent and scoops endpoints) is a real documented REST surface. Pair with Salesforce/HubSpot/Dynamics REST for dedupe and writes. Admin-portal settings (field mappings, workflows) have no public write API, so v1 is prospect/enrich/dedupe/push; admin explain/diff is read-only via exported config. Needs the customer's own API entitlement (extra cost on many contracts).

**Overlap check:** ZoomInfo ships an official read-only MCP (search and enrich) and a Copilot Studio connector. Bulk export and CRM write-back are outside it, which is where this card works. Based on ZoomInfo marketing pages; the docs overview could not be read.

**Demand 5/5 · Buildability 4/5**

### 4. Meta Robyn + Google Meridian (open-source Marketing Mix Modeling) `open-source`

**Why it's powerful:** Robyn and Meridian are the free, privacy-safe way to find which channels drive incremental revenue. They model adstock and saturation, calibrate against lift tests, and output marginal ROI and budget scenarios. They cover the spend that cookie loss and iOS ATT broke in last-click attribution.

**Why people bounce off it:** Users have to write R or Python and pick priors, adstock and saturation hyperparameters, geo/time granularity, control variables (holidays, promos, price) and ROI calibration from experiments. They then read convergence diagnostics (R-hat, Pareto-front plots) and decide whether the result can be trusted. Most DTC marketers and agencies stall at a messy weekly CSV and a notebook that won't converge. An MMM consultant costs $20-60k.

**AI operator:** An 'MMM Operator' agent that (1) pulls weekly spend, impressions and revenue from Google Ads, Meta, TikTok, GA4 and Shopify APIs or CSVs, (2) cleans and aligns the data and flags gaps, (3) generates and runs a Robyn or Meridian config with sensible priors, seasonality and promo controls, (4) calibrates priors from past lift tests, (5) reads diagnostics and re-runs when the fit is bad, and (6) turns the output into a plain-English budget recommendation. Budget changes are drafted for approval, never auto-applied.

**Killer example:** User says: 'We spend about $180k/month across Meta, Google, TikTok and influencers. Black Friday blew up, so where should the next $25k go?' The AI pulls 104 weeks of spend and Shopify net revenue, marks BFCM, free-shipping promos and a February price rise as controls, and runs Meridian. R-hat shows TikTok didn't converge, so it tightens the adstock prior and re-runs. It reports that Meta prospecting is saturated at about 1.6x marginal ROAS, Google brand search is mostly non-incremental, and YouTube is under-invested at about 3.1x. It drafts a $25k reallocation table and a Slack-ready one-pager with the confidence level to attach.

**Integration path:** Both are pip/CRAN packages and fully scriptable: run headless in a Python or R container with a CSV or DataFrame in and JSON, plots and an HTML summary out. Data ingestion uses standard read-only ad-platform REST APIs, so there is no write-API risk. Meridian benefits from a GPU or cloud runtime for large geo models. An MVP is a data-prep skill plus a config template plus a diagnostics-checker skill, with a PDF or markdown readout.

**Overlap check:** Meridian has community MCP servers that appear to query already-fitted models, plus Google's Meridian Agent Skills for model building. No Robyn MCP was found. Treat the Meridian half as partial overlap.

**Demand 5/5 · Buildability 3/5**

### 5. Argo Workflows (with Argo Events) and Tekton Pipelines as a second connector (CNCF, Apache-2.0): Kubernetes-native workflow and CI/CD YAML `open-source`

**Why it's powerful:** It runs massively parallel containerized jobs on Kubernetes, with artifact passing, cron scheduling, event-driven triggers and GitOps-friendly CRDs. It is a core engine under Kubeflow Pipelines, many MLOps stacks and several CI products.

**Why people bounce off it:** Argo Workflows powers ML, data and CI pipelines at a very large share of Kubernetes shops. A real workflow means hundreds of lines of YAML mixing DAG tasks, templates, parameters and artifacts, with templating such as `{{inputs.parameters.x}}` and `{{=expression}}`, withParam/withItems loops, retryStrategy, semaphores, volumeClaimTemplates and WorkflowTemplates/CronWorkflows. Errors surface only at runtime: a typo in an artifact path fails 40 minutes in, a stuck pod gives only 'Pending', and fan-outs overload the cluster. Only a few platform engineers can author or fix these, so everyone else files tickets.

**AI operator:** A 'Workflow Wright' that authors, lints, explains and debugs Argo and Tekton YAML. For authoring, it turns a plain-language pipeline into a WorkflowTemplate with sensible resource limits, retry strategy, TTL and podGC, validated with `argo lint` and a server-side dry-run. For debugging it reads the Workflow CR status, node tree, pod events and logs, says in plain English where and why it failed (OOMKilled, image pull, artifact credentials, semaphore wait, bad expression), then proposes a patch or a resubmit. It can also retrofit cost and reliability settings across a fleet of templates.

**Killer example:** User says: 'The nightly feature-pipeline run failed at 3am and again on retry. Figure out why and fix it so it stops eating the whole GPU pool.' The AI pulls the workflow, sees step 6 of a 40-way fan-out exits 137, confirms the pods were OOMKilled at a 2Gi limit while peak RSS in the logs was 5.8Gi, and notices the fan-out has no parallelism cap. It patches the template: 8Gi memory, `parallelism: 10`, a retryStrategy with a memory-bump expression, and `podGC: OnWorkflowSuccess`. It lints the patch, submits a dry-run, and opens a PR against the WorkflowTemplate repo with the evidence in the description.

**Integration path:** Everything is a Kubernetes CRD (Workflow, WorkflowTemplate, CronWorkflow, Sensor, EventSource). The `argo` CLI (`lint`, `submit`, `get`, `logs`, `retry`, `resubmit`) plus the Argo Server REST/gRPC API and the Kubernetes API cover read and write. Tekton has `tkn` and CRDs. A solo MVP is a read-only diagnose-and-explain agent that outputs YAML patches validated with `argo lint`; authoring and cluster writes follow.

**Demand 4/5 · Buildability 4/5**

### 6. Falco (CNCF graduated, Apache-2.0) + Falcosidekick: runtime security rules for containers and hosts `open-source`

**Why it's powerful:** Kernel-level (eBPF) visibility into every syscall in every container, with a large community ruleset mapped to MITRE ATT&CK. It is the open-source detection layer that Sysdig and others build on.

**Why people bounce off it:** Falco is the de facto open-source runtime detection engine, but its rule files (YAML with a custom condition syntax, macros, lists, exceptions, and syscall fields such as `evt.type`, `proc.pname`, `fd.name`) are hard to write. Teams install the default ruleset and get a flood of noisy alerts, then mute the rules or ignore the channel. Tuning means knowing which syscall fields identify your workload as benign, and a loose exception makes the rule useless. A tool installed for compliance rarely detects anything useful.

**AI operator:** A 'Falco Tuner' that ingests Falco's JSON alert stream (from Falcosidekick, Loki or a file) and clusters alerts by rule, image, process lineage and file path. For each noisy cluster it proposes the narrowest `exceptions` block or macro override and shows the exact events it would suppress. It also writes custom rules from plain-language intent and tests them with `falco --validate` plus capture-file replay. Every proposal ships as an override file kept apart from the upstream defaults, and as a PR.

**Killer example:** User says: 'Falco pages us 400 times a day and nobody reads it. Quiet it down, but I still want to know if a shell is spawned in the payments namespace.' The AI reads 7 days of alerts and finds 92% come from three rules: a log-rotation sidecar, a backup job and kubectl-exec debugging by a known CI role. It writes three narrow image-and-lineage exceptions and replays the week: alerts drop from 2,800 to 190. It adds a stricter custom rule, 'shell in namespace payments, no exceptions, CRITICAL', routed to PagerDuty, and proves it fires on a recorded replay of a simulated `kubectl exec`.

**Integration path:** Rules are YAML files (`falco_rules.local.yaml`) validated by `falco -V`. Falco emits JSON via stdout, gRPC or HTTP, and Falcosidekick fans alerts out to 60+ targets. Capture-file replay (`-e` with `.scap`) gives a test loop, and Helm values handle deployment. Solo MVP: an alert-log ingester, a clustering step, a rules-diff generator, a replay-based 'what would this suppress' checker, and PR output. No cluster write access needed.

**Overlap check:** Sysdig's MCP server reads Falco detections and drafts runtime-policy changes, but does not author Falco rule files. Weak negative: the falcosecurity org and Sysdig MCP README were not checked.

**Demand 4/5 · Buildability 4/5**

### 7. GitLab Plan (issues, epics, work items, boards, scoped labels, iteration cadences, milestones) `open-source`

**Why it's powerful:** One self-hostable platform covers code, CI and planning, with a scriptable GraphQL API. Done well, planning lives next to the code instead of in a separate paid tool.

**Why people bounce off it:** GitLab CE/EE is self-hostable and its planning layer is capable, but teams that adopt it for CI/CD never set up planning properly because the model is spread across levels with different rules: group vs project labels, scoped labels (workflow::in-review) acting as a state machine, group boards with per-list label filters, iteration cadences, milestones vs iterations, the epic/work-item hierarchy (Premium/Ultimate), templates in repo folders, and quick actions. Result: 400 unprioritized labels, dead boards, and managers asking for Jira anyway.

**AI operator:** A GitLab planning operator that inspects a group (labels, boards, cadences, epics, templates), proposes a normalized planning setup in plain language, and applies it via GraphQL. It audits label sprawl and merges or renames safely, builds boards from a described workflow, sets up iteration cadences, bulk re-parents issues under epics, and writes issue templates as MRs against .gitlab/issue_templates.

**Killer example:** User: 'We run two-week sprints with Backlog, Ready, In Progress, In Review, Done. Set that up for the Payments group, turn our 60 priority-ish labels into P0-P3 scoped labels, and show me last sprint's carryover.' The AI creates the iteration cadence and workflow::* and priority::* scoped labels at group level, maps old labels to new ones and relabels the affected issues (dry-run diff first), builds a group board with one list per workflow label, then queries the closed iteration and lists the 14 unfinished issues with assignees.

**Integration path:** GraphQL API at /api/graphql (labels, boards and lists, iteration cadences, work items/epics, milestones; verify exact mutation names via introspection) plus the REST API for labels/issues/milestones and the repo files API for templates. Group access token with api scope. Self-hosted CE in Docker or a free gitlab.com group makes MVP testing cheap. Epics and some work-item features sit behind Premium/Ultimate.

**Overlap check:** GitLab's Planner agent and official MCP server create epics, issues and work items, and edit labels and milestones on them. Neither documents iteration cadences, scoped labels or boards, so the card's MVP should lead with those and treat epic and issue creation as overlap.

**Demand 4/5 · Buildability 4/5**

### 8. Excel / Google Sheets: multi-submitter workbook collection and roll-up ('Workbook Roundup'): budgets, forecasts, timesheets, site reports, supplier questionnaires `closed`

**Why it's powerful:** Spreadsheet templates are how finance, HR, ops and education collect structured data from non-technical people with no new system to buy. Nearly every FP&A, school, NGO and facilities team runs at least one recurring collection cycle this way. The roll-up workbook is what leadership reads.

**Why people bounce off it:** Someone sends a template to 40 managers. Half return it with inserted rows, renamed headers, merged cells, extra tabs, numbers typed as text or wrong units. The coordinator spends days copy-pasting into a master and chasing non-responders by email. Power Query folder-combine breaks on the first schema drift, and writing macros to absorb the drift is beyond most people. Each cycle repeats the slog.

**AI operator:** The AI holds the golden template and a recipient list. It pulls returned files from a SharePoint, OneDrive or Drive folder and maps each file's drifted layout back to the template schema. It validates values (units, totals vs subtotals, required cells) and writes the consolidated master with a per-source audit column. It drafts chase emails to non-submitters and to submitters with specific fix requests, and remembers each cycle's mappings.

**Killer example:** User says: 'Q4 forecast templates are in the Finance Submissions folder. Roll them up, tell me who is missing or whose totals don't foot, and nudge them.' The AI reads 37 of 42 workbooks and auto-maps 6 files with inserted rows. It flags 4 submissions where the department total does not equal the sum of its line items, and drafts 5 personalised reminders for approval (3 non-submitters, 2 with cell-level fixes such as 'D14 is text, not a number'). The master has a Source column tracing every row to its file and cell.

**Integration path:** Microsoft Graph (drive item listing, Excel workbook REST API, sendMail) or Google Drive + Sheets + Gmail APIs. Headless parsing with openpyxl or ExcelJS handles arbitrary layout drift. The solo-dev MVP is a web app: connect a folder, upload the golden template, and get back the master workbook plus a status table, with sending kept behind an approval step.

**Overlap check:** Power Query From Folder combines files and Copilot can import from another workbook, so plain consolidation is already covered. The gap is the loop around it: template distribution, validation against the template and chasing late submitters. No official agent for the whole loop was found.

**Demand 4/5 · Buildability 4/5**

### 9. Microsoft Word: tables (layout, header rows, merged cells, column widths, number alignment, tables that split across pages, text-to-table conversion) `closed`

**Why it's powerful:** Contracts, reports, proposals, clinical documents, quotes and regulatory submissions are table-heavy. The Word table model, with table styles, header-row semantics, row-break rules and cell shading, can produce publication-grade layout and accessible structure. Almost nobody uses it that way.

**Why people bounce off it:** Word tables are the most-fought feature in the product. Autofit modes, preferred widths vs fixed layout, nested tables, vertical merges, 'repeat header rows', 'allow row to break across pages', table styles vs direct formatting and cell margins interact in non-obvious ways. Pasting from Excel or PDF produces ragged widths, stray merged cells and inconsistent borders. Users nudge borders by hand for an hour, and it breaks when anyone edits a cell.

**AI operator:** The AI reads the document's table inventory: shape, merges, widths, header rows, split-risk, numeric columns and direct formatting. It applies a house table style across all tables by creating or updating a named style, sets header-row repeat and 'don't split rows', aligns numeric columns, fixes widths to page margins, and converts tab-aligned or pasted text blocks into real tables. It shows a before/after change list before saving.

**Killer example:** User says: 'Make all 23 tables in this proposal look like the one on page 4, repeat headers where they run over a page, and right-align the money columns.' The AI extracts table 4 as the reference spec, builds a 'Proposal Table' style, restyles the other 22 tables and strips stray direct formatting. It sets header-repeat on the 9 tables that span pages, decimal-aligns the $ columns, and fixes the 3 tables overflowing the right margin. It reports 'tables 7, 12, 19 had merged header cells; I split them for accessibility; please confirm'.

**Integration path:** Office.js Word API (table, row and cell objects, plus insertOoxml) for in-app add-ins. For headless batch work, OOXML manipulation via python-docx or docx4j, with LibreOffice headless to render PDFs for visual verification. Word COM automation on Windows is the fallback. The solo-dev MVP is a .docx-in, .docx-out service with a diff report.

**Overlap check:** Copilot in Word can turn text into a table and Word's agentic features went GA on 2026-04-22; current table-formatting behaviour was not verified. Nothing found on header-row repeat, merged cells or page-split control, which remain manual Word settings.

**Demand 4/5 · Buildability 4/5**
