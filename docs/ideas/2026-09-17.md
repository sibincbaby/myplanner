### 1. Amazon SES `closed`

**Why it's powerful:** SES is the transactional-email backbone for a large share of AWS accounts — verified identities, Easy DKIM and BYODKIM, custom MAIL FROM domains, configuration sets with event destinations (SNS, Firehose, CloudWatch, EventBridge), dedicated and managed IP pools, account- and configuration-set-level suppression lists, reputation metrics, and Virtual Deliverability Manager with its authentication/infrastructure advisor. It carries the password resets, receipts and alerts for an install base spanning essentially the whole AWS customer surface.

**Why people bounce off it:** Getting out of the sandbox is a support-ticket ritual, and the real work is DNS archaeology: three CNAMEs for Easy DKIM, an MX plus SPF TXT for a custom MAIL FROM, and a DMARC record — none of which the console explains in terms of *alignment*. Then nobody can tell why Gmail spam-foldered them, because reputation metrics, VDM advisor findings, configuration-set event destinations, and the two different suppression lists (account vs configuration set) live on separate screens with no causal thread between them. Dedicated IP warm-up schedules are another silent failure mode.

**AI operator:** A CLI/MCP operator on top of the SESv2 API plus a live DNS check step, able to read the full account posture and propose a remediation plan before touching anything. Skills: end-to-end deliverability audit (DKIM/SPF/DMARC alignment via GetEmailIdentity + real DNS lookups), bounce/complaint pipeline setup, suppression-list hygiene, dedicated IP pool assignment and warm-up, production-access readiness check, and Mailbox Simulator verification. It executes via sesv2 calls and hands back the exact DNS records to paste at the registrar.

**Killer example:** User: "Our password reset emails are going straight to Gmail spam and AWS just emailed me about my complaint rate — I don't know what any of this means." → AI calls GetAccount for reputation and enforcement status, reads VDM advisor findings, sees via GetEmailIdentity that DKIM is verified but there's no custom MAIL FROM (so SPF is unaligned) and no DMARC record, creates the custom MAIL FROM domain, emits the exact MX/TXT/DMARC records to add, creates a configuration set with an SNS event destination for Bounce and Complaint, attaches it as the identity default, wires the suppression list, then sends through the Mailbox Simulator and re-checks alignment.

**Integration path:** Amazon SES v2 API (sesv2 REST/SDK + `aws sesv2` CLI), SNS/EventBridge event destinations.

**Scores:** demand 5/5 · buildability 5/5

### 2. Amplitude Analytics `closed`

**Why it's powerful:** Event segmentation, funnels with conversion windows and hold-property constraints, N-day/unbounded/custom retention, Pathfinder journeys, Compass correlation, behavioral cohorts, Experiment, and a Data governance layer with planned/blocked events and a tracking plan. Amplitude reported 4,700+ customers by Q4 2025 (698 over $100K ARR, 56 over $1M) including Atlassian, NBCUniversal, Under Armour and Block — it is the default product-analytics tool for modern software companies.

**Why people bounce off it:** The chart builder's three-slot grammar (event → where → group by → "measured as") silently changes the answer depending on uniques vs totals vs active %, and nobody can keep straight event properties vs user properties vs group properties. The behavioral cohort builder's nested "performed X at least N times in the last 30 days where property = Y" clause UI and the Data taxonomy screen with planned/blocked/deleted event states are where PMs give up and file a ticket with the data team instead.

**AI operator:** A side-panel app (or Slack bot) holding the org's event taxonomy in context. Skills: run segmentation/funnel/retention queries via the Dashboard REST API, read and repair the tracking plan via the Taxonomy API, create/list/export cohorts via the Behavioral Cohorts API, and drop context via the Chart Annotations API. Crucially it doesn't return one flat number — it iterates breakdowns automatically to isolate the regressing slice.

**Killer example:** User: "Checkout conversion tanked last week and I don't know why — also build me a cohort of people who added to cart twice and never paid, and push it to Braze." → AI runs the funnel query over both weeks, then loops breakdowns by platform, app version, country and plan to find that Android 8.2.1 dropped 14pts, creates the behavioral cohort (add_to_cart ≥2 AND purchase = 0, 30d) via the Cohorts API, triggers the cohort sync to the Braze destination, and posts a chart annotation on the 8.2.1 release date.

**Integration path:** Amplitude Dashboard REST API + Taxonomy API + Behavioral Cohorts API (HTTP Basic with API key/secret).

**Scores:** demand 5/5 · buildability 5/5

### 3. Cin7 Core (formerly DEAR Inventory) `closed`

**Why it's powerful:** A full light-ERP for product businesses: multi-level BOMs with auto-assembly and disassembly, landed-cost allocation, FIFO/FEFO batch and serial tracking, multi-warehouse transfers, a WMS module with pick/pack/ship and barcode scanning, a B2B portal, and two-way sync to Shopify, Amazon, Xero and QuickBooks Online. 8,500+ customers worldwide and 700+ integrations make it the de-facto inventory brain for mid-market e-commerce and wholesale.

**Why people bounce off it:** The Sale task pipeline (Quote → Order → Pick → Pack → Ship → Invoice → Credit Note) requires each stage to be individually "Authorised", and one half-authorised step silently blocks fulfilment with no explanation. Users cannot tell Stock Adjustment from Stocktake from Stock Transfer, botch "Auto-Assembly" vs Finished-Goods BOM setup, and the Chart-of-Accounts / tax-rule mapping screen quietly breaks the Xero/QBO sync for months before anyone notices.

**AI operator:** A browser side-panel over inventory.dearsystems.com plus a Slack bot for warehouse staff. Skills: order-pipeline unblocking, stock-discrepancy forensics (Stock on Hand vs channel availability vs open pick tasks), BOM and auto-assembly authoring, landed-cost allocation, reorder-point and purchase suggestion, and COA/tax mapping repair. Read-then-diff-then-write against the Cin7 Core API v2, showing the exact JSON payload before posting.

**Killer example:** User: "Amazon says we oversold the lavender candle 3-pack by 40 units — figure out what actually happened, fix the stock, and stop it happening again." → AI queries /StockOnHand and /Product for the SKU and its components, walks /StockAdjustmentList and /SaleList for the period to find an unauthorised assembly plus a stocktake posted to the wrong location, posts a corrective Stock Adjustment, authorises the stuck auto-assembly so the finished good rebuilds, then sets the reorder point and "Available" calculation on the product and re-pushes availability to the Amazon channel.

**Integration path:** Cin7 Core API v2 (JSON REST, `api-auth-accountid` / `api-auth-applicationkey` headers) plus an OData feed for reporting.

**Scores:** demand 5/5 · buildability 5/5

### 4. Google Drive `closed`

**Why it's powerful:** Drive is the storage and sharing substrate under all of Google Workspace — shared drives with member roles (Manager / Content manager / Contributor / Commenter / Viewer), link scopes, sharing restrictions (`copyRequiresWriterPermission`, `domainUsersOnly`, `sharingFoldersRequiresOrganizerPermission`), shortcuts, revision history, target-audience link defaults, and a full search-operator language. It backs 3B+ Workspace users and is the default file system for millions of businesses and schools.

**Why people bounce off it:** Nobody can answer "who can see this?" — the Share → Manage access dialog hides inherited vs direct permissions, the My Drive/shared-drive distinction silently changes ownership semantics, and "Anyone with the link" grants survive folder moves. Storage cleanup is worse: quota is charged to the file owner, so admins hunt orphaned files from ex-employees through the Admin console's opaque file transfer tool, and "Shared with me" items can't be bulk-audited from the UI at all.

**AI operator:** A web app (and Workspace Marketplace add-on) holding a Drive OAuth token, pre-loaded with skills for permission auditing, external-share revocation, shared-drive migration, ownership transfer, storage reclamation, and folder-structure refactors. It compiles plain language into Drive API v3 calls, always dry-runs first with a diff of every file and grantee it will touch, then executes and writes a rollback log.

**Killer example:** User: "Somebody outside the company can still open our board deck folder and I have no clue who shared what — lock it down and move it all into a proper shared drive." → AI runs files.list with q filters + permissions.list across the tree, flags every `type=anyone` and external `type=user/group` grant, deletes them, creates a shared drive via drives.create with `{domainUsersOnly: true, copyRequiresWriterPermission: true}`, moves files with files.update addParents/removeParents + supportsAllDrives, re-adds internal members at the right roles, and returns a before/after access table.

**Integration path:** Google Drive API v3 (files, permissions with transferOwnership/useDomainAdminAccess, drives, changes, revisions) + Admin SDK Reports for sharing audit events.

**Scores:** demand 5/5 · buildability 5/5

### 5. Stata `closed`

**Why it's powerful:** A research-grade estimation stack — xtreg/xtabond panel models, mixed multilevel models, ivregress, teffects/psmatch2 causal estimators, `svy:` survey-weighted estimation, meta-analysis and SEM, plus margins/marginsplot, esttab/outreg2 publication tables and fully reproducible do-files, extended by 3,000+ user-written SSC packages. It is the standard analytic tool in economics, epidemiology, public health and political science, with site licences at essentially every major research university and 16,000+ organisations recorded as users.

**Why people bounce off it:** There is effectively no discoverable UI — everything is terse command syntax typed into one box. The killers are `reshape long`/`wide` with its stub/i()/j() argument order, `merge 1:m` vs `m:1` and decoding `_merge` values, `egen` vs `gen`, bysort's mandatory sort ordering, `i.` factor-variable notation, and `xtset` panel structure versus `vce(cluster)` standard errors. Grad students and clinicians lose weeks to "variable not found" and a silently mis-specified reshape that corrupts their panel.

**AI operator:** A local wrapper that owns a live Stata session through the pystata API (`stata.run`, `pdataframe_to_data`) and writes/executes do-files. Pre-loaded with the command syntax reference, dataset-shape inspection routines (describe, codebook, isid, duplicates report), the reshape/merge idiom catalog, and table-export commands — so it inspects the data first, chooses the right specification, runs it, and keeps the do-file as the reproducible artifact.

**Killer example:** User: "I have survey data with one row per person per year. Does going part-time make people report worse health, controlling for age and income, with person fixed effects? And I need a table I can paste into the paper." → AI runs describe/codebook/isid to detect the id-year panel keys, issues `xtset id year`, recodes the health scale, runs `xtreg health i.parttime age income, fe vce(cluster id)`, follows with `margins parttime` and `marginsplot`, exports via `esttab using table1.rtf, se star(* 0.05)`, saves the do-file, and explains the coefficient in plain English.

**Integration path:** pystata Python API (`stata.run` / `pdataframe_to_data`) + `.do` batch execution (`stata -b do file.do`) + Stata Automation (COM) on Windows.

**Scores:** demand 5/5 · buildability 5/5

### 6. Google Ad Manager `closed`

**Why it's powerful:** GAM is the publisher-side ad server that runs monetization for the large majority of professional web and app publishers: orders and line items across 16 priority levels, key-value targeting, creative trafficking with size mapping, Programmatic Guaranteed and Preferred Deals, Open Bidding yield groups, competitive exclusions/labels, first look, and a dimension/metric report builder. Hundreds of thousands of publishers — from single-site blogs on the free tier to global media groups on Ad Manager 360 — depend on it for every impression they sell. This is the *sell* side, distinct from Google Ads.

**Why people bounce off it:** The line-item-type-vs-priority matrix (Sponsorship=4, Standard=6, Network=12, Price Priority=12, House=16) silently decides who wins every auction and is nowhere explained in the UI where you set it. Publishers also bounce off creating key-values and applying them as custom targeting, the creative-to-line-item association screen with size mapping, yield group setup for Open Bidding, and diagnosing "why is this line item under-delivering" across Delivery Inspector, forecasting, and competitive exclusion labels. Small publishers routinely serve house ads over paid demand and cannot tell why.

**AI operator:** A web companion signed into the publisher's network via OAuth, pre-loaded with skills for order/line-item creation, priority and goal selection, key-value and geo/device targeting, creative upload and association, yield group edits, and report queries. It reads current state through the Ad Manager REST API v1 and writes trafficking changes through the SOAP services (OrderService, LineItemService, CreativeService, LineItemCreativeAssociationService), always previewing delivery impact first.

**Killer example:** User: "My homepage leaderboard is showing house ads half the time and I just sold a Nike sponsorship — make Nike win that slot through Friday and tell me what it displaces." → AI runs a delivery report on the ad unit, finds the paid line item sitting at Price Priority 12 losing to a mistargeted Standard 6, checks competitive exclusion labels, creates a Sponsorship priority-4 line item with a 100% goal ending Friday, adds ad unit + key-value targeting, uploads and associates the Nike creatives at the right sizes, pauses the stale house line item, and returns a forecast of the impressions the change reallocates.

**Integration path:** Google Ad Manager API — REST v1 beta (admanager.googleapis.com) for reads/reports, plus the SOAP API (OrderService, LineItemService, CreativeService, ReportService, PQL statements) for full trafficking write coverage.

**Scores:** demand 5/5 · buildability 4/5

### 8. Godot Engine `open`

**Why it's powerful:** A complete game engine — node/scene composition, GDScript and C#, AnimationTree state machines and blend spaces, TileMapLayer, 2D/3D physics, its own shading language, high-level multiplayer, and export templates for desktop, mobile, web and console via third parties. Its share of Steam releases went from 0.9% in 2020 to ~7.1% in 2025, and it took 39% of GMTK Game Jam 2025 entries — now the default entry point for a very large indie population. Everything it stores is text (.tscn/.tres/project.godot) and the whole editor runs headless.

**Why people bounce off it:** The mental model is the wall: signals vs groups vs autoloads, and when a thing should be a Node versus a Resource, trips up nearly every newcomer. After that it's the Import dock's per-file reimport settings that silently override your textures, the collision layer/mask bit matrix, AnimationTree blend spaces and state machine transitions, and export presets — Android keystores, iOS provisioning, PCK embedding — which is where most first-time shippers give up entirely.

**AI operator:** An EditorPlugin dock inside the Godot editor, pre-loaded with skills for scene assembly and node wiring, signal/group refactors, input map setup, physics layer configuration, AnimationTree authoring, export preset generation, and headless CI builds. It executes through EditorInterface/EditorScript for live edits and falls back to direct text edits of .tscn/.tres/project.godot plus the `--headless` CLI for builds — so every change is reviewable as a diff.

**Killer example:** User: "My player sometimes falls straight through the floor, the jump feels like mud, and I've never managed to get an Android build out." → AI switches the player to `move_and_slide` with `floor_snap_length` set, enables continuous collision detection, raises the physics tick to 120 in project.godot, retunes gravity/jump_velocity and adds a coyote-time buffer in the player script, then writes an Android export preset, wires the debug keystore, and runs `godot --headless --export-release "Android" build/game.apk`.

**Integration path:** GDScript EditorPlugin/EditorScript against EditorInterface, the `godot --headless --export-release` CLI, and direct manipulation of the documented text formats .tscn/.tres/project.godot.

**Scores:** demand 4/5 · buildability 5/5

### 9. Akeneo PIM `open`

**Why it's powerful:** The leading product information management platform and de-facto open-source PIM: attributes and attribute groups, families and family variants with variant axes, product models for multi-level variation, per-channel/per-locale completeness scoring, a Rule Engine for automated enrichment, reference entities, asset manager, and import/export job profiles feeding Shopify/Amazon/print. Self-hostable Community Edition alongside a SaaS edition used by TaylorMade, Chico's, Kering and The Very Group; a repeat Leader in IDC MarketScape and Info-Tech PIM evaluations.

**Why people bounce off it:** The family / family-variant / product-model hierarchy is the killer — merchandisers must decide up front which attributes live at which level and which are variant axes, and getting it wrong means re-importing the whole catalog because axes are effectively immutable. The import profile screen (column mapping, product-model rows interleaved with variant rows, decimal/locale separators) defeats non-technical users, the completeness matrix across channel × locale is opaque about what is actually missing, and the Rule Engine's condition/action syntax reads like config-as-code inside a web form.

**AI operator:** A chat panel next to the product grid plus a backend agent on the Akeneo REST API, pre-loaded with skills for catalog-structure surgery (create family, create family variant with axes, promote/demote attributes), bulk product PATCH, import job profile authoring, Rule Engine rule generation, and completeness triage. It runs everything as a previewed plan against a sample set first, then executes in batches with rollback notes.

**Killer example:** User: "The 400 shoes we just imported came in as 400 separate products but they're really 80 styles in 5 sizes — reorganise them properly, and tell me which German descriptions are actually missing rather than just blank." → AI inspects the attributes to find the size axis, creates a family variant with size as the level-1 axis, POSTs 80 product models with the shared attributes, PATCHes all 400 products to attach parent + axis value, moves common attributes up a level so they stop being duplicated, then returns the per-channel/per-locale completeness breakdown separating truly empty `de_DE` descriptions from ones inherited or not required for that channel.

**Integration path:** Akeneo PIM REST API (`/api/rest/v1` with OAuth2) — products, product-models, families/{code}/variants, attributes, attribute-options, jobs/import-export — plus the App/connector framework with Events API webhooks.

**Scores:** demand 4/5 · buildability 5/5

### 10. MongoDB Atlas `closed`

**Why it's powerful:** The managed MongoDB service with tens of thousands of paying customers, spanning cluster tiers and sharding, Atlas Search and Vector Search index definitions, Online Archive, Data Federation, Triggers, Performance Advisor, Query Profiler, continuous backup with point-in-time restore, and network controls (IP access list, VPC peering, Private Endpoints). It is the default database for an enormous number of startups and enterprise teams, and the Atlas Administration API v2 covers effectively the whole surface.

**Why people bounce off it:** The console splits one problem across three unrelated screens — Database Access (users/custom roles), Network Access (IP list/peering/private endpoint), and the Project/Org role matrix — so "connection refused" has four unrelated causes and no single page tells you which. Performance work means reading Performance Advisor index suggestions and the Query Profiler and knowing whether a suggested compound index is worth the write cost. Atlas Search indexes are hand-written JSON with analyzers and field mappings, and backup/PIT restore depends on an oplog window most users never look at.

**AI operator:** A CLI/MCP operator holding an Atlas Service Account (OAuth2), read-only by default with an explicit approval gate for cluster-mutating calls. Skills: triage slow queries (Performance Advisor + slow query logs + measurement endpoints), create indexes rolling-style, author Atlas Search index JSON, untangle connectivity (access list vs private endpoint vs db user roles), tune backup policy and run PIT restores, and right-size tiers/auto-scaling against actual metrics.

**Killer example:** User: "The app got slow yesterday afternoon, Mongo keeps saying COLLSCAN, and I have no idea what an index even is — just make it fast." → AI pulls processes/measurements around the time window, fetches Performance Advisor suggested indexes and the slow-query log for the namespace, isolates the query shape doing the collection scan, explains it in plain English, creates the suggested compound index as a rolling build via the Admin API, then re-polls the slow query log and query-targeting metric and reports docs-examined dropping from millions to hundreds.

**Integration path:** Atlas Administration API v2 (REST, OAuth2 service accounts), Atlas CLI `atlas api`, Terraform MongoDB Atlas provider.

**Scores:** demand 4/5 · buildability 5/5

### 11. PowerSchool SIS `closed`

**Why it's powerful:** PowerSchool SIS runs enrollment, attendance, gradebook, standards-based grading, fees, health records, state compliance reporting, and the PowerScheduler master-schedule engine, plus a deep customization layer (custom fields, Data Access Tags, custom pages, ReportWorks/Object Reports, Data Export Manager). It is the dominant K-12 SIS in North America — roughly 23% of tracked US/Canada district implementations and ~17% of global SIS deployments, with PowerSchool citing 90M+ students across 90+ countries.

**Why people bounce off it:** PowerScheduler is the classic bounce point — registrars must load course requests, define terms/expressions like `1(A-B)`, set constraints and course relationships, then run Build and Load and interpret conflict matrices; districts hire consultants for this annually. Everyday admins also drown in the security model (page permissions + field-level security + group access), Bell Schedule/Calendar setup, and search expressions (`*attendance`, `/`, `;` operators) that behave like an undocumented query language.

**AI operator:** A district-installed PowerSchool plugin plus a browser sidebar inside the Admin portal, authenticating with the plugin's OAuth2 client ID/secret. Skills: student search-expression generation, mass enroll/transfer/drop, section and schedule edits with conflict and seat-count checking, custom field/page creation, PowerQuery authoring, and report/export template generation. Every mutating chain renders a dry-run diff (students affected, sections changed) before the operator commits through `/ws/v1`.

**Killer example:** User: "Every 9th grader who failed Algebra 1 last semester needs to move into the new support section third period, and their parents need a schedule-change letter." → AI runs a PowerQuery over stored_grades joined to enrollment for grade_level=9 and Algebra 1 with F, checks seat counts and period conflicts for the support section, POSTs section drops/adds via `/ws/v1/student/{id}/section_enrollment`, reschedules the conflicting electives, then generates the mail-merge letter set from the affected-student list.

**Integration path:** PowerSchool SIS REST API (`/ws/v1` core resources) + plugin XML package declaring named PowerQueries and Data Access Tags; OAuth2 client credentials issued by the Plugin Management Dashboard.

**Scores:** demand 5/5 · buildability 3/5

### 12. CorelDRAW Graphics Suite `closed`

**Why it's powerful:** CorelDRAW is the production backbone of sign making, screen printing and apparel decoration, engraving, and small-run packaging: Print Merge, PowerClip, Contour and Blend, Color Styles and harmonies, PowerTRACE bitmap tracing, imposition and prepress tooling, spot-colour separations, plus bundled Corel PHOTO-PAINT and Corel DESIGNER. Corel reports 100M+ active users across its products, and enlyft lists 37,000+ companies specifically on CorelDRAW. It exposes a full automation object model through VBA and VSTA, installed by default.

**Why people bounce off it:** The prepress chain destroys people — document colour settings vs the Color Proof Settings docker vs the Prepress tab of Publish to PDF are three separate places that all affect the output, and spot-vs-process, overprint and trap settings are buried. Outline widths that do or don't scale with the object, nested PowerClips you can't select into, the Print Merge Wizard's field mapping, and the CutContour spot-colour convention for vinyl plotters are all tribal knowledge — which is why print shops reject the same files over and over.

**AI operator:** A docked VSTA/GMS macro panel inside CorelDRAW, pre-loaded with skills for prepress preflight (colour space audit, live text detection, image resolution check), spot-colour separation, cut-line generation, Print Merge against spreadsheets, imposition/nesting, and batch export. It executes against the CorelDRAW automation object model, walking ActiveDocument shape collections and mutating fills, outlines, layers and export settings directly.

**Killer example:** User: "The print shop bounced my file AGAIN — text isn't outlined, there's RGB in it somewhere and they say my cut line is wrong. It's 300 name badges and the names are in this spreadsheet." → AI calls ConvertToCurves on every text shape, walks Shape.Fill and Shape.Outline converting stray RGB to the assigned Pantone/CMYK, creates a 100%-magenta CutContour spot outline on its own layer set to overprint, runs Print Merge against the CSV, imposes 3-up on the sheet, and exports PDF/X-4 with 3mm bleed and crop marks.

**Integration path:** CorelDRAW VBA / Corel VSTA automation object model (GMS macro projects, Scripts docker) over the `CorelDRAW.Application` COM interface.

**Scores:** demand 4/5 · buildability 4/5
