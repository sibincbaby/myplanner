### 1. Supabase Security Operator (RLS policies, Storage policies, Auth config, advisors) `open-source`

**Why it's powerful:** Supabase is a full backend on plain Postgres: row-level security, auth providers, storage, realtime, Edge Functions, pgvector and cron. One correct policy set can replace a hand-written API layer. Apache-2.0 and self-hostable.

**Why people bounce off it:** Everything depends on correct RLS policies, and the dashboard editor makes that hard. People get USING vs WITH CHECK and auth.uid() wrong, forget policies on new tables, and Storage policies are a separate system. Failures are either wide-open tables or locked-down apps that return empty arrays with no error. Advisors flag problems but don't fix them, and nobody can easily test 'what can user X actually see?'.

**AI operator:** Introspects schema, policies, auth config and Storage buckets via the Management API. Converts plain-English access rules into RLS SQL, then runs each policy as simulated roles (anon, authenticated with uid and JWT claims) inside rolled-back transactions. Shows a per-role readable/writable row matrix and writes the result as a reviewable migration file. Nothing touches the live DB until approved.

**Killer example:** User: 'Teams see their own projects, only owners can edit, and public share links must never expose the notes column.' The AI finds RLS disabled on projects, project_members and notes, drafts policies plus a column-safe view, then runs the access matrix as three fake users. It catches a security-definer function leaking one cross-tenant row, fixes it, and emits a supabase/migrations file as a PR. It also proves the 'empty array' bug: 'Before: Dana sees 0 rows because the policy compares auth.uid() to a text column. After: 14 rows.'

**Integration path:** Management API (api.supabase.com/v1) with a PAT: SQL endpoint, auth config, advisors, branches. Supabase CLI for migrations and db diff. Plain Postgres SET ROLE plus request.jwt.claims inside ROLLBACK transactions for simulation. An official Supabase MCP exists, so the differentiator is the policy-simulation and test harness, not the plumbing. Self-hosted works the same.

**Demand 5/5 · Buildability 5/5**

### 2. ServiceNow Access Explainer and Safe-Change Author (ACLs, roles, groups) `closed`

**Why it's powerful:** ServiceNow is the system of record for IT, HR and security workflows at much of the Fortune 500. Its role/ACL model protects individual fields and records by script. The ACL, role and group data lives in ordinary tables (sys_security_acl, sys_user_has_role, sys_user_grmember, sys_user_role_contains) reachable through the Table API.

**Why people bounce off it:** ACLs are table, field and operation rules combining roles, conditions and scripts, evaluated most-specific to least-specific, with group inheritance and contained roles on top. Tracing 'why can Maria see this field but not edit it?' takes hours of impersonation and security-debug logs. The usual fixes are over-broad ACLs or blanket admin roles.

**AI operator:** Reads the user/group/role graph and every ACL on a table and field, replays ServiceNow's evaluation order for a named user and operation, and explains in plain language which ACL allowed or denied and which role is missing. For changes it drafts the narrowest new ACL or role grant, shows a before/after effective-access matrix, applies only after approval, and saves prior state for revert. Also bulk-audits admin and high-risk roles.

**Killer example:** Admin: 'Priya in HR gets Security constraints prevent access on the Salary Review field of Employee Relations cases. Why, and give HR Analysts read-only access to just that field.' The AI resolves Priya's direct and group-inherited roles, shows the table-level ACL passes but field ACL hr_case.salary_review fails (needs hr_comp_admin plus a script condition that checks case.assigned_to), drafts a read-only field ACL for HR Analyst, lists the 14 users who would newly gain access, and creates it after confirmation with a one-click revert file.

**Integration path:** Table API (/api/now/table/...) reads and writes all ACL, role and group tables; free Personal Developer Instance for testing. MVP is a read-only explainer under a scoped integration user, then gated writes. Scripted ACL conditions are the hard part: the AI reads the script text and falls back to impersonation or security-debug logs for ground truth. Distinct from covered ITSM/ITOM, Service Catalog, CMDB and Import Set operators.

**Demand 5/5 · Buildability 4/5**

### 3. AWS IAM Identity Center Access Cartographer (permission sets, assignments, groups, ABAC) `closed`

**Why it's powerful:** Identity Center is the recommended way to give people and groups access to dozens or hundreds of AWS accounts, using reusable permission sets, a directory source (Okta, Entra or built-in), session durations and ABAC. Core AWS infrastructure with a complete API.

**Why people bounce off it:** The console shows assignments one account or permission set at a time. Nobody can answer 'what can this person do in production?' or 'who can reach the payments account?' once groups, nested membership, inline and managed policies, boundaries and SCPs are involved. Permission-set edits must be re-provisioned per account and partial failures leave silent drift. Access reviews end up as spreadsheets, and sprawl makes pruning scary.

**AI operator:** Pulls the Org tree, permission sets, assignments and identity-store groups into a queryable graph, computes effective access (including SCP and boundary effects where possible), answers who-can-do-what in plain English, produces access-review reports, drafts permission-set and group-assignment changes and cleanup of unused sets. Applies only after approval and watches re-provisioning status to completion.

**Killer example:** Manager: 'Dana is moving from data to platform. Remove what she no longer needs, give her what platform engineers have, and tell me if anything she had in prod looks over-privileged.' The AI resolves Dana's groups and every account and permission set she touches, finds AdministratorAccess in prod came via a stale 'data-lead' group, proposes moving her to 'platform-eng' and removing the old group, flags two overlapping permission sets, then after approval applies it and confirms re-provisioning succeeded in all 9 accounts with a before/after access diff.

**Integration path:** sso-admin (permission sets, assignments, provisioning status), identitystore, organizations, IAM policy simulator. Read-only role gives a risk-free MVP; writes behind human approval. Delivered as CLI, Slack bot or small web app via AWS SDK. Start with assignment mapping and review reports; SCP effective-access math later. Adjacent to covered IAM and Organizations operators but targets the people-to-account assignment layer.

**Demand 5/5 · Buildability 4/5**

### 4. Malaysia LHDN MyInvois e-invoice compliance operator (bookkeeper-firm console via intermediary mode) `closed`

**Why it's powerful:** The mandatory national e-invoice clearance system: every B2B/B2C/B2G sale, credit/debit note, refund and self-billed purchase passes through it as UBL 2.1 JSON/XML via a REST API with OAuth2, taxpayer-intermediary delegation, TIN validation, cancel/reject windows and document search/status.

**Why people bounce off it:** Rules differ by turnover band (relaxation windows to Dec 2027), single transactions over RM10,000 cannot be consolidated from 2026, self-billing is needed for foreign suppliers and agents, and every line needs the right classification code (45), MSIC code, tax type and exemption reason. Customer TINs must validate. Penalties apply for invalid or late documents. Most SMEs run Excel or old accounting packages that cannot emit compliant JSON.

**AI operator:** Sits between the books (CSV/Excel or accounting API) and MyInvois. Decides per transaction whether it is normal, consolidated or self-billed, maps lines to classification and MSIC codes with reasoning shown, validates buyer TINs, builds and signs UBL documents, submits, polls status and tracks the cancel/reject clock. Intermediary mode lets one accountant drive 50+ client taxpayers.

**Killer example:** Bookkeeper: 'Here is October's sales export for 14 clients. Consolidate the B2C cash sales, issue individual e-invoices for anything over RM10k, and self-bill the Singapore freight vendor.' The AI validates 212 buyer TINs and flags 9 failures, splits the transactions, picks classification codes, submits per client via the onbehalfof header, lists 3 rejected documents each with the exact field fix, and warns that two invoices are still inside their 72-hour cancel window.

**Integration path:** Official MyInvois REST API: login (client-credentials plus intermediary onbehalfof), documentsubmissions, documents search, cancel/reject, TIN validate; public SDK with sandbox and UBL JSON schemas. Signing needs the taxpayer's digital certificate. Inputs: CSV/Excel first, then AutoCount/SQL Account/Bukku/Xero exports. Fully scriptable and headless.

**Demand 4/5 · Buildability 4/5**

### 5. Instantly.ai (plus Smartlead connector): Deliverability Ops Operator for cold outbound `closed`

**Why it's powerful:** Engine behind most modern B2B outbound: unlimited mailbox rotation, warmup networks, lead databases, unified inbox, A/B sequences and API-driven campaigns.

**Why people bounce off it:** Agencies run 20-100+ domains and hundreds of mailboxes. The wall is infrastructure and judgement: SPF/DKIM/DMARC, mailbox provisioning, warmup, volume caps, ESP matching, sequence variables, and watching bounce and spam-placement trends. One misconfigured domain tanks deliverability and dashboards show per-inbox numbers with no diagnosis.

**AI operator:** On Instantly API v2 (accounts, warmup analytics, campaigns, leads, verification, tags, webhooks): provisions and tags inboxes, runs a daily health sweep, pauses or rotates burned inboxes, shifts volume to healthy ones and rewrites weak sequence steps. Hard guardrails: unsubscribe link, suppression list, daily caps and human approval before first send, keeping it a compliant B2B tool.

**Killer example:** User: 'Acme launches Monday. 6 new domains, 18 mailboxes, a 4,000-row list. Launch a 3-step sequence, only from inboxes with warmup health over 95, pause anything above 2% bounce.' The AI verifies emails, drops risky ones, splits leads across healthy inboxes, creates the campaign with schedule, timezone and ESP matching, and sets a webhook rule. Wednesday it messages: 'sam@getacme-co.com hit 4% bounce, paused and traffic moved to 3 others; root cause: missing DMARC on the tracking subdomain.'

**Integration path:** Instantly API v2 (Bearer key) for accounts, campaigns, leads, analytics, webhooks; Smartlead has a comparable API. DNS via registrar/Cloudflare APIs; mailbox provisioning via Google Workspace Admin or Microsoft Graph. MVP is a monitoring and auto-pause bot first, then the campaign builder. Some provisioning is vendor-gated.

**Demand 5/5 · Buildability 4/5**

### 6. Jira Cloud Filter & Dashboard Doctor (shared filters, owner transfer, permissions, gadgets) `closed`

**Why it's powerful:** Filters and dashboards are the reporting layer of every large Jira instance; boards, gadgets, subscriptions and automation sit on saved JQL. REST API covers filter search, permissions, change-owner and dashboard CRUD.

**Why people bounce off it:** Thousands of filters pile up. When an owner is deactivated the filter becomes unmanageable, boards and dashboards go blank or wrong, and nobody knows which filters are used. No bulk edit in the UI. JQL is a second wall for non-admins.

**AI operator:** Inventories every filter and dashboard with owner status, share scope and usage by boards, dashboards and automation rules; finds orphans, duplicates and over-shared filters; proposes and executes a plan (reassign, narrow sharing, merge, archive) with a before/after snapshot for undo. For non-admins, writes JQL from plain language into a saved filter and dashboard gadget.

**Killer example:** Admin: 'Dave and 3 others left. Fix anything of theirs our boards or dashboards depend on, and tell me what's safe to delete.' The AI lists 212 filters owned by the 4 deactivated accounts, finds 38 in use by boards or dashboards and 61 identical copies of 'My open issues'. It moves the 38 to the right team leads with correct project-role sharing, flags 113 unused ones for archive, and hands over a rollback file before running anything.

**Integration path:** Jira Cloud REST v3: GET /filter/search, filter permissions, PUT /filter/{id}/owner (Administer Jira), dashboard endpoints, JQL parse/validate. No built-in bulk owner change, so loop with rate-limit handling. Stick to filters, permissions, gadgets and read-only usage analysis for MVP. Free Jira Cloud site for testing.

**Demand 4/5 · Buildability 4/5**

### 7. Auth0 Tenant Pilot (Actions, connections, Organizations, MFA, attack protection, Deploy CLI) `closed`

**Why it's powerful:** Auth0 powers login for a huge share of SaaS products: social and enterprise SAML/OIDC, B2B Organizations, MFA, bot protection, custom flows via Actions and a full Management API. Deploy CLI and Terraform provider make the tenant treatable as code.

**Why people bounce off it:** Login behavior emerges from the interaction of Actions, legacy Rules/Hooks, connections, app settings, Universal Login templates, tenant flags and attack protection. Debugging 'why can't this user log in?' needs log forensics plus mental simulation of Action order. Environments drift, Actions get edited live, and a bad flow change can lock out every user.

**AI operator:** Exports the tenant, reads logs, explains login flows in plain language, diagnoses failed logins from log events and Action trigger order, diffs dev vs prod, drafts Action code and policy changes, applies to staging first, replays test logins, and only then promotes to prod via Deploy CLI.

**Killer example:** User: 'Globex says their SSO users are stuck in a redirect loop since Tuesday.' The AI pulls Globex's connection and the domain's logs, finds the failure code, sees a Tuesday Action added a post-login redirect that doesn't exempt Organization logins, explains it in two sentences, patches the Action with an exemption, deploys to staging, replays the login, and on approval promotes to prod with a PR recording the change.

**Integration path:** Management API v2 (scoped M2M app), logs API, open-source auth0-deploy-cli and Terraform provider for export/import/promotion. Actions are plain Node code with versioned deploys, good for LLM drafting and diff review. Prod writes behind explicit confirmation; test-login replay is the hardest part.

**Demand 4/5 · Buildability 4/5**

### 8. Cube semantic layer modeling agent (Cube Core + Cube Cloud) `open-source`

**Why it's powerful:** Neutral open-source metrics layer: one governed metric definition served over REST, GraphQL and SQL to every BI tool and LLM agent, with caching and row-level security.

**Why people bounce off it:** Analysts must hand-write YAML/JS cubes, get join direction and cardinality right (or measures fan out and double-count), and craft pre-aggregations whose dimensions, measures and grain exactly match queries or Cube silently falls back to the raw warehouse. Debugging means reading generated SQL.

**AI operator:** Introspects the warehouse or dbt manifest, drafts cubes, views and joins, tests via /v1/load and /v1/sql, uses /v1/dry-run and usedPreAggregations to explain pre-aggregation misses and propose the minimal match, checks fan-out by comparing totals with and without joins, and ships changes as a git PR.

**Killer example:** User: 'Revenue by region on the exec dashboard takes 40s and Finance says it's 3% higher than the ledger.' The AI finds the dashboard groups by week while the rollup is daily with a different segment, and that orders joins to order_items without a many_to_one declaration so revenue is counted per line. It opens a PR fixing the join and adding a weekly rollup_join pre-aggregation, then shows before/after: number now matches the ledger and p95 drops 40s to 1.2s.

**Integration path:** Data model is YAML/JS in git so the operator edits files and opens PRs. /v1/meta, /v1/load, /v1/dry-run, /v1/sql and the Postgres-compatible SQL API make validation scriptable; Cube Cloud Admin API for branches. Ship as MCP server plus CLI. Fully headless.

**Demand 4/5 · Buildability 4/5**

### 9. Follow Up Boss Team Ops Operator (real-estate CRM) `closed`

**Why it's powerful:** Default CRM for tens of thousands of US real-estate teams: lead flow round-robin and ponds, action plans, smart lists, automations and 200+ lead-source integrations.

**Why people bounce off it:** Lead Flow, action plans, stages, tags and many lead sources interact, run by agents and coordinators rather than admins. Config rots: leads in the wrong pond, duplicates from three portals, action plans that never fire, nobody knows why a lead was never called.

**AI operator:** On the FUB REST API: speed-to-lead and pipeline audits from event/call/task timelines; bulk plain-language ops (re-route, tag, stage change, apply action plan, reassign when an agent leaves) as dry-run diffs; a weekly 'what is broken' report. Lead Flow and Automation authoring are UI-only, so it emits an exact click-through spec.

**Killer example:** Broker: 'Zillow leads from the last 30 days that nobody called within 15 minutes: who are they and which agents sat on them?' The AI computes first-touch latency per agent from /events and /calls and returns a ranked list, then asks 'Reassign the 41 untouched ones to the last-resort pond and start the Hot Lead plan?' and PATCHes on approval.

**Integration path:** REST at api.followupboss.com/v1 with Basic auth; production needs registered X-System headers. Webhooks (peopleCreated, eventsCreated) enable real-time reactions. Read-heavy audit MVP in weeks, as MCP or Slack bot. Gap: action plan, automation and lead flow rules not writable via API.

**Demand 4/5 · Buildability 4/5**

### 10. DuckDB 'Excel can't open it' large-file analyst (CSV / Parquet / multi-workbook) `open-source`

**Why it's powerful:** MIT-licensed columnar engine that queries multi-GB CSV, Parquet, JSON and .xlsx in place with globs, window functions, PIVOT, ASOF joins and fuzzy matching: effectively a free Power Pivot with no row limit.

**Why people bounce off it:** Business users hit Excel's 1,048,576-row cap on ERP/POS/bank exports and need SQL, type inference and ragged-CSV cleanup (delimiters, encodings, dd/mm vs mm/dd). They truncate files by hand or give up; Power Query is too slow at this scale.

**AI operator:** Local agent loads files into DuckDB, sniffs dialect and types, prints a plain-English data profile, answers questions via SQL (shown for trust), exports answer-sized results to formatted .xlsx or Google Sheets, and saves queries as re-runnable recipes for next month's export.

**Killer example:** User: '14 monthly sales exports, 40M rows. Revenue by region and product family, flag the 20 customers down over 30% vs same quarter last year, in a workbook with a pivot-ready tab.' The AI globs the files, normalizes mixed date formats, de-dupes on order id, runs the YoY window query, writes a 3-tab xlsx plus a saved recipe for next quarter.

**Integration path:** DuckDB CLI/Python/Node, excel extension, openpyxl/XlsxWriter output, optional Tauri/Electron drag-and-drop shell. All local, a privacy selling point. Crowded space (Julius, Rows, Datasette), so the moat is Excel-shaped deliverables and saved recipes.

**Demand 4/5 · Buildability 5/5**

### 11. Brazil NF-e IBS/CBS tax-reform readiness operator (ERP product masters: Omie, Bling, Tiny; SEFAZ homologation) `closed`

**Why it's powerful:** NF-e is the legal backbone of goods trade in Brazil; the 2026 tax reform adds IBS, CBS and Imposto Seletivo groups with new validation rules and per-line cClassTrib/CST codes, phased in through Jan 2027.

**Why people bounce off it:** The hard part is classification: mapping every NCM to the right CST/cClassTrib under LC 214/2025 (reduced rates, zero rate, suspension, presumed credit). Validation rules keep changing between note versions, ERPs expose the new fields inconsistently, and accountants can't tell which of thousands of SKUs need judgment.

**AI operator:** Reads each client's product master via ERP API or CSV, proposes cClassTrib/CST per NCM citing the LC 214/2025 annex, groups ambiguous items for one ruling per NCM, writes approved mappings back, builds sample NF-e XML validated against official XSD and rule list, sends test authorizations to SEFAZ homologation and explains each rejection in plain Portuguese.

**Killer example:** Accountant: 'Cliente de autopecas, Simples Nacional, 1.800 SKUs. Prepare tudo para o destaque de IBS/CBS antes de 4 de janeiro.' The AI groups the catalog into 140 NCMs, auto-maps 118, lists 22 with the competing legal readings and the exact question to ask, updates the master after approval, emits 5 homologation NF-e and reports 2 rejections with the field to fix.

**Integration path:** Official NF-e XSD packages and technical notes, SEFAZ homologation SOAP (needs A1 test certificate), ERP REST APIs (Omie, Bling v3, Tiny) with CSV fallback. Pure XML/validation layer is the safe MVP.

**Demand 5/5 · Buildability 3/5**

### 12. Excel / Google Sheets Monte Carlo risk simulation layer (an @RISK / Crystal Ball replacement) `closed`

**Why it's powerful:** A spreadsheet already encodes the business logic (pricing, capex, cash flow, NPV). Probabilistic simulation over it (P10/P50/P90, tornado sensitivity) turns a point guess into a risk answer, but @RISK and Crystal Ball cost $1.5-3k per seat per year.

**Why people bounce off it:** Excel has no native Monte Carlo; RAND() plus Data Tables is slow, breaks with volatile functions and is unreadable. Picking distributions and correlations is a stats skill non-experts lack, so people report single-point forecasts or buy expensive add-ins.

**AI operator:** Reads the workbook, finds output and input cells, interviews the user for min/likely/max, maps answers to distributions, evaluates the model headlessly 10-50k times (formulas/pycel or LibreOffice UNO), and writes a Simulation sheet with histogram, percentiles, probability of exceeding target, tornado chart and assumptions log. Flags hardcoded inputs in formulas and offers to refactor them.

**Killer example:** User uploads a 40-tab project budget: 'Capex is $12M. What's the chance we blow past $14M? Steel is +/-20%, labor 10% under to 35% over, permit delay probably 2 months but could be 6.' The AI runs 20k iterations and adds a sheet: 'P(capex>$14M)=31%, P80=$14.6M, labor overrun drives 54% of variance' with a tornado chart and a live threshold cell.

**Integration path:** openpyxl/XlsxWriter for .xlsx; formulas/pycel, HyperFormula (GPLv3) or LibreOffice headless as evaluation engines; optional Office.js or Apps Script surface. Risk: function coverage (LAMBDA, dynamic arrays), so v1 refuses unsupported models and says why.

**Demand 3/5 · Buildability 4/5**
