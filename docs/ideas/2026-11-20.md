### 1. OpenTimelineIO (OTIO) editorial turnover/conform across Avid, Premiere, Resolve and FCP (AAF / FCPXML / EDL / Premiere XML) `open-source`

**Why it's powerful:** OTIO is the open interchange model between Avid, Premiere, Resolve, Final Cut, Nuke and Flame, with a Python API and adapters for EDL, FCP7 XML, FCPXML, AAF and ALE.

**Why people bounce off it:** Turnovers fail: offline clips, wrong frame rates or drop-frame timecode, lost speed ramps and nested sequences, dissolves turned into cuts. Assistant editors fix it by hand with spreadsheets and re-exports, nobody can see what an adapter silently dropped, and reel-name versus filename relinking is tribal knowledge.

**AI operator:** A Conform Doctor that loads any EDL/AAF/XML into OTIO and lints it for the target app: unsupported effects, nested sequences, mixed frame rates, duplicate reels, gaps, missing media. It proposes a relink map from source timecode, reel and filename against camera originals, writes a corrected turnover in the target dialect plus a plain-English loss report, and generates VFX or colour pull lists from markers.

**Killer example:** User: 'Here's the Premiere picture-lock XML and the camera card folders. Make a Resolve-ready turnover and a pull list for the VFX shots I marked red.' The agent imports the XML and finds 14 clips offline because reel names are blank. It relinks them by source timecode and filename against /camera_originals, flattens 3 nested sequences, and converts 2 speed ramps into markers with retime notes. It writes a Resolve-compatible AAF/XML and a CSV of the 9 red-marker VFX shots with handles, and reports '2 dissolves became cuts, here are the timecodes.'

**Integration path:** Pure local and headless. opentimelineio (Apache-2.0) with cmx_3600, fcp_xml, fcpx_xml and otio_json adapters, plus otio-aaf-adapter/pyaaf2. ffprobe or MediaInfo for timecode and frame rate. MVP is a CLI or MCP server with a drag-and-drop shell. Host apps are driven only through file export/import.

**Demand 4/5 · Buildability 4/5**

### 2. Google Sheets web-data import (IMPORTXML, IMPORTHTML, IMPORTDATA, GOOGLEFINANCE, with Apps Script or headless-browser fallback) `closed`

**Why it's powerful:** —

**Why people bounce off it:** The most common spreadsheet wish is 'keep this column updated from that website', but import formulas need an XPath or table index users can't find. They return #N/A the moment a page is JS-rendered or cookie-walled, and quota and cache delays make it look randomly broken. People copy-paste by hand every Monday.

**AI operator:** An agent that fetches the target page with a headless browser, finds elements matching the user's description, picks the most stable selector, first tries a native IMPORTXML formula, and falls back to a scheduled Apps Script or hosted fetcher writing to a helper tab. It sets up change detection and a last-known-value fallback and explains in plain language when the feed will break.

**Killer example:** User in a Sheet of 40 supplier URLs: 'Fill column C with the current price and D with whether it's in stock. Highlight if it's more than 10% above what I paid.' The agent opens sample pages, writes IMPORTXML with an XPath tied to the schema.org Product price for the two server-rendered ones, and deploys an Apps Script fetch helper for the JS-rendered one. It adds an IFERROR last-known-price fallback, a conditional-format rule at 110% of column B and a daily trigger, and names the 3 URLs most likely to break and why.

**Integration path:** Google Sheets API (values, batchUpdate for conditional formatting) and Apps Script API (create/deploy projects, triggers). Playwright or Puppeteer as the selector-discovery tool. MVP is a web app with Sheets OAuth plus a Playwright microservice. Caveats: overlaps other formula-oriented ideas, and scraping ToS and bot-blocking limit coverage.

**Demand 4/5 · Buildability 4/5**
