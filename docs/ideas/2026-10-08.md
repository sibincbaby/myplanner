### 1. Microsoft Excel: classic PivotTables, Slicers and Timelines (desktop and web, not Power Pivot/DAX) `closed`

**Why it's powerful:** Classic PivotTables are the most-used analysis feature in the most-used business app. They can group dates into months, quarters and years, bin numbers, add calculated fields and items, apply Show Values As (% of parent, running total, rank, difference from previous), use Top-N, label and value filters, switch between compact, tabular and outline layouts with repeated labels, connect slicers and timelines across several pivots, and feed GETPIVOTDATA-driven report sheets. None of this needs a data model.

**Why people bounce off it:** Most users can drag one field into Rows and one into Values, then get stuck. The common sticking points: 'Sum of' turning into 'Count of' because of blank or text cells, date grouping that won't work because a few dates are stored as text, the source range not including newly added rows, Show Values As and calculated fields being hidden behind right-click menus, slicers that won't connect to two pivots because they use different caches, and layout settings ('Repeat item labels', 'Show in tabular form') spread across three ribbon tabs. GETPIVOTDATA references confuse almost everyone.

**AI operator:** 'Pivot Pilot', an Office.js task-pane add-in. It profiles the source data first: it finds dates stored as text, numbers stored as text and blanks, and offers to convert the source to an Excel Table so new rows are picked up. It then turns a plain-language question into a PivotTable spec (row, column, data and filter hierarchies; summarize-by; Show Values As; date grouping; layout; grand totals). It builds or edits the pivot through the Excel PivotTable API, adds slicers wired to every pivot that shares the same source, and can 'freeze' a result into a formatted GETPIVOTDATA report sheet. Every change can be undone, and the add-in explains in one line which ribbon command it used, so users learn the UI as they go.

**Killer example:** A sales ops analyst types: 'Why won't my dates group? Show 2025 sales by region and month as % of each region's total, top 5 products only, and add a Sales Rep slicer that also filters the Margin pivot.' Pivot Pilot reports that 312 Order Dates are stored as text and 41 Amounts are blank, which is why the pivot says 'Count of Amount'. It fixes both, converts the range to a Table so next month's rows are picked up, and builds the pivot: Region on rows, months on columns, Amount as % of Row Total, a Top 5 filter on Product and tabular layout with repeated labels. It rebuilds the Margin pivot on the same cache so a single Sales Rep slicer controls both. A 25-minute fight with right-click menus takes about 20 seconds, and each step can be undone.

**Integration path:** The Office.js Excel JavaScript API (PivotTable, PivotLayout, PivotHierarchy, DataPivotHierarchy.showAs, PivotFilters in ExcelApi 1.12+, the Slicer API in 1.10+). It ships as an AppSource add-in that runs on Windows, Mac and the web. Anything the API can't do, such as some date-grouping and calculated-field operations, falls back to a generated Office Script (or a VBA snippet for desktop) that the user runs with one click. The LLM produces a JSON pivot spec, and the add-in validates and applies it.

### 2. Audacity (with mod-script-pipe scripting and Macros) `open-source`

**Why it's powerful:** It is the most-installed free audio editor in the world. It does multitrack editing, spectral editing and selection, Noise Reduction, the Loudness Normalization effect (LUFS targets), Truncate Silence, compressors and EQ (Filter Curve and Graphic EQ), label tracks, Nyquist and VST3/LV2 plugins, and batch Macros. That covers most of what a podcast or voice-over job needs without paying for Audition or iZotope RX.

**Why people bounce off it:** The tools are there, but the order of operations and the parameter values are left to the user. You have to know to take a noise profile from a room-tone selection before applying Noise Reduction, how many dB of reduction to use before speech sounds robotic, whether to compress before or after loudness-normalizing, and what -16 LUFS versus -19 LUFS mono versus -23 LUFS means for each platform. Truncate Silence thresholds wreck pacing when set wrong. Macros live in a separate, awkward dialog, and Nyquist is a Lisp dialect. Most users apply Normalize and Amplify by ear, ship muddy audio and give up.

**AI operator:** A sidecar agent talks to a running Audacity through mod-script-pipe, which accepts text commands such as Select:, Import2:, NoiseReduction:, LoudnessNormalization:, TruncateSilence:, Compressor:, Export2: and GetInfo: for tracks, clips and labels. It also reads analysis data: it runs ffmpeg ebur128 or a Python loudness meter on a temporary export, and it finds room tone by locating the quietest 0.5 to 1 second region. Skills include 'podcast mastering chain', 'remove ums and long pauses using a Whisper transcript, then make label-track cuts', 'match loudness across two guests', 'ACX audiobook compliance (RMS -18 to -23 dB, peak -3 dB, noise floor below -60 dB)' and 'export chapters from labels'. Every step stays in Audacity's undo history, and the agent can save the chain as a reusable Audacity Macro so the user owns it afterwards.

**Killer example:** A podcaster drops in a 48-minute two-person interview and types: 'Kill the fridge hum, cut the ums, even out my guest who's way quieter than me, get it ready for Spotify, and tell me if it would pass ACX.' The agent finds 1.2 s of room tone, applies 9 dB of Noise Reduction and a 60 Hz notch with harmonics, and raises the guest's track by 7.5 dB to match the host. It transcribes the audio and puts 43 fillers and 11 pauses over 1.5 s on a label track, so the user can listen to each cut and reject 4 of them. It applies the rest, compresses, exports at -16 LUFS for Spotify and makes a separate ACX master, then reports 'RMS -20.1 dB, peak -3.2 dB, noise floor -63 dB: PASS'. It saves the whole chain as the Macro 'MyShow Master', so next week's episode takes one click.

**Integration path:** mod-script-pipe is a named pipe on Windows, macOS and Linux that takes the full Audacity scripting command set (documented under 'Scripting Reference'), with a Python client (pipe_test.py pattern). Audacity Macros (.txt files) can be generated for batch reuse. Nyquist plugins can add custom effects. Whisper or faster-whisper produces word timestamps, and ffmpeg ebur128 or pyloudnorm handles metering. The MVP is a local Python agent plus a small chat panel. A headless batch mode needs no UI interaction.

**Demand 5/5 · Buildability 4/5**

### 3. Salesforce Nonprofit Success Pack (NPSP) and Nonprofit Cloud, the 'accidental admin' layer `open-source`

**Why it's powerful:** NPSP is BSD-licensed and the most widely installed nonprofit CRM. Salesforce's Power of Us program gives tens of thousands of nonprofits 10 free Enterprise licenses. It provides household accounts, Customizable Rollups (CRLP), Recurring Donations (Enhanced RD), Gift Entry templates, soft credits, matching gifts, GAU allocations, engagement plans and levels, and the full Salesforce platform underneath. Nonprofit Cloud, built on Industries, adds Gift Commitments, Programs/Benefits and Outcome management.

**Why people bounce off it:** Most of these orgs are run by an 'accidental admin', usually a development coordinator or a volunteer. Simple questions turn into config archaeology. 'Why is Total Gifts This Year wrong?' means checking CRLP filter groups, rollup definitions, the batch job schedule and which record types are excluded. Setting up a monthly-giving campaign means wiring Enhanced RD, a Gift Entry template, campaign hierarchy and an NPSP Data Import mapping. Year-end tax receipts need a report with soft credits and household rollups that nobody can build. Migrating to Nonprofit Cloud, a different data model (Person Accounts, Gift Transactions), is daunting enough that consultants charge $20k or more and many orgs just stay put.

**AI operator:** An NPSP-aware agent preloaded with skills for the NPSP object model (npe01/npo02/npsp__ namespaces), CRLP metadata (Rollup__mdt, Filter_Group__mdt, Filter_Rule__mdt), the NPSP Settings custom settings, Data Import (DataImport__c) batches, Gift Entry templates and Enhanced RD schedules. It reads the org's config and explains numbers in plain language. It builds reports and list views, stages bulk imports through NPSP's own Data Importer so household and dedupe logic still runs, and writes changes into a sandbox or a change-set diff for approval before deploying. A second skill pack plans the NPSP-to-Nonprofit Cloud mapping.

**Killer example:** A volunteer admin at a food bank types on December 28: 'The Garcias say their giving total is $500 short, and I need year-end receipts for everyone who gave over $250, counting soft credits.' The agent traces the Garcia gap to a CRLP filter group that excludes the In-Kind record type and shows the rule in plain English. It adds the filter rule in the sandbox, re-runs the rollup batch for that household, and shows that the total now matches. It then finds that 61 other households were under-counted by the same rule. It builds a household report of hard plus soft credits for 2026 over $250 (1,184 donors), flags 23 with missing mailing addresses, and exports a mail-merge CSV with the IRS-required 'no goods or services' wording. That job normally needs a $175/hr consultant in the busiest week of the year.

**Integration path:** Salesforce REST, Bulk 2.0, Tooling and Metadata APIs (CRLP is custom metadata, so it can be deployed). Use the sf CLI for sandbox deploys and retrieves, and the NPSP Apex global API (e.g. BDI_DataImport_API for Data Import batches, CRLP rollup batch invocation). NPSP source is public on GitHub (SalesforceFoundation/NPSP), so the skill pack can be grounded in the real code. Distribute as a connected app plus an LWC chat panel, or as an MCP server. The Salesforce Hosted MCP or the Salesforce DX MCP server can serve as the transport.

**Demand 4/5 · Buildability 4/5**

### 4. Azure RBAC + Azure Resource Graph (ARM role assignments across management groups/subscriptions, deny assignments, custom roles, Resource Graph KQL inventory) `closed`

**Why it's powerful:** Every Azure tenant's authorization runs through it: role assignments inherited down the management group → subscription → resource group → resource hierarchy, custom role definitions with control-plane and data-plane actions, conditions (ABAC) on storage, and deny assignments. Azure Resource Graph adds near-instant KQL queries over every resource, resource changes, and role assignments across thousands of subscriptions.

**Why people bounce off it:** Answering 'who can actually do X to resource Y, and why?' means walking inherited assignments across 4 scope levels, expanding nested Entra groups, and knowing that Contributor can't grant access while User Access Administrator can. Data-plane permissions like Storage Blob Data Reader differ from control-plane ones, and the portal's 'Check access' covers only part of this. Resource Graph is powerful but needs KQL and knowledge of the table schemas (resources, authorizationresources, resourcechanges), so most admins export CSVs instead.

**AI operator:** An access-and-inventory copilot with skills for: computing effective permissions for a principal or resource (inheritance plus group expansion plus deny assignments) with a plain-English explanation chain; translating questions into Resource Graph KQL; finding risky patterns (Owner on subscriptions, stale guest or service-principal assignments, classic admins, wildcard custom roles); proposing least-privilege custom roles from Activity Log usage; and executing assignment changes with a preview and rollback.

**Killer example:** An auditor asks the platform lead: 'Who can delete prod-sql-eu or read its backups, and why?' The lead types that into the copilot. It walks Tenant Root MG → Prod MG → sub-prod-eu → rg-data, expands 3 nested Entra groups, and returns 17 identities. Each one comes with its chain: 'j.smith → Platform-Eng → Contributor at Prod MG (inherited)'. It flags a 2022 pipeline service principal that holds Owner but in 90 days has only called 4 actions (sql/servers/write, databases/write, firewallRules/write, deployments/write). It also flags 7 humans with no sign-in for 90 days. It drafts a 4-action custom role for the SP and a removal plan for the 7, shows the before/after access graph, applies the changes after approval with a one-command rollback, and exports the evidence as an audit-ready CSV. A two-day manual exercise is done before the meeting ends.

**Integration path:** ARM REST API (Microsoft.Authorization roleAssignments, roleDefinitions, denyAssignments), the Azure Resource Graph query API (KQL over the resources, authorizationresources, resourcechanges and resourcecontainers tables), Microsoft Graph for group expansion and sign-in activity, and the Azure Monitor Activity Log for usage-based role mining. Az CLI and PowerShell can serve as fallbacks. Read-only by default (Reader plus Directory.Read). Writes are role-assignment PUT/DELETE calls behind a confirm-and-diff step. A solo dev can ship an MCP server and a report UI.

**Demand 4/5 · Buildability 4/5**

### 5. Krita (open-source digital painting, illustration and 2D animation) `open-source`

**Why it's powerful:** It has more than 10 brush engines, wrap-around and assistant tools (perspective, vanishing point, ellipse), filter, transform, clone and fill layers, filter masks, an HDR/OCIO color-managed canvas, a frame-by-frame animation timeline with onion skin, a comic-page manager, resource bundles and a full Python scripting API. Millions of hobbyists and indie studios use it as a free alternative to Photoshop or Clip Studio.

**Why people bounce off it:** Its power sits behind dense dockers and resource-management concepts: brush presets versus engines versus bundles versus tags, and the difference between selection masks, transparency masks and filter masks. Color-managed document setup (working space, bit depth, soft-proofing for CMYK print) confuses people. Assistant tools have to be placed precisely, and animation export depends on correctly configuring an external FFmpeg. Batch work (resize and export a sprite sheet, rename 80 layers, build a print-ready file with bleed) has no GUI at all, only Python, and most artists cannot write Python.

**AI operator:** A Krita Python plugin docker (pykrita) hosts a chat panel. Its tools wrap the libkis API: Document and Node creation, filter masks, transforms, selections, colorspace conversion, animation frames via setCurrentTime, exports with InfoObject options, and any of the roughly 400 actions through Krita.instance().action(name).trigger(). Skills include 'set up a print document (size, DPI, bleed, CMYK soft-proof)', 'organize and rename layers semantically using a vision model on layer thumbnails', 'build a sprite sheet or GIF from timeline frames', 'create a comic page with panel borders from a script', 'make a non-destructive colour-grade filter-layer stack' and 'brush preset hunt: find me a brush like X among installed bundles'. Every operation runs through Krita's undo stack, so it can be rolled back.

**Killer example:** An indie game artist finishes a 24-frame walk cycle and types: 'Make this a 4x6 sprite sheet at 256px per frame with a transparent background and a Unity-ready JSON atlas, a looping GIF for Twitter, and an A4 300dpi CMYK print of frame 1 with 3mm bleed for my Kickstarter postcard.' The agent reads the animation range, renders each frame offscreen and tiles a 1024x1536 PNG with a matching atlas JSON. It configures Krita's FFmpeg render for a looping GIF. It duplicates frame 1 into an A4-plus-bleed 300dpi document, converts it with a FOGRA39 soft-proof and warns that the cyan scarf is out of gamut, offering a filter-mask fix that the artist accepts. It saves a print PDF. That is three deliverables and zero Python, where it used to be an evening of forum searching.

**Integration path:** The Krita Python API (libkis: Krita, Document, Node, Window, View, Action, InfoObject) runs as a pykrita plugin with a docker UI. Krita can also be run headless (krita --export, or Python scripts run through the Scripter) for batch work. The plugin is distributed as a resource bundle or zip through the Krita plugin importer, and the agent backend is local or via API. Because it works inside a single process with a well-documented API, a solo developer can ship an MVP in a few weeks.

**Demand 4/5 · Buildability 4/5**

### 6. Exact Online, with Fortnox and Visma e-conomic as sibling connectors (European SME cloud accounting/ERP) `closed`

**Why it's powerful:** Exact Online is the dominant SME accounting/ERP suite in the Netherlands and Belgium, with hundreds of thousands of companies and nearly every accounting firm there. It combines general ledger, VAT/ICP returns, bank-feed matching, purchase/sales entries, inventory, manufacturing, projects/hours, and payroll. Accountants manage many client administrations ('divisions') from one login. Fortnox (Sweden) and e-conomic (Denmark) fill the same role in the Nordics.

**Why people bounce off it:** Exact is notoriously less intuitive than Xero. Bank-entry matching rules, VAT code mapping (reverse charge, ICP, margin schemes), cost-center/cost-unit dimensions, recurring entries, and closing a period across dozens of client divisions all live in deep, inconsistent menus. Accountants doing year-end across 80 client divisions repeat the same checks by hand, and SME owners call their accountant for anything beyond entering invoices.

**AI operator:** 'Exact Operator', built for bookkeepers and accountants. Its skills cover cross-division sweeps (unmatched bank lines, suspense-account balances, missing VAT codes, unposted entries), drafting and posting general-journal corrections, VAT-return pre-checks with an explanation per box, creating matching rules from examples, and NL reporting ('revenue by cost center vs last year'). It works one division or batch-wide, and every write goes through an approval queue.

**Killer example:** Three days before the Q3 VAT deadline, a bookkeeper at a 6-person Utrecht firm with 80 clients types: 'Across all my clients, find everything still on suspense 2999 or with no VAT code, and suggest the right ledger and VAT code based on how each supplier was booked before.' The agent sweeps all 80 divisions through the sync API, staying inside rate limits, and finds 214 open lines in 37 clients. It proposes a reclass for each based on supplier history, for example 'Hetzner €4,200 → 4500 IT costs, reverse-charge EU services, 97% confidence', and flags 9 lines it can't classify. The bookkeeper approves 205 in one queue, and the agent posts them as GeneralJournalEntries per division. It returns a per-client checklist and a box-by-box VAT pre-check that catches a missing ICP declaration at one client. That is about two days of clicking through 80 administrations.

**Integration path:** Exact Online has a mature OAuth2 REST/OData API scoped per division (financialtransaction, generaljournalentry, purchaseentry, salesentry, bankentries, VAT, GLAccounts, sync/bulk endpoints). Rate limits are strict (roughly 60 calls/min and a daily cap per division), so cache through the sync API. It also has an App Center for distribution. Fortnox (REST v3) and e-conomic (REST) follow the same tool abstraction. MVP: read-only cross-division health sweep, then journal-posting writes.

### 7. Customer.io Journeys (behavioral messaging: campaigns, segments, Liquid personalization, broadcasts, data pipelines) `closed`

**Why it's powerful:** Customer.io is the go-to event-driven lifecycle-messaging tool for SaaS, apps and DTC brands. It supports event and attribute-triggered campaigns across email, push, SMS, in-app, webhooks and Slack. It has multi-branch workflows with true/false and random cohort splits, wait-until conditions, time windows, frequency limits, objects and relationships (accounts, courses, subscriptions), Liquid templating with event payload data, transactional messages, and a full CDP pipeline (Data Pipelines) with reverse-ETL from warehouses.

**Why people bounce off it:** Users get stuck in three places. First, segment logic: nested AND/OR, event counts within time windows, and object relationships, plus the difference between data-driven and manual segments. Second, campaign trigger semantics: event-triggered versus segment-triggered, exit conditions, conversion goals and re-entry settings, which often cause duplicate sends or users who never enter. Third, Liquid templating against event JSON, which fails silently and renders blanks. Product marketers usually have to hand campaigns off to an engineer to set up the events and Liquid, and nobody can quickly answer 'why did this user get (or not get) message X'.

**AI operator:** A 'Lifecycle copilot' that knows the workspace's actual event and attribute schema, pulled through the API. It writes and validates segment definitions, drafts message content with Liquid that is checked against real sample event payloads, and builds campaign blueprints (trigger, filters, delays, branches, exit and goal settings) for the user to click through or apply where the API allows. It answers support-style questions by pulling a person's activity log and message deliveries ('Jane didn't get the trial-ending email because she matched the exit condition Paid Plan = true at 14:02'). It also runs broadcasts and manual-segment sends from chat.

**Killer example:** A growth marketer asks in Slack: 'Why did 30% of last week's trial signups never get the day-3 onboarding email? Send it now to everyone who missed it and still hasn't created a project.' The copilot samples 20 affected activity logs and finds the cause: the signed_up event fires before the plan attribute is written, so the trigger filter 'plan = trial' excludes them. It proposes moving the filter to a 2-minute delayed check. It also finds that the email's {{event.company_name}} renders blank for 18% of users, and suggests a fallback. It builds a manual segment of 412 people (signed up in the last 7 days, day-3 not delivered, project_created count 0), shows rendered previews for 3 real recipients, and triggers the API broadcast after a thumbs-up. Diagnosis and recovery take 5 minutes and no engineer ticket.

**Integration path:** Three APIs. The Track API and Data Pipelines API handle identify, events and attributes. The App API (bearer token) covers people search with filter JSON, activity logs, message deliveries and metrics, campaigns and broadcasts (read, metrics, triggering API-triggered broadcasts with per-recipient data), manual segments (create, add and remove members), transactional sends, newsletters and message templates content, plus exports. Reporting Webhooks provide delivery events. Creating full workflow graphs is only partly covered by the API, so for those the MVP produces a step-by-step blueprint and the operator does the rest through the API. Build it as an MCP server plus a Slack bot.

### 8. Atlassian Bitbucket (Cloud + Data Center: workspace/project permissions, branch restrictions, merge checks, Pipelines, deployments) `closed`

**Why it's powerful:** It is the Git host for a large share of Jira-centric companies. It has project- and workspace-level permissions, branch restrictions and merge checks (required approvals, passing builds, default reviewers), Bitbucket Pipelines with deployment environments and variables, Code Insights, access keys and tokens, IP allowlisting, and on Data Center: mirrors, hook plugins and rate limits.

**Why people bounce off it:** Governance across hundreds of repos is click-by-click and inconsistent: branch restrictions, merge checks and default reviewers are set per repo, project-level inheritance is partial, and drift is invisible. Pipelines YAML (caches, services, parallel steps, deployment variable scoping, OIDC to AWS) is fiddly. The Cloud and DC APIs differ, which makes Atlassian's announced Data Center sunset and DC-to-Cloud migration a real pain: permissions, hooks, and app-password-to-API-token changes don't map one-to-one.

**AI operator:** A repo-governance and pipeline operator with skills for: auditing branch restrictions, merge checks, default reviewers and access across every repo and reporting drift from a declared policy; bulk-applying fixes with a dry-run diff; generating and fixing bitbucket-pipelines.yml (caching, parallel steps, deployment environments, OIDC); diagnosing failed pipelines from step logs; and a migration assistant that inventories DC repos, permissions and hooks and maps them to Cloud equivalents.

**Killer example:** Ahead of a SOC 2 audit, an engineering manager types: 'Every repo in PAYMENTS must need 2 approvals plus a green build to merge into main, with no force-push. Show me who's out of line and fix it without breaking anyone.' The operator scans 87 repos and finds 23 that allow force-push, 11 with no build check and 6 where a departed engineer is still the only default reviewer. Before applying anything, it warns that 4 repos have no pipeline, so a required-build check would block every merge there. It generates starter bitbucket-pipelines.yml files (with caching and OIDC to AWS) as PRs for those 4. It applies the restrictions to the other 83 from a dry-run diff, saves the policy as YAML for nightly drift checks, and exports evidence for the auditor.

**Integration path:** Bitbucket Cloud REST API 2.0 (repositories, branch-restrictions, pullrequests, pipelines, deployments, permissions) and the Bitbucket Data Center REST API (separate endpoints, the same concepts). Auth is OAuth consumers, API tokens or workspace/project access tokens. Atlassian Connect and Forge cover in-product UI; the operator runs as an MCP server plus Slack or web chat. Policy-as-code (a YAML desired state) makes the bulk-fix and drift loop deterministic.

### 9. Microsoft Azure Cost Management + Billing (cost analysis, budgets, exports, reservations/savings plans, cost allocation rules) `closed`

**Why it's powerful:** It is the only authoritative source of Azure spend. It covers every scope, from billing account and billing profile down to management group, subscription and resource group, with actual and amortized cost views, tag-based grouping, anomaly alerts, budgets with action groups, reservation and savings-plan utilization and recommendations, cost allocation rules that split shared costs, and scheduled FOCUS-format exports to storage. Every org running on Azure has it.

**Why people bounce off it:** The scope model is the wall. EA, MCA, MOSA and CSP accounts expose different scopes and different features, and users often can't find their own spend because they're looking at the wrong scope. Reservation and savings-plan benefits apply across subscriptions in ways nobody can trace. The ad-hoc way to answer anything nontrivial is to set up an export, land it in storage, then query it.

**AI operator:** A FinOps copilot with skills for: detecting the account type and picking the right scope; Cost Management Query API calls with amortized vs. actual chosen deliberately; tag-coverage auditing plus enabling tag inheritance; creating budgets and anomaly alerts wired to action groups; reading reservation and savings-plan utilization and recommendations; drafting cost allocation rules; and setting up FOCUS exports. Each answer states which scope and cost type it used, so the numbers can be checked.

**Killer example:** User: 'Why did the data platform team's Azure bill jump 40% last month, and set a budget so we hear about it next time.' The AI resolves the 'team=data-platform' tag across 6 subscriptions and finds 31% of the spend untagged, so it proposes turning on tag inheritance. On amortized cost it finds the jump is a Databricks DBU spike plus an expired reservation that dropped 14 D-series VMs back to pay-as-you-go. It recommends a 1-year savings plan with projected savings, then creates a monthly budget at 80% and 100% of a $42k target, plus an anomaly alert routed to the team's Teams channel through an action group.

**Integration path:** Azure Resource Manager REST APIs (Microsoft.CostManagement query, forecast, exports, scheduled actions; Microsoft.Consumption budgets and reservation summaries; Microsoft.Billing for account and scope discovery; Microsoft.Capacity / BillingBenefits for reservations and savings plans). Auth uses an Entra app or az CLI with the Cost Management Reader or Contributor role. Ship it as an MCP server plus a Teams or web chat front end. All write operations (budgets, exports, allocation rules, tag inheritance) are idempotent ARM PUTs that are easy to preview first. Differentiate from Microsoft's built-in Copilot in Azure through multi-scope reasoning and write-back actions.

### 10. darktable (open-source RAW photo developer) `open-source`

**Why it's powerful:** It does scene-referred, 32-bit floating-point processing with filmic rgb and sigmoid tone mapping, color calibration (CAT16 white balance with channel mixing), and a color balance rgb grading module. It has parametric and drawn masks with feathering and guided filters, more than 60 processing modules, styles, tethering, a Lua scripting API and darktable-cli for headless export. Its image quality matches or beats Lightroom with no subscription.

**Why people bounce off it:** darktable is famous for its learning cliff. The 'scene-referred' default requires understanding exposure plus filmic or sigmoid, the white/black relative exposure settings and the order of the pixelpipe. White balance is split between the 'white balance' and 'color calibration' modules, and new users double-apply it. There are several overlapping modules for the same job (three ways to do contrast, deprecated modules still visible). Masks need blend-mode and parametric-range knowledge, and module instances and pixelpipe order are opaque. The forums are full of Lightroom switchers saying 'I gave up after a week'.

**AI operator:** An agent edits darktable's XMP sidecar history stacks: module parameters are versioned binary blobs per module, which it encodes and decodes with a param-schema library generated from darktable's introspection headers. It drives the live GUI through the Lua API (dt.gui.action() and dt.styles), and it renders previews with darktable-cli so it can look at the result with a vision model and adjust.
