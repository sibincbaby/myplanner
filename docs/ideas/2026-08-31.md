### 1. Gmail (filters, labels, multiple inboxes, forwarding, canned responses) `closed`

**Why it's powerful:** Gmail's automation layer is enormous but scattered: multi-criteria filters (from/to/subject/has:attachment/size/list-id), nested labels, auto-forwarding rules, delegate access, vacation responder, canned responses (templates), and a 'Multiple Inboxes' pane that can render custom saved-search panels alongside the main inbox — effectively a poor-man's Kanban view of email.

**Why people bounce off it:** The filter-creation UI only lets you build one AND-chain at a time through a form, so anything requiring OR-across-senders or exclusion logic forces users to hand-write Gmail's search-operator syntax (`from:(a OR b) -subject:receipt`), which almost nobody knows exists. Multiple Inboxes requires manually typing raw search queries into unlabeled text boxes in Settings > Advanced with zero preview. Canned responses are hidden behind a 'Labs'-style toggle. Result: most users just live with 40,000 unread emails instead of the 10-minute setup that would fix it.

**AI operator:** A 'Gmail Filter & Inbox Concierge' skill that turns plain-English inbox rules into correct Gmail search-operator syntax and calls the Gmail API to create filters, labels, forwarding addresses, vacation responders, and Multiple-Inbox panes — plus one-shot bulk cleanup ('archive everything from these 12 senders older than 90 days').

**Killer example:** User says 'Auto-label invoices from Stripe, PayPal, and QuickBooks as Finance/Invoices, skip the inbox, and mark them read.' In one turn the AI writes the compound search operator `from:(stripe.com OR paypal.com OR quickbooks.com) subject:(invoice OR receipt)`, creates the nested Finance/Invoices label via users.labels.create, and wires the filter via users.settings.filters.create with addLabelIds + removeLabelIds:[INBOX, UNREAD] — a rule that would take a typical user 20 minutes of trial-and-error with Gmail's search-operator syntax to get right, done in seconds and then applied retroactively to the whole backlog with one batchModify call.

**Integration path:** Gmail API (REST, OAuth2, free, no self-hosting): users.settings.filters, users.labels, users.settings.sendAs (canned responses via drafts), users.settings.forwardingAddresses, users.settings.updateVacation, users.messages.batchModify for bulk actions. Mature, extensively documented, no desktop dependency.

**Demand 5/5 · Buildability 5/5**

### 2. Sentry (error monitoring & performance/tracing platform) `open-source`

**Why it's powerful:** Full exception tracking with stack traces/breadcrumbs, ML-based issue fingerprinting/grouping, distributed performance tracing (transactions/spans), session replay, release health, and a Discover/Explore analytics engine for querying events across the whole org — plus a rules engine for alerting and issue ownership routing.

**Why people bounce off it:** The alert-rule builder (nested AND/OR conditions, frequency windows, multi-step actions) and the Discover query syntax (tags, aggregate functions like p95()/count_unique(), custom columns) have real learning curves; ownership/routing rules use path-matching syntax most devs never learn, so teams run on default settings, get alert fatigue, and miss real regressions while ignoring noisy ones.

**AI operator:** NL layer that compiles plain requests into Sentry alert-rule JSON (conditions/actions/integrations), runs ad-hoc Discover queries in English, and performs issue triage (assign/ignore/merge/resolve) by talking to the REST API.

**Killer example:** User says 'Page on-call if the checkout service's error rate spikes 20% above its 7-day baseline within 5 minutes, but only during business hours, and auto-resolve anything tagged "known-flaky" after 3 occurrences.' AI creates the metric alert (threshold, 5-minute window, business-hours schedule, PagerDuty action) via the Alert Rules API, adds an ignore rule keyed on the flaky tag, and confirms 'Live — alerting #oncall-checkout, auto-resolving known-flaky after 3x' — the kind of nested condition/action rule that normally takes an engineer 30+ minutes of trial-and-error in the rule builder to get right.

**Integration path:** Sentry REST API (orgs/projects/issues/alert-rules/discover endpoints, fully documented), sentry-cli for releases/source maps, webhooks for real-time issue events, self-hosted docker-compose stack for dev/testing.

**Demand 5/5 · Buildability 4/5**

### 3. Autodesk Maya `closed`

**Why it's powerful:** The industry-standard DCC for character rigging, animation (Graph Editor, HumanIK), procedural motion graphics (MASH), and dynamics (nCloth/nParticles) across film, TV, and AAA games — nothing else has its rigging depth.

**Why people bounce off it:** Rigging and animation-curve work demand navigating thousands of nodes in the Hypergraph, hand-writing constraint setups, cleaning tangents in the Graph Editor, and fixing skin weights vertex-by-vertex; new riggers/animators take years to become fluent, and even veterans spend hours on repetitive setup work (mirroring joints, driven keys, IK/FK switches) that is mechanical but tedious.

**AI operator:** An NL layer that drives Maya's Python API (maya.cmds/PyMEL) and MEL through a command-port or mayapy headless session to build joint chains, IK handles, constraints, driven keys, and clean up animation curves on request.

**Killer example:** User says 'Rig this biped, mirror the IK legs to the right side, and lay down a 24fps walk cycle over 48 frames.' The AI drives maya.cmds through a live commandPort session: builds the joint hierarchy, creates IK handles, runs mirrorJoint to clone the left leg rig to the right, sets driven-key poses for contact/passing/lift, and keyframes a seamless looping walk cycle — a full day of junior-rigger work compressed into one conversational request, with the artist's open scene updating live in the viewport as it happens.

**Integration path:** Maya exposes a full Python command surface (maya.cmds/PyMEL) that mirrors the entire UI; scripts run headlessly via mayapy/Maya batch mode or interactively through Maya's built-in commandPort socket, so an agent can hold a live session against the artist's open scene.

**Demand 5/5 · Buildability 4/5**

### 4. SideFX Houdini `closed`

**Why it's powerful:** Procedural, node-based 3D for simulation (pyro, fluids, RBD), scattering, and generative modeling that drives most modern film VFX and is rapidly spreading into games and archviz because nothing else matches its non-destructive, parametric power.

**Why people bounce off it:** Houdini is famous industry-wide as 'impossible to learn' — every operation is a wired SOP/DOP node network, and real control requires writing VEX expressions inline; artists coming from Maya or Blender routinely spend months just to build a basic procedural scatter or simulation setup.

**AI operator:** An NL agent that uses Houdini's hou Python module (run interactively or headlessly via hython) to assemble and wire SOP/DOP node networks and generate VEX wrangle code from plain descriptions.

**Killer example:** User says 'Scatter rocks on this terrain, avoid the road, vary size between 0.5 and 2, and make them denser near the cliff edge.' AI wires a Scatter SOP into the network, groups points by distance-to-curve to carve out a no-scatter zone along the road, adds a proximity-to-edge attribute to bias density, and chains an Attribute Randomize SOP for the size range — reproducing, node-for-node, a graph that normally costs a Houdini artist an hour of trial-and-error VEX wrangling to get right, and leaving the network fully editable afterward.

**Integration path:** Houdini's hou module gives full read/write access to node networks, parameters, and VEX code; hython (Houdini's bundled Python interpreter) runs completely headless, and the free Houdini Apprentice/Indie tiers make dev-loop testing cheap.

**Demand 5/5 · Buildability 4/5**

### 5. Google Docs `closed`

**Why it's powerful:** Structured paragraph Styles that drive an auto-generated, click-to-navigate Table of Contents; named ranges and Smart Chips (live people/file/date/place references) for building dynamic documents; suggestion/track-changes mode; and full programmatic control via the Docs API for template-driven document generation.

**Why people bounce off it:** Almost nobody uses paragraph Styles — they manually bold and resize text instead — so long documents (proposals, RFPs, contracts) have no real heading structure, which means no working Table of Contents and no consistent formatting. Smart Chips and named ranges are undiscoverable. Unlike Word, Docs has no built-in mail-merge wizard at all — producing one personalized document per recipient requires installing a third-party add-on or hand-writing Apps Script, which most users never attempt.

**AI operator:** A 'Docs Formatter & Merge Agent' that retroactively applies correct heading Styles to a messy long-form Doc based on its actual structure, inserts/refreshes a Table of Contents, and performs true one-doc-per-row mail merge from a Sheet + template Doc — including live Smart Chips instead of static placeholder text.

**Killer example:** User says 'This 40-page proposal has no real heading structure — fix it, add a table of contents, then generate one personalized cover letter per client from this contact sheet.' AI scans the doc, infers heading levels from font-size/boldness patterns, issues batchUpdate calls to apply real Heading 1/2/3 Styles, inserts a live clickable Table of Contents, then loops 60 rows in the linked Sheet, duplicating the template doc per client via the Drive API and merging fields with replaceAllText — turning a same-day scramble before a client deadline into a five-minute batch job, with every generated doc still fully editable.

**Integration path:** Google Docs API (REST, batchUpdate: updateParagraphStyle, insertTableOfContents, replaceAllText, createNamedRange) + Google Sheets API as the merge data source + Google Drive API for per-recipient file duplication/export. Fully documented REST, OAuth2, no desktop or license dependency.

**Demand 4/5 · Buildability 5/5**

### 6. CircleCI `closed`

**Why it's powerful:** Highly parametrized YAML pipelines with reusable orbs, dynamic config-in-config, matrix builds, fan-out/fan-in workflows, resource classes, secret-scoped contexts, test-splitting/parallelism, and an Insights dashboard for flaky-test and duration trends.

**Why people bounce off it:** Writing and debugging config.yml is notoriously painful — orb version pinning, dynamic-config generation, branch/tag workflow filters, and figuring out why a parallel job failed across scattered step logs — so most teams copy-paste a working config once and never revisit caching, parallelism, or cost optimization.

**AI operator:** NL-to-config-diff assistant that edits .circleci/config.yml directly (adding parallelism, caching, scheduled workflows, Slack/orb steps) and an Insights-API analyst that explains pipeline slowdowns and proposes fixes.

**Killer example:** User says 'Our test suite takes 22 minutes and keeps timing out — split it into parallel containers using real historical timing data, and cache node_modules so we're not reinstalling every run.' AI reads the project's Insights API timing data, rewrites .circleci/config.yml to add a `save_cache`/`restore_cache` step keyed on the lockfile hash and a parallelism: 4 block using `circleci tests split --split-by=timings`, then opens a PR with the diff and a comment projecting the new build time — a tuning pass most teams never get around to doing themselves.

**Integration path:** Config lives as git-diffable YAML in the repo; CircleCI REST API v2 (pipelines/workflows/jobs/insights/contexts); circleci CLI for local `config validate`/`process`.

**Demand 4/5 · Buildability 4/5**

### 7. Outreach (sales engagement / cadence platform) `closed`

**Why it's powerful:** Runs the entire outbound motion for enterprise SDR/AE orgs — multi-channel sequences, mailbox rotation, deliverability throttling, A/B testing, meeting scheduling, and AI prospect scoring — it's the de facto sequencer sitting on top of the CRM.

**Why people bounce off it:** A sequence that actually lands requires correct step spacing, sender rotation across warmed mailboxes, domain-level send throttles, and mixed email/call/LinkedIn/task steps — spread across admin-only mailbox and domain-health settings most reps never touch. Reps typically just clone an existing sequence, silently degrading deliverability and reply rates org-wide.

**AI operator:** NL sequence builder plus a deliverability guardrail: describe a cadence in plain language and the AI drafts the multi-step, multi-channel sequence with safe sender-rotation and send-window settings via the API, or audits an existing rep's sequence for deliverability landmines (mailbox overload, missing warm-up buffer, no exit trigger).

**Killer example:** User says 'Build an 8-touch, 3-week sequence for the fintech vertical — 4 emails, 2 calls, 1 LinkedIn touch, 1 video — rotate across our 3 warmed domains, and stop immediately if they reply or book a meeting.' AI creates the sequence via the Sequences API with correct step types and day-offsets, applies a mailbox-rotation rule across the 3 warmed domains to avoid deliverability throttling, and sets an auto-exit trigger on reply/meeting-booked — codifying guardrails most reps have no idea exist and would otherwise just clone a stale sequence and quietly tank the team's sender reputation.

**Integration path:** Outreach REST/GraphQL API (Sequences, Sequence Steps, Sequence States, Mailboxes, Prospects endpoints) with OAuth2; official SDKs for direct programmatic control.

**Demand 4/5 · Buildability 4/5**

### 8. Microsoft OneNote `closed`

**Why it's powerful:** Free-canvas note-taking with a real hierarchy (notebooks > sections/section groups > pages), ink and image OCR search, page tags (To-Do, Important, Question), shared/Class Notebooks for teams, embedded file/Excel objects, and linked side-by-side note-taking with browser or Word.

**Why people bounce off it:** There's no native bulk-reorganize: notebooks devolve into hundreds of untagged, unlinked pages within months. Tags are almost never applied consistently, so tag-search — the one feature that would rescue a messy notebook — returns nothing useful. Action items buried in freeform meeting notes never get pulled into a task list. Class/staff Notebook distribution tooling is byzantine even for IT admins.

**AI operator:** A 'OneNote Librarian' agent that reads a user's notebook tree via Graph, retroactively tags and cross-links pages, merges duplicate/near-duplicate pages, extracts untagged action items into properly tagged To-Do items with due dates, and files newly pasted content into the right section automatically.

**Killer example:** User says 'Go through my Work notebook, tag every untagged action item as To-Do with a due date pulled from context, merge the three duplicate "Q3 Planning" pages, and give me a digest grouped by project section.' AI walks the notebook tree via Graph (notebooks → sections → pages), pulls each page's HTML, detects action-item phrasing and nearby dates, PATCHes in OneNote tag spans with due-date metadata, merges the duplicate pages into one canonical version, and returns a section-grouped digest — rescuing a 300-page notebook that had become unsearchable because nobody ever applied a tag consistently.

**Integration path:** Microsoft Graph OneNote REST API (notebooks, sectionGroups, sections, pages, page content as editable HTML with data-id/data-tag attributes), OAuth via Entra ID app registration; works for both personal Microsoft accounts and Microsoft 365 work/school accounts. Page-HTML content model is real but fiddly to round-trip safely.

**Demand 4/5 · Buildability 4/5**

### 9. Tenable.io / Nessus (vulnerability management) `closed`

**Why it's powerful:** Continuous network/cloud/web-app vulnerability scanning with deduped asset inventory, Vulnerability Priority Rating (VPR) that fuses CVSS with live exploit/threat intel to cut through thousands of raw findings, dynamic tag-based asset groups, and CIS/PCI compliance auditing.

**Why people bounce off it:** A single scan can surface 10,000+ raw findings; building correct dynamic asset tags/scan policies, mapping VPR-prioritized findings to the right owning team, and running the manual remediation-ticket-and-rescan-verification loop is a full-time job most security teams are under-resourced to do well, so critical exploitable issues get lost in the noise.

**AI operator:** NL layer over the Tenable.io REST API that provisions scan policies/dynamic tags/alerts from plain requests, and a triage assistant that groups scan results by owning team and auto-files remediation tickets for the top VPR items.

**Killer example:** User says 'find every asset still vulnerable to Log4Shell and open a Jira ticket per owning team with the affected hosts' → AI queries vulnerabilities filtered by CVE-2021-44228, groups by asset tag = team, and creates Jira issues with host lists and remediation steps.

**Integration path:** Tenable.io REST API (scans, assets, vulnerabilities, tags, exports) plus the official pyTenable SDK; webhook/export endpoints for bulk results; Jira/ServiceNow APIs for ticket creation.

**Demand 5/5 · Buildability 3/5**

### 10. Twilio Segment (Customer Data Platform — Protocols, Personas/Engage, Connections) `closed`

**Why it's powerful:** Segment unifies every event stream (web, app, backend, POS) into typed customer profiles via Protocols tracking plans, computes real-time audiences and traits with Personas/Engage, and fans them out to 400+ downstream destinations (ad platforms, ESPs, warehouses) with a single API call — it's the plumbing that lets a marketing team run 'send to Klaviyo/Google Ads/Braze' without engineers wiring each integration.

**Why people bounce off it:** Defining a new audience or computed trait requires writing nested AND/OR condition trees over event history (e.g. 'did event A twice in 14 days AND did NOT do event B'), understanding trait computation windows, and mapping the result to a destination's field schema — this is effectively writing a small analytics query in a proprietary DSL. Marketers overwhelmingly hit a wall here and file a ticket with the data/eng team for every new segment, turning a 5-minute campaign idea into a multi-day backlog item.

**AI operator:** A natural-language audience/trait builder pre-loaded with Segment's Engage API schema: it parses the marketer's request into computed-trait and audience-condition JSON, creates/updates the object via API, wires the destination sync, and reports back the resulting audience size for sanity-check before activation.

**Killer example:** User says: 'Create an audience of anyone who added to cart in the last 14 days but hasn't purchased, exclude email unsubscribes, and sync it to Klaviyo as a new list.' AI calls the Engage API to define the computed trait (cart_add events with no matching order event in a trailing 14-day window), builds the audience with the unsubscribe exclusion filter, creates the Klaviyo destination sync, and activates it — then messages back 'Audience created: 4,213 profiles, syncing now.'

**Integration path:** Segment's Config API (workspace objects) + Engage API (audiences, computed traits, destination syncs) + Tracking API (events) — all REST/JSON with OAuth workspace tokens, extensively documented and stable, making it a strong LLM code-gen target.

**Demand 4/5 · Buildability 3/5**

### 11. Algolia (Search & Discovery — Rules, Ranking, Merchandising, Recommend) `closed`

**Why it's powerful:** Algolia powers instant, typo-tolerant search-as-you-type with a fully customizable ranking formula, a Rules engine for query-specific merchandising (boost/bury/pin products, banners, redirects), synonyms, faceting, and built-in A/B testing on relevance — it's what lets large catalogs surface the right product in milliseconds.

**Why people bounce off it:** Tuning relevance or launching a promotional boost means writing Rule condition/consequence JSON (query match, context, validity dates) and reordering custom-ranking attributes correctly relative to Algolia's tie-breaking cascade — get the order wrong and an entire category silently stops ranking well. Store merchandisers who want to react to 'boost this SKU for Black Friday' or 'hide out-of-stock items everywhere' routinely can't self-serve and wait on a developer to push the change through the dashboard or CLI.

**AI operator:** An operator pre-loaded with Algolia's Admin API for Rules, Synonyms, and index Settings — it turns merchandising requests into Rule objects (condition + consequence + validity window) and ranking/facet updates, previews the affected query results, then pushes the change live.

**Killer example:** User says: 'Boost Nike Air Max to the top 3 results for "running shoes" through Labor Day weekend, and hide any out-of-stock product from every search.' AI creates a time-boxed Rule promoting the objectID for that query, plus a global filter excluding inventory=0 items, and confirms: 'Live through Sept 1, 3,204 out-of-stock items now hidden.'

**Integration path:** Algolia's Admin REST/JS API gives full CRUD on indices, Rules, Synonyms, and A/B tests with scoped API keys — clean, stable, JSON-native, and a strong fit for structured LLM generation.

**Demand 3/5 · Buildability 4/5**
