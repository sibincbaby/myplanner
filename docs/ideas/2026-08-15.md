### 1. Salesforce Flow Builder (record-triggered, scheduled and screen flows) `closed`

**Why it's powerful:** Flow is now the *only* supported declarative automation engine in Salesforce — Workflow Rules and Process Builder are retired — so every one of ~150,000 customer orgs funnels its business logic through it. It supports record-triggered, scheduled, platform-event and screen flows with Get/Create/Update/Delete Records, Loops, Decisions, Assignments, Subflows, formulas, invocable Apex, and prebuilt Slack, Data Cloud and email actions. A competent builder replaces thousands of lines of Apex with a single flow, and every org's revenue process depends on flows nobody dares touch.

**Why people bounce off it:** People die at the Start element. Choosing "Fast Field Update" (before-save) versus "Actions and Related Records" (after-save) is a performance-and-semantics decision disguised as a radio button, and the checkbox "only when a record is updated to meet the condition requirements" silently changes whether the flow re-fires at all. Then come `$Record` versus `$Record__Prior`, collection variables inside Loops, missing fault paths, and the classic production outage `Too many SOQL queries: 101` caused by a Get Records element sitting inside a Loop. Debugging means the Debug modal plus a flow-interview error email full of element API names, and admins routinely ship recursive flows that update the record that triggered them. The admin who can describe the business rule perfectly in English cannot safely build it.

**AI operator:** An org-connected agent that authors, deploys and debugs Flow metadata from natural language. Pre-loaded with the Flow metadata schema (elements, connectors, entry criteria, formulas, scheduled paths), bulkification best practice (no DML or Get inside Loops, one record-triggered flow per object per context, always add a fault path), and a mapping from business phrasing to the correct trigger type. Critically it closes the loop: it deploys to a **sandbox** via Metadata API, runs a debug interview against a real sample record, reads the interview path and any fault, fixes itself, and only then offers to activate in production with a version diff. A second skill audits the existing flow estate — recursion risk, missing fault paths, Get-inside-Loop, overlapping record-triggered flows on the same object — which is the thing every inherited org needs and nobody has time for.

**Killer example:** User says: *"When an Opportunity goes Closed Won above $50k, spin up a renewal opp dated a year out, post it in #big-deals, and give the AE's manager an onboarding task."* → AI builds an after-save record-triggered flow on Opportunity with entry criteria `ISCHANGED(StageName) AND StageName = 'Closed Won' AND Amount > 50000`, a Get Records on User to resolve `Owner.ManagerId`, Create Records for a cloned Opportunity with `CloseDate = CloseDate + 365` and `Type = Renewal`, a Task assigned to the manager, the Slack "Send Message to Channel" action, and a fault path emailing the admin. It runs Debug on a $120k opportunity, shows the traversed interview path, and activates version 3.

**Integration path:** Metadata API (`Flow` and `FlowDefinition` types) plus Tooling API for versioning, driven through the `sf` CLI (`sf project deploy start`, `sf org assign`), with the REST Invocable Actions API to trigger and test flows and flow interview logs for debugging. Honest gap: Flow Builder's canvas layout metadata is fiddly to generate cleanly, so machine-authored flows can look ugly in the UI even when they are correct — worth investing in layout generation so admins trust the output.

**Demand 5/5 · Buildability 4/5**

### 2. Microsoft SQL Server performance tuning (SSMS, execution plans, Query Store, indexes, wait stats) `closed`

**Why it's powerful:** SQL Server underpins an enormous population of line-of-business apps, ERPs and vendor products, and it ships one of the richest built-in diagnostic surfaces in software: Query Store capturing every plan and its runtime regressions with forced-plan support, DMVs for wait statistics, missing/unused indexes and top resource consumers, Extended Events for lightweight tracing, statistics and index maintenance, plan guides, Resource Governor, and Always On instrumentation. Every answer needed to fix a slow system is already in the box.

**Why people bounce off it:** SSMS hands you a graphical execution plan with 40 operator properties and no opinion. The actual fix is buried in an estimated-vs-actual row mismatch, a key lookup, an implicit conversion that killed an index seek, or a parameter-sniffing regression — none of which the UI names. Missing-index DMV hints are famously naive, so admins either ignore them or blindly create fifteen overlapping wide indexes that wreck write performance. The typical victim is a small IT team with no DBA whose "ERP is slow at month-end": they have every diagnostic available to them and no idea which query, which wait type, or which index to touch.

**AI operator:** A companion that connects with a scoped SQL login and carries skills for "why is it slow right now" triage (top waits + active requests + blocking chain), Query Store regression hunting, plan reading translated into plain-English root causes, index recommendation that **de-duplicates and merges against existing indexes** instead of stacking new ones, statistics and fragmentation maintenance, and safe plan forcing. It separates zero-risk actions (reading DMVs, forcing a previously-good plan, updating statistics) from schema changes: `CREATE`/`DROP INDEX` is generated as reviewable T-SQL with estimated size and write-cost impact, dry-run by default, gated behind explicit approval plus an optional maintenance-window check, and always paired with a rollback script. `WITH (ONLINE=ON)` is used where the edition supports it. Ships with a strict read-only mode so it can be handed to non-DBAs.

**Killer example:** User says: *"The invoice screen has been slow since Monday — find out what changed and fix it if it's safe."* → AI queries Query Store for plans whose average duration regressed after 2026-08-10, pinpoints `usp_GetInvoiceLines` flipping from an index seek to a clustered index scan after an auto-parameterized plan change, shows the old `plan_id` at 40 ms versus the new at 2.6 s, verifies the old plan is still valid, and offers `sp_query_store_force_plan @query_id=8842, @plan_id=1173` as the zero-schema-change fix — with the alternative covering index on `(CustomerID, InvoiceDate) INCLUDE (Amount, Status)` scripted out and explicitly marked as requiring a maintenance window.

**Integration path:** Plain T-SQL over any standard driver (`sys.dm_exec_query_stats`, `sys.dm_os_wait_stats`, `sys.dm_db_missing_index_details`, `sys.query_store_query/plan/runtime_stats`, `sys.dm_exec_query_plan` XML), `sqlcmd` and the SqlServer PowerShell module, SMO for schema objects, Extended Events sessions for tracing, and Azure SQL's equivalent DMVs for the cloud editions. No vendor approval, no partner program, no API keys — this is the highest-buildability idea in the batch.

**Demand 5/5 · Buildability 5/5**

### 3. Make (Integromat) — scenario builder, iterators/aggregators, data stores `closed`

**Why it's powerful:** Make runs 2,000+ app connectors on a bundle-based execution model with routers, filters, iterators, array/text/numeric aggregators, error-handler routes with break/rollback/resume directives, data stores, instant webhook triggers, and scheduled scenarios with incremental state. Crucially, an entire automation is addressable as a **JSON blueprint** — a serializable, diffable artifact — and the Apps SDK lets you wrap any REST API not already covered. It is the automation substrate for a very large population of SMBs with no developer.

**Why people bounce off it:** The famous wall is the bundle model: users cannot grasp why a module "runs 12 times", so they drown in iterator→aggregator pairing, and the mapping panel's nested item references (`1.array[].field`, aggregator source-module selection) is where most builds die. Second wall: error handling — a scenario silently deactivates after three consecutive errors, and nobody knew they needed an error route with a Resume directive. Third: variables that simply vanish across a router because an aggregator collapsed their scope. The result is a half-built scenario burning thousands of operations a day that its owner cannot debug or afford.

**AI operator:** An operator that authors and repairs whole scenarios **as blueprint JSON** rather than clicking modules. Pre-loaded skills: generate a valid blueprint from a described workflow with correct module names, connection IDs, filter expressions, iterator/aggregator pairing and mapped item paths; diff a broken scenario against stated intent; add error-handler routes with the right directive; convert a naive per-item HTTP loop into an aggregator plus a single batched call to cut operation consumption; and narrate the bundle flow module by module so the user finally understands their own scenario. It validates by POSTing to a draft scenario and reading the execution log before activating. Packaged as a Make-connected web app plus a custom Make app so it drops into a team's own org with a scoped API token.

**Killer example:** User says: *"Every morning, pull yesterday's orders from our store API, group them by vendor, and email each vendor one PDF summary — and stop burning 4,000 operations a day."* → AI GETs the current blueprint, rewrites it to replace the per-order Email module with Iterator → Text Aggregator grouped by vendor key → one Email per group, adds a Data Store to dedupe order IDs across runs, attaches an error route with a Resume directive on the mail module, PATCHes `/api/v2/scenarios/{id}` with the new blueprint, runs one execution, and reports "operations per run: 4,120 → 190; 7 vendor emails sent; 0 duplicates."

**Integration path:** Make API v2 (`GET /scenarios/{id}/blueprint`, `POST /scenarios` with blueprint JSON, `PATCH /scenarios/{id}`, executions/logs, data-stores, connections, hooks) with token auth; Make Apps SDK plus VS Code extension for custom connectors. The blueprint being a first-class JSON document is what makes this unusually tractable — the operator never has to drive a canvas.

**Demand 5/5 · Buildability 4/5**

### 4. Windows Server Active Directory Group Policy (GPMC, ADMX settings, RSoP troubleshooting) `closed`

**Why it's powerful:** Group Policy is the configuration backbone of essentially every Windows domain on earth: tens of thousands of ADMX-backed settings, registry-based preferences, drive and printer mappings, scheduled tasks, security baselines, AppLocker, and per-user/per-computer scoping. Policies link at site, domain and OU level, filter by security group or WMI query, and invert with loopback processing. It remains the fastest way to change the behaviour of 5,000 machines at once.

**Why people bounce off it:** GPMC is a two-decade-old MMC snap-in where finding a setting means guessing its path through the ADMX tree — but the real difficulty is **precedence**. LSDOU order, Enforced links, Block Inheritance, security filtering plus the post-MS16-072 requirement that computers hold Read on user GPOs, loopback merge-versus-replace, and WMI filters that silently drop the policy: six independent mechanisms, any of which can eat your change with no error anywhere. When a setting "doesn't apply", admins burn hours on `gpresult /h` and RSoP with no explanation of which mechanism won. Small teams accumulate dozens of overlapping legacy GPOs nobody dares delete.

**AI operator:** Runs on a domain-joined admin host with skills for setting search (map plain English to the exact ADMX policy and registry value), GPO authoring, link/scope management, precedence explanation, RSoP diagnosis, drift comparison against Microsoft Security Baselines, and orphan/duplicate cleanup. The diagnostic skill is the headline product: it pulls resultant-set data for a real user+computer pair and narrates exactly which GPO won and why each loser lost. Safety is non-negotiable here — every write is preceded by an automatic `Backup-GPO` to a timestamped folder, staged into an **unlinked** GPO with the resulting HTML report diffed and shown, and requires explicit confirmation before `New-GPLink`. Deletions and Enforced/Block-Inheritance changes are dry-run only until approved. It runs with delegated Group Policy Creator Owners rights, never Domain Admin by default.

**Killer example:** User says: *"Laptops in the Sales OU still allow USB storage even though I blocked it — figure out why and fix it, but don't touch the servers."* → AI runs `Get-GPResultantSetOfPolicy` against a real Sales laptop, finds that "Removable Storage Access → All Removable Storage classes: Deny all access" in GPO `Sec-USB-Block` lost to an **Enforced** link on the domain-level `Legacy-Field-Kit` GPO, shows the full precedence chain, then proposes either removing the Enforced flag or setting the value in a new Sales-OU-scoped GPO with a WMI filter for `Win32_ComputerSystem.PCSystemType=2` (mobile) — backs up both GPOs and applies only the option you pick.

**Integration path:** PowerShell GroupPolicy module (`New-GPO`, `Set-GPRegistryValue`, `Set-GPPrefRegistryValue`, `New-GPLink`, `Backup-GPO`, `Get-GPOReport -ReportType XML`, `Get-GPResultantSetOfPolicy`), GPMC COM automation (`GPMgmt.GPM`) and `Microsoft.GroupPolicy` .NET classes, ADMX/ADML parsing from the central store, the ActiveDirectory module for OU/group scoping, and LGPO.exe from the Security Compliance Toolkit for local policy.

**Demand 5/5 · Buildability 4/5**

### 5. VMware vSphere / vCenter Server (clusters, vDS networking, storage policies, permissions) `closed`

**Why it's powerful:** vCenter runs the majority of on-prem enterprise workloads: DRS load balancing, HA admission control, vMotion and Storage vMotion, distributed switches with port groups and VLAN/uplink teaming, VM storage policies, content libraries, snapshot and clone lifecycle, and a fine-grained role/permission model across the whole inventory tree. A single cluster enforces affinity and anti-affinity rules, reservations, shares and limits per resource pool — and everything visible in the HTML5 client is addressable programmatically.

**Why people bounce off it:** The vSphere Client is a deep tree of nested modals where the settings that matter hide three levels down: DRS automation level and migration threshold, HA admission control policy and host failover capacity, vDS port group failover order, VM storage policy compliance. Small IT teams routinely misconfigure vDS uplinks and lock themselves out of hosts, leave snapshots running for months until a datastore fills, and cannot answer "who has permission to power off this VM" without clicking every object in the tree. Nobody remembers that the thing they need lives under Edit Settings → VM Options → Advanced → Configuration Parameters.

**AI operator:** Connects to vCenter with skills for inventory Q&A, VM lifecycle, cluster tuning, vDS/port-group changes, snapshot hygiene, datastore capacity triage and RBAC audit, each mapped to concrete PowerCLI/REST calls. It resolves fuzzy names ("the SQL box in the Bangalore cluster") against real inventory before acting, and every mutating skill renders a plan first: objects touched, current value, new value, blast radius. Destructive or connectivity-affecting actions — snapshot delete/consolidate, power off, vDS uplink or VLAN changes, datastore unmount, role removal — are dry-run by default and require explicit confirmation, with an auto-generated rollback script and a hard guardrail against touching management uplinks. Ships as a self-hosted container beside vCenter using a scoped service account, plus a read-only mode for auditors.

**Killer example:** User says: *"Find every VM with a snapshot older than 30 days, tell me how much datastore space they're eating, and delete the ones on the Dev cluster only."* → AI runs `Get-VM | Get-Snapshot`, joins `SizeGB` against each datastore's `FreeSpaceGB`, prints a table of 47 snapshots consuming 3.2 TB, filters to the Dev cluster (12 VMs / 780 GB), shows the exact `Remove-Snapshot -Confirm:$false` calls it intends to issue, waits for approval, then consolidates and reports reclaimed space per datastore.

**Integration path:** vSphere Automation REST API (`/api/vcenter/*`, `/api/appliance/*`, session-token auth) plus the VMware PowerCLI PowerShell module (`Get-VM`, `Set-Cluster -DrsAutomationLevel`, `New-VDPortgroup`, `Get-VIPermission`) and pyvmomi / govmomi (`govc`) for anything the REST surface omits. Worth noting the Broadcom licensing upheaval has left a lot of anxious, under-resourced vSphere estates — good timing for a tool that makes two people cover the work of five.

**Demand 5/5 · Buildability 4/5**

### 6. eBay Seller Hub (listings, item specifics, business policies, Promoted Listings) `closed`

**Why it's powerful:** Seller Hub is a full merchandising stack: multi-variation inventory, category-specific item specifics/aspects that drive search recall, business policies for payment/shipping/returns, Promoted Listings Standard and Advanced with ad-rate and keyword bidding, Markdown Manager and volume-pricing promotions, Best Offer auto-accept/decline rules, and traffic and impression analytics down to the individual listing. Millions of active sellers run their entire livelihood through it.

**Why people bounce off it:** The specific wall is **required versus recommended item specifics per leaf category**. eBay ranks and sometimes outright blocks listings on aspects a seller has never heard of — "Focus Type", "Compatible Brand", "Unit Quantity" — and the bulk editor is a spreadsheet-shaped maze. Layer on business policies that must exist before a listing can reference them, Promoted Listings ad rates that sellers set by superstition, and File Exchange / Seller Hub Reports flat files with their own column dialect. Casual and mid-size sellers leave listings unoptimized for years because the fix is thirty clicks per SKU and there are four hundred SKUs.

**AI operator:** Pre-loaded with the Sell API object graph — inventory items and item groups (variations), offers and publish state, category-to-aspect lookup, business policy binding, promotion and ad-campaign creation, traffic diagnostics. The user talks about their store in plain language; the operator pulls the affected listings, diffs each against the required and recommended aspects for its leaf category, proposes concrete fills, republishes offers in a batch with a rollback list, then acts on the ads side. It defends the seller from itself: no bulk republish without a preview table, no ad-rate change beyond a stated ceiling, and an always-on "what changed and what did it do to impressions" report. A nightly scheduled agent re-audits new listings.

**Killer example:** User says: *"My 40 vintage camera listings get views but no sales — fix whatever eBay wants and push ads on the ones that actually convert."* → AI calls Taxonomy API `getItemAspectsForCategory` for category 15230, finds Brand, Series, Film Format and Focus Type missing on 31 SKUs, fills them from titles and descriptions with a confirm table, republishes the offers via the Inventory API, attaches the seller's "Free 3-day" fulfillment policy where it was unset, then creates a Promoted Listings Standard campaign at a 5.5% ad rate scoped to **only the 9 listings with sales in the last 90 days**, and sets Best Offer auto-decline below the floor price.

**Integration path:** eBay Sell APIs over OAuth 2.0 user tokens — Inventory API (`bulkCreateOrReplaceInventoryItem`, `createOffer`, `publishOffer`, `inventory_item_group`), Taxonomy API (`getItemAspectsForCategory`, `getCategorySuggestions`), Account API (fulfillment/payment/return policies), Marketing API (`ad_campaign`, `ad`, keyword bidding, `promotion` for markdowns), Analytics API (`getTrafficReport`), Feed API for bulk jobs. A full sandbox environment exists, which makes this genuinely testable before touching a live store.

**Demand 5/5 · Buildability 4/5**

### 7. TikTok Ads Manager (campaign/ad group structure, pixel & Events API, catalogs) `closed`

**Why it's powerful:** TikTok Ads Manager offers Smart+ automated campaigns alongside full manual control: three-tier campaign → ad group → ad structure, cost-cap and lowest-cost bidding, Value-Based Optimization, interest/behavior and lookalike/custom audiences, catalog-driven Video Shopping Ads, Spark Ads that boost organic creator posts, and pixel plus server-side Events API conversion tracking. It is now a primary acquisition channel for an enormous population of SMB and DTC advertisers with no media buyer.

**Why people bounce off it:** The wall is the three-tier structure plus optimization-event plumbing. Budget can live at campaign or ad group but not meaningfully at both; the ad group's optimization goal **must match an event the pixel actually fires**, and nothing tells you when it doesn't; Spark Ads require an authorization code from the creator that most advertisers never successfully obtain. Add Business Center identity and permission tangles, catalog feed schemas, and a reporting UI where `cost_per_conversion` hides behind metric pickers, and small advertisers either dump money into a Smart campaign they cannot diagnose or abandon the platform entirely.

**AI operator:** Pre-loaded with the Marketing API schema — objective types, bid strategies, targeting enums (`age_groups`, `location_ids`, `interest_category_ids`), placement rules, video upload and thumbnail selection, pixel/optimization-event pairing, and the integrated reporting metric vocabulary. The user states budget, audience and a CPA ceiling in plain words. The operator's first move is the one humans skip: **verify the requested optimization event is actually firing on the pixel** before building anything. Then it creates campaign/ad group/ads with matching settings, uploads creative, and runs as a standing agent that reads `/report/integrated/get/` on a schedule and pauses or rebids ad groups that breach the stated CPA. It explains every enum it chose in plain English and refuses to spend beyond a hard daily cap.

**Killer example:** User says: *"Spend $80/day pushing my $39 sneakers to 18-34 year olds in metro India, and kill anything over a $6 cost per purchase."* → AI creates a CONVERSIONS campaign with `budget_mode BUDGET_MODE_DAY`, an ad group targeting `location_ids` for the six metro DMAs with `age_groups AGE_18_24` and `AGE_25_34`, `optimization_goal CONVERT` bound to `pixel_id` + `optimization_event COMPLETE_PAYMENT` (after verifying that event fired 47 times in the last 7 days), `bid_type BID_TYPE_CUSTOM` with `conversion_bid_price 6`, uploads three product videos via `/file/video/ad/upload/`, launches, and schedules a 6-hourly job that pauses any ad group whose `cost_per_conversion` exceeds 6 over a statistically meaningful impression window.

**Integration path:** TikTok Business / Marketing API v1.3 REST — OAuth app auth, `/campaign/create/` and `/update/`, `/adgroup/create/`, `/ad/create/`, `/file/video/ad/upload/` and `/file/image/ad/upload/`, `/dmp/custom_audience/`, `/pixel/track/` (Events API) and `/pixel/list/`, `/catalog/` endpoints, `/report/integrated/get/`. Requires developer app approval and Business Center asset permissions — the main gating factor on buildability.

### 8. Fortinet FortiGate (FortiOS policies, NAT, security profiles, IPsec VPN) + FortiManager `closed`

**Why it's powerful:** FortiGate is the default edge firewall for a huge share of SMB and mid-market networks: unified policy with NGFW app control, IPS, web filtering, antivirus, deep SSL inspection, SD-WAN rules with performance SLAs, site-to-site and dial-up IPsec, SSL-VPN, virtual domains, and a full address/service object model. FortiManager layers on multi-device policy packages, ADOMs and staged installs. One box carries routing, NAT, VPN and full L7 inspection for an entire site.

**Why people bounce off it:** The GUI hides the things that actually decide behaviour. Policy evaluation is strictly top-down, so a broad rule at sequence 4 silently shadows the specific rule you just added at sequence 40 — and nothing warns you. VIP (destination NAT) versus IP pool (source NAT) is a classic trap: publishing a server requires a VIP object *plus* a policy whose destination is that VIP, not the private IP. Deep-inspection profiles break applications until the CA cert is deployed everywhere. IPsec tunnels fail on phase1/phase2 proposal, PFS or selector mismatches diagnosable only via `diagnose debug application ike -1` on the CLI. A team with no network specialist makes the change in the GUI, loses connectivity, and has no idea which of five layers did it.

**AI operator:** Talks to FortiOS over REST (or FortiManager's JSON-RPC for multi-site fleets) with skills for policy authoring, shadow/overlap analysis, object hygiene, publishing a server end-to-end, SSL-inspection exemptions, SD-WAN rule tuning, and a connectivity debugger that correlates policy lookup, route lookup and IKE negotiation into a single plain-English cause. Policy writes are staged as a full diff of the resulting config stanza plus the computed new rule order, and it refuses to place a rule where an earlier policy already shadows it without flagging the conflict. The safety mechanism that makes it deployable: back up the running config, write, then **hold the session open and auto-revert if the operator loses reachability** — a bad rule cannot lock the admin out. Runs on-prem with a REST API admin restricted by trusted host.

**Killer example:** User says: *"Publish the new intranet server 10.10.5.40 on port 443 to the internet from our WAN IP, only for our two branch office IPs, and log everything."* → AI creates a VIP object (`extip` = WAN1 address, `mappedip` = 10.10.5.40, port forwarding 443→443), address objects for both branch WAN IPs plus a group, then a firewall policy `srcintf=wan1 dstintf=port3 srcaddr=BranchGroup dstaddr=<the VIP> service=HTTPS action=accept logtraffic=all` — shows the exact `/api/v2/cmdb/firewall/vip` and `/firewall/policy` payloads and where in the rule order it will land, confirms that existing policy 7 "Allow-Any-Outbound" does not shadow it, and applies only on your go.

**Integration path:** FortiOS REST API v2 (`/api/v2/cmdb/firewall/policy|vip|address`, `/api/v2/monitor/router/lookup`, `/api/v2/monitor/vpn/ipsec`, API-token bearer auth with trusted hosts), SSH CLI for `diagnose`/`debug` commands, FortiManager JSON-RPC (`/jsonrpc`, policy packages plus install tasks), with the official `fortinet.fortios` Ansible collection and Terraform provider as ready-made schema references.

**Demand 5/5 · Buildability 4/5**

### 9. Microsoft Project (desktop + Project for the Web / Planner Premium) `closed`

**Why it's powerful:** Project carries a real critical-path engine: task dependencies with lead/lag, the work-versus-duration-versus-units equation, resource calendars and exceptions, resource leveling, cost and material resources, up to 11 saved baselines, and full earned-value analysis (BCWP, CPI, SPI, VAC). Project for the Web / Planner Premium exposes the same engine to every Microsoft 365 tenant, backed by Dataverse tables (`msdyn_project`, `msdyn_projecttask`, `msdyn_projecttaskdependency`), with portfolio rollup and Power BI reporting on top.

**Why people bounce off it:** The Task Type (Fixed Units / Fixed Duration / Fixed Work) × Effort Driven matrix silently rewrites durations the moment you add a resource — the single most famous "why did all my dates just move?" moment in project software. Task Information → Advanced → Constraint Type ("Must Start On", "As Late As Possible") quietly fights auto-scheduling, and the Manually Scheduled toggle produces plans that look fine but never reflow. The Resource Leveling dialog and Set Baseline's roll-up options are where most PMs stop and go back to a spreadsheet — which is how a €40M programme ends up tracked in Excel.

**AI operator:** An operator that owns the whole plan graph and, crucially, writes through the **real scheduling engine** so recalculation matches the UI exactly — Project Schedule API custom actions (`msdyn_PssCreateV1` / `UpdateV1` / `DeleteV1`) on the cloud side, the COM object model via a VSTO add-in on the desktop. Pre-loaded skills: build a WBS from a narrative brief, wire dependency chains with correct FS/SS/FF plus lag, pick the right Task Type for a stated intent, apply calendars and exceptions, assign named or generic resources with effort, run leveling, capture and compare baselines, produce an EVM readout. The headline skill is **date forensics**: every date change is explained in plain language — "this slipped 4 days because Task 12 is FS+2 behind the permit task and your resource calendar excludes Fridays."

**Killer example:** User says: *"The permit approval slipped two weeks — reflow the build schedule, keep the handover date, and tell me what breaks."* → AI updates the permit task's duration and start, lets the engine cascade the FS dependency chain, detects that the handover milestone now breaches its Must-Finish-On constraint, proposes two fixes (fast-track two SS-linked tasks with −3d lag, or add a second generic Electrician at 50% to shorten the 60h wiring task), applies the chosen one, and returns a diff: "critical path changed from Wiring→Inspection to Drywall→Inspection; 9 tasks moved; float on QA dropped to 1 day."

**Integration path:** Dataverse Web API (OData v4) over the Project tables plus the Project Schedule API unbound actions for engine-backed writes; Microsoft Graph planner endpoints for Planner-side tasks and buckets; Power Platform solution with a service principal; Project Online tenants additionally via CSOM / ProjectServer OData; desktop via the Project COM/VBA object model in a VSTO add-in, with MPXJ for server-side MPP parsing. The split surface (desktop COM vs cloud Dataverse) is what holds buildability to 3.

### 10. SAP Concur (Expense + Invoice — itemization, allocations, audit-rule/workflow admin) `closed`

**Why it's powerful:** Concur is the default corporate travel-and-expense system for a large share of the Global 2000: corporate card feeds, per diems by country, VAT reclaim, receipt OCR, multi-level workflow with delegates and cost-object approvers, audit rules that enforce policy at submit time, and Concur Invoice for PO-matched AP, with Concur Detect layering fraud analytics on top. It touches nearly every employee in the companies that run it.
