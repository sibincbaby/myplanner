### 1. Confluence Data Center → Cloud macro and page repair `closed`

**Why it's powerful:** Confluence Data Center holds years of company knowledge, and macros turn many of its pages into small applications. Atlassian's end-of-life page says DC and its apps go read-only on 2029-03-28, and new subscriptions end on 2028-03-30.

**Why people bounce off it:** User macros and removed macros don't migrate, and the HTML macro has no direct Cloud equivalent (community threads and a vendor's migration docs; no Atlassian migration page was read). Admins have to find every affected page and decide what to do with each macro, usually by hand.

**AI operator:** It inventories macro use across spaces and maps each macro to a native Cloud element where one fits. It rewrites those pages, which keeps version history, and lists the rest as exceptions.

**Killer example:** 'Replace our `status-box` user macro everywhere and tell me what can't be converted.' The AI finds the pages with `GET /wiki/rest/api/search` and the CQL query `macro = status-box`, then reads each one with `GET /wiki/api/v2/pages/{id}`. It translates the macro in the storage-format body and writes it back with `PUT /wiki/api/v2/pages/{id}`, using `version.number` + 1. Pages that depend on the HTML macro go on the exceptions list.

**Integration path:** The v2 page endpoints and their required fields are confirmed in Atlassian's OpenAPI spec, and the search endpoint is v1 only. The CQL reference confirms the `macro` field with `=` and `IN`. Whether CQL still finds a user or removed macro on a page after migration wasn't tested, and the find step depends on it, so test that first. Scanning page bodies is the fallback.

Overlap: CCMA is described as a migration and app-assessment tool, with no sign it rewrites pages. No Rovo migration agent was found. Marketplace titles such as Legacy Assets Macro Converter, Macro Studio and Migration Assistance Tool were seen but not read, so read them before building.

**Demand 4/5 · Buildability 4/5**

### 2. Azure Key Vault access-policy → RBAC migration and API-version audit `closed`

**Why it's powerful:** Key Vault holds the secrets, keys and certificates behind most Azure workloads. RBAC adds scopes from management group down to a single secret, which access policies can't do.

**Why people bounce off it:** Migrating means translating per-vault permission lists into roles, and Microsoft's mapping table says "custom role required" for some templates. Existing vaults aren't forced to move. What is forced is the API bump: control-plane versions before `2026-02-01` retire on 2027-02-27, with no extension. Vaults created on the new version default to RBAC. So, by inference, a template bumped to the new version that still relies on access policies needs `enableRbacAuthorization=false` set explicitly.

**AI operator:** It first audits infrastructure code for old `apiVersion` values and implicit access-policy defaults. It then migrates vault by vault: inventory, equivalent roles, switch-over, validation and rollback.

**Killer example:** 'Get our production vaults ready for the Key Vault change without breaking any apps.' The AI reads policies with `az keyvault show --query properties.accessPolicies` and turns on `AuditEvent` logs with `az monitor diagnostic-settings create` to check the new roles cover what apps really call. It creates roles with `az role assignment create`, runs `az keyvault update --enable-rbac-authorization true`, and tests access. It also lists every Bicep, ARM and Terraform file that pins an old version.

**Integration path:** The dates and the no-extension wording are confirmed on Microsoft's API-version migration page. The RBAC-default detail is confirmed only on the Azure China mirror of the docs. The CLI commands are from Microsoft's RBAC migration guide as read by the scout; a second pass didn't see them on the pages it read. `az role definition create` is from memory. Enabling RBAC invalidates existing access policies (search excerpt).

Overlap: one search found no Copilot in Azure or SRE Agent migrator, which is weak evidence. Microsoft has a role-coverage script, a community compare tool and an Advisor recommendation, and none of them migrates anything. Because the migration is optional, sell the safety of the audit, not a deadline. The seen 10-08 Azure RBAC card already proposes least-privilege roles from usage logs, so this card stays on translating data-plane access policies.

**Demand 3/5 · Buildability 5/5**

### 3. Salesforce SOAP `login()` retirement (cutover to External Client Apps) `closed`

**Why it's powerful:** Salesforce orgs often have years of integrations that log in with a username and password: middleware, ETL jobs, packaged apps and old scripts. Moving them to OAuth touches the whole integration estate.

**Why people bounce off it:** `login()` retires in Summer '27. Admins have to work out which integrations still use it and who owns each one, choose an OAuth flow, and set up new apps and integration users without breaking production. The seen release-management card doesn't cover this.

**AI operator:** It inventories likely callers, then creates the replacement External Client App and a least-privilege integration user. It writes a cutover runbook per integration and tracks owners. It can't change a caller's code or a vendor's product, so it tracks those rather than claiming to fix them.

**Killer example:** 'Which integrations break in Summer '27, and get us ready.' The AI queries `LoginHistory` grouped by user, `ApiType` and `ApiVersion` to build a candidate list. It deploys `ExternalClientApplication` and `ExtlClntAppOauthSettings` metadata with permission sets, and walks the admin through the release update's test run in a sandbox. It finishes with a tracker of owner, vendor status and runbook for each integration.

**Integration path:** The Summer '27 retirement comes from excerpts of Salesforce pages (both fetches returned 403). The 31.0–64.0 range and the test-run release update come from third parties such as Higher Logic, AutoRABIT and Sage. The metadata types come from a help.salesforce.com excerpt: remove `oauthLink` before deploying with global settings. `LoginHistory` is the weak point. A Trailhead answer says `ApiType` shows SOAP use rather than `login()` itself and points to Event Monitoring login events, so treat the list as candidates. Whether consumer secrets can be retrieved programmatically wasn't checked and may stay a manual step.

Overlap: no Setup with Agentforce or Agentforce for Admins capability for this job was found, but Salesforce's docs were blocked, so that's a weak negative. Check it first: Setup with Agentforce killed a Salesforce tech-debt idea on 10-28.

**Demand 4/5 · Buildability 3/5**

### 4. Cross-channel promo rollout (Shopify, eBay, Google Merchant Center, Klaviyo) `closed`

**Why it's powerful:** One sale touches discount engines, marketplace promotions, shopping feeds and email. Black Friday 2026 falls on November 27, and the need comes back every year.

**Why people bounce off it:** Each channel has its own promotion model and eligibility rules. eBay, for example, requires a stable listing period before a markdown: 14 days in the UK and 7 in Australia (search excerpt). Sellers rebuild the same sale in each tool and find mismatched prices, dates or exclusions after launch.

**AI operator:** The user describes one sale. The AI checks eligibility and margin floors, creates the promotions on each channel, and reports differences before go-live. It also ends every promotion cleanly afterward.

**Killer example:** '20% off outerwear from Friday to Monday, except new arrivals, and email the VIPs.' The AI calls `discountAutomaticBasicCreate` on Shopify and `createItemPriceMarkdownPromotion` on eBay. It calls `accounts.promotions.insert` on Google and `POST /api/campaigns` on Klaviyo, leaving the send for approval through `POST /api/campaign-send-jobs`. It reports the listings that aren't eligible, and on Tuesday it ends the Google promotion by re-inserting it with a past end time.

**Integration path:** Shopify, Klaviyo and Merchant API come from excerpts of their official docs. Google's insert replaces the whole resource, can't delete, and needs a promotions data source created first. eBay's create and update endpoints come from excerpts of its Marketing API docs and require a Store subscription. A forum thread reports a single-item percentage limit that may be out of date. Amazon is left out because no promotion write API was confirmed.

Overlap: Sidekick reportedly sets up Shopify discounts, which is fine because the cross-channel job is the product. The Google & YouTube Shopify app syncs Shopify discounts to Google, so that step may be redundant on Shopify stores. ChannelUnity and Koongo sync catalogs and prices, with no promotion push seen. One search isn't proof that no such tool exists. This year's Black Friday is too close to build for, so plan around the next peak.

**Demand 4/5 · Buildability 3/5**

### 5. EU marketplace GPSR listing compliance (eBay, Amazon, Shopify) `closed`

**Why it's powerful:** Each channel holds manufacturer, EU Responsible Person and safety data in its own way, and that data decides whether a seller can keep selling into the EU.

**Why people bounce off it:** Every channel has different fields, and sellers with hundreds of SKUs fill them in per listing or per feed. eBay's bulk tool still needs documents uploaded listing by listing (search excerpt). Packaging rules (PPWR) added EPR registration numbers per country from 2026-08-12 (excerpts, including eBay's Seller Centre).

**AI operator:** It reads one seller compliance sheet, finds gaps per SKU, channel and country, and writes the GPSR data to each channel after a dry-run diff. Anything it can't write goes on a manual task list.

**Killer example:** 'Get my 900 SKUs ready for Germany, France and Italy, using our Dublin rep.' The AI audits offers and listings. On eBay it updates each offer with `PUT /offer/{offerId}`, setting `regulatory.manufacturer`, `regulatory.responsiblePersons` and `regulatory.productSafety`. On Amazon it submits `gpsr_safety_attestation` and `dsa_responsible_party_address` through a `JSON_LISTINGS_FEED`. On Shopify it writes the same data to metafields. It then returns the SKUs still blocked by missing national EPR registrations for the seller to resolve.

**Integration path:** The eBay `Regulatory` schema and its presence on offers (not on inventory items) are confirmed in the official Inventory API spec. The Amazon attributes and feed come from an excerpt of the SP-API changelog. Shopify `metafieldsSet` is from memory. No API write path for EPR numbers was found on Amazon or eBay, so the card doesn't write them. Etsy's write path wasn't confirmed, so it's left out.

Overlap: single-channel tools exist, including eBay's bulk editor, dewabit and ShoppingFeed. eBay's Lizenzero partnership covers packaging compliance. ChannelEngine and ChannelDock appeared but weren't checked, and neither were Seller Assistant, Project Amelia or Sidekick. Sources conflict on how strictly marketplaces enforce PPWR.

**Demand 4/5 · Buildability 3/5**

### 6. Zendesk Sell forced exit to Pipedrive `closed`

**Why it's powerful:** Sell is a full sales CRM with pipelines, leads, smart lists, a dialer and email. Every customer has to leave it.

**Why people bounce off it:** Zendesk retires Sell on 2027-08-31, and deletion starts at subscription end or on that date, whichever comes first, so it can be earlier. Zendesk says activity history, appointments, emails, call logs and documents "cannot be exported". Admins have to find out what they'd lose, remap custom fields and pipelines, and work out what can't move.

**AI operator:** It inventories the account and proposes a reviewed field and pipeline mapping. It recreates the structure and records in Pipedrive and reports what didn't move. The edge is recovering through the API what the export leaves behind.

**Killer example:** 'Move us to Pipedrive before our Sell renewal and tell me what we lose.' The AI reads the Sell Core API, including `/v2/calls` with `recording_url` and documents with `download_url`, which expires after 90 minutes. It creates the structure with `POST /api/v2/pipelines`, `POST /api/v2/stages` and `POST /api/v2/dealFields`, then loads the records and files. It reconciles the counts and lists what it couldn't recover, plus a checklist for rebuilding automations by hand.

**Integration path:** The retirement terms are confirmed in Zendesk's article. The calls and documents resources are confirmed in the Sell API docs. Core pages for `appointments` and `emails` return 404, and whether Firehose can backfill them wasn't checked, so the card doesn't promise them. Pipedrive's POST endpoints are confirmed in its v2 spec. Its record and file-upload paths are from memory. Pipedrive automations have no write API (dropped 10-28).

Overlap: raw record copying is commoditized. Pipedrive's guide is CSV import, Import2 is free up to 1M records, and Faye, Sanka and ClonePartner all target this exit. No Pipedrive AI agent was found. The closest seen shape is the 10-19 Opsgenie exit, a different job in a different category.

**Demand 3/5 · Buildability 4/5**

### 7. SQL Server 2016 side-by-side instance upgrade `mixed`

**Why it's powerful:** SQL Server runs line-of-business systems in a very large number of companies. Moving an instance also means moving logins, Agent jobs, linked servers and other server-level objects, not just databases.

**Why people bounce off it:** Support ended on 2026-07-14, so owners either pay for Extended Security Updates or do an upgrade they often have no DBA for. The hard part is finding everything outside the databases and proving nothing was missed.

**AI operator:** It inventories the instance, compares ESU cost with upgrading, rehearses the migration on a new server, then runs the cutover with a parity report and a rollback plan.

**Killer example:** 'Move our ERP database server off 2016 this weekend, with a rollback plan.' The AI inventories server objects and rehearses on the new server. It runs `Start-DbaMigration -Source old -Destination new -BackupRestore -SharedPath \\backup\mig`, compares source and target, sets compatibility levels and reports what didn't move.

**Integration path:** `Start-DbaMigration` and those parameters are confirmed on its dbatools page, along with the objects it copies. The dates and ESU terms come from excerpts, including Microsoft's blog. The rehearsal and parity steps would be new code.

Overlap: dbatools is free and does the copying, so the product is the orchestration and the proof around it. SSMS Copilot agent mode was in preview in 22.7.0 (third-party write-up) and killed a SQL Agent jobs idea on 10-28. Whether it can move server objects between two instances wasn't seen, so test it first. The seen RDS/Aurora fleet card covers managed engines only.

**Demand 4/5 · Buildability 3/5**

### 8. Microsoft Access back-end upsizing to SQL Server (SSMA console + front-end repair) `closed`

**Why it's powerful:** Access still runs many departmental line-of-business apps, and SQL Server adds real concurrency, security and backups. Microsoft's free SSMA tool already handles conversion and data movement.

**Why people bounce off it:** The owner is usually not a DBA and can't act on SSMA's assessment reports. Moving the data is the easier half. Forms, queries and VBA that worked against local tables can then break or slow down. The seen 08-06 macro card also decompiles Access apps with `SaveAsText`, but it explains and repairs code and never moves the back end.

**AI operator:** It runs SSMA end to end, explains each conversion error in plain language and fixes what it can. It then repairs the Access front end on a copy and tests that the forms still work.

**Killer example:** 'Move the orders database to our SQL Server, keep the forms working, and tell me what broke.' The AI runs `load-access-database`, `generate-assessment-report`, `convert-schema`, `synchronize-target`, `migrate-data` and `link-tables`. It exports the front end with `SaveAsText`, adds `dbSeeChanges` to recordsets, re-imports it and lists what it couldn't fix.

**Integration path:** The SSMA console commands and `project-type` `sql-server-2025` are confirmed on Microsoft's console page, updated 2026-10-19. The front-end half is the unproven part: the console has no write path beyond `link-tables`, and `SaveAsText`, `LoadFromText` and the repair patterns are from memory. It needs Windows with Access installed. There's no forcing date, so this rests on reach.

Overlap: the SSMA v10.5 notes describe Copilot-assisted conversion for SAP ASE and Oracle, with only a login fix for Access. Later releases weren't checked, and no dedicated search for AI upsizing tools was run.

**Demand 4/5 · Buildability 3/5**

### 9. Power BI real-time streaming exit to Fabric Real-Time Intelligence `closed`

**Why it's powerful:** Push models give any script, device or flow a live Power BI feed with no pipeline to run. Fabric adds Eventstream routing, Eventhouse storage and Real-Time Dashboards.

**Why people bounce off it:** Existing real-time semantic models retire on 2027-10-31, covering Push, Streaming and PubNub models and the streaming data tile. Nothing converts a feed in place. Owners must find every producer, design a KQL table, re-point each sender and rebuild the tiles. The target needs Fabric capacity, reportedly F4 or above for custom-app sources (community posts only). This re-plumbs ingestion, which the 10-28 BI migration card doesn't do.

**AI operator:** It inventories real-time models and their producers, then provisions the Eventstream-to-Eventhouse path and the dashboard. It generates the new send configuration per producer and compares old and new feeds until the numbers match.

**Killer example:** 'Our factory wallboard runs on a Power BI live dataset. Move it before the cutoff and tell me what it needs.' The AI finds push models with `GET /groups/{id}/datasets` and checks the workspace capacity. It calls `POST /v1/workspaces/{workspaceId}/eventstreams` and `POST /v1/workspaces/{workspaceId}/kqlDashboards` and creates the Eventhouse. It gives the flow owner the replacement send step and reports row-count parity.

**Integration path:** Create Eventstream (definition parts as InlineBase64, long-running, service principals supported) and Create KQL Dashboard are confirmed on their REST pages. Create Eventhouse and KQL Database come from an older Fabric blog excerpt. The retirement comes from an excerpt of the Power BI blog. `GET /groups/{id}/datasets` and `addRowsAPIEnabled` are from memory. Writing a changed flow definition wasn't checked, so producers are re-pointed by their owners.

Overlap: no converter was seen. skills-for-fabric showed only a read-only Eventhouse query skill on third-party listings (repo not read), and microsoft-fabric-rti-mcp wasn't examined. skills-for-fabric killed a sibling Fabric job on 11-05, so check its repo first.

### 10. ERP vendor-master address remediation for Swift structured addresses `closed`

**Why it's powerful:** The ERP vendor master feeds every cross-border supplier payment, so one fixed record carries through to all later payment runs. The same layer works across many ERPs.

**Why people bounce off it:** Free-text vendor addresses have to become structured or hybrid across thousands of records, with country-specific parsing. ERP screens edit one vendor at a time, and CSV round-trips risk overwriting remit-to sites. The timing is unclear: the 2026-11-14 removal was extended with no new date, with a Swift update expected by December 2026 (IntellectEU, plus an excerpt of Swift's notice). Some Swift and bank pages still show November, so each bank's own cutoff matters.

**AI operator:** It audits vendors paid cross-border, proposes structured addresses with confidence scores, gets approval, then patches records and lists exceptions for a person.

**Killer example:** 'Fix every vendor we wired this year before our bank's cutoff.' The AI pulls vendors and payment history from Business Central, parses the addresses and shows a diff. After approval it calls `PATCH .../companies({id})/vendors({id})` with `If-Match`, setting `addressLine1`, `city`, `postalCode` and `country`. It returns the records it couldn't resolve, and it doesn't touch bank payment-file templates.

**Integration path:** The Business Central `PATCH` and `If-Match` are confirmed in its docs, but the address fields appear only in the response example, so writing them is inferred. NetSuite's `addressBook` looks writable from forum excerpts, and one thread reports a PATCH adding duplicate entries, so test line IDs carefully. SAP Business One, Xero and QuickBooks weren't checked. The payment-history read is from memory.

Overlap: Swift's free AI address-structuring model commoditizes the parsing, so the value is the safe ERP write. IntellectEU Catalyst is pitched at financial institutions, and ioNova ARS claims corporate use (press material). Oracle, SAP and Microsoft agents got no named search, so check those. This is a deadline-dependent idea with the deadline currently unset, which is why it ranks last.

**Demand 3/5 · Buildability 3/5**
