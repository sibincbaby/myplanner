### 1. AWS Lambda (Functions console) `closed`

**Why it's powerful:** Pay-per-100ms serverless compute with 20+ trigger types (API Gateway, S3, SQS, SNS, DynamoDB Streams, EventBridge, MSK/Kafka), shared layers, provisioned/reserved concurrency, container-image packaging, and per-function VPC/network config — it runs a huge share of production event-driven workloads with zero servers to manage.

**Why people bounce off it:** Getting a function to actually fire correctly means threading together an IAM execution role plus a separate resource-based (invoke) policy, trigger-specific event source mapping settings (batch size, starting position, filter criteria), VPC subnet/security-group placement that silently kills internet/NAT access, env vars, and memory/timeout/concurrency tuning — spread across five unrelated console tabs, with cryptic 'AccessDenied' errors as the only feedback when any piece is wrong.

**AI operator:** A chat-driven Lambda operator pre-loaded with Lambda + IAM + EventBridge/S3 API skills that translates a plain-language request into the full bundle — function config, trigger wiring, least-privilege IAM policy, DLQ/alarms — and validates it before applying.

**Killer example:** User: 'Whenever a file lands in the uploads S3 bucket, resize it into thumbnails, and text me if it fails 3 times in a row.' The operator provisions the function, creates an S3 ObjectCreated trigger scoped to the exact prefix/suffix (so it never loops on its own output), writes an IAM role limited to just the two buckets, wires an SQS dead-letter queue with maxReceiveCount=3, sets a CloudWatch alarm that fires an SNS text, and hands back the ARNs plus a one-line summary of exactly what it was given access to.

**Integration path:** AWS SDK/CLI (Lambda, IAM, EventBridge, CloudWatch APIs) plus SAM/CDK for repeatable deploys — fully scriptable, no UI scraping needed.

**Demand 5/5 · Buildability 4/5**

### 2. Google Looker Studio (formerly Google Data Studio) — distinct from Google Cloud's Looker/LookML product `closed`

**Why it's powerful:** Free, blends multiple live sources (Sheets, BigQuery, GA4, Google Ads, 800+ partner connectors) into interactive shareable reports — it's the default 'everyone in the company already has access' BI tool with zero licensing friction.

**Why people bounce off it:** Calculated fields require learning Looker Studio's own formula/REGEX syntax; 'Blending data' (joining up to 5 sources) silently breaks when join keys or aggregation grain mismatch, producing confidently wrong numbers with no error; and report-level vs page-level filter scoping trips up nearly every non-analyst into building reports that double-count or silently drop rows.

**AI operator:** An operator skill built on the Linking API + Community Connector SDK + Apps Script: the user describes the report/blend in plain language, the agent resolves field names and join keys across the named sources, writes the calculated-field formulas and blend config, and creates the report explicitly setting filter scope to match intent.

**Killer example:** User: 'Blend our GA4 sessions with the Shopify sales export in Sheets, show conversion rate by campaign, and don't let last month's traffic spike double-count.' The operator inspects both schemas, keys the blend on campaign+date (not session ID, which would silently drop rows), writes `CalculatedField SUM(sales)/SUM(sessions)` at the correct aggregation grain, and sets page-level rather than report-level date filters — the exact silent-miscount trap that catches almost every self-serve blend.

**Integration path:** Looker Studio Linking API for report creation/cloning, Community Connector SDK (Apps Script) for wiring new data sources, Apps Script for scheduling/refresh/permissions. No full CRUD REST API exists for editing arbitrary existing report components, so the operator leans on the Linking API plus templated report clones.

**Demand 5/5 · Buildability 3/5**

### 3. Microsoft Excel — Power Pivot & DAX Data Model (native PivotTables, table relationships, measures) `closed`

**Why it's powerful:** Turns a spreadsheet into a full in-memory BI engine (the xVelocity/Analysis Services engine embedded in every Excel install) capable of modeling millions of rows across multiple related tables, writing reusable DAX measures, and building interactive PivotTable/slicer dashboards — no separate database or Power BI license needed.

**Why people bounce off it:** Power Pivot lives behind an add-in that's off by default; building a working model requires star-schema relationship discipline nobody teaches Excel users; DAX's row-context vs. filter-context semantics (CALCULATE, ALL, FILTER, DATEADD) look like Excel formulas but behave completely differently, so a wrong measure returns a plausible-looking but silently incorrect number with no error message — so most users give up and fall back to giant, non-scaling VLOOKUP/SUMIFS sheets.

**AI operator:** Model Copilot — inspects the workbook's tables via the Excel COM object model, infers/creates relationships, writes and sanity-checks DAX measures, assembles the PivotTable + slicer report, and explains the filter-context logic in plain English so the user can actually trust the number.

**Killer example:** User: 'Show me revenue by region and month with month-over-month growth.' The operator builds a proper Date table, relates Sales→Region and Sales→Date so the model isn't a flat VLOOKUP sheet, writes `MoM Growth % = DIVIDE([Total Revenue]-CALCULATE([Total Revenue],DATEADD('Date'[Date],-1,MONTH)), CALCULATE([Total Revenue],DATEADD('Date'[Date],-1,MONTH)))`, drops a PivotTable with a Region×Month slicer onto a new sheet, and explains in plain English why CALCULATE shifts the filter context — so the user can trust the number instead of quietly propagating a wrong one.

**Integration path:** Windows-only COM automation (VBA / pywin32 / .NET) against Excel's `Model` object (ModelRelationships, ModelMeasures) and PivotTables collection; for heavier modeling, drive the same workbook's embedded Analysis Services engine via the Tabular Object Model (TOM/AMO) or an XMLA endpoint. No clean REST API exists, so the operator ships as a desktop companion (Office Add-in task pane + VBA/COM bridge), not a pure cloud service.

**Demand 4/5 · Buildability 3/5**

### 4. Redash (open-source self-hosted SQL BI/dashboard tool) `open-source`

**Why it's powerful:** Connects to 50+ data sources (warehouses, SQL/NoSQL DBs, SaaS APIs), lets any team build parameterized, scheduled, alertable dashboards without a heavyweight BI suite, and everything (queries, visualizations, dashboards, alerts, data sources) is a first-class API object.

**Why people bounce off it:** The entire tool is gated behind writing raw SQL — a marketer or support lead who wants 'signups vs churn by plan tier' has to beg an analyst or learn joins/window functions/date-truncation syntax. Dashboard parameters use a fiddly {{ param }} templating syntax, and building a multi-widget dashboard with the right refresh cadence and alert thresholds is a multi-step manual process almost no non-engineer ever learns.

**AI operator:** A chat-based 'Redash Copilot' skill that introspects the connected data source's schema via Redash's API, turns plain-language asks into parameterized SQL, and creates/updates queries, visualizations, dashboard widgets, refresh schedules, and Slack/email alert destinations entirely through Redash's REST API — no SQL ever shown to the requester unless they ask.

**Killer example:** User: 'Every Monday, show me signups vs churn by plan tier for the last 8 weeks, split by region, and Slack me if churn crosses 5%.' The operator introspects the warehouse schema via the API, drafts the join/window-function SQL the user would otherwise have to beg an analyst for, POSTs a new query object, attaches a combo bar+line visualization, assembles a dashboard with a region-filter widget, and sets both a Monday 7am refresh and a >5% churn Slack alert.

**Integration path:** Full documented REST API (api_key auth) for queries/visualizations/dashboards/alerts/data sources/users; self-hosted so the operator can also read the Postgres metadata DB directly for deep schema introspection; `manage.py` CLI for admin-level automation.

**Demand 3/5 · Buildability 4/5**

### 5. LinkedIn Campaign Manager (Ads) `closed`

**Why it's powerful:** The only major ad platform with true professional/firmographic targeting: stacked facets for job title, seniority, company size/industry, skills, and Matched Audiences (retargeting, ABM contact/company-list uploads), plus Conversation Ads, native Lead Gen Forms, and multi-touch conversion attribution via the Insight Tag.

**Why people bounce off it:** The objective-based structure (campaign group -> campaign -> ad) forces advertisers through forecasted-reach estimates, audience-expansion toggles, and bid-strategy choices that don't map to how B2B marketers actually think ('VPs of Engineering at 200-2000 person SaaS companies'). Self-serve advertisers routinely overspend or under-target because translating an ICP into the stacked-facet UI is genuinely unintuitive.

**AI operator:** 'Campaign Manager Copilot': the user states their Ideal Customer Profile and budget in plain English; the AI resolves it to LinkedIn's internal facet IDs via the Audience API, assembles the campaign group/campaign/ad structure, uploads exclusion lists, and picks a bid strategy matching the stated goal.

**Killer example:** User: 'Target VPs and Directors of Engineering at B2B SaaS companies with 200-2000 employees in the US, $150/day, optimize for lead-gen form fills, exclude our current customers.' The operator resolves the seniority/function/industry/company-size facets to LinkedIn's internal IDs via the Audience API, uploads the customer list as a Matched Audiences exclusion so spend never re-targets existing accounts, builds the campaign group with a Lead Gen Forms ad, and sets a target-cost bid strategy matched to 'optimize for form fills' — collapsing 20 minutes of stacked-facet guesswork into one described intent.

**Integration path:** LinkedIn Marketing Developer Platform: Campaign Management API, Matched Audiences API, Lead Gen Forms API, and the Conversions API for the Insight Tag — full REST coverage, though the deeper tiers require LinkedIn Marketing Partner approval, adding onboarding friction for a solo developer.

**Demand 4/5 · Buildability 3/5**

### 6. BMC Helix ITSM (formerly Remedy / Remedyforce lineage) `closed`

**Why it's powerful:** Runs IT operations for a huge base of banks, telecoms, and Fortune 500s; the AR System engine underneath lets admins model arbitrarily complex incident/problem/change/CMDB relationships, SLA escalation chains, and approval matrices that flex to any org structure. On-prem (classic Remedy/AR System) and cloud (Helix) both still widely deployed.

**Why people bounce off it:** Creating a properly-routed ticket requires knowing which of a dozen category/operational-category/product-categorization fields drives SLA and assignment-group routing, which CI to attach for correct impact scoring, and which of several look-alike forms is correct for the situation. Admins configure this logic using a proprietary scripting paradigm most junior staff never learn, so end users just avoid self-service and email the help desk instead.

**AI operator:** A conversational front-end pre-loaded with the org's categorization taxonomy, CMDB schema, and SLA/assignment-group mapping rules that lets any employee or L1 agent describe an issue in plain language and have the AI pick correct categorization, CI linkage, priority/urgency, and routing, then create/update the record through the API.

**Killer example:** User: 'The payment gateway is down and it's hitting APAC customers — open a P1, route it to network, 1-hour SLA, and page whoever's on-call.' The operator resolves the correct categorization tier from the org's own taxonomy (skipping the dozen look-alike fields that actually drive routing), attaches the Payment-Gateway CI for correct impact scoring, sets Impact=1/Urgency=1, applies the matching SLA template, routes to the correct assignment group, and fires the on-call paging escalation — one API transaction instead of the 20-field form most employees avoid by emailing the help desk.

**Integration path:** Helix ITSM REST API (formerly AR System REST API) for full CRUD on incidents/changes/CMDB CIs/SLAs; AREA/Java or Web Services API as a fallback for older on-prem AR System instances; admin-side rule harvesting via Developer Studio export (Filters/Active Links as XML) to seed the AI's knowledge of routing logic.

**Demand 4/5 · Buildability 3/5**

### 7. Microsoft PowerPoint — Slide Master hierarchy, Animation Pane timeline & Morph transitions `closed`

**Why it's powerful:** Lets one person build a fully-branded template system (masters → layouts → slides) plus cinematic, cue-triggered motion graphics (motion paths, trigger animations, object-matched Morph) that rival Keynote or After Effects for a boardroom deck — all inside the app everyone already has and already knows how to open.

**Why people bounce off it:** The Slide Master/Layout/Slide inheritance chain is invisible in the UI, so edits land on the wrong layer and silently don't propagate; the Animation Pane's timeline has no plain-English view, so sequencing several effects is pure trial-and-error; Morph only works if two slides contain shapes with identical internal names, a constraint the UI never surfaces — so the feature randomly 'doesn't work,' and most people try it once and never touch it again.

**AI operator:** Deck Motion Copilot — takes a plain-language description of the desired branding/motion and edits the Slide Master hierarchy, programs the Animation Pane timeline via the VBA `Shape.AnimationSettings`/`TimeLine` object model, and duplicates+renames shapes correctly so Morph 'just works' on the first try.

**Killer example:** User: 'Make the title fly in from the left after a half-second delay, then fade in each bullet one at a time timed to my voiceover cues at 3s, 7s, and 11s.' The operator writes the VBA timeline directly — an EntryEffect on the title with a 0.5s delay, then three separate After-Previous fade effects on the bullets with explicit trigger times matching the cues — sequencing that would otherwise take an hour of Animation Pane trial-and-error.

**Integration path:** VBA (desktop, Windows/Mac) is the only surface with full Animation-timeline and Morph shape-matching control today — Office Scripts/Office.js can't touch animations yet. python-pptx (open-source, headless) can pre-build Slide Master layouts and matched shape names for the Morph handoff without PowerPoint installed, then a thin, auto-injected VBA macro finishes the live animation wiring.

**Demand 4/5 · Buildability 3/5**

### 8. Clip Studio Paint (Celsys — the industry-standard illustration/comic/manga and increasingly webtoon production tool) `closed`

**Why it's powerful:** Vector inking with line stabilization, 3D pose/prop assist, perspective and symmetry rulers, a frame-by-frame animation timeline, and print-grade multi-page comic management put an entire studio's worth of comic-production tooling in one app used by the vast majority of professional manga/webtoon artists.

**Why people bounce off it:** The features that actually save professional time — print-ready page setup (trim, bleed, gutter, page numbering), dual-format export (print PDF vs. vertical webtoon strip), and Auto Action macros — are buried in dense, jargon-heavy nested palettes; most users never touch them and either botch print submissions or spend hours manually re-laying-out pages for a second platform.

**AI operator:** 'CSP Studio Assistant' — uses Clip Studio's Plug-in SDK/Command API and its JS-based scripting console to configure multi-page comic documents, apply saved coloring/sub-tool presets, and drive dual-profile batch export, all from a plain-language request.

**Killer example:** User says: 'Set up a 24-page B5 print manga with 3mm bleed and gutter page numbers, then also export a vertical webtoon version at 800px width.' AI does: creates the multi-page canvas with the correct trim/bleed/page-number settings via the Command API, then runs a second export pass reflowing the same art to an 800px vertical strip.

**Integration path:** Clip Studio's official Plug-in SDK (C/C++ Command & Filter API) for document/layer/canvas manipulation, its JavaScript scripting console for lighter automation, and the Auto Action macro format (.csma) which can be generated programmatically and replayed — no REST API, so distribution is as an installed native plugin.

**Demand 4/5 · Buildability 3/5**

### 9. Akaunting (open-source double-entry accounting, Laravel-based, self-hostable) `open-source`

**Why it's powerful:** Full double-entry ledger, multi-company/multi-currency, bank reconciliation, recurring invoices/bills, budgeting, tax rules, and a module marketplace (payroll, CRM, POS) that turns it into a mini-ERP — all free and self-hostable, unlike QBO/Xero.

**Why people bounce off it:** The power comes from deeply nested configuration (Sales > Invoices > Categories > Taxes > Currencies, plus Chart-of-Accounts and journal concepts) that non-accountant small-business owners find alien; recording anything beyond a plain invoice requires understanding double-entry, so most users just stop after basic invoicing and never touch reconciliation, budgets, or reporting.

**AI operator:** An 'AI bookkeeper' skill pack pre-loaded with Akaunting's account/category/tax taxonomy that translates plain-English bookkeeping requests into correct journal entries, invoices, and reconciliations, then shows the user the resulting ledger lines for one-tap confirmation.

**Killer example:** User says: 'I paid $450 to Acme for office supplies from my business checking, split half to Office Expenses and half to Software, and attach this receipt photo.' AI creates a split transaction across the two expense accounts, tags the correct bank account, uploads the receipt as an attachment, and confirms the entry balances.

**Integration path:** REST API with OAuth2 personal access tokens (documented, first-class) for invoices/bills/transactions/reports; since it's self-hosted and open-source, can also fall back to Laravel Artisan/DB access for anything the API doesn't expose yet, and webhooks for reactive automation.

**Demand 3/5 · Buildability 4/5**

### 10. AWS CodePipeline + CodeBuild + CodeDeploy (native CI/CD suite) `closed`

**Why it's powerful:** A fully managed, deeply AWS-integrated CI/CD stack: CodePipeline orchestrates multi-stage, multi-account releases; CodeBuild runs arbitrary containerized build steps at scale; CodeDeploy performs blue/green and linear/canary rollouts to EC2, ECS, or Lambda with automatic rollback on CloudWatch alarms — no build infrastructure to run yourself, and it wires natively into every other AWS service.

**Why people bounce off it:** Each stage lives in a different console with its own dialect (pipeline JSON, buildspec.yml, appspec.yml) and its own IAM service role; cross-account artifact promotion, deployment groups, and alarm-based rollback require manually stitching together S3 artifact buckets, KMS keys, and per-stage IAM trust policies — so most teams give up and default to one dumb build-and-deploy stage instead of using canaries or automated rollback.

**AI operator:** An AI operator that understands the whole three-service surface and generates the pipeline JSON, buildspec, appspec, deployment group, and cross-service IAM roles from a described release process, then can adjust rollout strategy on request.

**Killer example:** User says: 'Deploy main to staging automatically, but production needs manual approval and should roll out 10% of traffic at a time, rolling back automatically if error rate spikes.' AI builds the CodePipeline stages, configures a CodeDeploy linear/canary deployment config with a CloudWatch-alarm rollback trigger, and inserts the manual approval action before the prod stage.

**Integration path:** AWS SDK/CLI (codepipeline, codebuild, codedeploy APIs) — every resource is API/CLI/CloudFormation-managed and fully scriptable.

**Demand 3/5 · Buildability 4/5**
