### 1. Discord server admin (roles, channel permission overwrites, AutoMod, Onboarding) `closed`

**Why it's powerful:** One of the most granular permission and moderation engines in mainstream software, running hundreds of millions of servers, including company, open-source, education and creator communities.

**Why people bounce off it:** Permissions are bit flags combined across role order, category sync and per-channel allow/deny overwrites. "Why can this role see #mods?" can't be answered from the UI. AutoMod keyword/regex rules with exemptions, and Onboarding questions that map to roles and channels, are easy to get wrong. Server owners end up with either everything open or a tangle nobody dares touch.

**AI operator:** A bot that holds the server's full effective-permission graph. It turns plain-English policy into role, overwrite, AutoMod and Onboarding changes, shows a diff first, and answers "who can do X where" questions.

**Killer example:** An owner says: 'Make a Contributors role that can post in #dev and #help but only read #announcements, hide #staff from everyone except Mods, and block invite links except from Mods.' The AI creates the role, writes overwrites on 4 channels, re-syncs the category, adds a keyword AutoMod rule with a Mods exemption, and prints an effective-permission matrix.

**Integration path:** Discord REST API: `POST/PATCH /guilds/{guild.id}/roles`, `PUT /channels/{channel.id}/permissions/{overwrite.id}`, `POST/PATCH /guilds/{guild.id}/auto-moderation/rules`, `PUT /guilds/{guild.id}/onboarding` (docs.discord.com/developers/resources/guild, /auto-moderation). Standard bot token with Manage Roles/Channels/Guild. Discord ships no first-party admin AI.

**Demand 4/5 · Buildability 5/5**

### 2. Google Sheets + Excel sheet protection and team setup (protected ranges, Allow Edit Ranges, filter views, named ranges) `closed`

**Why it's powerful:** Per-range editor lists and per-person filter views let one shared workbook safely serve dozens of contributors without copies.

**Why people bounce off it:** Nobody understands how locked cells, sheet protection, edit ranges and editor lists interact. Shared trackers end up either fully locked or fully open and then corrupted. In Sheets, every protected range and filter view is built one at a time through nested menus. Earlier cards (pivots/QUERY, conditional formatting) used these API calls only in passing; nobody pitched the "who can touch what" layer.

**AI operator:** The user describes who should edit what. The AI reads the sheet layout, plans protected and editable ranges with editors and warnings, creates a named filter view per person, and shows a "who can touch what" matrix before applying.

**Killer example:** 'Each regional manager can edit only their own region's rows in the Forecast tab, finance edits everything, and everyone gets their own filtered view.' The AI creates 6 protected ranges with editor lists, a filter view per manager and a named range for each region block.

**Integration path:** Sheets API `spreadsheets.batchUpdate` with `AddProtectedRangeRequest`/`UpdateProtectedRangeRequest`, `AddFilterViewRequest`, `AddNamedRangeRequest`. Excel: `worksheet.protection.allowEditRanges.add()` (ExcelApiOnline 1.1, so Excel for the web only; desktop needs a file-format write). Open risk: not yet checked whether Gemini in Sheets or Copilot in Excel already set up protection.

**Demand 4/5 · Buildability 4/5**

### 3. Salesforce Approval Processes (multi-step discount and deal-desk approvals) `closed`

**Why it's powerful:** Multi-step approvals with entry criteria, dynamic approvers, parallel or unanimous steps, record locking and field updates on approve, reject or recall. They run in essentially every Sales Cloud org.

**Why people bounce off it:** A long linear wizard (entry criteria → submitters → steps → approver assignment → approve, reject and recall actions) that never shows the whole process at once. Step skip logic and the ordering of active processes are error-prone. The 2026-07-31 Sales Cloud card covered Flow, validation rules and permission sets, not approvals.

**AI operator:** A deal-desk policy compiler. It turns a written discount policy into ApprovalProcess metadata, renders the step tree in plain English, deploys to a sandbox, runs a test opportunity through it, then promotes.

**Killer example:** A RevOps lead says: 'Deals over $100k or discount above 15% need manager then Finance; above 30% also needs the CRO; lock the record while pending.' The AI writes a 3-step ApprovalProcess with entry criteria, approver roles and record locking, deploys it to a sandbox and submits a test deal.

**Integration path:** Metadata API `ApprovalProcess` type (`.approvalProcess`, API 28.0+), deployed with `sf project deploy start`; `Approval.ProcessSubmitRequest` via Apex/REST for test submissions. Caveat: the Metadata API doesn't store the order of active processes, so ordering is a manual final step.

**Demand 4/5 · Buildability 4/5**

### 4. Confluence Cloud access layer: space permissions + inherited page restrictions `closed`

**Why it's powerful:** Confluence is the default enterprise wiki, and its access is layered: a space-permission grid plus view/edit restrictions that inherit down the page tree.

**Why people bounce off it:** Space permissions are a wide grid of groups × operations, and page restrictions inherit silently and are never shown in one place. Admins can't answer "is anything in the HR space visible to contractors?" or fix leaks in bulk. The 2026-07-31 Confluence card was about authoring pages and macros; it only mentioned permissions as a pain.

**AI operator:** An access auditor and fixer. It crawls space permissions and page restrictions, answers access questions in plain English, and applies grant, revoke and restrict changes in bulk with a before/after exposure report.

**Killer example:** 'Make sure contractors can't see anything under Compensation in the HR space, but HR-leads can edit it.' The AI finds the page subtree, puts view/edit restrictions on its root for HR-leads, checks the contractors group's space-level grants, removes them where needed, and lists any remaining exposure.

**Integration path:** Confluence REST v1, checked in Atlassian's official OpenAPI spec this run (no `deprecated` flags): `PUT/POST /wiki/rest/api/content/{id}/restriction`, `PUT /wiki/rest/api/content/{id}/restriction/byOperation/{operationKey}/byGroupId/{groupId}`, `POST /wiki/rest/api/space/{spaceKey}/permission`, `DELETE /wiki/rest/api/space/{spaceKey}/permission/{id}`. v2 space permissions are read-only, so watch for a v1 sunset. Rovo does not manage permissions.

**Demand 4/5 · Buildability 4/5**

### 5. NetSuite Advanced PDF/HTML Templates (FreeMarker invoice, statement and packing-slip layouts) `closed`

**Why it's powerful:** Every transaction document can be fully branded and driven by conditions, including multi-currency, multi-subsidiary and custom-field logic.

**Why people bounce off it:** It means hand-writing BFO-flavoured HTML plus FreeMarker in a source editor with no live preview. Most admins pay a consultant to move a logo or add a conditional remit-to block. The 2026-07-31 NetSuite card was about SuiteQL and saved searches, not documents.

**AI operator:** It reads the record schema and the existing template, generates or patches the FreeMarker, renders a preview against a real transaction, then deploys the template as an SDF object and binds it to the transaction form.

**Killer example:** An AR lead says: 'On EU invoices, show the VAT number under the customer address and add a bank-details footer only when the currency is EUR.' The AI edits the invoice template, adds `#if record.currency == "EUR"` blocks, deploys via SuiteCloud CLI and sets it as the invoice form's print template.

**Integration path:** SuiteCloud Development Framework custom object `advancedpdftemplate` (`custtmpl_` prefix plus a companion `.template.xml`), deployed with SuiteCloud CLI and referenced from the transaction form's `printTemplate`. Caveat: a community report says STATEMENT-type templates may not be supported in SDF.

**Demand 4/5 · Buildability 4/5**

### 6. Power BI service operations: refresh schedules, gateway binding, deployment pipelines `closed`

**Why it's powerful:** The Power BI service is how millions of reports actually go live and stay fresh, with Dev/Test/Prod promotion built in.

**Why people bounce off it:** A model that refreshes on schedule needs data-source mapping, gateway binding, per-model schedules within licence limits, and promotion between pipeline stages. That work is spread over separate settings pages and fails silently. The 2026-08-03 Power BI card was about DAX and modelling, not getting the model live.

**AI operator:** A "make it live" operator. It discovers a dataset's sources, binds them to the right gateway, sets the schedule, promotes the dataset through the deployment pipeline, and explains refresh failures from history.

**Killer example:** 'Refresh the Sales model at 6am and 1pm IST on weekdays, use the Kochi gateway, then push it from Test to Prod.' The AI calls Bind To Gateway In Group, then Update Refresh Schedule In Group, then a pipeline deploy from the Test stage, and reports the next three scheduled runs.

**Integration path:** Power BI REST: `Datasets - Bind To Gateway In Group`, `Datasets - Update Refresh Schedule In Group`, `Datasets - Get Refresh History In Group`; deployment pipelines `POST /pipelines/{id}/deployAll`. Service principal or delegated auth. Microsoft's modelling MCP targets model authoring, not service operations; a Copilot overlap check is still open.

**Demand 4/5 · Buildability 4/5**

### 7. Google Ads conversion value rules and rule sets (value-based bidding) `closed`

**Why it's powerful:** Advertisers adjust conversion value by audience, location and device so that tROAS bidding values high-value customers correctly. It is one of the biggest levers on Smart Bidding results.

**Why people bounce off it:** You have to understand ADD/MULTIPLY/SET semantics, the limit of 2 conditions per rule, account vs campaign rule sets and the constraints on SET rules. Most SMBs never touch it. Earlier Google Ads cards (2026-08-03 campaign builder, 2026-10-18 PMax) didn't cover value rules, and Ads Advisor's announced scope doesn't include them.

**AI operator:** Turns margin and customer-value logic into value rules and rule sets, attaches them to the right campaigns, and simulates the effect on reported conversion value before applying.

**Killer example:** 'Customers in California and Texas are worth 1.5x, mobile is worth 20% less, and add $40 for our customer-list audience.' The AI creates 3 rules (MULTIPLY 1.5 geo, MULTIPLY 0.8 device, ADD 40 audience), bundles them in a rule set on the tROAS campaigns and previews the change on last month's conversions.

**Integration path:** Google Ads API `ConversionValueRuleService.MutateConversionValueRules` and `ConversionValueRuleSetService.MutateConversionValueRuleSets` (developers.google.com/google-ads/api/docs/conversions/conversion-value-rules). Needs a developer token.

**Demand 3/5 · Buildability 4/5**

### 8. Xero Fixed Assets register (asset types, depreciation settings, opening balances) `closed`

**Why it's powerful:** Xero has a built-in depreciation register (straight-line or diminishing value, book vs tax) that posts depreciation journals automatically.

**Why people bounce off it:** Small businesses keep assets in spreadsheets because asset types, effective life, averaging methods and opening accumulated depreciation are confusing. Accountants re-key everything at every onboarding. Earlier Xero cards covered bank reconciliation and payroll.

**AI operator:** It ingests an asset spreadsheet or the year's capital purchase bills, proposes asset types and depreciation settings, explains the choices, then creates and registers each asset.

**Killer example:** An accountant uploads a client's asset XLSX and says: 'Laptops at 3 years straight-line, vehicles at 25% diminishing value, carry over the accumulated depreciation to 30 June.' The AI creates two asset types, then 48 registered assets with purchase price, date, depreciation start and opening balances.

**Integration path:** Xero Assets API, confirmed in Xero's official OpenAPI spec (`XeroAPI/Xero-OpenAPI/xero_assets.yaml`) this run: `createAssetType` (`POST /AssetTypes`), `createAsset` (`POST /Assets`). Settings are GET-only and there's no endpoint to run depreciation, so the monthly run stays a one-click UI step.

**Demand 3/5 · Buildability 4/5**

### 9. Dynamics 365 / Dataverse Word and Excel document templates (quotes, orders, invoices) `closed`

**Why it's powerful:** One-click "Word Templates" generate branded quote and proposal documents from any record, including related line items.

**Why people bounce off it:** Authoring means downloading a blank template, enabling Word's Developer tab and dragging XML-mapped content controls from the XML Mapping Pane. Line-item tables need nested repeating-section controls. Sales ops staff give up and hire consultants. The 2026-07-31 Dynamics 365 Sales card covered security roles and flows.

**AI operator:** It generates the `.docx` with content controls bound to the record's XML schema, including repeating quote-detail rows, from a plain description or an old PDF quote, then uploads it as an active template.

**Killer example:** 'Make our quote template look like this old PDF: logo, customer block, a line-item table with a discount column, totals and T&Cs.' The AI produces the mapped `.docx` and posts it as a document template for the quote table.

**Integration path:** Dataverse Web API `POST /documenttemplates` with `content` (bytes), `documenttype` (Word/Excel), `associatedentitytypecode`, `languagecode`. The `.docx` content controls are built with Open XML SDK. The binding XML schema comes from the table's metadata.

**Demand 4/5 · Buildability 3/5**

### 10. Microsoft Outlook search folders + master category list (retrieval views and category cleanup) `closed`

**Why it's powerful:** Search folders are live saved views across many folders, and together with a clean category list they let a busy inbox be sliced by client, project or urgency without moving any mail.

**Why people bounce off it:** This is about finding mail that's already there, not about rules for incoming mail (the seen Outlook card). Search folder criteria sit in a desktop-only dialog, and most category lists decay into duplicates ("Red Category", "Client-ACME", "ACME"). So nobody uses either feature.

**AI operator:** Audits existing categories, merges them into a consistent set and re-tags messages, then turns "views I want" into search folders built from OData filters.

**Killer example:** 'Give me a view of every unread email from anyone at acme.com or tagged ACME in the last 30 days, across all folders, and clean up my three duplicate ACME categories.' The AI merges the categories into "Client: ACME", re-tags 340 messages and creates a search folder over all nested folders.

**Integration path:** Microsoft Graph `POST /me/mailFolders/{id}/childFolders` with `@odata.type: microsoft.graph.mailSearchFolder`, `filterQuery`, `sourceFolderIds`, `includeNestedFolders`; `POST /me/outlook/masterCategories`; `PATCH /me/messages/{id}` for categories. Delegated `Mail.ReadWrite` + `MailboxSettings.ReadWrite`.

**Demand 3/5 · Buildability 5/5**

### 11. Magento Open Source / Adobe Commerce cart price rules and coupon generation `partial OSS`

**Why it's powerful:** The rule engine can express almost any promotion, including BOGO, tiered discounts, subselection conditions, attribute combinations, customer groups and bulk unique coupons.

**Why people bounce off it:** Users build nested condition and action trees by hand ("If ALL of these conditions are TRUE… subselection… product attribute…"). There are separate condition and action trees, and priority and "discard subsequent rules" interact unpredictably, so promotions stack by accident. The 2026-07-15 Magento card covered product and variant setup.

**AI operator:** Compiles plain-English promotions into condition and action trees, flags overlaps with existing active rules, and generates coupon batches.

**Killer example:** 'Buy 2 Outerwear items, get the cheapest 50% off, wholesale group excluded, 500 unique codes prefixed WINTER.' The AI posts the rule with the right condition and action trees, generates 500 codes and warns that rule #14 also matches Outerwear and will stack.

**Integration path:** Magento REST `POST /V1/salesRules`, `PUT /V1/salesRules/{ruleId}` (body carries the condition and action-condition trees), `POST /V1/coupons/generate` (adobe-commerce.redoc.ly). Admin integration token.

**Demand 3/5 · Buildability 4/5**

### 12. Tableau Cloud delivery layer: extract refresh tasks, subscriptions, data-driven alerts `closed`

**Why it's powerful:** It is how Tableau content reaches people on a schedule and when thresholds are crossed.

**Why people bounce off it:** Refresh tasks, subscriptions and alerts are set up one view and one user at a time, alerts only work on single-axis views, and nobody can see "who gets what, when" across a site. Earlier Tableau cards covered LOD calcs (2026-07-31) and permissions (2026-10-18).

**AI operator:** Plain language in, bulk delivery config out, plus an audit and cleanup pass that finds stale subscriptions and failing refreshes.

**Killer example:** 'Email the Regional Sales dashboard to every APAC manager on Monday 8am, refresh its extract at 6am first, and alert Priya when daily refunds go above 50k.' The AI creates the refresh task, a subscription per manager, and a data-driven alert on the refunds view.

**Integration path:** Tableau REST (Cloud, API 3.20+): `POST /api/{v}/sites/{site}/tasks/extractRefreshes`, Create Subscription, `POST /sites/{site}/dataAlerts`. Tableau Agent and Pulse cover authoring and metrics, not delivery admin.

**Demand 3/5 · Buildability 4/5**
