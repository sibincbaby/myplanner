### 1. Windows Server file server (NTFS + share permissions, access-based enumeration, DFS Namespaces, FSRM quotas and file screens) `closed`

**Why it's powerful:** Most on-prem and hybrid businesses still keep department data on Windows file shares. The stack covers NTFS inheritance, share ACLs, access-based enumeration (users only see folders they can open), DFS namespaces that hide server names, and FSRM quotas and file screens that can block ransomware extensions.

**Why people bounce off it:** Effective access is two ACL layers (share and NTFS) combined with broken inheritance, nested AD groups and explicit denies. Nobody can answer "who can open Payroll, and why?" without an afternoon in the Advanced Security dialog. FSRM and DFS live in separate MMC snap-ins most admins never open. The 2026-10-24 AD hygiene card cleaned up accounts and privileged groups, not file-level access.

**AI operator:** It crawls the share and NTFS ACLs and expands nested groups to answer effective-access questions in plain language. It proposes least-privilege fixes as a diff showing who gains and who loses access, then applies them over PowerShell remoting after approval. It also sets quota and file-screen policies.

**Killer example:** 'Why can the interns open the Payroll folder? Fix it, and stop ransomware file types landing on any share.' The AI finds the cause: Payroll inherits `Domain Users: Modify` from `D:\Shares`, and Interns is nested inside AllStaff. It proposes breaking inheritance on Payroll and granting only `GG_Payroll_M`, and lists the 41 users who would lose access. After approval it applies the change and turns on access-based enumeration with `Set-SmbShare -FolderEnumerationMode AccessBased`. It then creates a ransomware file group with `New-FsrmFileGroup` and an active `New-FsrmFileScreen` on every share root.

**Integration path:** PowerShell over WinRM, using:
- The SmbShare module: `Get-SmbShareAccess`, `Grant-SmbShareAccess`, `Set-SmbShare`.
- `Get-Acl` / `Set-Acl` or the community NTFSSecurity module.
- The DFSN module: `New-DfsnFolder`, `New-DfsnFolderTarget`.
- The FileServerResourceManager module: `New-FsrmQuota`, `New-FsrmFileGroup`, `New-FsrmFileScreen`.

The Active Directory module expands nested groups. No Windows Admin Center AI assistant was found. This card is distinct from the SharePoint permissions and Dropbox Business cards.

**Demand 5/5 · Buildability 4/5**

### 2. Windows Server DNS + DHCP (AD-integrated zones, scopes, reservations, failover, scavenging) `closed`

**Why it's powerful:** It is the default name resolution and IP allocation in nearly every Active Directory domain. It supports conditional forwarders, DNS policies, DHCP failover pairs, option sets and reservations, all built into Windows Server licences.

**Why people bounce off it:** Scavenging and aging, stale records, exhausted scopes, failover partner state and reverse zones are spread across two MMC consoles. Small-shop admins avoid touching them because one wrong change takes the office offline. Existing seen cards (Route 53, Cloudflare, MikroTik) cover public, cloud or router DNS, not AD DNS and DHCP.

**AI operator:** A health auditor and change operator. It reports stale records, scopes over 90% used, failover mismatches and missing reverse zones in plain language. It turns network plans into scoped changes, always shown as a `-WhatIf` dry run first.

**Killer example:** 'Add VLAN 40 for the warehouse: 10.40.0.0/24, gateway .1, our two DNS servers, 8-hour leases, reserve .10 for the label printer, and make sure it fails over to DHCP02.' The AI runs `Add-DhcpServerv4Scope` with an 8-hour lease and `Set-DhcpServerv4OptionValue -Router 10.40.0.1 -DnsServer ...`, then `Add-DhcpServerv4Reservation` for the printer's MAC. It adds the scope to the existing DHCP01–DHCP02 relationship with `Add-DhcpServerv4FailoverScope`, and creates the reverse zone with `Add-DnsServerPrimaryZone -NetworkId 10.40.0.0/24 -ReplicationScope Forest`. It also warns that scavenging is off and 1,900 stale A records are older than 90 days.

**Integration path:** The PowerShell DnsServer module (`Add-DnsServerPrimaryZone`, `Add-DnsServerResourceRecord*`, `Add-DnsServerConditionalForwarderZone`, `Set-DnsServerScavenging`) and the DhcpServer module (`Add-DhcpServerv4Scope`, `Add-DhcpServerv4Reservation`, `Add-DhcpServerv4Failover`, `Add-DhcpServerv4FailoverScope`, `Set-DhcpServerv4OptionValue`). Both run over WinRM, and every cmdlet supports `-WhatIf`.

**Demand 4/5 · Buildability 5/5**

### 3. Microsoft Word Table of Authorities and Index (TA / TOA / XE / INDEX fields) `closed`

**Why it's powerful:** From marked fields, Word builds a page-accurate Table of Authorities grouped by category (cases, statutes, rules) and a back-of-book index with subentries. Courts require a TOA in almost every appellate brief.

**Why people bounce off it:** Every citation has to be marked by hand through Mark Citation (Alt+Shift+I), with a long form and a short form per authority, and every "Id." and "supra" has to be marked too. One missed or mistyped TA field quietly drops or splits an entry. Paralegals spend hours on it or buy TOA add-ins. TOA isn't supported in Word for the web or Mac, so the work stays on desktop Windows.

**AI operator:** It reads the brief and finds every citation, including short forms and "Id.". It normalises each authority to one long form and inserts the TA fields with the right category. It then inserts and refreshes the TOA and reports what it marked and what it couldn't resolve. The same engine marks XE entries for manuals and books.

**Killer example:** 'Build the TOA for this brief: cases, statutes and rules in separate sections, and use passim for anything cited five or more times.' The AI inserts a TA field with the full and short citation at each occurrence. It adds one TOA field per category with the passim switch after the table of contents, updates all fields, and lists three citations it could not match to a long form.

**Integration path:** Office.js `insertField` on a Word range, using the `ta`, `toa` and `xe` members of `Word.FieldType`; the enum members exist, but the field-code strings need testing in real Word. Headless fallback: raw `w:instrText` field codes via python-docx or the Open XML SDK. Overlap caveat: one third-party blog claims Copilot in Word can mark TOA citations, but no Microsoft documentation confirms it, and Microsoft's TOA help still describes manual marking only. Re-check before building. Paid incumbents (TOA add-ins from Thomson Reuters and others) prove demand.

**Demand 4/5 · Buildability 4/5**

### 4. Google Merchant Center local inventory ads and free local listings (omnichannel settings, store inventory) `closed`

**Why it's powerful:** It puts in-store stock on Google Shopping, Search and Maps with "in stock nearby" and "pick up today" badges. It is the main Google channel for any retailer with physical stores.

**Why people bounce off it:** Setup is a long chain that fails without explanation:
- Link Business Profile and match store codes.
- Choose a storefront type (Google-hosted, or merchant-hosted basic or full).
- Get the About page verified.
- Request inventory verification, which can sit in "action required" for weeks.

Scripts built on the Content API for Shopping broke when that API was retired in favour of the Merchant API. The 2026-08-06 Merchant Center card was a feed doctor for online product disapprovals, not local inventory.

**AI operator:** It reads omnichannel settings per country and explains in plain words what is blocking each one. It creates or fixes the settings and pushes per-store inventory, price and pickup data.

**Killer example:** 'Turn on local inventory ads in the US and Canada for our 40 stores, with pickup today.' The AI checks the Business Profile link and finds 3 store codes that don't match. It creates omnichannel settings for US and CA with a Google-hosted storefront and pickup enabled, then bulk-inserts local inventory per store code. It reports that Canada is still waiting on About-page verification and says exactly what the page is missing.

**Integration path:** Merchant API `accounts.omnichannelSettings` create/get/list (confirmed in Google's "Manage omnichannel settings" guide) plus the local inventory sub-API for per-store availability and price. A Google Ads link is needed for the ads side. No Merchant Center agent for LIA setup was found. Google's Merchant Center AI features target product data, and an earlier run killed Merchant Center promotions for first-party AI.

**Demand 4/5 · Buildability 4/5**

### 5. Behringer X32 / Midas M32 / Behringer WING digital mixing consoles `closed`

**Why it's powerful:** One box gives 32+ channels, 16 mix buses, DCAs, matrices, full input/output routing, gates, compressors, onboard effects and scene recall. These consoles sit in a huge number of churches, schools, bars and small venues.

**Why people bounce off it:** Volunteers run them. Routing blocks, monitor sends, DCA and mute-group assignments and dynamics settings are buried in pages of menus. One bad Sunday breaks the scene and nobody knows how to rebuild it. The seen ATEM, OBS and vMix cards cover video, not live sound.

**AI operator:** It rebuilds, fixes and documents the console from plain language, either live over the network or by writing an offline scene file. It describes every change back before saving and keeps a readable "what this scene does" sheet for the next volunteer.

**Killer example:** 'Four vocal mics on 1–4, the pastor's lavalier on 9 with a gate, monitor mixes for the band on buses 1–4, all vocals on DCA 1, save it as Sunday AM.' The AI names the channels with `/ch/01/config/name`, sets the bus sends through `/ch/xx/mix/yy/on` and `/level`, and turns on `/ch/09/gate/on` with a sensible threshold. It sets the DCA bitmask under `/ch/xx/grp/dca`, checks the input routing, then saves the scene and prints a one-page cheat sheet.

**Integration path:** X32/M32 use OSC over UDP port 10023, with the community-documented address space, `/xremote` subscriptions and plain-text `.scn` scene files. WING publishes a "WING Remote Protocols" document covering OSC, a binary protocol and its native API. WING allows only one subscribed OSC client, so the binary protocol is the practical path. Yamaha TF/DM3 consoles would be the second connector (protocol unverified). No first-party AI was found; the vendor apps are remote controls only.

**Demand 4/5 · Buildability 4/5**

### 6. Microsoft Hyper-V + Failover Clustering (the VMware-exodus landing spot) `closed`

**Why it's powerful:** The hypervisor ships free with Windows Server licences. It handles live migration, Hyper-V Replica, VLAN-tagged virtual switches, checkpoints and cluster shared volumes. It is where many SMBs are landing after Broadcom's VMware pricing changes.

**Why people bounce off it:** Hyper-V Manager, Failover Cluster Manager and Windows Admin Center each show part of the picture. Virtual switch and VLAN design, Replica, CSV placement, anti-affinity and cluster validation are expert-only, and ex-VMware admins don't have the mental model. The seen vSphere, Proxmox and Veeam cards don't cover it.

**AI operator:** It speaks vSphere and does Hyper-V. It translates "DRS-style spread" or "vMotion this VM" into Hyper-V and cluster operations, builds VMs from a sentence, and sets up replication and DR runbooks. It runs `Test-Cluster` before risky changes.

**Killer example:** 'Create three Server 2025 VMs for the ERP app, 8 vCPU and 32 GB each, on VLAN 120, spread across the cluster, and replicate them to the DR host every 5 minutes.' The AI runs `New-VM -Generation 2` on a cluster shared volume, then `Set-VMProcessor -Count 8` and `Set-VMNetworkAdapterVlan -Access -VlanId 120`. It makes each VM highly available with `Add-ClusterVirtualMachineRole` and sets a shared `AntiAffinityClassNames` value so the VMs never share a node. It then runs `Enable-VMReplication -ReplicationFrequencySec 300` to DR01 and starts the initial replication.

**Integration path:** The PowerShell Hyper-V module (`New-VM`, `Set-VM*`, `Checkpoint-VM`, `Move-VM`, `Enable-VMReplication`) and the FailoverClusters module (`Test-Cluster`, `Add-ClusterVirtualMachineRole`, `Get-ClusterSharedVolume`), or WMI `root\virtualization\v2`. Windows Admin Center's virtualization mode is a dashboard, not an agent, and no AI assistant was found. Scope this to non-Azure-Local Hyper-V, since Azure Local falls under Copilot in Azure.

**Demand 4/5 · Buildability 4/5**

### 7. Mexico SAT CFDI 4.0 payment complements (REP / Pagos 2.0), Carta Porte and SAT reconciliation `closed`

**Why it's powerful:** Every Mexican taxpayer stamps every invoice, payment and shipment as a CFDI through an authorised certification provider (PAC). SAT's bulk-download service returns every CFDI issued or received, which gives a complete tax ledger.

**Why people bounce off it:** Instalment and later payments on PPD invoices need a separate type-P payment complement. It must point at each original UUID with the instalment number, previous balance, amount paid and remaining balance. Carta Porte needs dozens of catalog codes. Most SMBs pay a contador and still miss payment complements, which risks fines and blocks their customers' deductions.

**AI operator:** It holds the SAT catalogs and the payment-complement and Carta Porte rules. It turns a plain-language payment or shipment into correctly linked CFDIs. On a schedule it bulk-downloads SAT records and flags PPD invoices with no complement, cancelled supplier CFDIs and mismatches.

**Killer example:** 'Acme paid 40% of invoices A-1021 and A-1033 by transfer on Oct 20.' The AI looks up both UUIDs and computes the previous balance, amount paid, remaining balance and instalment number for each. It stamps one type-P CFDI with Pagos 2.0 through the PAC and sends the XML and PDF to Acme. It adds that 3 other PPD invoices from September still have no payment complement.

**Integration path:** A PAC REST API, e.g. Facturama, which documents payment-complement and Carta Porte endpoints. The SAT Descarga Masiva SOAP service handles bulk reconciliation using e.firma auth; the open-source `satcfdi` Python library wraps it, but the operation names weren't checked against SAT docs. No first-party agent was found: SAT ships none, and PAC "AI" is Q&A chat only. Not covered by the seen DATEV card or the other country e-invoicing runners-up.

**Demand 4/5 · Buildability 3/5**

### 8. Tableau / Qlik Sense → Power BI migration operator (writes PBIP / TMDL / PBIR) `closed`

**Why it's powerful:** Power BI has the biggest BI install base. Its project format (PBIP, with TMDL model files and PBIR report files) is documented text, so a whole estate can be rebuilt as files instead of clicked together.

**Why people bounce off it:** Leaving Tableau or Qlik means translating calculated fields, LOD expressions and set analysis into DAX, re-modelling relationships and rebuilding every visual. Each estate takes months of consultant time, and nobody can prove the numbers match afterwards.

**AI operator:** It reads the source workbook or app and builds a dependency graph. It writes an equivalent PBIP project with a parity score for every calculation and a list of what it couldn't convert, then publishes to a test workspace. It runs the same queries in both tools and reports any differences.

**Killer example:** 'Move the Sales Ops Tableau project to Power BI and keep the regional LOD margins.' The AI downloads the workbooks and converts the fixed Region LOD for SUM of Margin into `CALCULATE(SUM(Sales[Margin]), ALLEXCEPT(Sales, Sales[Region]))`. It writes the TMDL tables and relationships and the PBIR pages, then deploys to a Migration-UAT workspace. It reports that 2 of 61 calculations differ by more than 0.5% and explains why.

**Integration path:** Read side: Tableau REST workbook content download (.twb XML) and the Qlik Engine API (`GetScript`, object layouts). Write side: PBIP/TMDL/PBIR files, then the Fabric REST items API with an item definition, or Git sync. Not every visual type is covered by the PBIR schema yet. No Microsoft migration agent was found, but third-party converters (DataFactZ, ZS, BIChart, Pulse Convert) make this a crowded market. The edge has to be the parity check and the conversational fix-up loop, not conversion alone.

**Demand 4/5 · Buildability 3/5**

### 9. Salesforce Service Console Macros + Quick Text `closed`

**Why it's powerful:** One click runs a multi-step script on a case: open the email tab, insert a template, set Status and Reason, post to Chatter and submit, with IF/ELSE branches. Quick Text adds reusable snippets with merge fields.

**Why people bounce off it:** The macro builder is fragile:
- Instructions must run in exact order.
- Targets are cryptic strings such as `QuickAction.Case.SendEmail`.
- Conditional steps need extra configuration.
- Irreversible macros need a separate permission.

A support org's library of 200+ macros goes stale, and there is no bulk editing. The Trailhead material describes manual creation only.

**AI operator:** It writes and fixes macros from plain-language support playbooks. It audits the library for broken, duplicate and unused macros, and generates matching Quick Text.

**Killer example:** 'Make a macro for refund-approved cases: email the customer the refund template, set Status to Closed and Reason to Refund Issued, and if Priority is High also post to the Escalations Chatter group.' The AI creates a Macro with ordered MacroInstruction rows: select the case tab, run the send-email quick action with the template, apply the field updates, add an IF/ENDIF branch on Priority, then submit. It creates a Quick Text record for the refund wording and flags 14 existing macros that reference a deleted email template.

**Integration path:** The `Macro` and `MacroInstruction` sObjects support create and update through the REST API (confirmed in the object reference; conditional instructions need API 46.0+). `QuickText` is a standard sObject. No Agentforce macro-authoring feature was found. Third-party macro generators exist (Clientell, an Automation Anywhere bot); none found is first-party.

**Demand 3/5 · Buildability 4/5**

### 10. Salesforce Translation Workbench (multi-language orgs) `closed`

**Why it's powerful:** It translates every label in a global org: fields, picklist values, record types, layouts, quick actions, flow screens, validation messages and custom labels. Reps in every country can then work in their own language.

**Why people bounce off it:** You either work through components one at a time in a per-language grid, or round-trip bilingual .stf files. After every release, untranslated and stale labels pile up silently. Real-time translation (Einstein Conversation Translate) is a separate product and doesn't touch metadata labels.

**AI operator:** It diffs the org's metadata against translation coverage for each language. It drafts translations using a company glossary, shows the gaps and drafts for review, and deploys them.

**Killer example:** 'Add Brazilian Portuguese for Opportunity and Quote, and translate everything we added this quarter.' The AI retrieves the object translations and the pt_BR translation set and finds 84 untranslated field labels, picklist values and help texts. It drafts them with the glossary, so "Opportunity" stays "Oportunidade" everywhere. After approval it deploys the object, standard value set (StageName) and custom label translations.

**Integration path:** Salesforce Metadata API types `Translations`, `CustomObjectTranslation`, `GlobalValueSetTranslation`, `StandardValueSetTranslation` and `ExternalString`, deployed with `sf project deploy`. The second connector would be Dataverse `ExportTranslation` / `ImportTranslation` (unverified). No Setup with Agentforce capability for translations was found.

### 11. ServiceNow Import Sets + Transform Maps (spreadsheet data onboarding) `closed`

**Why it's powerful:** Any spreadsheet or feed can be staged and transformed into any table (users, locations, assets, CIs). Coalesce keys, reference resolution and transform scripts make it the standard way data gets into an instance.

**Why people bounce off it:** You have to understand the data source, staging table, field maps, coalesce keys and choice actions together. A wrong coalesce or a "create" choice action silently produces duplicate records or junk references, which someone then cleans up by hand. The seen ServiceNow ITSM and Service Catalog cards don't cover data loading.

**AI operator:** You upload a file and say what it is. The AI builds the data source and transform map, picks coalesce keys, and test-loads a sample. It reports how many rows would be inserted, updated or skipped, and why, before the real run.

**Killer example:** 'Load this laptop list into Hardware assets, match on serial number, and don't create new models.' The AI creates a data source and a transform map targeting `alm_hardware`, with field maps that coalesce on serial number and ignore unknown models. It test-loads 50 rows and reports that 6 rows reference models that don't exist and 2 serials appear twice. After the user fixes those, it runs the full import and summarises the results from the import set rows.

**Integration path:** The Table API on `sys_data_source`, `sys_transform_map`, `sys_transform_entry` and `sys_transform_script`, plus the Import Set API (`POST /api/now/import/{staging_table}`). Triggering a transform on an attachment-based load through REST still needs testing. Overlap caveat: Now Assist's Transform Mapping Assist generates transform lines but is documented only inside Technology Management Tools, and Workflow Studio's Data Mapper automap is for flows, not import sets.

**Demand 3/5 · Buildability 4/5**

### 12. Office pre-send metadata scrub (Word / Excel / PowerPoint hidden data, Document Inspector at folder scale) `closed`

**Why it's powerful:** Document Inspector can strip comments, tracked changes, author and company properties, hidden sheets, speaker notes and off-slide content. It's the last line of defence before a file leaves the firm.

**Why people bounce off it:** Inspector works on one file at a time and only if someone remembers to run it. It produces no audit trail and doesn't explain what it found. Users don't know a "very hidden" sheet or a pivot cache still holding deleted rows exists. Legal and finance teams buy metadata-cleaning add-ins to fill the gap. Purview labels classify files but don't scrub them, and the 2026-09-24 tracked-changes card handled redlines, not leakage.

**AI operator:** Before a folder goes out, it explains in plain language what each file is leaking. It applies a scrub policy, writes clean copies and keeps a log of what it removed. It stops on anything that needs a human decision, such as pending tracked changes.

**Killer example:** 'Clean this deal folder before it goes to opposing counsel. Strip comments, authors, hidden sheets and speaker notes, and tell me if any tracked changes are still pending.' The AI walks 37 files and stops on 2 Word files with unresolved revisions. It reports that the 'Margin_Calc' sheet is very hidden and that one pivot cache still holds a deleted customer list. It removes the author and last-modified-by properties, the very-hidden sheets, the stale pivot caches and the notes slides. It writes CLEAN_ copies and a one-page removal report.

**Integration path:** Direct OOXML edits with the Open XML SDK, python-docx, openpyxl or python-pptx; editing file parts is fully supported, so the write path exists. Microsoft Graph `driveItem` content GET/PUT reaches OneDrive and SharePoint folders. Office.js document properties cover the in-app path for the open file. No first-party chat agent for this was found.

**Demand 3/5 · Buildability 4/5**
