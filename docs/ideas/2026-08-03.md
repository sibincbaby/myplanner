### 1. Microsoft Power BI `closed`

**Why it's powerful:** Enterprise-grade semantic modeling with DAX + Power Query (M) over a fast in-memory VertiPaq engine, feeding interactive reports used by tens of millions of business users — free Desktop plus paid Pro/Premium/Fabric.

**Why people bounce off it:** Writing correct DAX measures and Power Query M transforms — `CALCULATE`/filter-context, time-intelligence, relationship cardinality, and blending/unpivoting messy source tables — defeats ordinary business analysts who can drag fields onto a canvas but can't express the actual logic. "Drag-drop is easy, DAX is a brick wall" is the single most common Power BI complaint.

**AI operator:** An AI modeler that reads your semantic-model schema and writes/validates the DAX measures, calculated columns, M queries, and relationships for you, then pushes them into the model via the XMLA read-write endpoint — you describe the metric in business English.

**Killer example:** A user types "show YoY revenue growth % by region, excluding returns, and only for customers active in the last 90 days." The AI authors the DAX measure with the right `CALCULATE` + `DATEADD` + filter logic — the exact combination that costs analysts an afternoon of forum-searching — writes it into the model via XMLA/TOM, and returns a working card visual.

**Integration path:** Power BI REST API (datasets/reports/refresh), the XMLA read-write endpoint via Tabular Object Model (TOM)/TMSL/TMDL for model edits, the `executeQueries` DAX endpoint, and Fabric Semantic Link (sempy) for programmatic model access.

**Demand 5/5 · Buildability 4/5**

### 2. GitHub (Org / Actions / Security Admin) `closed`

**Why it's powerful:** The default home for code, CI/CD (Actions), and org governance — branch-protection rulesets, environments/secrets, CODEOWNERS, and GitHub Advanced Security (secret + code scanning) across every repo in an org.

**Why people bounce off it:** Rolling consistent policy across dozens or hundreds of repos means hand-editing YAML workflows and clicking through per-repo settings screens; ordinary maintainers can't hand-write a correct Actions workflow or reason about an org-wide ruleset / GHAS rollout, so governance drifts repo by repo.

**AI operator:** An NL repo-governance + pipeline operator that applies rulesets and security settings fleet-wide and scaffolds/repairs Actions workflows from plain-language intent, always reporting exactly which repos it changed and which it skipped.

**Killer example:** A user says "require two approvals and green CI on the default branch of every repo in the org, and turn on secret scanning with push protection." The AI applies an org-level ruleset, enables GHAS everywhere it's licensed, and hands back the exact list of repos it changed plus any it skipped — a job that otherwise means opening hundreds of Settings tabs.

**Integration path:** GitHub REST API + GraphQL API, the `gh` CLI, and Octokit SDKs — a mature, first-class automation surface.

**Demand 5/5 · Buildability 5/5**

### 3. Google Analytics 4 (GA4) `closed`

**Why it's powerful:** Event-based cross-platform analytics with funnels, path/exploration reports, custom dimensions, audiences, and free BigQuery export — effectively enterprise-grade product analytics that nearly every website already has installed.

**Why people bounce off it:** The post-Universal-Analytics UI is notoriously hostile; ordinary users can't build Explorations, define custom events/dimensions, or answer a simple business question without getting lost in nested menus — the "GA4 is unusable" complaint is near-universal among marketers and SMB owners.

**AI operator:** A natural-language analyst that translates business questions into Data API report queries and provisions config (custom dimensions, key events, audiences) via the Admin API — no menu spelunking, no report builder.

**Killer example:** A user asks "which blog posts drove the most newsletter signups last month, and where did those readers come from?" The AI runs the right Data API query, returns a ranked table with source/medium, and offers to create a reusable audience of "readers who signed up" via the Admin API — a question most owners can't even phrase inside the GA4 UI.

**Integration path:** GA4 Data API (reporting) + GA4 Admin API (configuration), both clean REST surfaces.

**Demand 5/5 · Buildability 4/5**

### 4. Zendesk Support `closed`

**Why it's powerful:** The category-leading help desk — triggers, automations, macros, SLA policies, business rules, skills-based routing, and custom ticket fields/forms make it an extremely configurable ticketing engine used by huge support orgs.

**Why people bounce off it:** Admins drown in the interdependent web of triggers vs. automations vs. macros vs. SLA policies; ordinary users can't reason about firing order and conditions, so routing and SLAs get misconfigured or abandoned — and no one can explain why a given ticket routed the way it did.

**AI operator:** An NL admin that provisions and audits the whole rules layer — creating triggers, macros, SLA targets, and routing from plain-language intent, dry-running against open tickets, and explaining routing decisions after the fact.

**Killer example:** A user says "urgent tickets from enterprise customers should hit a 1-hour first-reply SLA and go to the Tier-2 group." The AI creates the org-tag logic, the SLA policy, and the routing trigger, then shows a dry-run of which currently-open tickets it would have caught — replacing a fragile afternoon in the rules editor.

**Integration path:** Zendesk REST API (Ticketing/Support API — triggers, automations, macros, SLA-policy endpoints), the ZAF Apps framework for an in-product panel, and webhooks.

**Demand 5/5 · Buildability 5/5**

### 5. ClickUp `closed`

**Why it's powerful:** Genuinely an "everything app" for work — tasks, docs, whiteboards, goals, sprints, time-tracking, dashboards, and a deep automation engine in one product, with per-view custom fields and 15+ view types.

**Why people bounce off it:** The sheer surface area — Spaces vs. Folders vs. Lists hierarchy, ClickApps toggles, custom statuses, per-view filtering/grouping, and Automation trigger/condition/action builders — means new users can't get a clean workspace stood up or even find where a setting lives.

**AI operator:** An NL admin that owns workspace structure and automations: describe the team and the desired process in words and the AI provisions the hierarchy, statuses, custom fields, and views, wires the automation rules, and then keeps running task ops conversationally.

**Killer example:** A user says "set up a marketing team space where every 'Blog Post' task auto-moves to Editing when the draft field is filled and assigns Priya." The AI creates the Space, the Blog Post task type with a Draft custom field, the custom statuses, and the automation rule wiring trigger → condition → assignee — the exact multi-screen setup that stalls most trials.

**Integration path:** ClickUp REST API v2 (tasks, lists, spaces, custom fields, views, webhooks) plus the Automations endpoints.

**Demand 5/5 · Buildability 4/5**

### 6. Airtable `closed`

**Why it's powerful:** A relational database wearing a friendly grid — linked records, lookups/rollups across tables, a rich formula language, Interfaces/dashboards, and a scripting + automation layer that lets teams build real internal apps without engineers.

**Why people bounce off it:** Non-technical users hit a wall at data modeling — when to split into linked tables, how to write lookup/rollup/formula fields, and how to wire multi-step automations — so their bases collapse into flat, duplicated spreadsheet messes that miss the whole point.

**AI operator:** A schema-and-automation operator: describe the app you want and the AI designs normalized tables with the right link/lookup/rollup/formula fields, builds Interface pages, and sets up the automations.

**Killer example:** A user says "I run a podcast — track episodes, guests, and sponsors, and auto-create a publish checklist when an episode is marked Recorded." The AI creates linked Episodes/Guests/Sponsors tables with rollups, then an automation that generates checklist records on the status change — the relational modeling most users never get right on their own.

**Integration path:** Airtable Web API (REST) for records plus the Metadata/Schema API for creating tables and fields; the Scripting extension (JavaScript) and automation actions for logic.

**Demand 5/5 · Buildability 4/5**

### 7. Webflow `closed`

**Why it's powerful:** A visual development tool that outputs production-grade responsive HTML/CSS with a real CMS, interactions, and hosting — professional web design and publishing without hand-coding.

**Why people bounce off it:** It surfaces the entire CSS box model (flexbox, grid, positioning, breakpoints, class inheritance) through a GUI, so non-developers still slam into the CSS learning cliff and can't build a clean responsive layout — the tool is only "no-code" if you already understand CSS.

**AI operator:** An NL web-design operator that builds the page on-canvas — creates the DOM structure, applies a coherent class/variable style system, makes it responsive, and wires CMS content — through Webflow's sanctioned Designer API rather than screen-scraping.

**Killer example:** A user says "build a 5-section SaaS landing page — hero, logo bar, features grid, pricing table, footer — in my brand colors, fully responsive, and publish to staging." The AI creates the element tree, applies styles/variables, builds responsive flex/grid layouts, binds a CMS testimonials section, and publishes — the responsive-layout archaeology that defeats most Webflow beginners.

**Integration path:** Webflow Designer Extensions API (JS SDK: create elements, set styles, components on-canvas) plus the Data API v2 (REST: CMS collections, pages, publish).

**Demand 5/5 · Buildability 4/5**

### 8. Pipedrive `closed`

**Why it's powerful:** A deep sales-pipeline engine with custom pipelines, multi-condition Workflow Automations, deal-rotting rules, products, and a Campaigns/LeadBooster add-on stack — it handles the full lead-to-close motion with granular field-level control.

**Why people bounce off it:** Ordinary reps can't build the multi-step Workflow Automations, custom fields, and pipeline-stage rules; the automation builder and filter/condition logic is where most trials stall and where paid features quietly go unused.

**AI operator:** An NL rep-copilot preloaded with skills to create/move deals, set custom fields, build filtered views, and stand up automations by describing the outcome instead of clicking through the builder.

**Killer example:** A user says "when a deal sits in Negotiation more than 5 days, assign it to me and email the contact a nudge." The AI creates the custom filter, the Workflow Automation trigger, the assignment action, and the email template — live, without the rep ever opening a builder screen.

**Integration path:** Pipedrive REST API v1/v2 (deals, persons, filters, webhooks, and the Automations endpoints) plus the Apps Marketplace / OAuth surface.

**Demand 4/5 · Buildability 5/5**

### 9. Google Ads `closed`

**Why it's powerful:** Reaches billions across Search, Display, YouTube, and Shopping with deep controls over bidding, audiences, keyword match types, and conversion optimization — it can profitably drive leads/sales for almost any business if configured well.

**Why people bounce off it:** Ordinary SMB owners can't build a sane campaign structure (ad groups, match types, negative keywords, bid strategy, geo/schedule) and end up torching budget on irrelevant search terms with no idea why — the gap between "boost my post" simplicity and real campaign hygiene is enormous.

**AI operator:** A conversational Ads manager pre-loaded with account-structure, keyword-research, and bid-strategy skills that builds/edits campaigns and continuously prunes waste from plain-language goals and a budget.

**Killer example:** A user says "I run a bakery in Austin, get me phone calls from nearby people for under $10 each, $30/day." The AI builds a call-focused local Search campaign with geo radius, tCPA bidding, call assets, tight keyword themes, and a negative-keyword list, then reports cost-per-call weekly — the setup that otherwise burns a month of budget learning.

**Integration path:** Google Ads API (gRPC/REST, official client libraries; requires an approved developer token — the main buildability gate).

**Demand 5/5 · Buildability 3/5**

### 10. Snowflake `closed`

**Why it's powerful:** An elastic separated-compute/storage warehouse that scales to petabytes with SQL, plus tasks, streams, RBAC, resource monitors, and Snowpark — the default warehouse for a huge slice of modern data teams.

**Why people bounce off it:** Non-expert users drown in the Snowsight console's operational surface — sizing/suspending virtual warehouses, the role-hierarchy grant model, resource monitors for cost control, and writing performant SQL over sprawling schemas — and a single mis-sized warehouse left running can balloon the bill overnight.

**AI operator:** An NL warehouse operator that translates plain requests into the right SQL DDL/DML and admin actions — provisioning warehouses, wiring grants, setting cost guardrails, and authoring analytical queries — while explaining the cost impact before it runs anything.

**Killer example:** A user says "give the marketing team read-only access to the CRM schema on a small auto-suspending warehouse capped at 50 credits a month." The AI generates and runs the `CREATE WAREHOUSE`, `RESOURCE MONITOR`, role, and `GRANT` statements, then confirms the guardrails — the exact admin ceremony that non-DBAs get wrong and pay for.

**Integration path:** Snowflake SQL API (REST), the Python Connector, Snowpark, and the SnowSQL CLI — every object (warehouses, grants, monitors, tasks) is addressable as SQL DDL/DML.

**Demand 5/5 · Buildability 5/5**

### 11. Microsoft Power Automate `closed`

**Why it's powerful:** Enterprise workflow automation with 1000+ connectors, triggers, loops, and a rich expression function library spanning Microsoft 365 and third-party services — the automation backbone bundled into most business Microsoft tenants.

**Why people bounce off it:** Ordinary users can't wire triggers to actions, correctly map "dynamic content," or write the nested Workflow Definition Language expressions (`formatDateTime`/`if`/`coalesce`) that any non-trivial flow demands — so flows either break silently or never get built.

**AI operator:** An NL operator preloaded with connector schemas and WDL expression syntax that assembles the entire cloud flow end to end from a described outcome.

**Killer example:** A user says "when an email with an invoice PDF arrives, save it to the Finance SharePoint folder and post the invoice amount in Teams." The AI builds the mail trigger, the SharePoint save action, the expression that pulls the amount, and the Teams message — the dynamic-content mapping and expression-writing that stops most users cold.

**Integration path:** Flows are JSON (Workflow Definition Language); the Power Platform CLI (`pac`) plus the Dataverse / Flow REST APIs provide programmatic create/update.

**Demand 5/5 · Buildability 3/5**

### 12. Adobe Premiere Pro `closed`

**Why it's powerful:** The industry-standard non-linear editor with frame-accurate multicam, deep color/audio tooling, and a massive pro plugin ecosystem used across most professional video teams.

**Why people bounce off it:** The timeline + keyboard-shortcut + panel model plus the codec/sequence/export-settings soup overwhelms casual creators who just want a clean cut with captions — many can't even match sequence settings to their footage, let alone strip filler and export per-platform.

**AI operator:** An NL editor that owns the sequence — ingests media, reads the auto-transcript, and performs cuts, silence/filler removal, captioning, and format-specific exports from plain-language direction.

**Killer example:** A user says "turn this 45-min podcast recording into a 90-second vertical highlight reel, strip the ums and dead air, and burn in captions." The AI scans the transcript, ripple-deletes silences/filler, assembles the selects on a new 1080×1920 sequence, enables auto-captions, and exports — collapsing hours of timeline scrubbing into one instruction.

**Integration path:** UXP/CEP HTML panels driving the ExtendScript engine (`app.project`, sequences, `importFile`, the QE DOM) via the Premiere Pro Panel SDK.

**Demand 5/5 · Buildability 3/5**
