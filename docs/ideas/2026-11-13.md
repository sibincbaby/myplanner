### 1. Amazon Lightsail (VPS, WordPress blueprints, static IPs, DNS zones, HTTPS, snapshots, CDN) `closed`

**Why it's powerful:** AWS's flat-price bundle of VPS, WordPress/LAMP blueprints, load balancers, CDN distributions and DNS. It is the default AWS entry point for small businesses, bloggers and agencies.

**Why people bounce off it:** Getting a WordPress site live on its own domain with HTTPS means juggling a static IP, a DNS zone, firewall ports, `bncert` over SSH or the certificate workflow, then snapshots and a CDN. Most failures come from requesting a certificate before DNS has propagated, or from hitting Let's Encrypt rate limits.

**AI operator:** A "put my site live, safely" operator. It runs the whole path in the right order, checks DNS resolution before requesting a certificate, sets up nightly snapshots, and explains renewal.

**Killer example:** User: 'Put my blog on myshop.com with the padlock, and back it up every night.' AI: allocates and attaches a static IP, opens 443, creates the DNS zone with apex and www records, waits until both resolve, runs HTTPS setup for apex and www, enables the auto-snapshot add-on at 03:00, then reports: 'Live at https://myshop.com. The certificate renews automatically, and the renewal notice goes to you@myshop.com.'

**Integration path:** Lightsail API: `AllocateStaticIp`, `AttachStaticIp`, `OpenInstancePublicPorts`, `CreateDomain` / `CreateDomainEntry`, `SetupInstanceHttps` (Let's Encrypt on the instance), `EnableAddOn` (AutoSnapshot), `CreateDistribution`. Verified: docs.aws.amazon.com/lightsail/2016-11-28/api-reference/API_SetupInstanceHttps.html. No Lightsail-specific Amazon Q agent or awslabs MCP was found, only the generic AWS API MCP.

**Demand 4/5 · Buildability 5/5**

### 2. Yahoo! Shopping Japan (Store Creator Pro): item edits, sale pricing and publish `closed`

**Why it's powerful:** One of Japan's three big marketplaces, with a very large store base because opening a store has been free since 2013. It supports variations (options/subcodes), sale prices, categories and tags.

**Why people bounce off it:** Store Creator Pro is old and form-heavy. Saved edits are not visible to shoppers until a separate publish step runs. The API has a trap: any field left out of an edit is reset to its default, so naive bulk tools wipe listings.

**AI operator:** A Japanese/English operator that reads each current item, merges in only the requested change so nothing gets wiped, saves, queues the publish, and schedules reverts.

**Killer example:** User: 「冬物アウター全部、今週末だけ20%オフにして、月曜朝に戻して」 ("All winter outerwear 20% off this weekend only, back to normal Monday morning.") AI: finds 63 outerwear items, sets `sale_price` on each with the full payload re-sent, queues the publish for Friday 18:00, schedules the revert and its publish for Monday 06:00, and lists 2 items it skipped because they already had a sale price.

**Integration path:** `POST https://circus.shopping.yahooapis.jp/ShoppingWebService/V1/editItem` (Bearer token; required `seller_id`, `item_code`, `path`, `name`, `product_category`, `price`), followed by the separate publish call. Verified: developer.yahoo.co.jp/webapi/shopping/editItem.html. The only first-party AI is "Store Creator Pro AI Chat", which answers how-to questions and takes no actions.

**Demand 4/5 · Buildability 4/5**

### 3. Fatture in Cloud (TeamSystem, Italy): reverse-charge self-invoices (TD17/TD18/TD19) and SDI rejection repair `closed`

**Why it's powerful:** Italy's default cloud invoicing and SME accounting app for freelancers and small businesses. It covers quotes, invoices, e-invoices through SDI (the mandatory state exchange), received documents and cash flow.

**Why people bounce off it:** Self-invoices for foreign suppliers (Google Ireland, AWS, Meta, EU freelancers) need the right document type (TD17/TD18/TD19) plus the matching Natura code (N2.x/N3.x/N6.x) and deadlines. Withholding tax, the professional pension levy and virtual stamp duty add more. One wrong code and SDI rejects the invoice with a terse error.

**AI operator:** It reads foreign supplier invoices and plain-language instructions, picks the document type, Natura code and withholding fields, runs the app's own XML check, sends to SDI, then reads any rejection reason and fixes and resubmits.

**Killer example:** User: 'I got invoices from Google Ireland, AWS and a Dutch freelancer this month, do the self-invoices.' AI: creates 3 self-invoices of the correct types with N6.x codes, checks each XML, sends all 3, then reports: 'All accepted. Heads-up: the AWS invoice dated 28/10 had to go out by 15/11, and it went out today.'

**Integration path:** `POST /c/{company_id}/issued_documents` (`type: self_supplier_invoice`), `GET .../issued_documents/{id}/e_invoice/xml_verify`, `POST .../e_invoice/send` (supports `dry_run`), `GET .../e_invoice/error_reason`. Verified: developers.fattureincloud.it/docs/guides/e-invoice-management/. Risk: the two official guide pages disagree on which enum value maps to which TD case, so test against the live API. TeamSystem's 2026 AI covers bank reconciliation and Q&A, not document creation. This is a different job from the GSTN/ZATCA/KSeF e-invoice regime cards.

**Demand 4/5 · Buildability 4/5**

### 4. Blackbaud Raiser's Edge NXT: gift-batch processing (Neon CRM as a second connector) `closed`

**Why it's powerful:** The default donor CRM for mid-to-large nonprofits in the US, UK and Canada. It handles constituents, funds, campaigns and appeals, gift batches, recurring gifts and soft credits.

**Why people bounce off it:** Gift batch entry is slow work, often done part-time. Staff match each donor from a deposit slip, Stripe/PayPal/Givebutter export or lockbox file, code fund, campaign and appeal, split gifts and soft-credit spouses. One wrong match corrupts years of giving history.

**AI operator:** Upload any gift file. The AI fuzzy-matches donors on name, address and email, flags new and ambiguous donors, applies coding rules stated in plain language, and builds an unapproved batch with expected count and total for a human to approve.

**Killer example:** User: 'Here's the October Givebutter export and the bank deposit. Anything tagged Gala goes to the 2026 Gala appeal, unrestricted fund. Soft-credit spouses.' AI: matches 412 of 431 donors and lists 19 for review (3 likely duplicates, 16 new). It creates batch GB-2026-10 with the expected total set to the deposit amount, adds the gifts, and reports a $25 gap between the file and the deposit (one refunded gift).

**Integration path:** SKY API `POST /gift-batch/v1/giftbatches` (create batch), then `POST /gift/v1/giftbatches/{batch_id}/gifts` (AddGiftsToBatch; supports Donation, RecurringGift, RecurringGiftPayment, Other, GiftInKind). Both appear as actions in Blackbaud's own Power Platform connector (learn.microsoft.com/en-us/connectors/blackbaudgifts/). Gotcha: batch gift IDs don't map to committed gift IDs after approval. Blackbaud's MCP connector is documented for lookups and communications only. Its Development Agent covers outreach, not gift entry. Neon CRM `POST /v2/donations` is the second connector. This is a different product from the seen Financial Edge NXT card.

**Demand 4/5 · Buildability 4/5**

### 5. Adobe Acrobat digital IDs: certificate PDF signing (PAdES-LTV, USB-token DSCs), with pyHanko as the headless engine `closed`

**Why it's powerful:** Certificate signatures are legally binding: EU eIDAS advanced/qualified signatures, India's Class 3 DSCs for GST/MCA filings and tenders, and engineering and architectural seals. They also show whether the file was changed after signing.

**Why people bounce off it:** Digital ID setup, PKCS#11 token drivers, timestamp servers, LTV, signature fields and appearances. Most users give up and print-sign-scan, or send files that show "signature validity unknown".

**AI operator:** The user says what to sign and with which certificate. The AI places fields, signs with the USB token or .pfx, adds a trusted timestamp and validation info for long-term validity, then checks every output.

**Killer example:** User: 'Sign all 37 invoices in this folder with my ePass DSC, bottom-right of the last page, with a timestamp, and make them stay valid long-term.' AI: detects the token over PKCS#11, asks for the PIN once, signs each PDF as PAdES B-LT, checks all signatures, and reports: '35 signed and valid. 2 failed because they were already certified and locked against changes. Here they are.'

**Integration path:** pyHanko CLI/library: `pyhanko sign addsig --field PAGE/X1,Y1,X2,Y2/NAME --timestamp-url ... --with-validation-info --use-pades pkcs11 --lib ... --token-label ...` (docs.pyhanko.eu/en/latest/cli-guide/signing.html). Acrobat route: `Field.signatureSign()` with `security.getHandler(security.PPKLiteHandler)` from a privileged Action Wizard or folder-level script. This is a different job from the seen Acrobat accessibility and redaction cards and from the DocuSign cloud e-sign card.

**Demand 4/5 · Buildability 4/5**

### 6. KoboToolbox (with ODK Central as a second connector): XLSForm field-survey authoring and deployment `open-source`

**Why it's powerful:** The standard for offline mobile field surveys in humanitarian work, NGOs, development economics and public health. It handles GPS, media, repeat groups, cascading selects and multilingual forms on cheap Android phones.

**Why people bounce off it:** Real forms are XLSForm spreadsheets. Skip logic goes in a `relevant` column as XPath (`${age} >= 15 and selected(${consent}, 'yes')`), alongside constraints, `choice_filter` and calculate fields. One typo breaks deployment with a cryptic error, and field staff can't fix it.

**AI operator:** It turns a plain questionnaire (a Word document or a sentence) into a valid XLSForm, deploys it, edits logic in place, and redeploys without orphaning submitted data.

**Killer example:** User: 'Add a section asking mothers of children under 5 about vaccinations. Skip it if there are no kids, dose date can't be in the future, and translate it to French and Swahili.' AI: writes the group with relevance `${num_children_u5} > 0` and constraint `. <= today()`, adds `label::French` and `label::Swahili` columns, validates, imports, redeploys as v7, and reports '0 existing data columns orphaned.'

**Integration path:** Kobo: `POST /api/v2/imports/` (XLSForm upload) and `POST`/`PATCH /api/v2/assets/{uid}/deployment/`. The flow comes from the live API browser and community threads, with known deploy bugs (HTTP 500 when a draft exists). ODK Central: `POST /v1/projects/{id}/forms?publish=true` and `.../forms/{xmlFormId}/draft` (docs.getodk.org/central-api-form-management/). Kobo's only first-party AI (May 2026) analyses audio answers and does not build forms.

**Demand 4/5 · Buildability 4/5**

### 7. Yahoo! JAPAN Ads / LINE Yahoo Ads (Search Ads) `closed`

**Why it's powerful:** Japan's second search-ad platform after Google and a must-buy for Japanese SMBs. It has campaigns, ad groups, keyword criteria, shared budgets and geo/device targeting.

**Why people bounce off it:** It uses Japan-specific objects (separate budget, targeting and dictionary services) and changes them often. In 2025 it removed `cpcBiddingScheme` and added CampaignBudgetService. SMBs and small agencies struggle to keep account structure current.

**AI operator:** A plain-language operator for a Japanese search account. It builds campaigns, adds keywords and negatives, sets regional targeting, drafts ads, and absorbs the API spec churn.

**Killer example:** User: 'Start a campaign for our Osaka moving service, Kansai only, ¥5,000 a day, and block anything with "job" or "free".' AI: creates the budget and campaign, targets the six Kansai prefectures, adds an ad group with 24 keywords and the negatives, drafts three responsive ads for approval, and reports the estimated daily clicks.

**Integration path:** `CampaignService/add`, `CampaignBudgetService`, `CampaignTargetService`, `AdGroupCriterionService/add` on `ads-search.yahooapis.jp` (yahoojp-marketing.github.io/ads-search-api-documents). API access requires an application. The first-party AI only suggests ad text (capped at 30 per month per account) and has no agent.

**Demand 4/5 · Buildability 3/5**

### 8. Cisco IOS XE (CLI-managed Catalyst switches and ISR routers, not Meraki) `closed`

**Why it's powerful:** The largest installed base of enterprise switching and routing: VLANs, trunks, ACLs, port security, STP, static routes and SVIs.

**Why people bounce off it:** Small-business IT generalists inherit a CLI-only Cisco stack and freeze. Config mode, interface ranges and ACL entry order are opaque, and changes are lost when someone forgets `write mem`.

**AI operator:** It reads the running config, explains it in plain words, proposes a diff, applies it through RESTCONF, and saves only after a reachability check passes.

**Killer example:** User: 'Put the 3rd-floor printers on their own VLAN and stop guests reaching them.' AI: finds the printer ports from MAC/CDP tables, creates VLAN 40 and its SVI, moves 6 ports, adds an extended ACL that denies the guest VLAN, re-tests printing from a staff subnet, then saves the config and shows the diff.

**Integration path:** RESTCONF (RFC 8040) `PATCH /restconf/data/Cisco-IOS-XE-native:native/...` and NETCONF `edit-config`, with YANG-Patch in 17.17 (cisco.com IOS XE 17.17 programmability guide). Cisco's AI Assistant and official MCPs cover Meraki and Catalyst Center, while IOS XE MCPs are only community/Code Exchange samples. Meraki is already carded. This card targets the standalone-CLI estate.

**Demand 4/5 · Buildability 3/5**

### 9. DHIS2 (national health information system): metadata configuration `open-source`

**Why it's powerful:** The health information system of record in dozens of countries' ministries of health and many NGOs. It covers aggregate and tracker data, indicators, analytics, maps and dashboards on Postgres.

**Why people bounce off it:** Metadata setup is notoriously hard. Data elements, category combos and options, datasets, org-unit hierarchies, indicator formulas (`#{uid.coc}`) and tracker program rules all depend on one another. Ministries rely on scarce HISP consultants for every change.

**AI operator:** It configures and repairs metadata from plain requests, reusing existing category combos, runs a VALIDATE dry run, then commits atomically.

**Killer example:** User: 'Add a monthly malaria form: RDT tested and positive by sex and age under 5, 5–14, 15+. Add a positivity-rate indicator and put it on the district dashboard.' AI: reuses the existing Sex×Age category combo, creates 2 data elements, the dataset and the indicator `#{pos}/#{tested}*100`, adds a pivot and dashboard item, and shows '0 conflicts' from the validate run before it commits.

**Integration path:** `POST /api/metadata?importMode=VALIDATE|COMMIT&atomicMode=ALL` (docs.dhis2.org metadata API), then `/api/visualizations` and `/api/dashboards`. dhis2.org/ai describes metadata AI only as a future possibility, and the MCP servers are community pilots. BAO's Convo app covers natural-language charts, so focus on configuration.

**Demand 4/5 · Buildability 3/5**

### 10. Chatwoot (open-source omnichannel support inbox): automation rules, routing and labels `open-source`

**Why it's powerful:** One shared inbox for email, web chat, WhatsApp, Instagram, Telegram and SMS, with teams, labels, automation rules, canned responses and SLAs. MIT-licensed and widely self-hosted as the open-source alternative to Intercom and Zendesk.

**Why people bounce off it:** The small businesses and agencies who adopt it get stuck on the automation rule builder (event, nested AND/OR conditions, actions) and on routing across many inboxes and teams. Most installs end up with one unrouted inbox and labels added by hand.

**AI operator:** The admin describes routing and triage in plain words. The AI creates the rules, labels, teams and canned replies, shows the rules as a readable diff, and replays last week's conversations against them before enabling.

**Killer example:** User: 'Send Hindi or Malayalam WhatsApp messages to the Kochi team, label anything with refund or chargeback as billing high-priority, and auto-reply after hours on Instagram.' AI: creates labels `billing` and `priority-high`, writes 3 automation rules and an after-hours canned reply, then reports from the 7-day replay: '41 would have routed to Kochi, 12 flagged billing, 0 rule conflicts.'

**Integration path:** `POST /api/v1/accounts/{account_id}/automation_rules` (`event_name`, `conditions[]`, `actions[]`; full CRUD), plus `/canned_responses`, `/teams` and `/labels` (developers.chatwoot.com/api-reference/automation-rule). Chatwoot's Captain AI replies to customers and drafts for agents. It does not author rules, and the only MCPs are community-built.

**Demand 3/5 · Buildability 4/5**

### 11. PowerPoint slide-library sync after the Reuse Slides retirement `closed`

**Why it's powerful:** PowerPoint is the universal sales and exec deck tool. Teams reuse standard slides (company overview, pricing, legal disclaimers) across thousands of files.

**Why people bounce off it:** Microsoft retired Reuse Slides on Windows and Mac desktop (MC1179161, removal from December 2025 to January 2026), and reused slides never linked back to their source anyway. When a number changes, every deck on SharePoint goes stale. Paid tools (BrandIn, Templafy, think-cell's library) fill the gap at enterprise prices.

**AI operator:** It keeps a register of canonical slides, finds outdated copies across a library by tags and text similarity, swaps in the current master slide using each destination deck's theme, and flags copies that were hand-edited.

**Killer example:** User: 'Our ARR moved to $48M. Update the Company at a glance slide in every deck in the Sales Enablement library and tell me which decks someone edited by hand.' AI: scans 212 .pptx files and finds 140 copies. It replaces 131 in place, keeping each deck's theme, flags 9 hand-edited copies with side-by-side previews, and writes a change log.

**Integration path:** Office.js `PowerPoint.Presentation.insertSlidesFromBase64(base64, {sourceSlideIds, targetSlideId, formatting})` plus `Slide.delete()` (PowerPointApi 1.2) for interactive use. Headless bulk route: Graph driveItem download/upload plus the Open XML SDK. Copilot Agent Mode can pull slides from one file into one deck, but nothing first-party syncs across decks. This is a different job from the seen template-deck generation card.

**Demand 3/5 · Buildability 4/5**

### 12. Pipedrive bulk-change undo ("CRM undo"), with Dynamics 365 / Dataverse as a second connector `closed`

**Why it's powerful:** Pipedrive has a very large SMB install base. Bulk edit, imports and automations change thousands of deals, people and organizations in seconds.

**Why people bounce off it:** There is no native undo for bulk edits. Pipedrive can only revert imports, and community threads asking how to undo a bulk change have no fix. Recovery today means reading each record's history by hand.

**AI operator:** The user describes the mistake in plain language. The AI finds every affected change through the changelog, shows a dry-run diff, and writes old values back, skipping records someone edited legitimately afterwards.

**Killer example:** User: 'Yesterday around 3pm Priya bulk-moved deals into Enterprise – Lost by mistake. Put them back, but leave any deal someone touched after that.' AI: finds 1,184 changes by Priya between 15:02 and 15:04, skips 37 deals edited later, restores pipeline and stage on 1,147, and posts a CSV audit trail.

**Integration path:** Pipedrive `GET /v1/deals/{id}/changelog` (and the same for persons and organizations), then the standard update endpoints for write-back. Dataverse: `RetrieveRecordChangeHistory` plus a Web API PATCH. Check before building: whether the new changelog endpoints include custom-field changes and a bulk-update flag is only reported by third parties. HubSpot (native Backup & Restore) and Salesforce (Backup & Recover) are excluded because they ship first-party undo. This is a different job from the seen Pipedrive and Zendesk Sell → Pipedrive cards.

**Demand 3/5 · Buildability 4/5**
