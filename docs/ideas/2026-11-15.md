### 1. Active Directory service accounts → gMSA / dMSA conversion (on-prem Windows Server) `closed`

**Why it's powerful:** Group managed service accounts (gMSA) and, on Server 2025 DCs, delegated managed service accounts (dMSA) let AD rotate service-account passwords itself. That ends the "svc_sql password never expires" pattern and shuts off Kerberoasting of those accounts.

**Why people bounce off it:** Before converting anything, an admin has to find every Windows service, scheduled task, IIS app pool and SQL instance that runs as a domain user, on every server. Then comes the KDS root key, a gMSA per workload, the right host group in `PrincipalsAllowedToRetrieveManagedPassword`, SPN moves, per-host installs and a rollback plan. Most shops never start.

**AI operator:** It inventories where each service account is used across the server estate and groups workloads by host set. For each account it writes a plan: gMSA, dMSA, or "can't convert, rotate and harden". It runs the cutover in a maintenance window, restarting one node at a time, and checks that the services come back.

**Killer example:** User: 'Get rid of svc_sql and svc_backup.' AI: finds svc_sql on 4 SQL nodes (MSSQLSERVER plus Agent, 3 SPNs) and svc_backup in 11 scheduled tasks on 6 servers. It creates `gmsa-sql$` and `gmsa-bkp$`, adds the hosts to `GRP-gMSA-SQL`, moves the SPNs, switches the services and tasks, and restarts them node by node. It disables the old accounts after 7 days with no logons.

**Integration path:**
- Inventory: `Get-CimInstance Win32_Service` (StartName), `Get-ScheduledTask`, `Get-IISAppPool`.
- Create and scope: `Add-KdsRootKey`, `New-ADServiceAccount`, `Set-ADServiceAccount -PrincipalsAllowedToRetrieveManagedPassword`, `Install-ADServiceAccount` / `Test-ADServiceAccount`, `setspn`.
- Switch over: `sc.exe config obj=`, `Set-ScheduledTask`.
- dMSA on Server 2025: `Start-` / `Complete-` / `Undo-ADServiceAccountMigration`.

Docs: learn.microsoft.com/windows-server/identity/ad-ds/manage/delegated-managed-service-accounts/delegated-managed-service-accounts-faq.

The verifier confirmed that Defender for Identity's Service Accounts page finds service accounts and where they connect, but it only filters and exports, with no conversion. No Microsoft agent that converts accounts was found. Two scouts proposed this independently. It is a different job from the 10-24 AD hygiene card, which only puts service accounts under a password policy.

**Demand 4/5 · Buildability 4/5**

### 2. Mews PMS: rate restrictions and stay-rule strategy (min stay, closed to arrival, lead time) `closed`

**Why it's powerful:** Mews is a cloud hotel PMS used by thousands of hotels, mostly in Europe. Restrictions can be set by rate, base rate, rate group, room category and weekday. They are condition/exception records covering minimum and maximum stay, booking lead time and price.

**Why people bounce off it:** Revenue managers think in sentences like "3-night minimum on summer weekends except long-stay". In Mews that becomes dozens of restriction records across rate groups and room categories, and it is hard to tell how they combine. Many small hotels never use restrictions at all.

**AI operator:** It turns a plain-language yield strategy into a restriction set. Before writing, it shows which arrival dates and rates will be blocked. It can roll back a season's set in one step.

**Killer example:** User: 'For Jul–Aug, require 3 nights minimum for Fri/Sat arrivals on every Flexible rate in Deluxe and Suite. Stop selling Early Bird inside 21 days. Close arrivals on Non-Refundable for 15–17 Aug (festival).' AI writes three `restrictions/set` batches:
- a Fri/Sat start condition on the Flexible rate group for the two room categories, with MinLength 3 nights;
- MinAdvance 21 days on the Early Bird rate;
- closed to arrival on Non-Refundable for 15–17 Aug.

It shows a calendar diff before committing.

**Integration path:** Mews Connector API: `POST /api/connector/v1/restrictions/set`, `restrictions/clear` and `restrictions/getAll`, plus `rates/getAll` (docs.mews.com/connector-api/operations/restrictions).

Caveats:
- The API can only set and clear restrictions it created itself, not ones made in the Mews UI.
- Production needs Mews partner certification.

On overlap: Mews' June 2026 blog describes a beta "rate management agent" for portfolio-wide rate changes, and Mews owns Atomize for automated pricing. Neither is shown setting restrictions, and there is no official Mews MCP. Keep the pitch on restrictions and stay rules, not price.

**Demand 4/5 · Buildability 4/5**

### 3. HPE Zerto: DR protection groups and test failovers (VMware Live Site Recovery as a second connector) `closed`

**Why it's powerful:** Zerto replicates VMs continuously, with recovery points seconds apart. It runs failover tests without touching production, and controls boot order, re-addressing and failback for vSphere and Hyper-V estates.

**Why people bounce off it:** Each Virtual Protection Group (VPG) needs several settings: boot-order groups with delays, re-IP per network card for both the test and live networks, journal sizing, and storage, network and folder mappings. DR plans quietly go stale as new VMs are added, and few teams re-test them.

**AI operator:** It reads vCenter and the existing VPGs, finds VMs that are unprotected or whose settings have drifted, and builds or fixes protection from a plain description. It then schedules a test failover and reports RTO per VM.

**Killer example:** User: 'Protect the new ERP stack: SQL first, the two app servers 3 minutes later, then the web tier. Test network 10.50.x, DR network 172.20.x. Run a test failover Friday.' AI: creates a VPG for ERP-SQL01, ERP-APP01/02 and ERP-WEB01/02 with boot groups and delays, sets re-IP per network card for both networks, and commits it. It runs the test on Friday and reports RTO per VM.

**Integration path:** Zerto REST: `POST /v1/vpgSettings` returns a settings ID; edit the VMs, boot order, NICs and journal; then `POST /v1/vpgSettings/{id}/commit`. Zerto 10 appliances keep the `/v1/` base and sign in with Keycloak tokens. For the second connector, VMware Live Site Recovery's REST gateway (SRM 9.0+) creates protection groups and runs test, planned migration and failback (developer.broadcom.com/xapis/vmware-live-site-recovery-api).

HPE's only published Zerto AI is an agent for troubleshooting, built on Amazon Bedrock with a diagnostic MCP. Nothing shows it creating VPGs. The 10-28 Hyper-V card mentions replication and DR runbooks as a side pack. This card is about DR orchestration itself: boot order, re-IP, drift and test failovers.

**Demand 4/5 · Buildability 3/5**

### 4. New Outlook for Windows cutover readiness (COM add-ins, client-only rules, opt-in waves) `closed`

**Why it's powerful:** New Outlook is where every Microsoft 365 tenant is being moved. Message-center post MC949965 says the enterprise opt-out phase starts March 2027.

**Why people bounce off it:** New Outlook doesn't run COM add-ins, and in-house ones must be rewritten. Admins have to work out, user by user, what will break: add-ins, client-only rules and workflows built on PST files. They then have to sequence the toggle policies across four places: the Microsoft 365 Apps admin center, Integrated Apps, Intune/GPO registry policy and Exchange.

**AI operator:** It sorts users into three groups: ready now, ready once web add-ins are deployed, and blocked by an in-house COM add-in. It deploys the web add-ins to the second group, moves client-only rules to the server, and turns on the opt-in policy one wave at a time.

**Killer example:** User: 'Who can move to new Outlook next week?' AI:
- reports that 1,840 of 2,300 users are ready;
- deploys the Acrobat Sign and Zoom web add-ins for 310 more users to `GRP-NewOutlook-Wave2` with `New-OrganizationAddIn -Members`;
- holds back 150 users blocked by the in-house `LegalDocFiler` COM add-in, with a report;
- sets the opt-in policy for Wave 2 only.

**Integration path:**
- Add-ins: O365CentralizedAddInDeployment cmdlets (`New-` / `Set-` / `Get-OrganizationAddIn`).
- Rules: Graph `mailFolders/inbox/messageRules`, to recreate client-only rules on the server.
- Toggle and migration keys: an Intune `deviceManagementConfigurationPolicy`, or GPO.

The Apps admin center add-in inventory has no confirmed public API, so device inventory may have to come from Intune or Defender. Microsoft automatically offers web versions of known add-ins to users who switch. The cross-signal readiness verdict and wave orchestration are what's missing. This sits at the edge of the Outlook rules card and the Intune card, but neither covers the cutover.

**Demand 4/5 · Buildability 3/5**

### 5. Oracle OPERA Cloud: rate plan and package builder via OHIP `closed`

**Why it's powerful:** OPERA is the dominant enterprise hotel PMS. Rate codes, rate classes and categories, derived rates, and packages with transaction codes decide everything distributed to the web and to GDS.

**Why people bounce off it:** One promotional rate means a rate header, daily schedules, package attachments with valid transaction codes, and market and channel settings. It takes many screens, so chains leave it to a corporate rate loader or a consultant.

**AI operator:** Describe the offer in words. The AI builds the rate header, schedules and packages through OHIP, polls the async job, and reports anything it couldn't map.

**Killer example:** User: 'Create "Stay 3 Pay 2 + Breakfast" for Jan–Mar at the Lisbon property: BAR minus 10%, breakfast for 2 on transaction code BKFST, members only, web and GDS.' AI calls `postRatePlan` for the header, then the schedule calls for daily pricing, then `postRatePlanPackages` for BKFST, and polls the job status.

**Integration path:** OHIP Rate Management API (docs.oracle.com/en/industries/hospitality/integration-platform/crsig/c_5_rate_management.htm). OHIP is a paid pay-as-you-go subscription from the Oracle Store, with a shared sandbox hotel. Going live needs a customer hotel on OPERA Cloud. The OPERA Cloud Assistant (June 2026) was verified to only *write rate descriptions* from existing rate data. It doesn't create rate codes, schedules or packages.

**Demand 4/5 · Buildability 3/5**

### 6. IRIS Staffology Payroll: April 2027 payrolling of benefits in kind (company cars, medical) `closed`

**Why it's powerful:** Staffology is an API-first UK payroll engine popular with payroll bureaus. It handles many employers, pension schemes, pay codes mapped to ledger codes, and benefits in kind (BiK).

**Why people bounce off it:** From 6 April 2027 UK employers must put company cars, fuel, vans and medical cover through payroll, with other benefits following in 2028. Today that data sits in P11D spreadsheets and insurer schedules. Each benefit needs a record per employee with the right inputs (CO2, list price, fuel type, dates). Bureaus have to repeat this for dozens of employers and track which benefits fall in which phase.

**AI operator:** It reads the client's P11D workbook, fleet list and insurer schedule, and sorts each benefit into a phase. It creates the Benefit records, previews taxable pay per period and the employer's Class 1A NIC cost, and flags problems before the first April pay run.

**Killer example:** User: 'Move Acme Ltd's 14 company cars and the Bupa cover for 62 staff onto payroll from April 2027; leave the 3 employee loans on P11D.' AI creates 14 car benefits and 62 medical benefits and maps the pay code to the right ledger code. It warns that 2 low-paid drivers would hit the 50% cap on tax deducted from pay in a period. It leaves the loans on P11D.

**Integration path:** Staffology REST: `POST /employers/{employerId}/employees/{employeeId}/benefits` (Create Benefit, with `BenefitDetailsCar` and `BenefitDetailsLoan` models; app.staffology.co.uk/api/docs/operations/createbenefits), plus PayCode and Nominal Code mapping endpoints. Staffology already has "Import Benefits" and beta AI column mapping, so the value is in reading the P11D, scoping it and validating it, not in loading rows. Staffology's own AI agent lives in Staffology HR and answers support questions. This revives the "UK payrolling of BiK" idea dropped earlier for lack of a write path: the endpoint is now confirmed.

**Demand 3/5 · Buildability 4/5**

### 7. Active Directory Kerberos SPN and delegation fixer (double-hop, unconstrained → RBCD) `closed`

**Why it's powerful:** Kerberos constrained and resource-based delegation (KCD/RBCD) is what lets IIS → SQL, SSRS, SharePoint and file-share double-hop access work without NTLM.

**Why people bounce off it:** Duplicate or missing SPNs, confusion between classic KCD and RBCD, and protocol transition are all hard to see into. The usual "fix" is to turn on unconstrained delegation, which opens a security hole.

**AI operator:** It traces a failing double-hop, finds the gaps in SPNs and delegation, and applies the narrowest fix. It also finds existing unconstrained delegation and offers to replace it with RBCD.

**Killer example:** User: 'Reports on SSRS01 fail with "Login failed for NT AUTHORITY\ANONYMOUS LOGON" to SQL02.' AI finds that `MSSQLSvc/SQL02.corp.local:1433` is missing and that a duplicate HTTP SPN sits on two accounts. It registers the right SPN, removes the duplicate, and runs `Set-ADComputer SQL02 -PrincipalsAllowedToDelegateToAccount SSRS01$`. It then lists 4 other servers with unconstrained delegation and offers to convert them.

**Integration path:** `setspn -L/-S/-D/-X`, `Set-ADComputer` / `Set-ADUser -PrincipalsAllowedToDelegateToAccount`, the `msDS-AllowedToDelegateTo` and `TrustedForDelegation` attributes, `klist`, and DC events 4769/4771. These are standard tools, but this run didn't verify any of them or check for a first-party agent. This card is close to the 11-10 lockout investigator in style, but it is a different job. It would ship well bundled with #1.

**Demand 3/5 · Buildability 4/5**

### 8. ShootProof: price sheets and print storefront setup for photographers `closed`

**Why it's powerful:** ShootProof is the gallery and print-sales platform for a large share of US wedding, school and portrait photographers. Price sheets tie lab catalogs, markups, groups, discounts and shipping to every gallery.

**Why people bounce off it:** A price sheet means picking dozens of lab products, setting a markup on each, then building groups, discount rules and shipping options. Photographers copy old sheets and end up with prices that lose money after lab costs.

**AI operator:** It builds and maintains price sheets from plain pricing rules. It reads lab costs from the catalog, applies margin rules and floors, and adds discounts and shipping.

**Killer example:** User: 'Make a 2027 wedding price sheet from my WHCC catalog. Prints at 3x lab cost with a $25 minimum, canvases at 2.2x, 15% off orders over $300 for 30 days after the gallery opens, and free shipping over $150.' AI copies the current sheet with `duplicatesId`, reads each lab product's cost, writes about 60 priced items, and adds the discount and shipping option. It flags the 4 products where 3x falls under the $25 minimum.

**Integration path:** ShootProof Studio API (developer.shootproof.com/reference/studio/price-sheets/): `POST /studio/brand/{brandId}/price-sheet` (which can copy a sheet via `duplicatesId`), plus price-sheet items, discounts, groups and shipping options. The lab catalog can only be read. API access needs a client ID requested from support, and there is no sandbox. No ShootProof AI or MCP was found.

**Demand 3/5 · Buildability 4/5**

### 9. Printavo: messy customer requests → structured print-shop quotes `closed`

**Why it's powerful:** Printavo is the main shop-management system for US decorated-apparel (screen-print and embroidery) shops. It runs quotes, invoices, imprints, mockups, production tasks and payments.

**Why people bounce off it:** Orders arrive as emails or spreadsheets, like "40 black Gildan 5000, S–3XL, 2-color front, 1-color sleeve, plus 12 hoodies". Each one is keyed in by hand: line-item groups, quantities per size, imprints, fees and task presets.

**AI operator:** It reads the request, writes a structured quote, applies the shop's production preset, and sends the customer an approval request.

**Killer example:** User pastes a customer email with a size breakdown. AI:
- calls `quoteCreate`;
- writes two line-item groups with sizes S–3XL (`lineItemGroupCreates`);
- adds 3 imprints with `imprintCreates`: front 2-color, sleeve 1-color, hoodie back 3-color;
- adds a $35 screen-setup fee (`feeCreates`);
- applies the "Screen print standard" task preset (`presetTaskGroupApply`);
- sends `approvalRequestCreate`.

**Integration path:** Printavo GraphQL v2 (printavo.com/docs/api/v2/operation/mutation). The rate limit is 10 requests per 5 seconds, and API access may need the Premium tier. There is no pricing-matrix mutation, so the operator has to compute prices itself.

On overlap: Vinkius' 11-tool Printavo MCP covers customers and orders, but no line-item group or imprint tools were seen. Its full tool list returned 404. One third-party blog mentions a Printavo "AI quote assist", which has no official confirmation. Re-check both before building.

**Demand 3/5 · Buildability 4/5**

### 10. Fiix CMMS: building the preventive-maintenance program from manuals `closed`

**Why it's powerful:** Fiix (Rockwell) triggers scheduled maintenance by time, meter reading or asset event. Each schedule carries task lists, parts and labour across a full asset hierarchy. It is a mid-market leader in manufacturing.

**Why people bounce off it:** Building a PM program means turning OEM manuals and technicians' know-how into many schedules and triggers. The trigger rules are fiddly. A schedule must be paused before its triggers can be edited, and it won't raise a new work order while the last one is still open. Most sites leave PM half-built.

**AI operator:** It reads manuals, nameplate data and work-order history, proposes a PM plan per asset class, and creates the schedules, task lists and triggers. It also audits existing PMs for duplicates, schedules paused for months, and meter triggers that never fire.

**Killer example:** User: 'Set up PM for our 14 Atlas Copco GA37 compressors from the manual: 2,000-hour oil change on the run-hours meter, quarterly belt check, and skip any that already have an active oil-change PM.' AI creates 11 meter-triggered oil-change PMs and 14 quarterly belt checks, each with its task list and parts (oil kit, belt). It skips the 3 compressors that already have an active oil-change PM, and reports 2 PMs that have been paused for over 6 months.

**Integration path:** Fiix REST/JSON API (fiixlabs.github.io/api-documentation) with add/change/find on `ScheduledMaintenance` and `ScheduleTrigger`, both verified in Fiix's API permissions table. The v2.20 API also adds the `ScheduleTriggerAssetEvent` RPC. Fiix MAX only retrieves records and gives recommendations, and doesn't create PMs. It's a race, though: Limble already ships an AI PM Builder, and Fiix could follow. UpKeep is a possible second connector.

**Demand 3/5 · Buildability 3/5**

### 11. Twinfield (Wolters Kluwer): firm-wide dimension setup across client companies `closed`

**Why it's powerful:** Twinfield is a multi-company cloud ledger used by accounting firms in the Netherlands, the UK and Belgium. Everything is a "dimension": GL accounts, customers and suppliers, cost centres (KPL), projects (PRJ) and fixed assets (AST), across hundreds of client companies.

**Why people bounce off it:** The dimension model is abstract, and the dated UI works one company at a time. Firms rebuild cost centres, projects and asset dimensions by hand for each client, and setups drift apart over time.

**AI operator:** It compares each client company's dimensions with the firm's standard, explains the drift in plain language, and bulk-creates or corrects cost centres, projects and fixed-asset records.

**Killer example:** User: 'Give all 38 hospitality clients the standard cost centres (Keuken, Bar, Zaal, Overhead), and register Café Noord's new €8,400 espresso machine, 5-year straight line from 1 March.' AI creates up to 152 KPL dimensions, skipping existing ones and reporting 3 renamed duplicates. It creates the AST dimension at Café Noord with the depreciation settings.

**Integration path:** Twinfield XML web services (ProcessXml with `<dimension>` types KPL/PRJ/AST/BAS, plus Finder for search; developers.twinfield.com/documentation/getting-started/dimensions). Since late 2025, API access has carried per-company and data-traffic fees (writes cost 3 credits). Whether the depreciation fields on fixed assets can be written, and whether Wolters Kluwer ships an AI assistant for Twinfield, are both unverified.

**Demand 3/5 · Buildability 3/5**
