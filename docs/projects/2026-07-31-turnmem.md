# TurnMem

> A lean context-compression hook for Claude Code: instead of letting raw tool traces accumulate and bloat the context window, TurnMem auto-summarizes each completed turn into a compact memory entry — keeping sessions sharp and cheap even on long tasks.

**Inspired by:** [mochow13/keen-code](https://github.com/mochow13/keen-code)  
**Date discovered:** 2026-07-31

---

## What gap it fills

Keen Code's key design insight is *TurnMemory*: rather than accumulating the full verbatim tool call / output / result chain in context (which explodes token usage fast), each turn is summarized into a single compact entry — "Modified `auth.py`: moved token refresh to `refresh_access_token()`, added 15-minute expiry check. Tests pass." — before the next turn begins.

Claude Code doesn't do this today. Long sessions accumulate the raw transcript of every Bash output, every file read, every grep result. Useful for debugging but wasteful for context. TurnMem plugs into Claude Code's PostToolUse hook to intercept completed turns and write lean summaries to a session `.turnmem` file; the next prompt includes only this compact record instead of the full raw history.

Concrete daily value: a 4-hour refactoring session that would normally blow past 200k tokens can stay under 40k. Claude remains sharp at hour 3 instead of starting to mis-remember earlier decisions.

Viability score: **4/4** (weekend_buildable ✅, fills_gap ✅, novel ✅, daily_utility ✅)

## Stack recommendation

| Layer | Choice | Why |
|-------|--------|-----|
| Hook trigger | Claude Code `PostToolUse` hook | Fires after each tool call completes |
| Summarizer | Claude API (`claude-haiku-4-5-20251001`) | Sub-200ms, cheap, accurate at task summaries |
| Storage | `.claude/.turnmem/session-<id>.jsonl` | One line per turn; grep-friendly, git-ignorable |
| Injector | `UserPromptSubmit` hook prepends recent entries | Injects compact history before each new prompt |
| CLI | `turnmem show` / `turnmem clear` / `turnmem export` | Session review and export |
| Config | `~/.claude/turnmem.toml` | Compression threshold, max entries to inject |

---

## MVP scope (1-2 Claude sessions)

**Session 1 — Hook + summarizer:**
- `post_tool_use.py`: invoked by PostToolUse hook; receives the tool name + raw output; calls Haiku API with a 2-sentence summary prompt; appends JSON entry `{turn, tool, summary, tokens_saved}` to `.turnmem/session-<id>.jsonl`
- Compression heuristic: only summarize turns where raw output > 2000 chars (short turns aren't worth compressing)
- `user_prompt_submit.py`: invoked by UserPromptSubmit; reads last N entries from `.turnmem`; prepends as a `<prior-context>` block before the user's prompt
- Test: run a 10-turn session, compare raw vs compressed token counts in session log

**Session 2 — Polish + adaptive injection:**
- Track cumulative context size; ramp up compression aggressiveness as context grows (summarize more aggressively after 50k tokens)
- `turnmem show` CLI: pretty-prints session history with per-turn token savings
- `turnmem export <file>`: exports session summary as a handoff document
- Configurable: which tool types to compress (Bash output always; file reads only if > 5k chars)

---

## 3-Phase roadmap

### Phase 1 — Compress + store (Session 1)
PostToolUse hook summarizes turns above threshold. JSONL storage per session. Basic token savings logging.

### Phase 2 — Inject + adapt (Session 2)
UserPromptSubmit hook injects compact history. Adaptive compression threshold based on current context size. CLI for session inspection and export.

### Phase 3 — Cross-session memory (Session 3)
On session end, write a final "session summary" entry (key decisions, files changed, open questions). On next session start in the same repo, inject the last 3 session summaries as project context. This gives Claude persistent awareness of what happened yesterday, not just today.

## Blockers / watch-outs

- **Hook latency budget**: PostToolUse hook must complete before Claude processes the next tool — keep Haiku calls under 800ms. Use streaming + timeout fallback (if over budget, skip compression for that turn).
- **Summary quality**: Haiku summaries for long Bash outputs (e.g., `npm install` logs) can be noisy — test with a prompt like "Summarize what this tool output changed or revealed in one sentence. Focus on outcomes, not mechanics."
- **Circular injection**: The `user_prompt_submit.py` injector must not re-inject summaries of the injected prior-context block itself — track injected content by turn index.
- **Token counting**: Use the Anthropic token-count API endpoint to get accurate before/after counts for the savings log, not a rough char-based estimate.

---

## Why now

Keen Code's 454-commit Go implementation proves TurnMemory works as a production strategy: the tool is lean and fast because it *never* carries raw tool output into subsequent turns. Claude Code's hook system (`PostToolUse`, `UserPromptSubmit`) now provides exactly the intercept points needed to replicate this pattern externally, without modifying Claude Code itself. As context windows stay expensive per-token regardless of their nominal size, any mechanism that cuts session token usage by 60–80% pays for itself on the first long coding task.
