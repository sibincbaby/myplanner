# COGBrain

> A self-evolving second brain with 17 AI skills, 6 worker agents, and a people CRM built for Claude Code — inspired by Garry Tan's gstack/gbrain. Manages knowledge, tracks people, and surfaces context automatically.

**Inspired by:** [huytieu/COG-second-brain](https://github.com/huytieu/COG-second-brain)  
**Date discovered:** 2026-07-30

---

## What gap it fills

Every prior discovery run has covered personal knowledge bases and journal MCPs. COG-second-brain introduces one genuinely new element: **a people CRM layer woven into the second brain.** The user's current toolkit has no tool that tracks contacts, surfaces context about people (last conversation, shared interests, things to follow up on), and links that context back to notes, projects, and tasks — all from the terminal via Claude Code.

The gap: when working with collaborators, users face the same "who is this person again?" tax over and over. COGBrain eliminates that by maintaining a `people/` section of the vault where each contact has a living document Claude can add to after every interaction: "met Alice at the Flutter meetup, building a Dart MCP SDK, wants to open-source it next month."

Combined with a general second brain (knowledge notes, project notes, daily log), COGBrain gives you one place to ask "what's going on with X project", "who should I reach out to about Y topic", and "what did I learn last week" — with Claude answering from your own local Markdown corpus.

Viability score: **4/4** (weekend_buildable ✅, fills_gap ✅, novel ✅, daily_utility ✅)

## Stack recommendation

| Layer | Choice | Why |
|-------|--------|-----|
| Host | Claude Code (skills + agents) | SKILL.md + CLAUDE.md; no server needed |
| Storage | Plain Markdown + YAML frontmatter | Human-readable, git-friendly, Obsidian-compatible |
| Search | `ripgrep` (local, fast) | Zero-dependency full-text; add sqlite-vec later for semantic |
| People CRM schema | YAML frontmatter in `people/` notes | Name, last-contact, tags, follow-ups, related-projects |
| Scheduler | Claude Code `Stop` hook | Auto-file daily log + update people notes after each session |
| Optional sync | `git push` to private repo | Cloud backup of your brain without a SaaS platform |

## MVP scope (1-2 Claude sessions)

**Session 1 — Second brain core + people CRM:**
- `CLAUDE.md` in brain root: declares vault layout (`people/`, `projects/`, `notes/`, `log/`), naming conventions, tagging taxonomy
- `/add-note` skill: take text/URL/file → extract title + summary + tags → file in `notes/` with YAML frontmatter
- `/add-person` skill: take a name + context blurb → create or update `people/<name>.md` with last-contact date, tags, follow-up items, linked projects
- `/recall` skill: natural-language query → ripgrep search → return top-5 relevant notes/people with excerpts

**Session 2 — Worker agents + daily log:**
- Daily log agent: each morning, Claude auto-creates `log/YYYY-MM-DD.md`, surfaces 3 people to follow up with (by last-contact date), and shows 3 notes from "this day last month"
- `/update-person` agent: after you describe a meeting, Claude parses it and updates the person's note (new follow-ups, relationship context, shared projects)
- Review agent: weekly summary of new notes + people added + projects updated

---

## 3-Phase roadmap

### Phase 1 — Core brain + CRM (Session 1)
`/add-note`, `/add-person`, `/recall` skills. CLAUDE.md vault schema. Manual test with 10 real people entries and 20 notes.

### Phase 2 — Worker agents + daily rhythm (Session 2)
Daily log agent (morning briefing), `/update-person` agent, weekly review agent. `Stop` hook to auto-file session outputs.

### Phase 3 — Self-evolution
"Evergreen" agent: surfaces stale notes (not touched in 60 days) for review or archiving. "Link discovery" agent: proposes backlinks between notes Claude hasn't connected. Optional: export to Obsidian or Logseq vault.

## Blockers / watch-outs

- **Schema discipline**: The people CRM schema (YAML frontmatter fields) must be defined rigidly in Phase 1; retrofitting later requires touching every person note
- **Privacy**: A people CRM in a git repo is sensitive — gitignore `people/` or use a separate private repo; document this in CLAUDE.md
- **Naming collisions**: Common names (e.g., "Alex") need a disambiguation convention in filenames — use `people/alex-wang-anthropic.md` not just `alex.md`
- **Agent scope creep**: Worker agents that "auto-update" person notes can over-write context if the source text is ambiguous — add a dry-run mode before committing writes
- **Recall quality**: ripgrep keyword search degrades on sparse, abstract notes; add sqlite-vec in Phase 3 before the brain grows past ~200 notes
