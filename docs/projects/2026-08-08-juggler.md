## What it is

Juggler is an open-source GUI coding agent from Julian Storer (creator of JUCE, Tracktion DAW, Cmajor). It gives you a visual workbench for AI coding sessions: every tool call is inspectable, every session is a CRDT document on disk, and any point in a thread can be branched into a sub-thread. The Miller-column (Finder-style) layout shows nested sub-threads side by side. The upstream supports multiple AI backends; the native build is C++ (macOS/Windows/Linux).

**Why it matters for this project:** Claude Code sessions live in `~/.claude/projects/` as JSONL files — they are already on disk. The missing piece is a lightweight web-based explorer that shows conversation trees, lets you branch from any message, and re-launches Claude at the branch point via `--resume`. This is a 1-2 session build using existing files without needing the full upstream C++ toolchain.

## Stack Recommendation

```
Backend:   Node.js 22 / Express — reads ~/.claude/projects/ JSONL; fs.watch for live updates
Storage:   SQLite (better-sqlite3) — branch metadata, user annotations
Frontend:  React 18 + Vite + Tailwind CSS
Tree view: react-arborist (free MIT tree component, virtualized)
Resume:    child_process.spawn("claude", ["--resume", sessionId])
```

No Electron needed — a local web server on port 7337 is sufficient for a personal tool. The browser opens `http://localhost:7337` and the backend watches the JSONL directory.

## MVP Scope (1 Claude session)

1. `GET /api/sessions` — scan `~/.claude/projects/` recursively, parse each `.jsonl`, return `{id, project, startedAt, messageCount, lastModel}`
2. `GET /api/sessions/:id/messages` — stream the JSONL as an array of `{role, content, toolCalls, cost, tokens}`
3. `POST /api/sessions/:id/branch?from=<msgIndex>` — write a SQLite row `{parentId, parentMsgIndex, branchId}` and spawn `claude --resume <parentId>` in a new terminal tab
4. React UI: session list sidebar → click to open message thread → click any message → "Branch here" button → confirmation → spawns Claude in terminal
5. Cost sidebar: token count, USD estimate (from `costUsd` field in JSONL events)

## Phases

### Phase 1: JSONL Reader + REST API (2-3h)
- Parse `~/.claude/projects/**/*.jsonl` — each line is a JSON event (`{type, message, costUsd, ...}`)
- Build `SessionStore`: index sessions by `sessionId`, group messages, compute metadata
- `GET /api/sessions` returns array sorted newest-first
- `GET /api/sessions/:id` returns full message array with tool-call blocks flattened
- `fs.watch` on the projects directory — emit a SSE event `/api/events` when any file changes
- Verify: load a real session from disk, confirm message count matches `~/.claude/` directory

### Phase 2: React Session Browser (2-3h)
- Left panel: session list (project name, date, message count, cost badge)
- Main panel: message thread — user / assistant / tool-call cards with syntax-highlighted content
- Tool-call cards show `tool_name`, collapsed input JSON, output summary
- SSE subscriber: auto-refresh session list and active thread when file changes
- Verify: open an active Claude Code session, watch new messages appear in real time

### Phase 3: Branching (2h)
- SQLite schema: `branches(id, parent_session_id, parent_msg_index, branch_session_id, created_at, label)`
- "Branch from here" button on every assistant message
- Branch dialog: optional label input → creates SQLite row → spawns `claude --resume <parentId>` via `exec`
- Branch indicator: message cards show a branch icon if any branch was created from that point
- Branch tree sidebar: shows parent → child session links with labels
- Verify: branch from message 5 of a session, confirm new Claude Code session resumes correctly

### Phase 4: Context + Cost Display (1-2h)
- Token counter per message (input/output/cache tokens from JSONL `usage` field)
- Session-level cost accumulator: sum all `costUsd` events, show in header
- Model badge per message (sessions can switch models mid-thread)
- Filter bar: show only user messages, only tool calls, only errors
- Verify: compare accumulated cost against `~/.claude/` usage stats

### Phase 5: Annotations + Export (1h)
- Right-click any message → "Add note" → stored in SQLite with `{sessionId, msgIndex, text}`
- Notes appear as yellow sticky-note overlays on the message card
- Export: "Copy thread as Markdown" for pasting into docs or PR descriptions
- Verify: add a note, close the app, reopen, confirm note persists

## Blockers / Risks

- The `~/.claude/projects/` JSONL schema is internal to Claude Code and may change across CLI versions; parse defensively (ignore unknown fields, don't crash on missing ones)
- Tool-call content blocks can be very large (full file contents); render collapsed by default with a "Expand" toggle to keep the UI fast
- `claude --resume <id>` spawns in the same terminal that runs the Node server — for a cleaner UX, use `osascript` (macOS) or `gnome-terminal --tab` (Linux) to open a new window
- Branch session IDs are generated by Claude Code on session creation — you only know the branch's ID *after* the user runs `claude --resume` and types something; poll for new sessions in `~/.claude/projects/` after spawning to discover the child ID
