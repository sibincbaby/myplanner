# SelfSpec

> A personal context specification file — structured YAML describing who you are, how you work, your preferences and skills — served to any AI agent or app via a local MCP resource, so you never re-introduce yourself to a new Claude session or a new AI tool

**Inspired by:** [Unabyss](https://www.producthunt.com/products/unabyss) (Product Hunt July 2026 top-10)  
**Date discovered:** 2026-07-28

---

## What gap it fills

Every new Claude Code session, every new agent, every new AI tool starts from zero: same intro, same preferences, same project context. Unabyss proved people will pay for cross-agent context sharing. SelfSpec is the personal, open, self-hosted version: one `self.yaml` file on your machine, one MCP server, and every agent that reads it immediately knows who you are.

Concrete daily value: start a new Claude Code session → it reads `self.yaml` → already knows your preferred stack (TypeScript, Flutter, SQLite, Anthropic SDK), your active projects and their purpose, your coding style preferences, your timezone and working hours, and that you use Tailwind for web and Material Design for Flutter. No typing. No `CLAUDE.md` copy-paste in every repo.

This differs from `CLAUDE.md` in scope: `CLAUDE.md` is per-project; `SelfSpec` is per-person and portable across every session and every agent.

## Stack recommendation

| Layer | Choice | Why |
|-------|--------|-----|
| Spec format | YAML (`.yaml`) | Human-editable, machine-parseable, Claude-readable |
| Schema validation | `zod` + TypeScript | Type-safe; `parse-self.ts` validates on edit |
| MCP server | `@modelcontextprotocol/sdk` (TypeScript) | Official SDK; zero-boilerplate resource registration |
| Transport | stdio | Standard for local MCP; works with Claude Desktop + Claude Code |
| Storage | Single file `~/.selfspec/self.yaml` | One file on your machine; back up to a private repo |
| Access control | Local only (no network exposure) | Agents on your machine only; no cloud sync risk |

## MVP scope (1 Claude session)

A `self.yaml` file + an MCP server that exposes it as a resource:

1. Defined `self.yaml` schema covering: identity, skills, active projects, preferences, working style, timezone
2. A `validate.ts` script to type-check your `self.yaml` against the schema
3. An MCP server with a single `resource: selfspec://me` returning your YAML as a structured document
4. A Claude Desktop + Claude Code config snippet to mount the MCP server automatically
5. A `CLAUDE.md` template instruction: "Read selfspec://me resource to understand the user before starting"

Out of scope for MVP: per-agent filtering (what to share with which agent), encryption, sync across machines.

## Phases

### Phase 1 — Define the self.yaml schema (1 h)
- `identity`: name, timezone, email, languages spoken
- `skills`: map of `{area: proficiency}` (TypeScript: expert, Flutter: intermediate, Rust: beginner)
- `active_projects`: array of `{name, description, stack, status, repo?}` — top 3–5 only
- `preferences.coding`: indentation, comment style, test framework, preferred patterns (functional/OOP)
- `preferences.ui`: web stack (React/Vue/etc.), mobile stack (Flutter), design system name
- `working_style`: focus hours, preferred PR size, test-first vs build-first, code-review style
- `tools`: `{editor, shell, ai_agents, mcp_servers_active}`
- Write your own real `self.yaml` as the reference implementation

### Phase 2 — Schema validator (45 min)
- `validate.ts`: load `~/.selfspec/self.yaml`, parse with `gray-matter` or `js-yaml`, validate with `zod`
- Schema: strict on required fields (`identity.name`, `skills`, `active_projects`), lenient on optional
- Human-friendly error messages: "active_projects[1] is missing a `description`"
- `npm run validate` exits 0/1; add to shell alias or git hook

### Phase 3 — MCP resource server (1.5 h)
- `server.ts` using `@modelcontextprotocol/sdk` TypeScript SDK
- Single resource: `selfspec://me` — returns the parsed YAML as a structured object
- Single tool: `get_self_context(fields?: string[])` — optionally filter to specific fields (e.g. only `active_projects`)
- stdio transport, registered in `~/.claude/claude_desktop_config.json` and `~/.claude/settings.json`
- `package.json` with `"main": "server.js"` and a `start` script

### Phase 4 — Claude Code integration (30 min)
- `CLAUDE.md` template to add to any project: first line reads `selfspec://me` via the MCP resource, loads identity and active projects, never asks "what's your preferred stack?"
- Document the resource call pattern in README for other agents (Codex, Cursor, etc.)
- Test: fresh Claude Code session, confirm it greets by name and knows your active project without prompting

### Phase 5 — Per-agent context filtering (1 h)
- Add `share_with` field to each top-level section: `share_with: [all]` or `share_with: [claude, codex]`
- `get_self_context(agent_id?: string)` returns only fields where `share_with` includes `agent_id` or `all`
- Use case: share `active_projects` with coding agents but not `personal_notes` with work tools

## Effort estimate

~4.75 hours all phases · 1–2 Claude sessions  
Phases 1–4 alone deliver a fully functional cross-agent context system in ~3.75 hours

## Blockers / risks

- **Security:** `self.yaml` contains personal data. Document that the MCP server is stdio-only, never network-exposed, and suggest storing `self.yaml` in a private encrypted directory or 1Password vault.
- **Stale context:** As active projects change, `self.yaml` gets stale. Add `last_updated` field and a Claude reminder: "If last_updated is > 14 days ago, ask user to update SelfSpec."
- **Overlap with CLAUDE.md:** CLAUDE.md is per-project, SelfSpec is per-person. They compose — SelfSpec provides identity and cross-project preferences; CLAUDE.md provides project-specific rules.
- **Overlap with MemLayer (2026-07-26):** MemLayer was about persistent session memory across Claude Code runs. SelfSpec is static structured identity context — complementary, not redundant.
- **Unabyss as a paid product:** If Unabyss launches a free tier or open-sources, evaluate whether self-hosting adds enough value. For now, SelfSpec is local-first and free.
