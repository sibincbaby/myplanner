# ccanvas — Infinite Canvas for Claude Code Agents

**Source:** [DevoidSloth/ccanvas](https://github.com/DevoidSloth/ccanvas) (Tauri desktop app, Oct 2026)  
**Tagline:** "Spawn shells, agents, editors, and previews on a boundless canvas — wire them with arrows."  
**Discovered:** 2026-10-25 (cloud backup)

---

## Why it fits

When you run multiple Claude Code sessions, the current workflow is one tmux pane or tab per agent — no spatial context, no visible relationships, no way to see the "shape" of a multi-agent task at a glance. ccanvas puts each agent in a widget on an infinite dark canvas: drag to arrange, draw arrows to show data flow, open web previews alongside the agents that generate the code. Workspaces save as self-contained `.ccnvs` files you can reopen later.

The user interest profile calls out **Agent UIs: custom agent interfaces** and **Dev productivity: coding assistants**. ccanvas hits both: it's a spatial shell for the multi-agent work the user already does, not a new agent framework.

Nothing in seen.json covers the infinite-canvas-as-agent-UI slot. The parallel-agent orchestrators (OpenRig, Orca, hivemind) handle scheduling; ccanvas handles *perception* — seeing what's running and where things connect.

## Shape

Two options:

Option A — **adopt upstream ccanvas.** If it builds cleanly on the user's system (Tauri, macOS/Linux), use it directly and add any missing keybindings or widget types.

Option B — **minimal local build.** A simpler web-based canvas (React + react-flow or tldraw) that embeds xterm.js terminals and xframe-style Claude previews is a weekend project. Ships as an Electron or Tauri app.

The plan below covers Option B (minimal local build) as a fallback; if Option A installs, skip to Phase 4.

## Stack

- Tauri 2 (desktop shell, Rust + WebView)
- React + tldraw or react-flow (canvas layer)
- xterm.js (terminal widgets)
- Node.js / Bun (file watching, workspace serialization)

## MVP scope

1. Empty infinite canvas with pan/zoom.
2. Add a terminal widget: real xterm.js shell, resizable, movable.
3. Inside that shell, run `claude` — the widget is now a live Claude Code session.
4. Add a second widget type: web preview (iframe).
5. Draw an arrow between two widgets (visual only, no data binding in MVP).
6. Save/load workspace as `.ccnvs` JSON.

## Phases

1. **Canvas scaffold (1 h).** Tauri project with a blank tldraw canvas. Pan, zoom, dark theme.
2. **Terminal widget (1.5 h).** Add an xterm.js terminal node type. It spawns a real shell (`$SHELL`) in the Tauri backend via Node PTY. Resize works.
3. **Claude widget (0.5 h).** A terminal widget pre-configured to run `claude` in a working directory you set at creation. No extra logic needed — it's just a shell with `claude` already running.
4. **Web preview widget (1 h).** An iframe node type. URL is editable inline. Useful for `localhost:3000` while an adjacent Claude agent works on the app.
5. **Arrow wiring (0.5 h).** tldraw handles this natively. Add a custom arrow handle on each node edge.
6. **Workspace save/load (0.5 h).** Serialize node positions, types, configs to `.ccnvs` JSON. Load restores the layout; shells restart in the saved directory.

## Effort

About 5 h total. A focused Saturday session. Option A (upstream) is under 15 min if Tauri builds cleanly.

## Blockers / risks

- **Tauri PTY on macOS:** Spawning real PTYs from Tauri's Rust backend requires `portable-pty` or `node-pty` via a sidecar. The upstream ccanvas README mentions this; follow its approach.
- **xterm.js resize:** Syncing terminal size to the node widget size is the trickiest part. Use xterm's `FitAddon` and fire a resize event on node resize.
- **Arrow semantics:** In the MVP, arrows are decorative. A later version could pipe stdout of one terminal into stdin of another — that's a significant scope expansion.
- **ccanvas creation date:** Could not confirm exact creation date from aggregators alone. The local agent should verify whether the repo predates the 7-day freshness window.
