# Orca — Multi-Agent Parallel Coding IDE

**Source:** GitHub — https://github.com/stablyai/orca  
**Tagline:** "Fan one task prompt across Claude Code, Codex, OpenCode, and Pi simultaneously — each in its own git worktree — then compare diffs and merge the winner."  
**Discovered:** 2026-10-20

---

## Why it fits

Prior tools in the parallel-agent space covered in this toolkit: **OpenRig** (Oct 13 — Claude + Codex harness), **Shadok** (Oct 13 — parallel agent cockpit). Both were early-stage. Orca is the mature version of the same idea: it has 65k+ GitHub stars, ships as a desktop app (macOS, Windows, Linux) with a companion mobile app (iOS/Android), and is MIT-licensed.

The core value is **worktree isolation**. Each agent gets its own `git worktree` so their file changes never collide and you can diff each agent's output against the shared base. Today the standard workflow is single-agent with retry-on-failure; Orca changes the model to multi-agent with explicit winner selection. For ambiguous tasks where different agents have different strengths (Claude Code for reasoning, Codex for autocomplete, OpenCode for free/local), the parallel compare is genuinely faster than sequential retries.

The mobile companion app is particularly relevant: while agents run on the desktop, you can approve/reject each agent's diff from a phone — the same itch that ccgram (Oct 19 digest) scratches for tmux, but with a native mobile UI.

## Stack Recommendation (for building a minimal Orca-like harness if desired)

- **Node.js / TypeScript** — orchestration layer
- **simple-git** — `git worktree add` per agent; `git diff` between worktrees after completion
- **child_process** — spawn `claude`, `opencode`, `codex` CLIs each in their worktree
- **Ink** (React for CLI) — terminal UI showing parallel progress + diff output side by side
- **Blessed / neo-blessed** — alternative TUI if Ink feels heavy

The standalone desktop app is Electron-based; for a weekend harness, a TUI is sufficient.

## MVP Scope (minimal harness, not full Orca)

1. Accept a task prompt on stdin
2. `git worktree add ../agent-claude HEAD` and `../agent-opencode HEAD` in a temp directory
3. Spawn `claude code <task>` and `opencode <task>` each in their worktree in parallel
4. When both complete, run `git diff HEAD` in each worktree; display side by side in the terminal
5. Prompt: "accept claude / accept opencode / abort" → apply the winner's patch to the main worktree and remove temporaries

Not in MVP: mobile app, Pi/Codex support, diff scoring, persistent session log.

## Phases

| Phase | Description | Effort |
|-------|-------------|--------|
| 1 | `git worktree add` wrapper: given a repo, create N named worktrees from HEAD | 30 min |
| 2 | Parallel agent spawn: run `claude --dangerously-skip-permissions -p "<task>"` and `opencode "<task>"` each in their worktree; collect exit codes | 45 min |
| 3 | Diff capture: `git -C <worktree> diff HEAD` for each agent; store as strings | 15 min |
| 4 | TUI: use Ink or blessed to show agent progress (running/done/error) and diffs side by side in the terminal | 60 min |
| 5 | Winner selection: apply chosen agent's diff to main worktree with `git apply`; `git worktree remove` both temps | 20 min |

**Total estimate:** ~3 h (1–2 Claude sessions for the harness; just install Orca for the full product)

## Blockers

- **Multiple subscriptions**: to run Claude Code and Codex in parallel you need active subscriptions for both; OpenCode supports local models via Ollama as a free fallback
- **Worktree conflicts**: if the repo has unstaged changes, `git worktree add` fails — stash first
- **Agent completion detection**: coding agents don't emit a clean exit signal when done; poll for file modification cessation or use a wrapper prompt that ends with a sentinel line
- **Diff merge conflicts**: if both agents modify the same file, the merge step requires manual resolution — limit MVP to winner-takes-all (no partial merging)
