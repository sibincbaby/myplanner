# heard — voice readback for Claude Code and Codex sessions

**Source:** [heardlabs/heard](https://github.com/heardlabs/heard) on GitHub — open-source (Apache 2.0) macOS voice tool for Claude Code and Codex; Kokoro TTS locally, no account needed; short spoken summary on finish / fail / needs-approval
**Discovered:** 2026-11-23
**Viability:** 4/4

> `heard` reads your coding agent's progress aloud so you don't have to watch the terminal. When a Claude Code session finishes, fails, or needs your approval it generates a one-sentence spoken summary and plays it through the system speaker. The build here is a macOS Claude Code hook implementation: Phase 1 uses the built-in `say` command (zero dependencies), Phase 2 adds Kokoro for a richer voice, and Phase 3 adds a tiny web UI for history and voice-preference settings.

## Implementation Plan

### Overview

A set of Claude Code hooks that fire on session events and read a brief summary aloud. No separate daemon or process manager.

```
# install into Claude Code hooks
heard install          # writes hooks into .claude/settings.json
heard uninstall        # removes hooks
heard test             # fires a sample "session complete" readback
heard config           # set voice, speed, length (brief / full)
```

### How Claude Code hooks work

Claude Code (2.1.x+) supports hooks in `.claude/settings.json` under `hooks`:

```json
{
  "hooks": {
    "Stop": [{ "type": "command", "command": "heard-hook stop" }],
    "Notification": [{ "type": "command", "command": "heard-hook notify" }]
  }
}
```

The `Stop` hook fires on every session exit (success or failure). The `Notification` hook fires when Claude needs approval. Both receive a JSON payload on stdin.

### Stack

| Layer | Choice |
|-------|--------|
| Phase 1 TTS | macOS `say` command (built-in, no install) |
| Phase 2 TTS | [Kokoro TTS](https://github.com/thewh1teagle/kokoro-rs) — MIT, runs locally, no account |
| Summary LLM | Claude claude-haiku-5-5 (fast, cheap) via `@anthropic-ai/sdk` |
| Hook runner | Bash script / Node.js shim |
| Config | `~/.config/heard/config.json` |

### MVP Scope (Phase 1, ~1h)

- Claude Code `Stop` hook: receives session summary from stdin JSON, generates a 1-sentence spoken summary with Haiku, calls `say "<summary>"`
- Claude Code `Notification` hook: reads the notification message and calls `say "Claude needs you: <message>"`

**Done when:** finishing a Claude Code session, walking away from the desk, and hearing "Session complete: added dark-mode toggle to the settings page" through the speakers.

### Phases

#### Phase 0: Setup (15 min)
1. Create `~/.local/bin/heard-hook` bash script (or `npx heard-hook`)
2. Add `Stop` and `Notification` hooks to `.claude/settings.json` (or `~/.claude/settings.json` for global)
3. Test with `echo '{"stop_hook_active":true}' | heard-hook stop` → `say "test"`

#### Phase 1: Basic readback with macOS say (1h)
1. `heard-hook stop`: reads stdin JSON, extracts last assistant message or session summary, calls `say`
2. `heard-hook notify`: reads stdin JSON, calls `say "Claude needs your attention: <notification text>"`
3. `heard install`: writes hooks into `.claude/settings.json` with backup
4. `heard test`: fires a mock stop event

#### Phase 2: Kokoro TTS + summary LLM (2h)
1. Download Kokoro model (~90 MB, `~/.config/heard/kokoro/`) on first use
2. Replace `say` with Kokoro for richer voice; fall back to `say` if Kokoro fails
3. Use Claude Haiku to generate a 1–2 sentence summary from the full session payload (more accurate than raw last-message)
4. Config flag: `voice: "kokoro" | "say" | "elevenlabs" | "speechify"`

#### Phase 3: History + web UI (2h)
1. Each readback logged to `~/.config/heard/history.jsonl` with timestamp, project, duration, summary
2. `heard history`: prints last 20 sessions in the terminal
3. Optional: `heard serve` → tiny local web page at `localhost:5555` with session history and voice config

#### Phase 4: Codex + multi-harness support (1h)
1. For Codex CLI: same approach but via Codex's hook mechanism (or a wrapper script that appends to a shared event pipe)
2. Test with `codex` sessions firing the same `heard-hook stop` script

### Effort Estimate

~0.5 Claude sessions to Phase 1 (working readback in <1h). Phase 2+3 adds another 0.5–1 session. Phase 4 is a quick add-on once Phase 2 is stable.

### Blockers / Risks

| Risk | Mitigation |
|------|-----------|
| Hook stdin payload format | Test with `claude --debug` to capture exact payload structure before coding against it |
| `say` rate-limiting / overlap | Add a lock file; skip readback if one is already playing |
| Kokoro model availability | Bundle the download step in `heard install`; fall back to `say` gracefully |
| Session payload too large for Haiku | Truncate to last 2000 tokens before summary call; note truncation in spoken output |
| Linux / Windows | Phase 1: scope to macOS only; note `espeak-ng` as a Linux substitute for `say` |
