# agenthud — TUI Dashboard for Live Claude Code Sub-Agent Sessions

**Source:** [neochoon/agenthud](https://github.com/neochoon/agenthud) · GitHub (updated August 2026) · TUI, LLM digest
**Date discovered:** 2026-08-20

## What it is

AgentHUD is a terminal-UI dashboard that monitors Claude Code sessions in real time — specifically parallel sessions and their sub-agents. It reads the JSONL session logs that Claude Code writes to `~/.claude/projects/`, parses tool calls and cost data as they land, and renders a live instrument panel: which sessions are active, what each sub-agent is doing right now, how many tokens have been spent, and which are stalled. A second feature is the LLM-generated daily/weekly digest: at end-of-day it feeds the session log to a model and emits a structured summary of what was attempted and what shipped.

The gap it fills is different from `hud-mode` (08-06), which wraps a single agent session with a heads-up display at the terminal. AgentHUD is a cross-session observer: it sits outside all your sessions and gives you the fleet view — who is running, what it cost, and whether anything needs attention. The digest feature is the novel half — nothing in the backlog attempts to summarize across sessions with an LLM.

## Why it fits

- Core interest: **agent UIs** — fleet-level terminal dashboard, not a single-session wrapper
- Core interest: **Claude/LLM tooling** — reads the same JSONL format Claude Code writes; the digest calls the same API
- Core interest: **dev productivity** — end-of-day summary of what your agents actually accomplished vs. what you set them up to do
- `novel = 1`: the cross-session view + LLM digest combination is not in any prior plan; `hud-mode` covers the within-session instrument panel

## Stack Recommendation

```
Language:  Python 3.11+ with uv
TUI:       rich (Layout, Live, Panel, Table, Tree) — already the de facto standard for this
JSONL:     stdlib json + watchdog for live file-change events
Digest:    Claude API (claude-sonnet-5 or haiku for cost) — summarize today's session logs
Config:    ~/.agenthud.toml — session dir, digest model, cost thresholds, alert rules
```

No database. The JSONL files are the database. If the JSONL format changes with a Claude Code update, this breaks — that is the single biggest risk, and it is not fixable from outside Anthropic.

## MVP Scope (1-2 Claude sessions)

One session, one file:
1. Scan `~/.claude/projects/` for `.jsonl` files modified in the last 24h
2. Parse each file: extract timestamps, model, tool\_use calls, token counts, cost
3. Render a `rich.Live` panel: sessions as rows, tool call activity as nested list, running cost
4. Refresh every 2 seconds using `watchdog` file-change events
5. Print a plain-text summary at `Ctrl-C` (today's sessions, total cost, top tools)

Digest is phase 2. The live panel is the MVP.

## Phases

### Phase 1: JSONL Parser (1h)
- Read a Claude Code session JSONL; extract: timestamp, role, model, tool\_use (name, input keys), token usage, cost
- Handle the deduplication trap: streaming writes the same API response multiple times with growing `output_tokens`; keep the copy with the largest usage (same fix as `mtok`)
- Handle sub-agent transcripts: these are separate JSONL files under a `--session-id`; link them by parent session ID
- Verify: parse 10 real sessions without crash, total cost matches what Claude Code's own cost display shows

### Phase 2: Live TUI (1.5h)
- `rich.Layout` with three panels: session list (left), active session detail (centre), cost summary (right)
- Session list: session ID + age + status (active / stalled / done) + cost so far
- Active detail: last 5 tool calls with name, file path (for file tools), elapsed time
- Stall detection: a session that has made no tool call in >90s is highlighted in yellow; >5m is red
- Verify: open two Claude Code sessions in parallel; both appear in the dashboard within 2s

### Phase 3: Sub-Agent Tree (1h)
- Parse the `subagent_id` field (or equivalent) in JSONL to build a parent/child tree
- Render as `rich.Tree` in the active-detail panel
- Colour by status: green = active, grey = done, red = stalled
- Verify: a workflow that spawns 3 sub-agents shows the correct tree with correct status colours

### Phase 4: LLM Digest (1h)
- At day end (via cron or manual `agenthud --digest`), read all today's JSONL files
- Prompt: "Given these Claude Code session logs, summarise: tasks attempted, tasks completed, cost, most-used tools, anything that looks stalled or failed. Be concise."
- Write to `~/.agenthud/digests/YYYY-MM-DD.md`
- Verify: the digest for yesterday's sessions is accurate, under 500 words, and takes under 30s to generate

### Phase 5: Alerts (0.5h)
- Desktop notification (macOS `osascript` / Linux `notify-send`) when a session stalls >5m
- Optional: webhook URL for Slack/Discord notifications
- Verify: start a session, block it artificially, receive a notification within 6 minutes

## Blockers / Risks

- **JSONL format is undocumented and changes.** Claude Code's session format is an internal implementation detail. A Claude Code update that changes the file format breaks this silently — it does not crash, it just parses the wrong fields. The mitigation is to log the parsed field names on first run and alert when a new session file has unknown keys.
- **The lane is crowded.** Five prior plans in the agent-monitoring space are unbuilt. If the friction is "no clean way to parse JSONL", that is Phase 1. If the friction is something else, this plan will not be built either. Run `hud-mode` first and find out what is actually missing.
- **Sub-agent linking.** Claude Code sub-agents may not write their parent session ID into the JSONL in a machine-readable way. If the link is only in the display text, Phase 3 is not implementable from outside the CLI. Verify before writing any tree code.
- **Digest cost.** Summarising a full day's sessions for an active user could be 50–100k tokens of input. Use Haiku for the digest pass; add a `--max-tokens` flag that truncates to the last N tool calls before the API call. Do not let the digest cost more than the sessions it summarises.
