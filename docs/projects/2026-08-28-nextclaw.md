# NextClaw — Self-Hosted Agent Workspace with Panel Apps and Scheduled Workflows

**Source:** [Peiiii/nextclaw](https://github.com/Peiiii/nextclaw) · TypeScript · 253★ · GitHub (Aug 2026)
**Date discovered:** 2026-08-28

## What it is

NextClaw is a self-hosted AI agent workspace that consolidates conversations, files, tools, and results into a unified interface. Its two architectural differentiators vs prior picks are:

**Panel Apps** — mini-applications built inside a task that persist in the sidebar when the conversation ends. An agent writes a SQL query form, a markdown diff viewer, or a test runner button during a session; the Panel App stays pinned and reusable across future sessions. No prior workspace pick has retained intermediate artifacts this way.

**Scheduled Workflows** — recurring briefs and automated checks that run independently of a live session. Set a 07:00 daily brief ("summarise open PRs, check CI, report anomalies"), a 30-minute deploy monitor, or a weekly code-quality sweep. These fire without you opening the workspace.

Additional capabilities:
- **Multi-runtime support** — native, Codex, Claude Code, OpenCode, Hermes runtimes switchable per task
- **Messaging integrations** — Weixin, Feishu/Lark, Telegram, Slack, Discord, and others; agents can send and receive messages
- **File inspection** — opens code, Markdown, Excel, Word, and PowerPoint alongside the conversation
- **Local-first** — configurations and conversations remain on-device; `npm install -g nextclaw` or Docker
- **3,074 commits**, MIT licensed, macOS/Windows/Linux desktop app available

## MVP Scope (1 Claude session)

Install, wire Claude Code + Telegram, and run the first Scheduled Workflow:

1. **Install + launch** — `npm install -g nextclaw && nextclaw`
2. **Claude Code runtime** — select Claude Code runtime; verify it spawns a Claude Code subprocess for tasks
3. **Telegram integration** — create a Telegram bot via BotFather; paste token into nextclaw; send `/ping` from phone to confirm agent replies
4. **First Panel App** — ask agent to "build me a SQL query form for the users table" — observe the Panel App appear in the sidebar; close the session; confirm the Panel App persists

## Phases

### Phase 1: Install + Claude Code Runtime (0.5h)
- `npm install -g nextclaw && nextclaw`
- Select Claude Code runtime; set ANTHROPIC_API_KEY or use claude CLI auth
- Open a task; run a simple coding request to verify Claude Code subprocess fires
- Verify: task shows Claude Code tool calls in the activity log with correct token counts

### Phase 2: Telegram Messaging Integration (0.5h)
- Create a bot via @BotFather → get token
- Add to nextclaw Integrations → Telegram → paste token
- Test: trigger a task from the Telegram chat; confirm the agent replies in thread
- Test: long-running task → agent sends "done" push notification to Telegram when finished
- Verify: two-way messaging works from phone without opening the workspace

### Phase 3: Morning Brief Scheduled Workflow (1h)
- Create `~/.nextclaw/workflows/morning-brief.yaml`:
  ```yaml
  name: morning-brief
  schedule: "0 7 * * *"
  runtime: claude-code
  prompt: |
    Check: open PRs on all watched repos, CI status on main branches,
    any new GitHub issues assigned to me. Summarise in 5 bullets.
  notify: telegram
  ```
- Enable workflow; wait for next 07:00 trigger (or use `nextclaw workflow run morning-brief` to test immediately)
- Verify: Telegram receives the 5-bullet summary with PR/CI links

### Phase 4: Panel Apps Workflow (1h)
- In a normal coding task, ask agent: "build a Panel App that lets me query the users table — text input, submit button, paginated results"
- Confirm the Panel App appears in the sidebar and persists after closing the task
- Save the Panel App as a template: `nextclaw panel save users-query`
- In a new task, ask agent: "load the users-query Panel App and show me users created in the last 7 days"
- Verify: agent opens the persisted Panel App and runs the query, not re-generating it from scratch

### Phase 5: Deploy Monitor Workflow (1h)
- Create `deploy-watch.yaml`:
  ```yaml
  name: deploy-watch
  schedule: "*/30 9-18 * * 1-5"
  runtime: claude-code
  prompt: |
    Check latest deploy on <project>: status, error rate vs. yesterday, p95 latency.
    If error rate increased >10% or latency >2s, send urgent Telegram alert.
  notify: telegram
  alert_threshold: error_rate > 10% OR p95_latency > 2000ms
  ```
- Wire to CI/CD provider via MCP or webhook
- Verify: trigger a mock deploy failure; confirm urgent Telegram alert arrives within 30m

## Blockers / Risks

- **Claude Code runtime requires local claude CLI.** The nextclaw Claude Code runtime spawns a `claude` subprocess — the Claude CLI must be installed and authenticated on the same machine. In the cloud session, this works; on a fresh machine, run `npm install -g @anthropic-ai/claude-code && claude login` first.
- **Scheduled Workflows require nextclaw to be running.** Unlike a cron daemon, the scheduler is in-process. Use the Docker image with `--restart=unless-stopped` to keep workflows firing after reboots.
- **Panel App persistence is local.** Panel Apps are stored in `~/.nextclaw/`; they don't sync across machines yet. Back up the directory alongside project configs if using multiple machines.
- **Telegram bot visibility.** A Telegram bot must be started by the user before it can send messages (Telegram API limitation). Send `/start` to the bot from your phone before the first workflow fires, or the notification will silently fail.
- **Workflow YAML schema.** The schema in Phase 3 is illustrative — verify the actual field names against `nextclaw workflow --help` or the README schema after install. The `alert_threshold` field in Phase 5 may need a different syntax.
