# claude-journal — Personal Memory Layer for Claude Code

**Source:** [obra/private-journal-mcp](https://github.com/obra/private-journal-mcp) · [chrismbryant/claude-journal-mcp](https://github.com/chrismbryant/claude-journal-mcp) · GitHub (both new, Aug 2026)
**Date discovered:** 2026-08-21

## What it is

Two independent MCP servers for Claude journaling appeared this week:

**private-journal-mcp (obra):** A comprehensive MCP server that provides Claude with private journaling and semantic search. Multi-section journal (thoughts, insights, reflections), dual storage options (SQLite + markdown), timestamped entries with YAML frontmatter, semantic search using local AI embeddings, no external API calls.

**claude-journal-mcp (chrismbryant):** A lightweight journal/memory plugin for Claude Code with zero ML dependencies. Slash commands (`/journal add`, `/journal search`), proactive skills, auto-capture hooks that save relevant context from each session end.

Together they define the same gap: Claude has no memory between sessions. Everything you tell Claude in one session is gone by the next. These tools give Claude a personal journal it can read from and write to, so context, decisions, and insights accumulate over time.

## Stack Recommendation

```
Language:   Python 3.11+ with uv (MCP server via mcp[cli] package)
Storage:    SQLite (stdlib via sqlite3) — entries as rows with timestamp, section, content, tags
Search:     Phase 1: keyword search via SQLite FTS5 (zero ML, works offline)
            Phase 3: optional semantic search via sentence-transformers local model
MCP tools:  add_entry, list_entries, search_entries, get_entry, daily_summary
Config:     ~/.config/claude-journal/config.toml — db path, default section
```

Storage: one SQLite file at `~/.claude-journal/journal.db`. All entries are also mirrored as markdown files in `~/.claude-journal/entries/YYYY-MM-DD-<id>.md` for git-committability and human readability.

## MVP Scope (1-2 Claude sessions)

Five MCP tools, one session:

1. `add_entry(content, section="general", tags=[])` — append a timestamped entry
2. `list_entries(limit=20, section=None, date=None)` — list recent entries
3. `search_entries(query, limit=10)` — keyword search via SQLite FTS5
4. `get_entry(id)` — retrieve a specific entry with full content
5. `daily_summary(date=None)` — concatenate today's entries as a briefing

One Claude Code skill (`SKILL.md`): on session start, call `daily_summary` for today and yesterday. On session end, call `add_entry` with a one-line reflection on what happened this session.

## Phases

### Phase 1: MCP Server Core (1.5h)
- Set up Python MCP server with `mcp[cli]`
- SQLite schema: `entries(id, timestamp, section, content, tags, source_session)`
- Implement 5 MCP tools listed above
- FTS5 virtual table on content for keyword search
- Verify: add 3 entries, list them, search for a word that appears in one — correct result returns

### Phase 2: Claude Code Skill (0.5h)
- `.claude/skills/journal/SKILL.md` with:
  - On-load trigger: "reflect", "remember", "journal", "what did I learn", "last session"
  - On-load: call `daily_summary(today)` and include in context
  - Proactive hook on session end: call `add_entry` with a summary
- Verify: start a session, load skill, call `add_entry` manually, end session, restart — `daily_summary` includes the entry

### Phase 3: Auto-Capture Hooks (1h)
- Claude Code `PostToolUse` hook: when a file is written or a test passes, automatically call `add_entry(section="code", content="<filename> written / test passed")` — silent background logging
- `PostSessionStop` hook: capture total cost and tools used as a session stats entry
- Verify: write a file in a Claude Code session — journal entry appears without any manual action

### Phase 4: Semantic Search (1.5h)
- Add optional dependency: `sentence-transformers` (local model, no API calls)
- On `add_entry`: generate embedding, store in a `vectors` table (SQLite BLOB)
- `search_entries` falls back to FTS5 if `sentence-transformers` is not installed; uses cosine similarity if it is
- Verify: add entries about "token budgets" and "cost optimization"; search for "spending limits" — semantic match finds them even without the exact phrase

### Phase 5: Daily Digest CLI (0.5h)
- `claude-journal digest [--date YYYY-MM-DD]` — print a markdown summary of the day's entries, grouped by section
- `claude-journal export [--from YYYY-MM-DD] [--to YYYY-MM-DD]` — export entries as a single markdown file for review or sharing
- Verify: 10 entries from today produce a clean readable digest in under 2 seconds

## Blockers / Risks

- **Hook reliability.** Claude Code hooks (`PostToolUse`, `PostSessionStop`) are the mechanism for auto-capture, but the hook system is not guaranteed to fire on crash or kill. Entries from interrupted sessions may be missing. Accept this: the journal is best-effort, not transactional. A missed entry is not a crisis.
- **Embedding model size.** `sentence-transformers` with a small model (`all-MiniLM-L6-v2`) is ~90MB. On a machine with limited disk this might be unwanted. The FTS5 fallback makes semantic search optional, not required. Phase 3 is explicitly an upgrade, not a prerequisite.
- **Section schema creep.** Both source repos invented different section schemas. Don't design the schema in advance — start with `section = "general"` and let the actual journal entries reveal what sections you actually use. Migrate sections later with a simple SQL UPDATE.
- **MCP server process management.** The MCP server runs as a background process alongside Claude Desktop/Code. If it crashes, journal writes fail silently. Add health-check logging on start and a `claude-journal status` command that verifies the server is reachable before each session.
