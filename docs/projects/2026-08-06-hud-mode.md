# hud-mode — Compact Terminal HUD for Coding Agents

**Source:** [adrida/hud-mode](https://github.com/adrida/hud-mode) · [Show HN 49184388](https://news.ycombinator.com/item?id=49184388)
**Language:** Node.js ≥18 (zero dependencies, MIT) · **Platform:** Terminal wrapper for Claude Code / Codex / OpenCode
**Date discovered:** 2026-08-06

## What it is

A heads-up display that sits in front of a coding agent's CLI. Instead of an unbounded wall of scrolling tool output, you get a fixed instrument panel — status, model, message count, tokens, elapsed time, running cost — plus an always-writable prompt bar that queues your next message mid-turn. When the agent finishes, it renders the full answer. You can toggle between HUD and raw CLI without losing session state.

It drives each agent through its JSON event stream (`--output-format stream-json`), so nothing is scraped or screen-parsed. Extras: a per-session ledger of every URL the agent touched (clickable), QR-code session sharing, and a `/gauges` command to pick which instruments show.

Problem it solves: during a long agent turn you either stare at 400 lines of `Read`/`Grep`/`Edit` noise or you look away and lose all sense of whether it is stuck, burning tokens, or nearly done. The HUD answers "what is it doing and what has it cost me" in one glance.

## Stack Recommendation

```
Node.js 20+           — matches upstream; stream-json parsing is a two-liner
(no dependencies)     — process.stdout.write + ANSI escapes is enough for a fixed panel
child_process.spawn   — run `claude -p --output-format stream-json --verbose`
readline              — the always-writable prompt bar on the bottom line
```

Deliberately no blessed/ink/react-ink. A HUD is a fixed set of lines redrawn in place; a full TUI framework is more machinery than the job needs. Reach for `ink` only if the layout grows past a static panel.

Key primitives:
- `\x1b[s` / `\x1b[u` — save/restore cursor around a redraw
- `\x1b[<n>A` + `\x1b[2K` — move up and clear a line
- `\x1b[?25l` / `\x1b[?25h` — hide/show cursor during redraw to kill flicker

## MVP Scope (1 Claude session)

1. Spawn `claude -p "<prompt>" --output-format stream-json --verbose` and read stdout line-by-line as NDJSON
2. Maintain a state object from the events: current tool name, message count, cumulative input/output tokens, elapsed seconds
3. Redraw a 3-line panel in place on every event — `status · model · msgs · tokens · $cost · elapsed`
4. On the terminal `result` event, clear the panel and print the final assistant text in full
5. Verify against a real task: token count matches what `/cost` reports at the end

## Phases

### Phase 1: Stream Reader + Static Panel (2h)
- Spawn the agent with `--output-format stream-json --verbose`, pipe stdout through a line splitter
- Parse each NDJSON event; branch on `type` (`system`, `assistant`, `user`, `result`)
- Accumulate: `usage.input_tokens`, `usage.output_tokens`, `total_cost_usd`, tool name from the last `tool_use` block
- Redraw a fixed 3-line panel with ANSI cursor-up + clear-line on each event
- Verify: run a task that reads 5 files, confirm the tool name updates live and the final token count matches `result.usage`

### Phase 2: Final Answer Render (1h)
- On `result`, tear down the panel and print the assembled assistant text
- Handle the error/`is_error` path — show the failure, do not swallow it into a blank panel
- Handle Ctrl-C: restore the cursor (`\x1b[?25h`), kill the child, exit non-zero
- Verify: the answer is byte-identical to what plain `claude -p` prints

### Phase 3: Always-Writable Prompt Bar (2-3h)
- Reserve the bottom line for input via `readline` with the panel drawn above it
- Typed messages while a turn is in flight go into a queue, not to the agent
- On turn end, drain the queue as the next prompt (resume with `--resume <session-id>` from the `system.init` event)
- Verify: type three messages mid-turn, confirm all three are delivered in order after the turn completes

### Phase 4: Configurable Gauges (2h)
- `~/.hud/gauges.json` — an ordered list of instrument ids to render
- Ship: `status`, `model`, `msgs`, `tokens`, `cost`, `elapsed`, `tool`, `cwd`, `branch`
- `/gauges` command toggles them at runtime and persists the choice
- Verify: remove `cost`, restart, confirm the panel is narrower and the value is no longer computed

### Phase 5: Link Ledger + Raw Toggle (2-3h)
- Scan every event's text and tool args for URLs; dedupe into a per-session list
- `/links` prints the ledger with OSC 8 hyperlink escapes so the terminal makes them clickable
- `Ctrl-R` toggles between HUD mode and raw passthrough of the underlying stream, without restarting the session
- Verify: run a task that does three WebFetches, confirm all three URLs land in the ledger exactly once

## Blockers / Risks

- The `stream-json` event schema is not a stability guarantee — field names like `usage.cache_read_input_tokens` have shifted between Claude Code releases. Read defensively (`?.` everywhere, never destructure required fields) and pin the CLI version in `CLAUDE.md`
- Cost is only exact on the `result` event; per-turn running cost must be estimated from token counts and model pricing, so label it as approximate until the turn closes
- Terminal resize (`SIGWINCH`) mid-redraw corrupts the panel — recompute widths on resize and force a full repaint
- The queued-prompt design assumes a linear session. Subagent/Task fan-out produces interleaved events from multiple agents; the MVP should show the parent only and count subagent tokens into the total rather than trying to render parallel panels
- `--output-format stream-json` implies `-p` (non-interactive), so permission prompts cannot be answered mid-turn. Either run with a pre-approved allowlist or accept that a permission-blocked tool call ends the turn
- Terminals without OSC 8 support (older tmux, some Linux consoles) render hyperlinks as raw escape noise — feature-detect via `$TERM_PROGRAM` and fall back to printing bare URLs
