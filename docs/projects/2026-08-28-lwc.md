# LWC — Machine-First Persistent Memory for AI Agents

**Source:** [JanYork/llm-wiki-cli](https://github.com/JanYork/llm-wiki-cli) · Rust · 48★ · GitHub (Aug 2026)
**Date discovered:** 2026-08-28

## What it is

LWC (llm-wiki-cli, published as `@i-xor/lwc`) is a Rust CLI built as a machine interface — not a note-taking app for humans but a structured knowledge store that AI agents read from and write to between sessions. Where traditional RAG retrieves raw document chunks at query time, LWC lets the agent maintain a living wiki: synthesized pages with citations, links, and provenance that survive across conversations.

Knowledge is organised in four layers:
- **Immutable source snapshots** — verbatim captures, never modified after ingest
- **Agent-maintained wiki pages** — synthesised, cross-linked pages agents edit as they learn
- **Temporal memory records** — indexed by time range; agents can recall "what did I decide last Tuesday"
- **Project-specific schemas** — per-repo structure definitions so the wiki knows the codebase shape

Additional capabilities:
- **CodeGraph** — analyses code structure across 30+ languages; agents resolve symbols, callers, and dependency chains cross-session
- **Hierarchical recall** — document → passage → sentence; agents can pin the exact sentence they are reasoning from
- **Multi-machine sync** — reconcile knowledge across dev machine and CI box via SSH
- **Full-text search** — deterministic, lexical, CJK-aware; no vector drift between runs
- `npm install -g @i-xor/lwc` or Homebrew, works with Claude Code, Cursor, Codex, OpenCode, Gemini CLI

## MVP Scope (1 Claude session)

Install LWC, wire it to Claude Code, and add 10 pieces of persistent knowledge during a normal coding session:

1. **`lwc init`** — initialise wiki in `~/.lwc/` with project-level schema for the main repo
2. **Agent-write test** — tell Claude Code: "after every major architectural decision, run `lwc add decision:<title>` and summarise the reasoning". Verify a wiki page appears.
3. **`lwc codegraph`** — point at the main repo root; verify symbol index is built and queryable
4. **`lwc recall "auth flow"`** — confirm recall works across a fresh session (no prior context)
5. **Daily summary** — add a `lwc summary` call to the session-start hook in CLAUDE.md

## Phases

### Phase 1: Install + Wire (1h)
- `npm install -g @i-xor/lwc && lwc init`
- Define project schema for main repo: modules, key classes, architectural invariants
- Add to CLAUDE.md: after each architectural decision agent runs `lwc add decision:<slug>`
- Add session-start hook: `lwc recall --since 7d --limit 10` echoes recent decisions to context
- Verify: open a new Claude Code session; confirm recent decisions appear at turn 1

### Phase 2: CodeGraph Integration (1h)
- Run `lwc codegraph --root ~/projects/<main-repo>` — builds symbol index
- Add `/graph-search` slash command: `lwc graph search <symbol>` returns callers, call sites, and dependency chain
- Test: ask Claude Code "where is UserAuthService used?" — confirm it calls `lwc graph search UserAuthService` rather than re-reading source
- Verify: agent correctly cites the 3 files that import the service

### Phase 3: MCP Bridge (1h)
- Write a thin TypeScript MCP server (`lwc-mcp`) with three tools:
  - `wiki_add(key, content, source_url)` → shells `lwc add`
  - `wiki_recall(query, since?)` → shells `lwc recall` and returns JSON
  - `wiki_graph(symbol)` → shells `lwc graph search`
- Register in `~/.claude/mcp.json` so all Claude Code sessions share the same wiki via MCP
- Verify: two separate Claude Code sessions both read the same wiki page without re-generating it

### Phase 4: Daily Summary Skill (0.5h)
- Add a Claude Code skill: `lwc-daily-summary`
- At session start: `lwc summary --since yesterday --format bullets`
- Output: 5-bullet "what changed in the wiki since yesterday" — surfaces architecture drift and resolved ambiguities
- Verify: add 3 wiki pages one day → next morning summary lists all 3

### Phase 5: Multi-Machine Sync (0.5h)
- Configure `lwc sync --ssh user@ci-box` in a post-session hook
- CI box can now `lwc recall` the same knowledge before running agent-assisted refactors
- Verify: add a decision on dev machine → CI box reads it within 30s

## Blockers / Risks

- **Rust binary distribution.** `npm install -g @i-xor/lwc` works on macOS/Linux but Windows support is unclear for the binary targets. If on Windows, use WSL2 or Homebrew-via-Linuxbrew as fallback.
- **Agent discipline.** The tool is only as good as the agent's habit of calling `lwc add` consistently. Enforce via a post-turn hook in CLAUDE.md: if the agent's last action touched any architectural file, it must call `lwc add decision:` before ending the session.
- **Wiki page quality on early ingests.** The first 10 pages will be rough — the agent is calibrating what level of detail to write. Review them manually at the end of Phase 1 and correct 2-3 as examples; the agent will follow the pattern.
- **CodeGraph index size.** A large repo (500k+ LOC) produces a large SQLite index. Set `--max-depth 5` during initial `lwc codegraph` to limit the symbol graph to the most relevant layers; deepen incrementally.
- **Temporal recall precision.** `--since 7d` returns everything for the past week; on a busy week with 50 decisions this is too much context. Add a `--limit 10 --sort relevance` flag to the session-start recall so only the most-queried items appear at turn 1.
