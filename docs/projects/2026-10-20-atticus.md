# Atticus — macOS Voice Assistant on Claude Plan

**Source:** GitHub — https://github.com/SaarthurR/atticus-mac  
**Tagline:** "Hold Control+Option+Space, speak your request, get a Claude response — no API key, no monthly cost beyond your existing Claude Pro or Max plan."  
**Discovered:** 2026-10-20

---

## Why it fits

Every voice-to-Claude tool in this toolkit so far has required a separate Anthropic API key, which means a second billing relationship and a rate-limited bucket outside the Claude plan subscription. Atticus closes that gap: it routes through `claude -p` (the Claude Code subprocess interface) so the request consumes your existing Claude Pro/Max plan quota, not a pay-per-token API balance.

The implementation is also genuinely simple: Apple's on-device Speech Recognition transcribes the audio locally — no cloud transcription cost, no Whisper server — and the text goes to `claude -p`. For short commands, the loop is faster than typing. A safe-mode flag runs commands through the Claude Code sandbox, blocking destructive shell operations.

Prior voice tools covered: `OpenWhispr` (Aug 30), `TypeWhisper`, `voice-to-code` (Oct 14), `vupai` (Oct 19). None of these use the Claude plan subscription path; all require an API key. Atticus is the first covered tool that can run on a free-tier or subscription plan with zero additional cost.

## Stack Recommendation

- **Swift / SwiftUI** — native menu bar app with `NSStatusItem`, zero dependencies beyond Xcode
- **AVFoundation + Speech framework** — on-device transcription; no Whisper server required
- **Process / Foundation** — shell out to `claude -p "<text>"` and capture stdout
- **UserDefaults** — persist shortcut keys, safe-mode flag, memory snippets

Alternatively, a **Python** port using `pyobjc-framework-Cocoa`, `sounddevice`, and `speechrecognition` (with the macOS speech backend) is viable if you prefer Python and want a shorter iteration loop with Claude Code.

## MVP Scope

1. Global hotkey (Control+Option+Space) registers via `NSEvent.addGlobalMonitorForEvents`
2. While held: record audio from default microphone via AVFoundation
3. On release: run Apple Speech Recognition on the buffer; get transcript
4. Pass transcript to `claude -p "<transcript>"` and wait for stdout
5. Display response in a floating HUD (NSPanel, non-activating) or speak it back via `NSSpeechSynthesizer`

Not in MVP: persistent memory, learned shortcuts, safe mode, multi-pane routing.

| 5 | Response display: NSPanel floating overlay with the reply text; dismiss on next hotkey press or click-outside | 20 min |

**Total estimate:** ~2.5 h (1 Claude session)

## Blockers

- **`claude -p` availability**: requires Claude Code installed and authenticated (`claude --version` must succeed from a shell launched by a non-Terminal app — set `PATH` explicitly in the subprocess environment)
- **macOS permissions**: microphone access (`NSMicrophoneUsageDescription`) and Accessibility (for the global hotkey) must be granted; test early
- **Response latency**: `claude -p` cold-starts a subprocess; for snappy feel, keep the process warm or use a persistent stdin pipe
- **Safe mode scope**: if exposing shell-command execution, restrict to the Claude Code sandbox; `claude --sandbox -p "..."` applies the permission model
