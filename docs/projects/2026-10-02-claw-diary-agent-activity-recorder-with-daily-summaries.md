# Claw Diary – Agent Activity Recorder with Daily Summaries

**Source:** <https://github.com/0xbeekeeper/claw-diary>
**Discovered:** 2026-10-02
**Viability:** 4/4

> Answers "what did my agent actually do today?" with a narrative diary rather than a raw log. The hook integration means the recorder is always-on inside Claude Code with no manual effort. Daily narrative summaries (generated by the same LLM) turn a JSONL audit log into something readable and searchable — a daily entry that names what was built, what was decided, what was blocked. Visual timeline replay is the standout feature: replay a session step-by-step to understand how a complex task unfolded.

## MVP Scope

Always-on Claude Code hooks that record every tool call (name, inputs, output summary, duration) to a JSONL file keyed by session ID and date. At session end, a Stop hook generates a narrative Markdown summary. A `diary show` CLI command displays today's summary. A `diary timeline <session-id>` command renders the tool call sequence in the terminal.

Out of scope for MVP: cross-session search, visual HTML export, replay animation, team sharing.

## Implementation Phases

### Phase 1: Hooks + JSONL Logger
**Goal:** Every tool call in Claude Code is recorded to a timestamped JSONL file with no user action required.

**Files:**
- `.claude/hooks/diary_pretool.py` — PreToolUse hook: records tool start
- `.claude/hooks/diary_posttool.py` — PostToolUse hook: records tool completion + output summary
- `.claude/hooks/diary_stop.py` — Stop hook: finalises the session record
- `src/claw_diary/logger.py` — `DiaryLogger`: `log_tool_start`, `log_tool_end`, `log_session_end`
- `src/claw_diary/paths.py` — `session_log_path(session_id)`, `daily_summary_path(date)` under `~/.local/share/claw-diary/`

**Key steps:**
1. Hooks receive JSON on stdin (Claude Code hook contract). `diary_pretool.py`: parse stdin, extract `session_id`, `tool_name`, `tool_input` dict. Write a `{"type": "tool_start", "session_id": ..., "tool": ..., "input_summary": ..., "ts_start": ...}` line to the session JSONL.
2. `input_summary`: for large inputs (e.g. file contents > 500 chars), truncate to first 200 chars + `… [N chars]`. For small inputs, include verbatim.
3. `diary_posttool.py`: same stdin parsing; write `{"type": "tool_end", ..., "duration_ms": ..., "output_summary": ..., "exit_code": ...}`. `output_summary` = first 200 chars of the output string.
4. `diary_stop.py`: write `{"type": "session_end", "session_id": ..., "ts_end": ..., "tool_count": N}`.
5. Log path: `~/.local/share/claw-diary/sessions/<YYYY-MM-DD>/<session_id>.jsonl`. Create dirs on first write.
6. Each hook must exit 0 and never raise (wrap in `try/except`; on error write to `~/.local/share/claw-diary/errors.log` and exit 0).

**Verify:** Run a Claude Code session that uses Read, Edit, and Bash tools. Inspect the JSONL file. Every tool call has a `tool_start` + `tool_end` pair with correct timing. `diary_stop` fires at session end.

---

### Phase 2: Narrative Summary Generation
**Goal:** At session end, a narrative Markdown summary is generated from the JSONL log using Claude.

**Files:**
- `src/claw_diary/summariser.py` — `generate_summary(session_id)` → Markdown string
- `src/claw_diary/reader.py` — `load_session(session_id)` → list of event dicts
- `.claude/hooks/diary_stop.py` — updated to call `generate_summary` after finalising the log
- `prompts/diary_summary.txt` — system prompt for narrative generation

**Key steps:**
1. `load_session`: reads all JSONL lines for a session, pairs each `tool_start` with its matching `tool_end` by `tool_id` (UUID generated at start, threaded through both events).
2. Build a compact session transcript for the LLM: `[HH:MM:SS] Read src/foo.py (200ms) → "class Foo:" ...`, one line per tool call, capped at 6 000 tokens.
3. System prompt (`diary_summary.txt`): "You are writing a developer's diary entry for a coding session. Given a list of tool calls, write a narrative paragraph describing what was built, what decisions were made, and what problems were encountered. Be specific about file names and outcomes. Write in past tense, first person, as if the developer wrote it."
4. Call `messages.create` with the transcript; write the Markdown to `~/.local/share/claw-diary/daily/<YYYY-MM-DD>.md` (appending if the file exists — multiple sessions in one day each append a new entry).
5. Print a one-line summary to stderr after generation: `[claw-diary] Session summary written → 2026-10-02.md`.

**Verify:** Complete a real Claude Code session. Check `~/.local/share/claw-diary/daily/2026-10-02.md`. Entry reads as a coherent narrative naming the files touched and tasks completed.

---

### Phase 3: CLI — Show + Timeline
**Goal:** `diary show` displays today's summary; `diary timeline` renders a session as a step-by-step visual timeline.

**Files:**
- `src/claw_diary/cli.py` — Typer app: `diary show [--date]`, `diary timeline <session-id>`, `diary sessions`
- `src/claw_diary/timeline.py` — `render_timeline(events)` → Rich `Tree` or `Table`

**Key steps:**
1. `diary show [--date YYYY-MM-DD]`: reads the daily Markdown file and prints it with `rich.markdown.Markdown`. Defaults to today.
2. `diary sessions [--date YYYY-MM-DD]`: lists all session IDs for a date with start time and tool count. Prints from directory listing.
3. `diary timeline <session-id>`: calls `load_session`, then `render_timeline`. Timeline is a Rich `Tree` where each branch is a tool call:
   ```
   Session abc123 — 2026-10-02 14:32 — 23 tool calls
   ├─ 14:32:01 Read src/main.py (120ms) ✓
   ├─ 14:32:03 Edit src/main.py (89ms) ✓
   ├─ 14:32:05 Bash: pytest (4823ms) ✓
   └─ 14:32:11 Edit src/main.py (95ms) ✓
   ```
4. Colour coding: green for success (exit 0 / no error), red for errors, yellow for long-running (> 5 s).
5. `diary timeline --replay` animates the timeline by printing one row at a time with a short sleep, recreating the session cadence.

**Verify:** `diary show` prints a readable narrative. `diary timeline <session-id>` shows the correct tool sequence with timing. `--replay` animates correctly.

---

### Phase 4: Search + HTML Export
**Goal:** Full-text search across all diary entries; static HTML timeline for sharing.

**Files:**
- `src/claw_diary/search.py` — `search(query)` → list of `{date, session_id, excerpt}`
- `src/claw_diary/html_export.py` — `export_html(session_id)` → writes `<session_id>.html`
- `src/claw_diary/cli.py` — adds `diary search <query>` and `diary export <session-id>`
- `templates/timeline.html.j2` — Jinja2 template for the HTML export

**Key steps:**
1. `search`: scan all daily `.md` files; use `re.findall` to find lines containing the query (case-insensitive). Return `{date, session_id (from the "## Session" heading), excerpt (±1 lines)}`.
2. HTML export: Jinja2 template renders a vertical timeline with tool cards. Each card shows tool name, timestamp, input/output summary, and duration. Colours match the terminal colour coding. Fully static (no JS dependencies).
3. `diary search "authentication"` → prints matching excerpts with date and session link.
4. `diary export <session-id>` → writes HTML to current directory and prints the path.

**Verify:** Run a session involving authentication-related code. `diary search "auth"` returns the relevant session. `diary export <id>` produces a valid, self-contained HTML file.

## Potential Blockers

1. **Hook stdout/stderr contract** — Claude Code hooks must exit 0 and must not write to stdout (reserved for the hook return value). All diary output goes to the JSONL file or stderr for status messages. Violating this silently breaks the Claude Code session. Wrap every hook in `try/except` and redirect all output to the error log on failure.
2. **Large input truncation in hooks** — File contents passed to Edit/Read can be megabytes. Truncate aggressively in the hook (first 200 chars) before writing to JSONL; a large JSONL file slows down the summary reader and inflates the LLM prompt.
3. **Stop hook timing** — The Stop hook fires at Claude Code session end, but if the user kills the terminal (SIGKILL) it may not fire. Accept this gracefully: sessions without a `session_end` event are treated as incomplete; `diary timeline` still works on the partial log.
4. **Multiple sessions per day** — The daily summary file is appended to by multiple sessions. Use a `## Session <id> – <time>` heading before each session's narrative to keep entries distinct and searchable.
