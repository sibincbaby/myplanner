# DejaVu — Zero-LLM Agent Memory Indexer Across Coding Sessions

**Source:** [github.com/vshulcz/deja-vu](https://github.com/vshulcz/deja-vu)  
**Stars:** 506 · **Language:** Go  
**Date discovered:** 2026-08-02

## What it is

A local-only memory indexer for AI coding agents. It reads conversation logs from 17 coding agent harnesses (Claude Code, Codex, Cursor, opencode, Pi, etc.), builds an inverted index with token buckets, and exposes a single MCP `search_memory` tool. No LLMs, no embeddings, no cloud — just a Go binary doing BM25-style retrieval.

Benchmarks: 84.9% hit@1 on LongMemEval-S, searches 3.5GB of history in ~1.5ms.

## Why it fits

- Direct Claude/LLM tooling: becomes an MCP tool in Claude Code
- Dev productivity: recall past fixes without re-reading full sessions
- Retroactively indexes existing logs — starts providing value immediately
- No GPU, no API key, no cloud dependency

## Stack Recommendation

```
Go 1.25+
Inverted index (custom token buckets, no deps)
MCP server (Anthropic Go SDK or stdio JSON-RPC)
Optional: Ollama endpoint for embedding-enhanced recall
```

## MVP Scope (1-2 Claude sessions)

Claude Code-only memory indexer with MCP:
1. Walk `~/.claude/projects/` and find all `*.jsonl` conversation files
2. Parse each file: extract `assistant` messages, strip ANSI, tokenize
3. Build in-memory inverted index: token → [(session_id, message_idx, score)]
4. Serve MCP `search_memory(query: string, top_k: int) → [{session, timestamp, snippet}]`
5. `deja-vu index` and `deja-vu search "postgres timeout"` CLI commands

Skip for MVP: 16 other harness formats, SSH sync, SQLite persistence.

## Phases

### Phase 1: Log Parser (2-3h)
- Discover Claude Code session dirs and JSONL format
- Parse messages: role, content, timestamp
- Strip tool calls and ANSI codes; extract readable text chunks

### Phase 2: Inverted Index (3-4h)
- Tokenizer: lowercase, strip punctuation, simple stemming
- Token → sorted posting list (session_id, offset, tf)
- BM25 scoring function
- Build + serialize to disk (gob or JSON)

### Phase 3: MCP Server (2h)
- JSON-RPC 2.0 over stdio (MCP spec)
- `initialize` + `tools/list` + `tools/call` handlers
- `search_memory` tool: query → top-5 sessions with snippet + timestamp

### Phase 4: Watch Mode (2h)
- `fsnotify` on `~/.claude/projects/` — incrementally update index on new JSONL lines
- No full re-index needed between sessions

### Phase 5: Multi-Harness Support (4-6h)
- Add Codex (`~/.codex/`), Cursor, opencode log parsers
- Normalize across formats to common schema

## Blockers / Risks

- Claude Code session JSONL format is undocumented and may change
- Index rebuild time for large histories (months of sessions) could be slow on first run
- Go 1.25+ required; MCP Go SDK is relatively new
- Memory: 3.5GB of logs in-memory inverted index could be large — needs disk-backed index
- False positives: token matching without semantics may miss contextual similarity
