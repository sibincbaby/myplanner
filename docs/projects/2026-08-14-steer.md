# steer — Turn the Agent's Silent Assumptions into Three Toggles Before It Writes Code

**Source:** [pirate/codex-structured-steering](https://github.com/pirate/codex-structured-steering) · GitHub, created Aug 11 2026, 2★, Python, no license file · Show HN Aug 13
**Language:** Python 3.11 stdlib + one Haiku call per gate
**License:** upstream unlicensed — read the schema and the watcher rules, write the code fresh
**Date discovered:** 2026-08-14

## What it is

Upstream is `Structured Steering.app`: a macOS overlay for Codex where a cheap watcher subagent reads the session as it runs, extracts the **implicit** decisions the agent has made — how many tests, unit or E2E, keep compat adapters or break callers — and renders each one as a toggle or a dropdown in a popup. Flipping a control injects the correction into the main thread as `additionalContext`, so it never appears as a back-and-forth message in the history. Four hooks, one schema, no tools in the watcher.

Two details show the author has actually been burned by this. The watcher surfaces a control after a *single* occurrence when correction still matters, and it restores a preference as an explicit control once the human has reversed it three times — at which point you are the ambiguity, not the model. And the injection path exists specifically because correcting an agent mid-flight costs twice: once in tokens, once in the flip-flopping that makes every later decision less confident.

**Why it matters here:** yesterday's screening of aakit ended with a sentence that reads like a spec for this: *"The version worth building is a `PreToolUse` check that blocks the edit contradicting a recorded assumption, and that is not what shipped."* This is what shipped. It is on the wrong OS and the wrong agent, and the mechanism — hooks, a cheap extractor, out-of-band injection — transfers to Claude Code exactly.

## Stack Recommendation

```
Language:  Python 3.11, stdlib only — json, pathlib, subprocess, difflib
Extractor: one Haiku call per gate (claude-haiku-4-5-20251001), JSON out, hard 3s timeout
Trigger:   PreToolUse hook, matcher ExitPlanMode — the plan→execute boundary already exists
Inject:    UserPromptSubmit hook → hookSpecificOutput.additionalContext, deltas only
Store:     ~/.claude/steer/<session_id>.json — one file per session, deleted on SessionEnd
UI:        the existing plan-approval prompt, plus `steer` in a second terminal. No overlay
```

No overlay, no daemon, no live-updating watcher. Upstream needs those because Codex-in-iTerm has no gate to hang this off; Claude Code has `ExitPlanMode`, which is the one moment where a list of assumptions is both cheap to compute and still worth changing. **Skipped: the running watcher, pins, sliders — add when the plan gate proves too coarse.**

Haiku and not the session model: this runs inside a blocking hook. It has to cost nothing and return in under three seconds, and extracting three assumptions from a plan you were handed is not a task that needs a frontier model.

## MVP Scope (1-2 Claude sessions)

1. `steer scan <file>` — plan text in, at most **three** implicit assumptions out, each with `{id, label, options, selected}`
2. `PreToolUse` hook on `ExitPlanMode` — runs the extractor, writes the session file, returns `permissionDecision: "ask"` with the assumption list as the reason so it renders inside the approval prompt you already answer
3. `steer ls` / `steer set <id> <value>` — read and flip from a second terminal
4. `UserPromptSubmit` hook — injects only assumptions changed since the last injection, as `additionalContext`
5. Fail-open everywhere: any error, any timeout, any malformed JSON → allow, silently

## Phases

### Phase 1: The Extractor (2h)
- Input is the `tool_input.plan` string from the hook payload. Output is strict JSON — use a tool-call schema so a retry happens at the API layer instead of in a regex
- The prompt does one job: *decisions the plan made that the user never stated*. Explicitly exclude anything the user asked for verbatim, and anything already settled earlier in the session
- **Cap at three.** This is the whole design. A list of eight assumptions is a wall of text at the exact moment someone wants to press `y`, and it will be skimmed once and ignored forever after
- Prefer the assumption with a cheap flip and an expensive rewrite — test strategy, migration compatibility, which files are in scope. Skip naming and formatting
- Verify: run it against three real plans from `~/.claude/projects/**/*.jsonl` and check by hand that each surfaced item was genuinely never stated by the user

### Phase 2: The Gate Hook (1.5h)
- `PreToolUse`, matcher `ExitPlanMode`. Read the payload from stdin, take `session_id` and `tool_input.plan`
- Return `hookSpecificOutput.permissionDecision: "ask"` with `permissionDecisionReason` set to the three lines. The approval prompt is already on screen at that instant — this adds information to a decision being made, rather than creating a new one
- **Hard 3s timeout on the API call, and fail open.** A hook that hangs blocks the session; a hook that errors must behave as if it were never installed. This is not defensive politeness, it is the difference between a tool that survives a week and one that gets deleted the first time the network is slow
- Verify: kill the network, enter plan mode, confirm the approval prompt appears normally with no delay beyond the timeout

### Phase 3: Flip From a Second Terminal (1h)
- `steer ls` prints the current session's controls; `steer set tests e2e` writes the change with a timestamp
- Session selection: newest file in `~/.claude/steer/` wins. One session at a time is the honest scope — `steer ls --session <id>` covers the rest without a picker
- Verify: flip a value, confirm the file shows the new value and a `changed_at` newer than the last injection marker

### Phase 4: Injection Without Pollution (1.5h)
- `UserPromptSubmit` hook emits `additionalContext` containing **only** controls whose `changed_at` is newer than `last_injected_at`, then stamps `last_injected_at`
- Format as instructions, not as a status dump: `Test strategy: E2E only, not unit (corrected by user).` A restated preference the agent already follows is pure token cost
- Nothing to inject means print nothing and exit 0. A hook that emits a banner on every turn is furniture by day two
- Verify: two consecutive prompts after one flip — the correction appears once, the second turn is silent

### Phase 5 (optional): The Flip-Flop Detector (2h)
- Count reversals per control across the session file. On the third, re-surface it as an explicit pinned control with the current value stated
- This is upstream's sharpest idea and the one that needs real usage data to tune, which is why it goes last

Phases 1-2 alone — three assumptions printed inside the approval prompt — are **3.5h** and deliver most of the value. Whether flipping needs to be a CLI at all is a question those two phases answer, since rejecting the plan with a one-line correction may turn out to be enough.

## Blockers / Risks

- **A blocking hook is a foot-gun aimed at every session.** It sits in front of plan approval, calls the network, and parses model output. Every one of those can hang. Fail-open with a hard timeout is Phase 2's first requirement, not a polish item — and it needs testing with the network *actually* down, not mocked.
- **`ExitPlanMode` only fires if plan mode is used.** Quick tasks skip straight to editing and never hit the gate, which means the assumptions most likely to be wrong — the ones in work nobody planned — are exactly the ones this misses. The fallback trigger is the first `Write`/`Edit` of a session, but that fires mid-flight where a prompt is an interruption rather than a checkpoint. Ship the plan gate, measure how often it fires, then decide.
- **Three is a design constraint, not a default.** The pressure to raise the cap will arrive the first time a genuinely-important fourth assumption is missed. Raising it converts the tool from a checkpoint into a wall of text that gets skimmed, and skimmed is the same as off.
- **Extraction will surface things the user did state.** The plan restates the user's request in its own words, so an assumption extractor reads paraphrase as invention. Pass the original request alongside the plan and instruct exclusion explicitly — and expect to tune this prompt more than once.
- **Injected corrections have no expiry.** A preference flipped for one task will keep being injected for the rest of the session. Session-scoped storage bounds the damage; anything longer-lived belongs in `CLAUDE.md`, where it is visible and editable, not in a hidden JSON file.
- **Cost is small but not zero, and it lands at the worst moment** — the pause before approval. Haiku, capped input, three-second ceiling. If the plan is 8k tokens, truncate to the first and last sections rather than sending all of it.
- Upstream is 2★, eleven days old, unlicensed, and macOS-only. Take the watcher's ten prompt rules and the control schema — both are in the README — and write everything else against Claude Code's hook payloads directly.
