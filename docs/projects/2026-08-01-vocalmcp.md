# VocalMCP

> A local-only MCP server for Apple Silicon Macs that gives any MCP-capable AI tool a bidirectional voice channel: Voxtral Realtime (4B int4) for speech-to-text and Kokoro (82M) for text-to-speech, exposed as simple MCP tools `listen()` and `speak()`.

**Inspired by:** [shreyaskarnik/voice-mcp](https://github.com/shreyaskarnik/voice-mcp)  
**Date discovered:** 2026-08-01

---

## What gap it fills

Previous voice tools for Claude Code (Jul 22 run: LocalMic, VoiceCode, EchoCode) were CLI wrappers: they intercepted stdin/stdout and added voice on top. MCP changes the architecture completely. A voice *MCP server* means Claude Code (or any MCP-capable agent) can call `listen()` to capture speech and `speak()` to respond — making voice a first-class tool in the agent's tool belt, not a transport wrapper. The agent can decide *when* to speak and *when* to listen, enabling genuinely conversational workflows rather than push-to-talk-only sessions.

voice-mcp proves the concept works; VocalMCP is a clean-room build that adds a UI toggle, explicit session API, and an `announce()` tool for background notifications (e.g., "tests finished, 3 failures").

Viability score: **3/4** (weekend_buildable ✅, fills_gap ✅, novel ✅, daily_utility ✅)

*Note: voice tools for Claude Code have been covered in prior runs. VocalMCP is viable specifically because the MCP-native architecture — voice as a tool the agent calls, not a wrapper — is meaningfully different from prior approaches.*

## Stack recommendation

| Layer | Choice | Why |
|-------|--------|-----|
| MCP framework | `FastMCP` (Python) | Minimal boilerplate; handles tool registration and stdio/SSE transport |
| STT | `mlx-audio` + Voxtral Realtime 4B int4 | voice-mcp's proven combination; runs in ~200ms on M1 |
| TTS | Kokoro 82M via `mlx-audio` | 54 voices, 9 languages; ~50ms synthesis latency on Apple Silicon |
| VAD | `webrtcvad` | Auto-detects speech end; critical for `listen()` to know when to stop |
| Audio I/O | `sounddevice` | Cross-platform; works with Mac system audio; no extra deps |
| Session state | In-process dict (no DB) | Voice sessions are short; no persistence needed |

## MVP scope (1-2 Claude sessions)

**Session 1 — Core MCP tools:**
- `listen(timeout_s: int = 10) → str`: activates mic, runs VAD to detect speech start/end, runs Voxtral Realtime on captured audio, returns transcript string
- `speak(text: str, voice: str = "af_heart") → None`: synthesizes audio via Kokoro, plays immediately via sounddevice, blocks until done
- `announce(text: str) → None`: like `speak()` but queues behind current speech; for background notifications
- CLAUDE.md snippet: configure VocalMCP as an MCP server so Claude Code auto-discovers it
- Test: open Claude Code, say "what files are in this directory?", Claude calls `listen()` → hears question → runs bash → calls `speak()` with answer

**Session 2 — Polish + session management:**
- `start_session(voice: str, language: str) → session_id`: stores voice preference per conversation thread
- `list_voices() → list[str]`: lets agent pick from available Kokoro voices for different contexts (e.g., formal voice for announcements, casual for chat)
- Health check tool: `audio_check() → dict` reports mic/speaker availability so Claude can degrade gracefully if hardware is missing
- Config file `~/.vocalmcp.toml`: set default voice, VAD sensitivity, model paths
- Auto-start: launchd plist for macOS that starts VocalMCP at login

## 3-Phase roadmap

### Phase 1 — Core listen + speak tools (Session 1)
FastMCP server exposing `listen()`, `speak()`, `announce()`. VAD-gated capture. Voxtral + Kokoro local inference. CLAUDE.md config snippet.

### Phase 2 — Session + config (Session 2)
Session API (`start_session`, `list_voices`, `audio_check`). Config file. launchd auto-start. Graceful degradation if mlx-audio models aren't downloaded yet.

### Phase 3 — Cross-platform + streaming TTS
Port STT to `faster-whisper` for Linux/Windows (mlx-audio is Apple Silicon only). Streaming TTS: pipe Kokoro tokens to sounddevice as they generate rather than waiting for the full synthesis — removes the delay for long responses.

## Blockers / watch-outs

- **mlx-audio model download**: Voxtral 4B int4 is ~2.5GB and Kokoro is ~300MB. Phase 1 should auto-download on first run with a clear progress indicator; don't silently fail.
- **Mic permissions on macOS**: The process needs microphone access; on first run, macOS will show a permission dialog. The FastMCP server runs headlessly, which can confuse the dialog. Workaround: include a one-time `python -c "import sounddevice; sounddevice.rec(...)"` setup step that triggers the permission prompt in a foreground terminal.
- **VAD sensitivity**: webrtcvad has 0-3 aggressiveness modes; 2 is good for quiet rooms, 3 for noisy environments. Expose this in the config file.
- **Blocking `speak()`**: If the agent calls `speak()` with a 5-minute monologue, the MCP call blocks for minutes. Enforce a `max_chars=2000` limit in the tool contract and instruct the agent to chunk long responses.
- **Concurrent calls**: FastMCP processes tools serially by default; if Claude calls `listen()` while `speak()` is running, it queues. Document this; it's the expected behaviour for a voice interface.

## Why now

The MCP ecosystem is now mature enough that a voice-as-tool pattern is immediately useful: any MCP-capable agent (Claude Code, Cursor with MCP, Gemini CLI) gets voice capability without code changes — just add VocalMCP to the MCP server list. The combination of Voxtral Realtime (fast, local, high-quality STT) and Kokoro (small, fast, 54-voice TTS) running on Apple Silicon makes a genuinely low-latency local voice loop feasible in 2026 in a way it wasn't in 2024. VocalMCP is the thin glue layer between these models and the MCP protocol.
