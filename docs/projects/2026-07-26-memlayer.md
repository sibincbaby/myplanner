# MemLayer

> A local-first MCP server that gives Claude Code (and Cursor, Codex) a real cross-session memory: decisions, lessons, gotchas, and personal facts — stored in SQLite on your disk

**Inspired by:** [oleksiijko/pmb](https://github.com/oleksiijko/pmb) + [riponcm/projectmem](https://github.com/riponcm/projectmem) (GitHub discovery July 26 2026)  
**Date discovered:** 2026-07-26

---

## What gap it fills

Every Claude Code session starts amnesiac. You re-explain the same architecture decisions, re-warn about the same gotchas ("never use X library — it breaks on M-series Macs"), and re-teach the same personal style preferences session after session. PMB and PROJECTMEM both prove there is appetite for a local memory layer — but pmb is minimal (JSON flat-file) and projectmem leans academic (event-sourced, arxiv paper). MemLayer sits between them: SQLite for durability and full-text search, MCP server for zero-config integration with Claude Desktop and Claude Code, and a CLI for quick `memlayer add "lesson: always run migrations before seeding"` from the shell. The user already has MemSync (encrypted cloud sync) and Memex (personal journal) in their collection — MemLayer is the *agentic-workflow* variant: read-write from inside Claude Code mid-session, not just from a journal app.

## Stack recommendation

| Layer | Choice | Why |
|-------|--------|-----|
| MCP server | Python + `fastmcp` | Fastest path to a working MCP server; excellent Claude Desktop compat |
| Storage | SQLite via `sqlite3` (stdlib) | Zero config, single file, FTS5 full-text search built in |
| CLI | Python `click` | Simple ergonomics for `memlayer add / search / list / rm` |
| Schema | Single `memories` table | id, body, tags, project, source, created_at |
| Search | SQLite FTS5 | BM25 ranking, no embedding pipeline, no vector DB |
| Config | `~/.config/memlayer/config.toml` | Points to the DB file; multiple DB profiles (work / personal) |

## MVP scope (1 Claude session)

A Python package that:

1. Runs as an MCP server (`memlayer serve`) with 4 tools: `add_memory`, `search_memory`, `list_memories`, `delete_memory`
2. CLI: `memlayer add "..."`, `memlayer search "..."`, `memlayer ls`, `memlayer rm <id>`
3. Stores everything in `~/.local/share/memlayer/memories.db` (SQLite)
4. `claude_desktop_config.json` snippet in README for one-command install
5. Optional: `--project` flag scopes memories to a git repo (reads `git rev-parse --show-toplevel`)

Out of scope for MVP: encryption, cloud sync, embedding-based semantic search, web UI.

## Phases

### Phase 1 — SQLite schema + search (1 h)
- `db.py`: creates `memories` table and `memories_fts` (FTS5) virtual table on first run
- Columns: `id INTEGER PRIMARY KEY`, `body TEXT`, `tags TEXT`, `project TEXT`, `source TEXT`, `created_at TEXT`
- Functions: `insert_memory(body, tags, project, source)`, `search_memory(query, project=None, limit=10)`, `list_memories(project=None)`, `delete_memory(id)`
- FTS5 query on `body || ' ' || tags`; returns rows ranked by BM25

### Phase 2 — MCP server (1.5 h)
- `server.py` using `fastmcp`: register 4 tools with typed parameters and docstrings
- `add_memory(body: str, tags: str = "", project: str = "")` → returns inserted id
- `search_memory(query: str, project: str = "", limit: int = 10)` → list of `{id, body, tags, project, created_at}`
- `list_memories(project: str = "", limit: int = 20)` → ordered by `created_at DESC`
- `delete_memory(id: int)` → confirmation string
- Entry point: `memlayer serve` (stdio transport for Claude Desktop)

### Phase 3 — CLI (45 min)
- `cli.py` with `click` group: `add`, `search`, `ls`, `rm`
- `memlayer add "Claude prefers explicit return types in TypeScript" --tags "typescript,style"`
- `memlayer search "typescript"` → tabular output with id, snippet, tags, date
- `memlayer ls --project myplanner` → all memories scoped to a project
- `memlayer rm 42` → confirms before delete

### Phase 4 — Auto project detection (30 min)
- At `add` or `search` time, run `git rev-parse --show-toplevel` silently; if in a git repo, default `--project` to the repo name
- MCP server tools do the same: Claude Code sessions inside a repo automatically see project-scoped memories first
- Fallback: `--project global` for cross-project lessons

### Phase 5 — Install + README (30 min)
- `pyproject.toml` with `[project.scripts] memlayer = "memlayer.cli:cli"` and `memlayer-server = "memlayer.server:main"`
- `README.md`: one-liner install (`pip install memlayer` or `uv tool install memlayer`), Claude Desktop JSON snippet, 5-command quick-start
- GitHub repo with MIT license

## Effort estimate

~3.5 hours Phases 1–3 (working MCP + CLI) · 1 Claude session  
~4.5 hours complete with auto project detection and publish

## Blockers / risks

- **fastmcp API churn**: `fastmcp` has moved fast in 2025-2026. Pin a version and test against the Claude Desktop MCP runtime. Mitigation: wrap server registration in a thin adapter so swapping to raw `mcp` SDK is a one-file change.
- **FTS5 vs semantic search**: BM25 misses synonyms and paraphrases. Mitigation: document this clearly; add a `--semantic` flag in Phase 2 (future) that calls a local embedding model via Ollama when available.
- **Overlap with MemSync**: MemSync focuses on encrypted *sync across machines* for AI tool context. MemLayer focuses on *agentic write access from inside Claude Code mid-session*. Make the distinction clear — they complement each other; MemSync could eventually sync MemLayer's SQLite file.
- **Collision with prior "Claude Finance MCP" / "claude-journal-mcp"**: Those are domain-specific MCPs. MemLayer is a general-purpose memory primitive — it can store any fact, not just finance or journal entries.
