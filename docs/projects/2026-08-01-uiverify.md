# UIVerify

> A CLI skill for Claude Code that gives it eyes on the UI it just built: after any UI change, Claude automatically launches a browser, navigates to the feature, records a short session with screenshots and console errors, and bundles the proof into a self-contained HTML artifact — all without human intervention.

**Inspired by:** [AmElmo/proofshot](https://github.com/AmElmo/proofshot)  
**Date discovered:** 2026-08-01

---

## What gap it fills

ProofShot (847 stars) is a standalone CLI: the human runs it separately to record a browser session after the agent finishes. UIVerify closes the loop: it's a Claude Code SKILL.md that teaches Claude to initiate UI verification autonomously. After any bash command that involves `npm run dev`, `flutter run`, or `vite build`, Claude calls the UIVerify skill, which opens Playwright, navigates to the feature under development, captures screenshots at defined checkpoints, collects console errors, and writes the proof artifact. The agent sees the artifact, spots any visible bugs, and self-corrects — without the developer needing to open a browser at all.

Viability score: **3/4** (weekend_buildable ✅, fills_gap ✅, novel ✅, daily_utility ✗)

*Note: daily_utility is low (only relevant during UI development cycles, not every session). Viable on the other three dimensions.*

## Stack recommendation

| Layer | Choice | Why |
|-------|--------|-----|
| Browser automation | Playwright (Node.js or Python) | Pre-installed in Claude Code remote environments; handles dynamic SPAs |
| Claude Code integration | SKILL.md + PostToolUse hook | Skill teaches Claude when/how to invoke; hook triggers automatically |
| Screenshot capture | Playwright `page.screenshot()` | Full-page or element-specific; built-in |
| Console error capture | `page.on('console', ...)` | Catches JS errors, warnings, network failures |
| Proof artifact | Self-contained HTML with embedded base64 images | No server needed; can be opened offline; inspectable in any browser |
| Dev server detection | Port scan (check 3000, 4000, 5173, 8080) | Detects common Vite/React/Flutter web dev server ports |
| CLI | `uiverify capture <url> [--checkpoints nav1,nav2]` | Direct CLI use when not running via skill |

## MVP scope (1-2 Claude sessions)

**Session 1 — Core capture + artifact:**
- `capture.py` (or `.js`): opens a Playwright browser (headless), navigates to URL, collects console errors and network failures for 10s, takes full-page screenshot, bundles into `uiverify-report.html`
- `uiverify-report.html` template: screenshots in an `<img>` tag (base64), console errors in a `<pre>` block, network failures in a red-bordered section, timestamp + URL in the header
- `uiverify capture http://localhost:5173 --wait 5` as the CLI entry point
- Test: run against a React dev server; confirm the HTML report opens in the browser and shows the screenshot + any console errors

**Session 2 — Skill + PostToolUse hook + checkpoint navigation:**
- `SKILL.md` for UIVerify: instructs Claude to call `uiverify capture` after any bash that starts or rebuilds a dev server; teaches Claude to read the HTML report and self-report visible issues
- `uiverify install-hook`: writes a `PostToolUse` hook to `.claude/settings.json` that triggers capture when bash output contains `Local:` (Vite) or `ready in` (Webpack) or `Server started on`
- Checkpoint navigation: `--checkpoints "click:#login-btn,fill:#username:admin,click:#submit"` mini-DSL for driving multi-step user flows
- Diff mode: `uiverify diff report1.html report2.html` highlights screenshots side by side using `pixelmatch`

## 3-Phase roadmap

### Phase 1 — Core capture (Session 1)
Playwright capture script. Console error collection. Self-contained HTML artifact with embedded screenshots. `uiverify capture <url>` CLI.

### Phase 2 — Skill + hook + checkpoints (Session 2)
SKILL.md that Claude auto-discovers. PostToolUse hook for dev server detection. Checkpoint navigation mini-DSL. Diff mode for before/after comparison.

### Phase 3 — GitHub PR integration
`uiverify pr-comment <pr_number>`: posts the HTML artifact URL (uploaded to a temp GitHub Pages branch or Gist) as a PR comment with an inline screenshot. Closes the "show don't tell" gap in code review.

## Blockers / watch-outs

- **Chromium in remote environments**: Claude Code remote environments have Playwright pre-installed but you must pass `executablePath: '/opt/pw-browsers/chromium'` — do not run `playwright install`.
- **Dynamic app wait time**: `--wait 5` may not be enough for an app that loads data asynchronously. Add `--wait-for-selector <css-selector>` so capture waits until a key element is visible before screenshotting.
- **Base64 artifact size**: A full-page screenshot of a complex SPA can be 500KB+ as base64. Set a max width (1280px) and use JPEG at 80% quality to keep the HTML artifact under 1MB.
- **Dev server detection heuristic**: The PostToolUse hook pattern-matching is fragile. Offer `uiverify install-hook --pattern "localhost:5173"` as an explicit URL pattern so false triggers don't waste captures on unrelated bash commands.
- **Flutter web vs. native**: `flutter run -d web-server` spawns a web dev server; `flutter run` (native) does not. UIVerify should detect `flutter run --web-port` specifically and skip native device runs.

## Why now

ProofShot's 847 stars in a relatively short window (it's a focused, well-scoped tool) show that UI verification for AI coding agents is a felt pain. The next step is closing the loop: instead of the developer running ProofShot separately, the agent runs UIVerify automatically and reads the output. With SKILL.md instructions, Claude Code can be taught to treat UIVerify as a first-class verification step — the same way a human developer opens a browser to check their work, but without breaking the flow of the agentic session. The self-correcting loop (build → verify → fix → verify again) is the key unlock.
