# Memorix — Cross-Agent Project Memory

**Source:** [AVIDS2/memorix](https://github.com/AVIDS2/memorix) · TypeScript · 692★ · GitHub (Aug 2026)
**Date discovered:** 2026-08-26

## What it is

Memorix is a local-first shared memory system for AI coding agents. It maintains a persistent, project-scoped SQLite database of observations, reasoning, git-derived facts, and code state that survives context resets, IDE switches, and agent handoffs.

The core insight: when you move from Claude Code to Cursor to Codex within the same project, each agent starts from zero. Memorix gives every agent the same read/write access to the project's accumulated knowledge via MCP, so context is cumulative rather than ephemeral.

Key features:
- **Multi-source memory layers:** observations, design rationale, git commit facts, and code state
- **MCP interface** compatible with Claude Code, Cursor, Windsurf, Codex, Copilot, and 10+ others
- **Git Memory** — converts commit messages into searchable engineering facts automatically
- **Semantic + BM25 search** with SQLite + Orama (no API key required; embeddings optional)
- **Memory Autopilot** — bounded task contexts with automatic pruning
- **CLI + HTTP + SDK** interfaces; `memcode` bundled terminal agent

## Stack Recommendation

```
Language:      Python 3.12+ with uv
Storage:       SQLite via sqlite3 stdlib (no ORM needed for MVP)
Search:        BM25 via rank_bm25 library (no embeddings in Phase 1)
MCP:           mcp Python SDK (pip install mcp)
Git facts:     gitpython to walk commit log
Transport:     stdio MCP (works in Claude Desktop without a server process)
CLI:           pmem add / pmem recall / pmem git-ingest / pmem status
```

## MVP Scope (1-2 Claude sessions)

A single Python package `pmem` with four MCP tools and a project-scoped `.pmem/memory.db`:

1. **`pmem_add(text, kind)`** — save an observation (`obs`), design note (`design`), or fix (`fix`) with timestamp and optional file reference
2. **`pmem_recall(query)`** — BM25 search across all memory entries; return top-5 with kind labels
3. **`pmem_git_ingest()`** — walk the last N commits, extract subject + body, store as `git` kind entries
4. **`pmem_status()`** — count entries by kind, last-modified, DB path

MCP config in `~/.config/claude/mcp.json`:
```json
{
  "pmem": {
    "command": "uv",
    "args": ["run", "--project", "/path/to/pmem", "pmem", "--project-root", "${workspaceFolder}"]
  }
}
```

## Phases

### Phase 1: Storage + Add/Recall (1.5h)
- Create `.pmem/memory.db` at project root on first run (auto-discovered by walking `cwd` upward)
- Schema: `id, text, kind, file_ref, created_at`
- Implement `pmem_add`: insert row; `pmem_recall`: load all rows, BM25 rank, return top-5 as JSON
- Wire as MCP stdio server: two tools, works in Claude Desktop immediately
- Verify: add 5 observations, recall "auth error" — correct entries surface

### Phase 2: Git Ingest (1h)
- `pmem_git_ingest(n=50)`: walk last N commits via gitpython, concatenate subject + first paragraph of body
- Store as `kind="git"` with `file_ref = commit_hash[:8]`
- Auto-ingest on first `pmem_recall` call if git store is empty (lazy init)
- Verify: project with 30 commits → recall "database migration" → relevant commit messages appear

### Phase 3: File-Scoped Recall (0.5h)
- Add optional `file_filter` param to `pmem_recall`: restrict search to entries where `file_ref` starts with the given path
- Lets Claude recall only the memory relevant to the file currently being edited
- Verify: add 3 entries for `src/auth/*.ts`, recall with `file_filter="src/auth"` → only those entries

### Phase 4: CLI for Terminal Use (0.5h)
- `pmem add "text" [--kind obs|design|fix|git]` — add from terminal
- `pmem recall "query"` — search from terminal; pretty-print results
- `pmem status` — show DB path, entry counts by kind, last-modified
- `pmem git-ingest [--n 100]` — manual ingest trigger
- Verify: end-to-end in terminal without Claude Desktop open

### Phase 5: Memory Expiry (0.5h)
- Add `created_at` TTL: `pmem prune [--days 30]` removes entries older than N days
- Default: git entries never expire; obs/design/fix expire after 60 days (configurable in `.pmem/config.toml`)
- Verify: seed 3 old entries, run prune, confirm they are gone; git entries survive

## Blockers / Risks

- **Try memorix first.** `npm install -g memcode && memcode` — if it works out of the box with Claude Desktop, use it directly and skip this plan. The personal build is only worth it if the memorix footprint (Node, npm, background daemon) is too heavy.
- **Multi-project DB collision.** If two projects share a parent directory, auto-discovery must stop at the project root (look for `.git`, `package.json`, or `pyproject.toml`). Missing this causes entries from project A to appear in project B's recalls.
- **BM25 recall quality.** BM25 is good for keyword matching but misses semantic similarity ("auth failure" vs. "login issue"). Phase 1 is intentionally BM25-only. If recall quality is poor after real use, add optional embedding via the `sentence-transformers` local model in a Phase 6.
- **MCP stdio per-project.** The stdio transport means one server process per active project in Claude Desktop. With many projects open, this multiplies. The HTTP transport (Phase 5+) can serve all projects from one process; add it when the per-project process count becomes a problem.
- **Git ingest on large repos.** Walking 10k commits is slow. Clamp `n` to 200 commits on first ingest; add a `--since` date flag for incremental re-ingests.
