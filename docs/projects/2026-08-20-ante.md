# ante — Offline-First Coding Agent, No Cloud Control Plane

**Source:** [AntigmaLabs/ante-preview](https://github.com/AntigmaLabs/ante-preview) · Show HN (102 points, 65 comments, 2026-08-10) · Rust, MIT
**Date discovered:** 2026-08-20

## What it is

Ante is a coding agent in a single ~15 MB Rust binary with zero runtime dependencies. No Node.js, no npm tree, no cloud auth. Drop the binary on a machine — any machine — point it at a local GGUF model via an OpenAI-compatible endpoint, give it a task, and it behaves like Claude Code or Codex: it reads files, writes them, runs shell commands, and reasons through the loop. Its pitch is the inverse of the prevailing shape of the category: coding agents as thin clients for a hosted frontier model. Ante is the binary that runs offline.

The HN thread surface is about distribution and trust: one artifact you can audit, no sidecar process, no telemetry endpoint, no account required. The model constraint is real — you are not getting Claude Sonnet from a local GGUF — but the use case is equally real: sandboxed environments, air-gapped machines, cost-sensitive loops, or situations where the control plane having a copy of your code is a non-starter.

## Stack Recommendation

```
Runtime:   Python 3.11+ with uv (single-file install)
Endpoint:  OpenAI-compatible — ollama, llama.cpp server, or LM Studio
Tools:     read_file, write_file, list_dir, run_shell (subprocess with timeout)
Loop:      manual tool-call loop over the messages array (no framework)
Config:    ~/.ante/config.toml — model, endpoint URL, system prompt, max turns
Packaging: PyInstaller or shiv → single binary (phase 5 only)
```

This is not Ante. Ante is Rust and took months. The plan here is a Python version of the same loop — the architecture is simpler because Python is not Rust, and the value is learning the structure, not shipping a competitor.

## MVP Scope (1-2 Claude sessions)

One session, one file, one loop:
1. Accept a task prompt (CLI arg or stdin)
2. POST to a local OpenAI-compatible `/v1/chat/completions` with tools defined
3. Parse `tool_use` calls, execute them, feed results back
4. Loop until `stop_reason == "end_turn"` or max turns
5. Print the final response

Four tools only: `read_file`, `write_file`, `list_dir`, `run_shell`. Everything else is phase 2.

## Phases

### Phase 1: Core Loop (2h)
- Single Python file: argument parsing, HTTP request to local endpoint, tool-call loop
- Tools implemented as plain functions, registered as JSON schema in the system prompt
- Hard limit: 20 turns, configurable
- Verify: `uv run ante.py "add a docstring to every function in utils.py"` completes on a real file

### Phase 2: Config and Safety (1h)
- `~/.ante/config.toml` for endpoint, model, system prompt, max turns, allowed paths
- Sandboxing: `run_shell` uses a subprocess allowlist (configurable); `write_file` refuses paths outside the working directory unless explicitly permitted
- Verify: running `run_shell "rm -rf /"` is blocked at config check, not after the process starts

### Phase 3: Context Management (1h)
- Token counter using tiktoken (cl100k approximate for GGUF models)
- Sliding window: drop oldest tool-result turns when context exceeds threshold
- Resume: write each turn to `~/.ante/sessions/<timestamp>.jsonl`; `--resume <id>` continues from last tool result
- Verify: a 60-turn session on a large file does not exceed the endpoint's context limit

### Phase 4: Richer Tools (1h)
- `search_files` (ripgrep subprocess) — the one tool that makes file-search fast enough to be useful
- `apply_patch` (unified diff format) — reduces write noise on large files
- `web_fetch` (httpx, behind a `--allow-web` flag) — optional, disabled by default
- Verify: the agent can refactor a 300-line module using search → read → patch without exceeding 10 turns

### Phase 5: Distribution (1h, optional)
- `uv build --wheel` then `shiv` to produce a single `.pyz` with no install step
- Confirm it runs on a machine with only Python 3.11 and no internet access
- Verify: binary boots in under 200 ms

## Blockers / Risks

- **Local model quality.** The gap between Claude Sonnet and a local GGUF is real. Tasks that require reasoning through ambiguous file structures will stall on a 7B or 13B model. Set expectations: this is for well-scoped, deterministic tasks (format, document, refactor a single module), not for open-ended architecture work.
- **Endpoint compatibility.** `ollama` and `llama.cpp --server` both expose OpenAI-compatible APIs, but their tool-call support varies by model and version. The loop needs a fallback for models that return tool calls in the content rather than in the `tool_calls` field. Test against at least two backends before claiming compatibility.
- **Shell sandboxing is hard.** A subprocess allowlist blocks the obvious cases; it does not block `python -c "import os; os.remove(...)"`. The safe answer is: run only on repos that are already in git, so `git checkout .` is the recovery. Document this; do not pretend it is solved.
- **This is not Ante.** Ante ships the binary; this plan ships the loop. If the goal is a drop-in replacement for Claude Code in an air-gapped environment, the Rust binary is the thing — the plan should link Ante's repo and stop there.
