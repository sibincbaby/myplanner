# FinMCP

> A self-hosted personal finance MCP server: connect bank CSVs or Plaid, ask Claude natural-language questions about your spending, get category breakdowns, budget alerts, and monthly summaries — all without your data leaving your machine

**Inspired by:** [alderfi.org](https://alderfi.org/) (discovered July 29 2026, born from OpenAI/Hiro Finance shutdown)  
**Date discovered:** 2026-07-29

---

## What gap it fills

The user has no personal finance AI tool in the current toolkit. Every existing option — Mint (dead), YNAB (cloud-only, expensive), Hiro Finance (acquired and shutdown), MoneyMatter (already seen, cloud-hosted) — either requires cloud data or lacks Claude-native MCP integration. Alderfi is the right idea but is pre-alpha with no working release.

FinMCP is a personal, working implementation: a Python MCP server that ingests CSV exports from any bank (or live data via Plaid if desired), stores transactions in a local SQLite database, and exposes Claude-queryable tools for spend analysis, budget tracking, and monthly reporting. Claude becomes the interface: "how much did I spend on food in June?", "am I on track with my July budget?", "which merchant am I overpaying compared to last quarter?"

Concrete daily value: open Claude Code, ask a finance question, and Claude pulls live data from your local database — no dashboards, no SaaS subscriptions, no sharing transaction history with a third party.

## Stack recommendation

| Layer | Choice | Why |
|-------|--------|-----|
| Language | Python 3.12 | Fastest for MCP servers; pandas for data transforms |
| MCP SDK | `mcp` (official Python SDK) | Standard, Claude Code compatible |
| Database | SQLite via `sqlite-utils` | Zero-ops local storage; works offline |
| CSV parsing | `pandas` | Handles every bank export format in one library |
| Optional: Plaid | `plaid-python` | Live transaction sync for Phase 4 |
| Config | TOML (`tomllib` built-in) | Simple `config.toml` with account names, categories, budget limits |

## MVP scope (1 Claude session)

A working MCP server with 5 tools that Claude can call:

1. `import_csv(file_path, account_name)` — parse a bank CSV, normalize columns, insert into SQLite
2. `get_spending_by_category(start_date, end_date)` — return aggregated spending per category
3. `get_transactions(account, start_date, end_date, limit)` — list raw transactions with optional filters
4. `get_budget_status(month)` — compare actual vs. budget per category, flag overages
5. `get_monthly_summary(month)` — total income, total spend, net, top 5 merchants, delta vs. prior month

Out of scope for MVP: Plaid live sync, web UI, multi-user, investment tracking, currency conversion.

## Phases

### Phase 1 — Data model + CSV import (1.5 h)
- SQLite schema: `accounts`, `transactions` (id, account_id, date, amount, merchant, category, raw_description), `budgets` (category, monthly_limit)
- `import_csv()`: detect column names heuristically (date/amount/description patterns differ per bank), normalize to schema
- Support at least: HDFC, SBI, ICICI, Axis export formats — or generic "date, description, debit, credit" format
- `sqlite-utils insert` for batch import; duplicate detection via (account, date, amount, description) hash

### Phase 2 — MCP tools + Claude registration (1.5 h)
- Implement all 5 MCP tools with `@mcp.tool()` decorator and typed Pydantic inputs
- Register server in `~/.claude/claude_desktop_config.json` (or via `claude mcp add`)
- Validate with Claude: "what's in my database?" → "how much did I spend on dining in the last 30 days?"
- Fix any schema issues surfaced by Claude's questions

### Phase 3 — Budget configuration + alerts (1 h)
- `config.toml` section for monthly budgets by category: `[budgets] food = 8000 transport = 3000`
- `get_budget_status()` computes % used for current month, flags > 80% and > 100%
- Claude can query: "am I over budget anywhere this month?" and get a ranked list of red/amber/green categories

### Phase 4 — Category intelligence (1 h)
- Auto-categorize: merchant name → category map loaded from `categories.toml`
- Claude-powered re-categorization: expose `suggest_categories(uncategorized_limit)` that returns merchants with no category; user approves or corrects
- Once a merchant is mapped, all past and future transactions inherit the category

### Phase 5 — Monthly report tool (30 min)
- `get_monthly_summary()` returns structured JSON: income, total spend, savings rate, net change, top 5 merchants by spend, MoM delta per category
- Claude renders this as a prose paragraph on request: "give me my July financial report"

## Effort estimate

~5.5 hours all phases · 1–2 Claude sessions  
Phases 1–3 deliver a fully working finance assistant in ~4 hours — Phase 4–5 are polish

## Blockers / risks

- **Bank CSV format variety:** Every Indian bank exports slightly differently. Build a format detector (check column headers, try known patterns) and a fallback "generic" parser for unknown formats. Keep a `formats/` directory of bank-specific column mappings.
- **Plaid India coverage:** Plaid doesn't support Indian banks. Phase 5 Plaid integration is only useful if the user has international accounts (US/UK/EU). For Indian accounts, CSV import is the only path.
- **Category drift:** As merchant names change (e.g. "SWIGGY*12345" vs "SWIGGY ORDER"), the category map needs fuzzy matching. Use `rapidfuzz` for merchant normalization.
- **Similar existing project:** The user's vault already contains `claude-finance-mcp` (2026-07-21) and `local-finance-mcp` (2026-07-19). FinMCP differentiates by: (a) full Phase 3 budget alerts, (b) Claude-assisted Phase 4 categorization, (c) Indian bank CSV format support. Review those plans before building to avoid re-implementing the same tools.
