# VoxCtrl

> A self-hosted Python daemon that wraps any number of Claude Code tmux sessions into a unified voice-and-text control plane — push-to-talk, live output monitoring, multi-agent task dispatch, and a "Council" deliberation mode where multiple agents tackle the same problem in parallel.

**Inspired by:** [dotdevdotdev/agentwire-dev](https://github.com/dotdevdotdev/agentwire-dev)  
**Date discovered:** 2026-08-01

---

## What gap it fills

AgentWire proves that a unified multi-session controller for Claude Code (905 commits, task scheduler, voice I/O, SSH support) solves a real problem: when you run more than one Claude Code agent — one for backend, one for frontend, one for tests — there is no central dashboard or voice interface. You juggle terminal windows manually. AgentWire's 18 stars suggest the project is emerging rather than polished; VoxCtrl builds the core loop in a single weekend with a tighter focus: voice-dispatch and session awareness, without the complexity of AgentWire's full scheduler.

Viability score: **4/4** (weekend_buildable ✅, fills_gap ✅, novel ✅, daily_utility ✅)

## Stack recommendation

| Layer | Choice | Why |
|-------|--------|-----|
| Session management | `libtmux` (Python) | Programmatic read/write to tmux panes without reinventing terminal emulation |
| Voice STT | `faster-whisper` (tiny/base model, local) | Fast enough for push-to-talk; no API cost |
| Voice TTS | `pyttsx3` or `Kokoro` via subprocess | `pyttsx3` for zero-dep quick start; swap to Kokoro for quality |
| VAD | `webrtcvad` | Detects end-of-speech automatically; prevents cut-off |
| Web UI | FastAPI + WebSockets + HTMX | Minimal frontend; session list auto-updates; no build step |
| CLI | `typer` | `voxctrl start`, `voxctrl session add <name>`, `voxctrl council` |
| Safety | Blocked-command list (configurable) | Mirrors AgentWire's 300+ blocks; default list covers rm -rf, git push --force |

## MVP scope (1-2 Claude sessions)

**Session 1 — Session view + text dispatch:**
- `session.py`: discover all tmux sessions, attach read-only pipes, stream last N lines to a shared buffer
- FastAPI server with a `/sessions` WebSocket endpoint; browser refreshes pane output every 500ms via HTMX polling
- Text dispatch: POST `/sessions/{name}/send` writes to that pane's stdin
- `voxctrl start` spins up FastAPI + discovers sessions; `voxctrl session add frontend` creates a new Claude Code session named `frontend`
- Test: three sessions visible in browser, type into one, see response stream in the UI

**Session 2 — Voice + Council mode:**
- Push-to-talk: browser MediaRecorder → POST `/voice` → server runs faster-whisper → dispatches transcript to selected session
- VAD auto-stop: webrtcvad on server side trims silence before passing to Whisper
- TTS reply: detect when agent output pauses for 2s, synthesize last assistant paragraph, stream audio back to browser via `/tts-stream`
- Council mode: `POST /council` broadcasts the same prompt to all sessions; collects responses; a summary agent (small Claude call) distills the consensus and highlights disagreements
- Safety gate: configurable JSON blocklist; relay intercepts matching commands and shows a "Approve?" modal before passing to pane

## 3-Phase roadmap

### Phase 1 — Session dashboard + text (Session 1)
libtmux session discovery, FastAPI WebSocket server, HTMX browser UI showing all panes, text-dispatch endpoint. Single binary `voxctrl` CLI.

### Phase 2 — Voice + Council (Session 2)
Push-to-talk with faster-whisper STT and pyttsx3/Kokoro TTS. VAD auto-stop. Council broadcast mode with Claude summary pass. Blocked-command safety gate.

### Phase 3 — Scheduler + remote SSH
Cron-style task scheduler: define recurring agent prompts (e.g., "run tests at 09:00"). SSH tunnel support for remote machines. Session templates: define a workspace as a set of named sessions + startup commands, launch all with `voxctrl workspace start`.

## Blockers / watch-outs

- **tmux pipe-pane latency**: Reading from a tmux pane via `libtmux` requires polling or `pipe-pane` output; use `pipe-pane -o` to a named pipe and tail it in a background thread for real-time feel.
- **faster-whisper model size**: `tiny.en` runs in ~80ms on CPU for 5s clips; `base.en` is more accurate (~200ms). Start with `tiny`, let the user set the model in config.
- **Council divergence**: When three agents get the same prompt, their contexts differ (each has its own session history). The summary pass must explicitly note which agent said what; otherwise "consensus" is misleading.
- **TTS interruption**: If a new voice command arrives while TTS is playing, interrupt immediately. Track a `speaking` flag; cancel the audio stream on new MediaRecorder data.
- **Cross-platform tmux**: Works on Linux and macOS; Windows requires WSL2. Document this clearly.

## Why now

AgentWire's active development (905 commits) with only 18 stars signals the project is filling a real need but hasn't reached escape velocity. Building VoxCtrl now captures the pattern before it becomes a polished commercial tool: Python + libtmux + faster-whisper is a stack any developer can own and extend.
