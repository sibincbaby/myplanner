# ccgram — Telegram ↔ tmux Bridge for AI Coding Agents

**Source:** GitHub — https://github.com/OmidS/ccgram  
**Tagline:** "Bridge Telegram to tmux: monitor your coding agent's output, reply to its approval prompts, and manage multiple sessions from any phone — no web server, no SSH, no desktop."  
**Discovered:** 2026-10-19

---

## Why it fits

Claude Code, Codex, and OpenCode run in tmux panes on a local or cloud machine. When you step away — commute, lunch, AFK — the agents keep running but you lose visibility: you can't approve tool calls, you don't know if they've hit an error or stalled, and you can't redirect them mid-task. Existing solutions all require a web server (CCManagerUI, kojo, Shellular, agent-deck) or SSH (twicc). ccgram instead routes the bridge through a Telegram bot you already have on your phone: the bot tails the active pane, strips ANSI codes, forwards output, and sends your typed replies back as keystrokes. No open ports, no cloud infra beyond Telegram's servers.

The gap is unmet: every "mobile remote" in this toolkit (`kojo`, `PUNK`, `Shellular`, `agent-deck`) needs either a custom app install or a running HTTP server. ccgram's transport is a Telegram bot — setup takes one `BotFather` command and a token in `.env`.

## Stack Recommendation

- **python-telegram-bot** (≥ 21, async) — stable Telegram Bot API wrapper; handles long-polling or webhooks
- **libtmux** (≥ 0.28) — Python binding for tmux control mode; read pane contents and send keys
- **asyncio** — concurrent pane-tail loop + Telegram update handler
- **python-dotenv** — `TELEGRAM_TOKEN`, `CHAT_ID`, `SESSION`, `PANE` from `.env`

No cloud infrastructure beyond Telegram; runs on the same machine as the agent. Everything runs with `pip install python-telegram-bot libtmux python-dotenv`.

## MVP Scope

1. Telegram bot polls for `/status` → replies with the last 50 lines of the target pane (ANSI stripped)
2. Any non-command message is sent as keystrokes to the pane via `tmux send-keys`
3. Auto-forward: new output lines are pushed to the chat as they arrive (tail loop, 500 ms poll)

Not in MVP: multi-session selection, per-pane routing, inline keyboard buttons, session list.

## Phases

| Phase | Description | Effort |
|-------|-------------|--------|
| 1 | Create Telegram bot via BotFather; get token; store `TELEGRAM_TOKEN` + `CHAT_ID` in `.env`; install deps | 15 min |
| 2 | libtmux: attach to named session/pane; read last N lines; strip ANSI with `re.sub` | 30 min |
| 3 | Tail loop: track last-seen byte offset; push new lines to Telegram on change | 30 min |
| 4 | Input handler: non-command messages → `pane.send_keys(text)` | 20 min |
| 5 | `/sessions` command — list all tmux sessions and panes; let user `/switch <session>:<pane>` | 45 min |

**Total estimate:** ~2.5 h (1 Claude session)

## Blockers

- ANSI strip must be thorough: Claude Code emits OSC sequences for hyperlinks and complex CSI codes for the status bar — test with `pane.capture_pane(strip_colors=True)` first, then fall back to a regex if needed
- Long Telegram messages (>4096 chars) are refused — split by line and send in chunks
- `CHAT_ID` must be your own account or a private group; bots cannot message users who haven't started them first
- Approval prompts that require a keypress (e.g. `y/n`, a tool-call confirm) work fine; full TTY interactive prompts (e.g. `vim`) do not
