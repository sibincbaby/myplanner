# OpenCockpit — Multi-Engine Agent IDE with Smart Bubbles

**Source:** [Surething-io/cockpit](https://github.com/Surething-io/cockpit) · Next.js 16 + Claude Agent SDK · 33★ · GitHub (Aug 2026)
**Date discovered:** 2026-08-28

## What it is

OpenCockpit is an open-source IDE-like workbench built on Anthropic's Claude Agent SDK that runs multiple AI engines side-by-side in independent tabs. Each tab maintains its own session history, so you can run Claude on one project and DeepSeek on another without terminal chaos.

The headline feature is **Smart Bubbles**: agent-controllable interfaces for Chrome, PostgreSQL, MySQL, and Redis. An agent can open a browser, navigate to a page, query a database, and check a cache key without any human in the loop — from within the IDE session. This is the architectural differentiator: most GUI wrappers let you see what the agent is doing; Smart Bubbles let the agent do things other tools can't reach.

Additional capabilities:
- **Multi-engine BYOK** — Claude (default), Codex, DeepSeek, GLM, Kimi, and local Ollama; tab-per-engine with independent histories
- **Code Map** — caller/callee graph with 10 HTTP endpoints for symbol queries; CodeGraph + LSP integration
- **LAN Code Review** — shareable review pages with line-level comments, no SaaS dependency
- **Slash Modes** — `/qa` (clarifying questions only), `/fx` (diagnosis), `/ex` (exploration), `/go` (implementation)
- **Local-first** — credentials stay local; no telemetry; `npm install -g @surething/cockpit && cockpit`

```

Engines:       Claude (primary), Ollama (local fallback for offline sessions)
```

## MVP Scope (1 Claude session)

Install, wire the Smart Bubbles to the local dev stack, and run one full feature development cycle inside the IDE:

1. **Install + launch** — `npm install -g @surething/cockpit && cockpit`
2. **Engine setup** — configure Claude as primary, Ollama as fallback; verify both tabs open independently
3. **Postgres Smart Bubble** — connect to local dev DB; ask agent "how many users signed up this week" — confirm it queries Postgres directly
4. **Chrome Smart Bubble** — point at local dev server; ask agent "what does the login page look like after the last CSS change" — confirm it screenshots and reports
5. **LAN code review** — `cockpit review --lan` on the current branch diff; share link with team; leave a comment

## Blockers / Risks

- **Smart Bubble Chrome extension requires local browser.** The cloud session (where these plans run) cannot install Chrome extensions. Wire the browser bubble in an interactive local session only.
- **Postgres Smart Bubble uses plain TCP.** If the dev database is behind a VPN or SSH tunnel, cockpit needs the tunnel to be up before the bubble connects. Document this in `~/.cockpit/config.json` as a `pre_connect_cmd`.
- **Multi-engine token costs.** Running Claude and Codex in parallel tabs doubles token spend. Assign primary engines per project type: Claude for product code, Codex for infrastructure scripts, Ollama for offline diffs.
- **LAN review link expiry.** The review server runs in-process; if cockpit is closed the link dies. Pin review sessions by running `cockpit review --daemon` which keeps the server alive between cockpit restarts.
- **Code Map index on large repos.** Same CodeGraph index-size risk as LWC: run with `--max-depth 4` first, deepen after verifying performance.
