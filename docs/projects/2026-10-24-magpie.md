# magpie — Unified Coding-Agent Model Router / Switcher

**Source:** [yetone/magpie](https://github.com/yetone/magpie) (MIT, cross-platform, Oct 2026 trending)  
**Tagline:** "Use every coding agent, any model, from one menu — without touching individual config files."  
**Discovered:** 2026-10-24 (cloud backup)

---

## Why it fits

Most of this toolkit's work goes through Claude Code, but the right model for a task changes: Opus 5.5 for architecture, Sonnet 4.6 for fast iteration, a local model for private files, an Anthropic beta for new features. Right now, switching means editing `~/.claude/config.json` by hand or running `claude config set model …` before every session. Magpie replaces that friction with a single menu.

Unlike the parallel-agent orchestrators in the lane (Orca, OpenRig, AgentMux), magpie is a **router**, not an orchestrator. You pick one agent + one model, it edits the agent's own config, and your next session runs exactly what you chose. The implementation is additive: it reads each agent's config format, writes one key, and offers a TUI, menu bar, window, and CLI surface. Nothing else in the seen.json does this at the routing layer rather than the orchestration layer.

The user interest profile calls this out directly: **Agent UIs: custom agent interfaces.** Magpie is the missing piece between "I have six model options" and "I'm using the right one for this task."

## Shape

Option A — **adopt upstream magpie as-is.** MIT, cross-platform, actively developed. If the repo is accessible and installs cleanly, there is no reason to rebuild it. Run `npm install -g @magpie-ai/cli` (or the Homebrew/Scoop route) and wire a keybinding or shell alias.

Option B — **build a minimal local equivalent** if upstream can't be installed (binary-only, gated, or creation-date outside the window). The MVP is ~150 lines.

The plan below covers the minimal local build (Option B) so it works regardless. If Option A works, skip to Phase 4.

## Stack

- Node.js 24 (already on path: `~/.nvm/versions/node/v24.14.0/bin`)
- Ink (React for CLI) for the TUI, or plain readline if you prefer zero deps
- `~/.claude/config.json` for Claude Code model config
- `~/.codex/config` and `~/.gemini/config.yaml` for optional Codex/Gemini CLI routing

## MVP scope

1. Read `~/.claude/config.json`, extract current model.
2. Show a TUI picker with available model IDs (Opus 5.5, Sonnet 4.6, Haiku 5.5, a local Ollama endpoint, a beta model).
3. Write chosen model back to the config.
4. Optionally restart the shell session so the next `claude` invocation picks it up.
5. Ship as `model-pick` or `mpick` CLI, invokable from a shell alias or a Claude Code `/mod`.

## Phases

1. **Read + list (0.5 h).** Parse `~/.claude/config.json` → print current model. If the file doesn't exist, show a sensible default. Add a hardcoded list of the five model IDs you actually use (Opus 5.5, Sonnet 4.6, Haiku 5.5, a local endpoint, a beta ID).

2. **TUI picker (1 h).** Use `@inkjs/ui` `Select` component (or plain `readline` arrow-key handling). Highlight the active model. On selection, write back to config and print a one-line confirmation.

3. **Codex routing (0.5 h, optional).** Read `~/.codex/config` for the `model` field. Add the same picker for Codex sessions. Magpie upstream uses a unified config store; the minimal version just writes each agent's native format.

4. **Alias + mod wiring (15 min).** Add `alias mp='~/.local/bin/model-pick'` to `.zshrc`. Optionally add a Claude Code mod that invokes it from the toolbar. Wire a keybinding in `~/.claude/keybindings.json` if `keybindings-help` is loaded.

5. **(Later) Sync with upstream.** If `yetone/magpie` installs cleanly: delete the local build, alias `mp` to the upstream binary, and verify the same four agents route correctly. The upstream adds menu bar, Docker, and Termux support.

## Effort

About 2 h total for Phases 1–3; Phase 4 is 15 min. Option A (upstream) is under 5 min if it installs.

## Blockers / risks

- **Config format drift:** Claude Code's config format changes occasionally; pin to the current `model` key and add a fallback that reads `claude config get model` as source of truth.
- **magpie creation date:** The upstream version history (v0.1.1169 → v0.1.1304 in Oct 2026) suggests it has been active since early 2026, possibly predating the local agent's 7-day window. If so, the upstream repo is a repost; the local build is still the right path.
- **`/model` built-in:** Claude Code's `/model` slash command switches the model for the current session only, not persistently. This plan targets persistent config, which `/model` doesn't reach.
