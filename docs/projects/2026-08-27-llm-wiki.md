## What it is

llm-wiki-agent is a personal knowledge base that builds and maintains itself. You drop in documents (PDF, DOCX, EPUB, Markdown, web pages) and the agent reads them, extracts entities and concepts, and writes interlinked markdown wiki pages — then keeps them consistent as you add more sources.

Core innovations over a standard RAG setup:
- **Interlinked pages:** entities, people, companies, and ideas each get their own wiki page with cross-references; a knowledge graph (`graph.html`) shows the link structure
- **Contradiction detection at ingest:** if a new source contradicts existing wiki content, the conflict is flagged at ingest time rather than surfacing as a confusing query result later
- **No API key needed:** runs through your existing Claude Code, Codex, or Gemini CLI session (no separate API billing)
- **Living synthesis document:** a `synthesis.md` regenerates after each new source, summarising what the whole knowledge base now "knows"
- **Multi-agent support:** Claude Code slash commands (`/wiki-add`, `/wiki-ask`), Codex/OpenCode via AGENTS.md, Gemini CLI via GEMINI.md

## MVP Scope (1 Claude session)

Clone the repo, test ingestion of 5 sources, then wire up a `wiki` CLI alias that wraps the Claude Code slash commands for quick terminal use:

1. **`wiki add <path|url>`** — drop in a file or URL; Claude Code reads and extends the wiki
2. **`wiki ask "query"`** — search and summarise from wiki pages; returns top-3 relevant pages
3. **`wiki graph`** — open `graph.html` in the browser to browse the knowledge graph
4. **`wiki status`** — count pages, list sources, show last-modified

### Phase 2: CLI Wrapper (1h)
- Write a `wiki` shell script or Python entry-point that shells into Claude Code with the right slash commands
- `wiki add` → triggers `/wiki-add <path>` in Claude Code background session
- `wiki ask "query"` → triggers `/wiki-ask "query"`, streams result to terminal

### Phase 3: Daily Digest (1h)
- At 07:00 via cron or Claude Code `/loop` skill: run `wiki digest`
- Digest agent reads git diff of `wiki/` since yesterday, writes a 5-bullet daily summary
- Output written to `wiki/digests/YYYY-MM-DD.md` and echoed to terminal on next `wiki status`
- Verify: commit 2 new sources at night → morning digest lists what changed

### Phase 4: Capture from Browser (1h)
- Browser bookmarklet: `javascript:fetch('http://localhost:9321/add?url='+encodeURIComponent(location.href))`
- Local Flask/FastAPI server receives URL → calls `wiki add <url>` in background
- Status notification via macOS/Linux desktop notification when ingestion completes
- Verify: click bookmarklet on 3 news articles → pages appear in `wiki/` within 30s

### Phase 5: Voice Capture (0.5h)

## Blockers / Risks

- **Token consumption on large ingests.** Each source goes through Claude Code which uses Claude API tokens via your Max plan. A 300-page PDF may consume significant tokens. Mitigate: add a `--chunk-limit N` flag to cap how many pages are ingested per session; ingest books chapter-by-chapter.
- **Wiki drift on high-frequency updates.** If 20 sources are added in a day, the synthesis document regenerates 20 times. Add a debounce: only regenerate `synthesis.md` if at least 5 new sources have been added since last synthesis run.
- **Graph becomes dense fast.** With 50+ sources the `graph.html` vis.js graph becomes unnavigable. Add a Louvain community filter (already in the repo's NetworkX graph) to show only top-N nodes by degree for the default view.
- **URL ingestion behind auth.** The markitdown URL fetcher cannot handle pages that require login. For paywalled articles or internal wikis, `wiki add /path/to/saved.html` works but the bookmarklet workflow breaks. Document the workaround: save the page as HTML and pass the local path.
- **Contradiction detection false positives.** LLMs flag contradictions conservatively; a date formatted two ways ("Aug 2026" vs "2026-08-27") may be flagged as a conflict. Review the conflict log weekly, not per-ingest, to avoid alert fatigue.
