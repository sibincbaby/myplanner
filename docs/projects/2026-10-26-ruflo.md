**Source:** [ruvnet/ruflo](https://github.com/ruvnet/ruflo) (MIT, formerly Claude Flow)  
**Tagline:** "Run a coordinated swarm of AI coding agents from a single command."  
**Discovered:** 2026-10-26 (cloud backup)

---

## Why it fits

Claude Code and Codex are powerful solo — but they're still single-agent tools. Ruflo is the meta-layer that wraps them in a swarm: 100+ specialized AI agents coordinated by an HNSW vector memory store, with persistent state across sessions and a built-in MCP server so any client can trigger and observe the swarm.

The user profile calls out **Claude/LLM tooling**, **Agent UIs**, and **dev productivity**. Ruflo hits all three: it's the execution layer sitting above Claude Code that makes multi-agent work feel like a first-class workflow rather than a manual copy-paste loop.

The key differentiator from what's already in seen.json: ruflo natively orchestrates *multiple coding agents at once*, with shared memory and swarm-level coordination. The closest entries (omnara, hivemind) are agent control planes or Kanban wrappers — ruflo is an opinionated harness with 100+ pre-built agent personas and an HNSW memory graph baked in.

## Shape

**Adopt upstream** — `npx ruflo init` is the entry point, not a build.

Two adoption modes:

- **Claude Code plugin only** (shallow): adds slash commands to an existing Claude Code session. Good for kicking the tyres.
- **Full init** (`npx ruflo init`): installs 98 agent roles, a background daemon, the MCP server, hooks, and the HNSW memory store. This is the full loop.

The interesting custom-build angle: the user could build their own *specialized agent personas* layered on top of ruflo's runtime — e.g. a "personal finance reviewer" agent that runs alongside a "code reviewer" agent, both sharing the same vector memory.

## Stack

- npx / npm (Node.js)
- Claude Code and/or Codex CLI as execution backends
- HNSW vector memory (bundled)
- MCP server (bundled — any MCP client can interact)
- AGPL / MIT depending on component

## MVP scope

1. `npx ruflo init` in a test project directory.
2. Confirm the background daemon and MCP server come online.
3. Issue a multi-step task ("refactor this module, write tests, and summarize the diff") — watch ruflo distribute across agent roles.
4. Inspect the vector memory store to see how context persists between steps.
5. Try a second, unrelated task and verify the memory carries prior context.

## Phases

1. **Install & verify (1 h).** `npx ruflo init`, check daemon logs, confirm MCP server endpoint.
2. **First swarm task (1 h).** Issue a 3-step coding task. Observe which agent roles activate and how results chain.
3. **Custom persona (2 h).** Write one custom agent role (e.g. a finance-specific code reviewer). Register it with ruflo and include it in a task.
4. **(Later) Memory tuning.** Adjust HNSW memory TTL and persistence strategy for your workflow cadence.
5. **(Later) CI integration.** Trigger ruflo swarm tasks from a GitHub Actions workflow.

## Effort

~2 h to install + first real swarm task. ~4 h total for custom persona and memory inspection.

## Blockers / risks

- **Star count variance:** Sources report 60–66k stars, but these come from aggregators — verify the GitHub page directly before relying on adoption metrics.
- **Daemon complexity:** A background daemon on your dev machine adds a moving part; confirm how to gracefully shut it down and whether it consumes meaningful CPU at idle.
- **Hermes support:** Coverage sources conflict on whether Hermes is natively supported or only Claude Code + Codex. Check the README before building Hermes-specific flows.
