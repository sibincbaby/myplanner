## Screening Notes

- **Three separate 4/4 drafts died today, all to the same check, and the check took one tool call each.** Yesterday's digest ended with an instruction to itself: before writing a project doc, run the plan's own thesis as a `search/repositories` query dated well before the plan, and score `novel` from the results rather than from memory. That instruction was followed for the first time this morning and it killed every project on the board. This is the first run in 48 digests where the screen worked *before* the plan was written instead of a day after somebody else shipped it. **Zero viable projects is what a working novelty check looks like on a day with no gap.** The three kills are below, with the numbers that were measured before each one died.
- **Kill one: the skill-usage ledger. Measured 168 skills installed, 32 ever invoked — and five tools already report exactly that.** The numbers on this box are real and worse than expected: **26 enabled plugins ship 145 skills**, plus **23 loose skills** in `~/.claude/skills/`, for **168 in the listing every session**. Across **1,019 transcripts** there have been **101 skill invocations spanning 32 distinct skills** — roughly **one skill call every ten sessions**, against a listing that is paid for in full at every startup. The top of the distribution is thin: `superpowers-extended-cc:brainstorming` 10, `ai-discovery` 8, `superpowers-extended-cc:writing-plans` 7, `ai-operator-ideas` 7. It died on a single search: **[cc-skill-usage](https://github.com/FlorianBruniaux/cc-skill-usage)** (5★, 2026-07-28, MIT) is a *single-file Python CLI* that "reads your existing `~/.claude` transcripts, counts real Skill `tool_use` invocations (not prose mentions), no hook to install ahead of time" — the exact design, including the exact caveat about prose mentions. Alongside it: **[skills-hub](https://github.com/Liang-HZ/skills-hub)** (11★, 07-12), **[skill-graveyard](https://github.com/sfrangulov/skill-graveyard)** (7★, 04-29, "surface dead installs and hallucinated invocations"), **[skillsight](https://github.com/PackmindHub/skillsight)** (9★, the team version) and **[selftune](https://github.com/selftune-dev/selftune)** (16★). `novel = 0`, five times over.
- **The interesting half of that finding survives the kill, and it is a `pipx install`, not a project.** `ccplug` is installed here and is the *actuator* — it writes a per-project `enabledPlugins` subset so a project pays only for what it needs. Its own instructions say to re-tune when "a skill keeps not firing (disable it)" and to judge fit "on **fit × cost**" using each skill's `estTokens`. It has no data source for either half of that sentence: the agent reads 168 descriptions and guesses. The sensor exists, the actuator exists, and nothing joins them — but the join is a script that reads one JSON and writes another, which is rung five of the ladder, not a weekend. **The action is `cc-skill-usage` this week, then `ccplug disable` whatever has never fired.** Nothing gets built.
- **Kill two, and it is a correction to a recommendation this digest published yesterday.** The 08-18 digest proposed adding a zero-width and homoglyph scanner to [nightwatch](../projects/2026-08-17-nightwatch.md), on the reasoning that this repo pushes unedited model prose to a public site nightly and invisible watermark artifacts would make that corpus a dated public sample. The scan was finally run this morning over the whole published corpus — **191 markdown files, 175,123 words — and it returns zero hits.** Not a low count: zero zero-width spaces, zero zero-width joiners, zero word-joiners, zero BOMs, zero non-breaking spaces, zero narrow no-break spaces. The check would have run every night forever and found nothing, because there is nothing there to find.
- **And the detector that actually works does not look at invisible characters at all, which retires the idea rather than just the implementation.** *Detecting Claude by Counting Letters* (HN, 2026-08-18) strips everything that is not a letter — "it cannot see punctuation, sentence length, paragraph structure, capitalisation or any individual word" — lowercases the remainder, and counts 4-letter n-grams. It scores **0.977 ROC AUC on fresh Claude writing**, 0.925 on held-out authors, 0.889 on the external RAID benchmark, and separates the author's own blog at a median of 0.09 human versus 0.85 Claude. The tell is vocabulary root: Claude leans Germanic (`g h l r n y`), humans leaner Latinate (`i c f s m`). A scanner for characters you cannot see is the wrong defence against a detector that only reads characters you can. **The honest response to a 0.977 AUC detector is not to build a scorer that helps this repo slip under it — it is to note on the site that the prose is model-written, which is true, costs one line, and is the thing a scanner would have been used to avoid saying.** Yesterday's nightwatch check is withdrawn; the secret-shape check on the outgoing diff stands, because that one has 19 confirmed hits behind it.
- **Kill three: the subagent prompt recorder, killed twice — once by a repo, once by the filesystem.** The chronic failure documented across six runs of this pipeline is subagents derailed by injected context: `read-seen` returning `"[]"`, `write-digest` making zero tool calls and echoing assistant guidelines, `derive-date` returning the literal string `date +%F`. The proposed fix was a proxy on `ANTHROPIC_BASE_URL` capturing exactly what each subagent receives. **[subagent-startup-cost](https://github.com/andresjmnz92-jpg/subagent-startup-cost)** was created 2026-08-17 — 9 KB of Python, and a thesis worth quoting in full: *"Your rules file is loaded into every subagent you start — including the rules it cannot act on."* That is precisely this box, where a read-only search agent is handed a system prompt telling it to be a lazy senior developer and a superpowers block whose first line is a `<SUBAGENT-STOP>` tag that exists because the problem is known. The second kill is cheaper: **the injected prompt is already on disk.** Each subagent's first user message is in `agent-<id>.jsonl` in the workflow transcript directory — this pipeline's own recovery procedure already depends on reading it. A proxy to capture data that a `grep` already reaches is the definition of building the thing you already have.
- **`agent-codemode` is today's most interesting idea and it is one of two implementations of it shipped inside eleven days.** *"Let the scripts your coding agent writes call your connected MCP servers (no extra auth)"* — instead of the model calling MCP tools one at a time through its context window, it writes a script and the script calls the servers in-process. `mchen6/countinghouse` (created 08-08) posted the same pitch to Show HN today: *"MCP tools that call each other in-process, not via model."* Worth knowing why it does not score here: this harness already defers roughly **250 MCP tool schemas** behind `ToolSearch`, so the context tax codemode exists to remove has already been removed by the runtime. `fills_gap = 0` on a problem the platform fixed underneath it — the same reason `/context` killed the context-accounting class of candidate on 08-17.

This repo's backlog holds `voicecode`, `localmic`, `echocode`, `voxctrl`, `speakoflow`, `vocalmcp`, `voxdag` and `voxdiary-flutter` — eight voice plans, all unbuilt, and the reason the lane kept re-scoring is that everything that shipped was macOS-only.
