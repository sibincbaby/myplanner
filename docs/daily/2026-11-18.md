## Viable Projects

- **[expenditures-control - MCP server that turns bank notification emails into a live spending report inside Claude](../projects/2026-11-18-expenditures-control-india-bank-email-mcp.md)** — This is a strong fit for the user's personal-finance AI and Claude tooling interests. The only related project in ~/my-works is mycards, an offline card vault, so nothing they have ingests transactions automatically. An MVP is buildable in one or two sessions: read-only Gmail, Claude-proposed parsers checked against sample emails for their Indian banks (HDFC/ICICI alerts), SQLite storage, and a report tool. The learn-from-examples parsers and in-Claude report also set it apart from manual-entry tools like Firefly III and Actual Budget. Daily utility scores 0 because people check spending reports and budgets a few times a week rather than every day, and once the ingestion runs on its own the tool mostly sits in the background.
- **[seshka - macOS menu bar app that kills dev servers and watchers Claude Code left behind](../projects/2026-11-18-seshka-linux-claude-ps-procs-reaper.md)** — weekend_buildable=1: the user is on Linux, so the Swift app is no use as-is, but a Linux version is a small job: walk /proc from the claude PIDs, group child processes by session, show memory use and ports (ss/lsof), kill them, and add an optional idle-reaper as a CLI/TUI or tray app. fills_gap=1 and novel=1: the user runs many Claude Code sessions every day and has nothing that tracks processes by session (~/my-works/fkill only closes X11 windows, and csess only reads transcripts), and generic tools like htop or fkill-cli don't group by Claude session, while seshka itself is macOS-only. daily_utility=0: leftover dev servers and port clashes come up often, but once auto-kill is on it is a background cleanup tool rather than something the user would open every day, so this is a borderline 3.
