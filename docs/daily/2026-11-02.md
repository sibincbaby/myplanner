## Why each scored the way it did

- **memdoor (viable, install-first):** Two features make this gap-filling beyond what Claude Code covers: deterministic YAML workflows runnable headlessly from CI/cron, and model-agnosticism (use cheap Haiku for simple steps, Opus for complex ones within one workflow). WB=0 because Go+SSH+YAML engine+phone link is a full-day install, not a half-day one. FG/N/DU all = 1. The headless automation gap is real: there's nothing in the current toolkit that runs an LLM coding task on a schedule without a human in the loop.
- **Orkas (viable, install-first):** Local-first multi-agent team is the clearest architectural alternative to cloud-based multi-agent products in the ecosystem. The current practice of manually opening 3 Claude Code sessions for a complex feature is the gap Orkas fills. WB=0 (don't build it — install it). Evaluation plan is straightforward.
- **ilse (viable, build-first, strongest candidate):** Visual-context code targeting is a genuinely new interaction primitive. The "describe the element textually" workaround in Claude Code is the exact friction ilse eliminates. WB=1 because a CLI MVP (screenshot + coordinates + Claude vision + file edit) is a well-defined build achievable in one session. 4/4.
- **fastbrowse (viable, install-first + extend):** The page-candidate-indexing approach is architecturally novel in the browser-agent space. The safety gates (explicit authorize for irreversible actions) are production-practical, not academic. DU=0 because browser automation is task-specific, not daily. WB=1 because `pip install fastbrowse` + a 30-line script is enough for the first real task. Worth wrapping as an MCP tool for Claude Code sessions.
- **iFixAi (viable, build-first):** Agent behavior auditing — "does this agent reliably do what it claims?" — fills a real gap that LLM evals and unit tests don't cover. Build-first because the concept generalizes better as your own harness than as an installed tool. WB=1, DU=0 (use when building agents, not every day).
- **XWiki MCP (viable, build-first, generalized):** The XWiki product is for XWiki users specifically; this plan re-frames it as a local knowledge MCP for your own notes/docs. N=0 because the pattern is established, but FG=1 (live note access in Claude Code sessions) and DU=1. WB=1 (2–3 hour build). Marginal on strict standards (N=0) but passes 3/4.
- **Claude-Code-Game-Studios:** Clever but fills no gap — game development is not in the interest profile. N=1 for creative multi-agent orchestration, but FG=0, WB=0, DU=0. Skip.
- **OpenMausBot:** Another open AI bot alternative with no differentiated feature relative to the toolkit. 0/4. Skip.
