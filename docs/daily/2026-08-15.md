## Screening Notes

- **Three independent teams shipped "approve the agent's permission request somewhere else" inside two weeks, and the reason is visible in this machine's own config.** `~/.claude/settings.json` here holds **151 entries in `permissions.allow`** — the accumulated output of the `fewer-permission-prompts` skill, a static allowlist that by construction only covers what has already been asked once. And `run-discovery.sh`, the cron job that produces this very digest, invokes `claude --dangerously-skip-permissions`. So the two available settings on this machine are *151 hand-grown rules and a prompt* when someone is watching, and *no gate whatsoever* when nobody is. There is no middle setting, and the unattended half is the one running unsupervised at 3am with network and filesystem access. claude-remote-approve is the first of the three to hang off `PermissionRequest` — confirmed today against the hooks reference as a real event returning `hookSpecificOutput.decision` of `allow`/`deny`/`escalate` — which is the correct attachment point because it fires *only* when a decision is genuinely needed, not on every tool call. See [airlock](../projects/2026-08-15-airlock.md).
- **SLL is the enforcing version of a skill this repo has been failing to follow for six weeks.** Three hooks: a stated test result must reproduce, a fabricated import never reaches disk, every command's real output is recorded. The project memory for this repo is, almost in its entirety, a list of runs where the agent reported success and the file was never written — `write-digest` making zero tool calls and returning boilerplate on 07-09, `update-sidebar` silently omitting 08-11 from `config.ts` for a full day, `read-seen` returning `[]` and re-surfacing four already-seen URLs on 08-14. Every one of those was committed with a message that said it had worked. The standing fix has been a five-point checklist a human runs afterwards, and `verification-before-completion` is installed as a *skill* — which is an instruction delivered at session start, roughly 200k tokens before the moment it needs to fire. SLL's insight is that this belongs in a hook, where it is deterministic. `novel = 1` on the narrow reading: SLL gates tool-by-tool as calls happen, and nothing yet gates the *claim in the final message* against the repo's own declared checks. See [notary](../projects/2026-08-15-notary.md).
- **clean-recap is a two-hundred-line shell script carrying one genuinely good idea.** The Stop hook fires the instant the model decides it is done; returning `{"decision": "block"}` refuses the stop and feeds `reason` back as the next instruction — with nothing after it in the context to dilute it. The README states the problem exactly right: an instruction in `CLAUDE.md` works for ten turns and then is 150k tokens back, competing with everything else. That mechanism is what [notary](../projects/2026-08-15-notary.md) is built on. The shipped *product* — making Opus write a friendlier summary — is worth `daily_utility = 0` here, and the repo carries a skool.com funnel above the fold and no license file.
- **breakwatch has the best engineering reasoning of anything screened this week and still is not a project.** Streaks rather than sessions, thresholds weighted by hour (90 minutes in the afternoon, 25 past midnight) tuned against two months of one person's real history, an alarm that restores your previous volume *and* mute state afterwards because one 2am blast gets a tool uninstalled, and a `report` subcommand that measures what share of its own nudges were followed by an actual break. All of it is macOS: CoreAudio output detection, Focus-mode suppression, volume floors. What survives the port to this Linux box is a JSON streak log plus `notify-send` — which is a shell script, the same verdict speak-ez earned yesterday. `fills_gap = 0` regardless: a break reminder is not a gap in a toolkit.
- **opencode-auto-permissions is the right idea aimed at the wrong agent, and it is the strongest prior art for today's first pick.** Model-driven review of exactly the requests configured as `ask`, never granting permanent `always`, using whichever model the requesting session already selected, with 87 tests and a published npm package — this is a serious piece of work for a repo with zero stars. It is also OpenCode-only, and `fills_gap = 0` here only because [airlock](../projects/2026-08-15-airlock.md) covers the same ground for Claude Code. Its configuration advice is the part worth stealing verbatim: do **not** set everything to `ask`; allow routine work outright and reserve `ask` for the operations where context is what decides.
- **claude-conversation-graph does the one thing the session-browsing pile has not.** Hindcast (08-12), mirror (08-10), chatlens (08-14) and the installed `csess` skill all read transcripts forward. This renders the *branch* structure that rewinds and edits actually produce, merges files from one lineage into a single session so the list stops showing duplicates, and lets you resume from a chosen historical node rather than only from the latest context. It is also a Chinese-language VS Code extension whose Python exporter is stdlib-only and single-file — read that exporter for the lineage-merging heuristic. `daily_utility = 0`: nothing here forks conversations often enough to need a map of them.
- **sloptrim earned 39★ in two days for refusing to use a model.** Python standard library only, no network, no weights, prose files only and never code, scoring the spans your agent just wrote and asking for the flagged ones back. The restraint is admirable and the timing is not accidental — this landed the same week Anthropic's output watermarking became the top story on HN four separate times. `fills_gap = 0`: the prose this machine generates is these digests, and their failure mode has never been slop, it has been files that were never written at all.
- **cliclaw and Port22 are the phone-shaped answer to today's first project, and both are HN reposts wearing new dates.** cliclaw's Show HN placement was 08-14; the repo was created 2026-05-13 and last pushed 2026-07-27 — a Telegram bot fronting four CLIs, macOS daemon, `novel = 0` and stale. Port22 is polished (iOS, free tier, end-to-end encrypted, no wrapper or config, taps the actual options the agent offered rather than guessing keystrokes) and unbuildable here on all three axes: closed source, iOS-only client, macOS-only host. What both confirm is demand for the escalation half of [airlock](../projects/2026-08-15-airlock.md) — and that the honest MVP is a push notification with two buttons, not an app.
- **yazses is the Linux dictation tool the last thirty-nine voice entries kept not being.** X11 *and* Wayland, faster-whisper on-device, hold-to-talk, 12 forks against 9 stars — an unusually high ratio that says people are patching it for their own machines. Created 06-22, so it is not new; it surfaced on HN 08-13. It is the correct answer to yesterday's speak-ez note, and `novel = 0` after thirty-nine prior entries in this category is what the score is for.
- **mcp_on_mobile_workshop is the only Dart entry in weeks worth reading.** An on-device agent whose tool list is half local and half remote MCP, and — the interesting half — a phone that registers *itself* as an MCP server, so the agent on your laptop can call the sensors in your pocket. Workshop material from MCP Dev Summit Seoul, 1★, so it is a reference implementation and not a product. Filed for the Flutter interest: this is the shape a mobile-first agent app takes now.
- **Hexis is well-built and aimed over this machine's head.** Git-backed control plane for skills, tools, context, permissions and identity, MCP-native, self-hosted, Apache-2.0, 60★ — the open core of a commercial platform, sold on "engineers and non-technical people alike can browse and load plugins." Single-operator machines do not have that problem; `ccplug` already handles the local version of it. `weekend_buildable = 0` on a control plane, honestly.
- **Also screened, not tabled:** the DeepSeek Harness wave has gone from a trend to the majority of GitHub's new-repo results — dsh-TUI (881★ in two days), dsh-hud, dsh-work, dsh-vision, dsh-pet, dsh-doctor, dsh-mcp-manager, dsh-telegram-channel, dsh-import, dsh-fail-logger, dsh-plugin-cc, dsh-chat-import, awesome-deepseek-harness, plus a VitePress tutorial site, nearly all of them re-implementing a Claude Code feature inside another harness. Also: agent-safe-pipeline (359★, immutable intent capture with an ALLOW/ESCALATE/DENY policy verdict), Agent-Permission-Gateway-Agent-IAM and deputy ("autonomy is a permission, not a default") — three enterprise policy-engine takes on the same permission theme, all reference architectures rather than installable tools; Graft (2651★ but created 07-03, already screened 08-13); mcp-stama (Rust single-binary MCP server); Hillock (created 06-11, HDC/VSA memory engine); emend (17★, verified dependency migrations that prove the result still compiles); crucible, godmode, Skill_Atlas and iso-24495-skill (more skill bundles); claude-code-ratelimit-hook (pauses and resumes on usage limits — the installed `ccauto-resume` skill already does this); claude-code-guardrails and ucsandman/claude-harness (hook packs); mole (Go deep-research agent with an enforced budget); Gnat, netra and sixteen student expense trackers with no AI in them.
