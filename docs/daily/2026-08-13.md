## Screening Notes

- **shiplog is the find of the day because it costs nothing to use.** The backlog has seven journalling entries — agentjournal (07-25), claude-journal-mcp (07-10), moodiary (07-01), memex (07-16), voxdiary-flutter (07-21), and the voice-capture tools that feed them. Every one of them requires you to *say or type the entry*. That is the reason none of them survive contact with a busy week. shiplog inverts it: the log is derived from commits that already exist, so the input cost is zero and the habit cannot lapse. Against this machine specifically — Linways bugfix work where every fix already carries a Redmine issue id in the branch or commit — a week of commits compiles into something that can be pasted into a ticket or a standup with no writing at all.
- **cc-usage-awareness is small, and the small part is the point.** The backlog already has aiusage-tracker (08-07), and today added tokentab and tokenBar-companion — three cost dashboards for a human to read. This one is the only one that hands the number *to the model*. That is a different primitive: an agent that can see it has 12% of its window left can compact early, decline to fan out sixteen subagents, or say so before starting. The strongest evidence that the gap is real is already installed on this machine — the `ccauto-resume` skill exists purely to restart a session after a usage limit resets overnight. That is a tool for the wall you already hit. There is nothing for seeing it coming.
- **aakit is a good idea one step away from being useful.** Extracting the assumptions an agent made and linking each to the code that depends on it is genuinely novel — agentblame (08-10) attributes authorship and selfspec (07-28) records intent, neither tracks assumptions. It scores `fills_gap = 0` and `daily_utility = 0` anyway, because the output is a report you read after the fact, and reports-you-read-after-the-fact have a near-zero survival rate in this backlog. The version worth building is a `PreToolUse` check that blocks the edit contradicting a recorded assumption, and that is not what shipped.
- **beacon_widget is the strongest Flutter signal in a week and still not buildable here.** Flutter came up empty for three straight days; this is a real Dart package, MIT, that closes the point-at-the-UI loop for Flutter the way yesterday's pinpoint plan does for the desktop. `novel = 0` because Flutter DevTools' widget inspector already resolves a tapped widget to its source location — the delta is putting it on the clipboard in agent-pasteable form, which is the last 10%. `daily_utility = 0` for a harder reason: this machine has no Dart SDK installed (the session hook reports it missing on every startup). Bookmark it for whenever Flutter work resumes; installing it will be a one-line `pubspec` change, not a build.
- **aidimag's premise is right and its gap is already closed by a sentence.** Seven memory projects precede it — memlayer, turnmem, atlaso-memory, memsync, deja-vu, cog-brain, contextpop — and none of them re-verify. But the failure mode it targets is handled here by an instruction rather than a tool: the memory system already says that a recalled memory reflects what was true when written and that any file, function or flag it names must be verified before being recommended. With two memory files in the store, a re-verification engine is machinery for a problem that has not arrived. Revisit at fifty.
- **Three token-cost dashboards shipped in three days** — tokentab (14★, 08-12), tokenBar-companion (Flutter + Rust, 08-10) and cc-probeline (statusline, resurfaced 08-12) — on top of aiusage-tracker already in the backlog. The category is saturated on the reading side and empty on the acting side, which is exactly why the viable pick above is the one that changes agent behaviour rather than rendering a chart.
- **mcpd is the right diagnosis and a month of work.** Running one process per MCP server per client is genuinely wasteful, and this session is holding roughly 200 deferred tool schemas across a dozen servers. But a supervising daemon with shared instances, lazy start and lifecycle management is not a weekend — `weekend_buildable = 0` is what kills it, not the idea. MIT, so install it if the RAM ever actually hurts.
- **spendglass is the sixteenth personal-finance entry.** Local-only transaction store plus a read-only MCP server is the correct shape and is essentially what local-finance-mcp, claude-finance-mcp, finmcp and copilot-money-mcp already specify in this backlog. `fills_gap = 0` here means the plan exists five times over, not that the interest lapsed. Nothing new shipped against finance in the window besides this.
- **local-agent-senses, askance and whoport are all one-feature tools against features that already exist.** Claude Code reads images natively; pulse (07-15) and pocketclaw (08-01) already cover phone-side human-in-the-loop; and `ss -ltnp` answers the port question in one line. whoport is a nice piece of writing about agent swarms and a shell script.
- **Also screened, not tabled:** Hax (52 pts, minimalist terminal coding agent in C — a harness, not a tool), activity-frames (550★ but created 07-04, resurfaced on HN; overlaps the memory pile), Graft (2085★, created 07-03 — established, not new), delegate-skills (920★, 06-14), operator-oss (200★, 07-13 — parallel-session mission control, covered by claude-fleet and agentsquad), repo2skill (book-to-skill and skillpilot cover it), PolicyApprovalGate (third permission gate in three days after toolpermit and toolgate), aileaks (reasoning-trace secret scanner — security, outside the interest profile), PersonalJarvis and openhare (both predate the window by months), and kharcha (Flutter UPI expense tracker, 08-06 — Android-only and India-UPI-specific, finance category already saturated).
