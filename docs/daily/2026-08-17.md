## Screening Notes

- **Ten separate things shipped in forty-eight hours about the token bill, and this box has never once measured its own.** On GitHub: mcpaxe (audit the token cost of every MCP server and tool, find the ones you never use), mcp-diet (a Go proxy cutting tool-schema tokens 50-78%), routre-cli (−90% on tool-heavy traffic), contextbrief (a change log sized for the reader). On Hacker News: *The AI Credit Resale Economy* at **164 points** — brokers reselling unused API credits at **40-50% off list**, one offering **$100k a day** of spending capacity; *Is the industry ready for tokens-constrained work?* at **36 points and 68 comments**, quoting a status line reading `5h:100% 7d:100%` and an org whose **year's token budget was gone by April**; plus Show HN entries for RNet ("AI token service provider") and TokenLab MCP (model discovery and pricing). Measured here today: **1,115 sessions** on this machine carry a first-request token count, median **32,122** tokens; the `myplanner` project alone has burned **85.8 M cache-read, 10.8 M cache-write and 2.7 M output tokens** across 60 transcripts. The two nightly cron jobs that produced all of it log exactly one word each: `Done`. See [yield](../projects/2026-08-17-yield.md).
- **`/context` is a built-in command, and that is the whole verdict on the MCP-audit cluster.** Confirmed in the docs today: `/context [all]` visualises current context usage as a grid with a per-item breakdown, plus optimisation suggestions for context-heavy tools and memory-bloat indicators — and the Skills row reports the listing size *after* the skill-listing budget is applied. This session goes further: roughly **250 MCP tools arrived as bare names**, schemas deferred behind `ToolSearch` until one is actually needed. mcpaxe weighs an MCP config; mcp-diet proxies one to shrink it. Both are solving, in a sidecar, a problem the harness now solves natively and lazily. `fills_gap = 0` for the pair, and the honest advice is to type `/context` before installing either. mcp-diet is worth a second look only for the claim in its 14 KB README — 50-78%, sub-millisecond, no model in the decision path — sitting on top of a package skeleton with no implementation in it yet.
- **`Done` is the entire record of a run that spends eight million tokens.** `run-discovery.sh` ends with `echo "[$DATE] Done"`, printed whenever `claude -p` exits 0 and `git push` succeeds. It is not conditional on the digest existing, the sidebar being updated, `state/seen.json` growing, or the commit message containing a real date — and every one of those has silently failed at least once on this repo: a commit reading `chore: daily discovery date +%F` on 08-03, dedup disabled by an empty read on 08-09 and again on 08-15, `docs/daily/2026-08-11.md` written but left out of `config.ts` for a day. `discovery.log` is 65 KB and its last six lines are `[2026-08-11] Done` through `[2026-08-16] Done`. The checks that catch these are already written down in prose and run by hand the next morning; nothing runs them at 01:00. See [nightwatch](../projects/2026-08-17-nightwatch.md).
- **Two of today's best Show HN posts are months-old repos, which is now a weekly occurrence worth stating as a rule.** grafana-agento11y-hermes (25 points, 34★) was created **2026-04-29**; Meridian, the local-first work journal that drafts your project updates, posted twice today and was created **2026-05-06** with 34★ and 4,471 lines of Rust; Kungfu ("keep agent work alive across sessions") is **4,471★ and dates to 2017**; Mole, the terminal research agent at 98 points, is 213★ from 2026-08-01; jit, at 51 points, is from 2026-07-13. The star count is the tell every time — a two-day-old repo does not have 34 stars. Only `created:>YYYY-MM-DD` on the REST search API is date-honest, and it stays the backbone of this pipeline.
- **agmux scored 3/4 and is still not the project, because it already exists and it is a tmux config.** *"k9s for coding agents. A thin manager layer over the tmux you already run: fuzzy-jump, spawn, and monitor Claude Code / Codex / opencode / grok / pi."* That is the right instinct — no new runtime, no daemon, no Electron window, just bindings over the multiplexer that is already open — and it is the fourth agent-supervisor UI screened in three days after Managerie, waku and rungraph. `fills_gap = 0`: nothing on this box needs to *watch* concurrent agents, because the agents here run at 01:00 and 01:33 unattended and the question is never "which pane is stuck", it is "did last night's run do what it said". That is a different tool, and it is tonight's second project.
- **uiver-plugin also scored 3/4 and is filed rather than built, for the plainest possible reason.** Local-first UI version snapshots — capture, browse, compare and share every iteration of a web UI as agents build it, as a Claude Code plugin plus CLI plus dashboard. It is a genuinely good idea and the failure mode it addresses is real: the agent's fourth attempt is often worse than its second and nobody keeps the second. `daily_utility = 0` here and only here, because the only front-end work on this machine is a VitePress sidebar, and it is edited by regex.
- **The safety-plugin wave crossed from pre-flight into egress this week.** agent-guard is one shell file with no dependencies that refuses destructive commands; customhouse is a deterministic MCP proxy that blocks money-moving and data-egress tool calls **in any session that has received untrusted content**, with no model in the decision path. That taint-tracking framing is the first real advance on this theme since [airlock](../projects/2026-08-15-airlock.md) — a rule that fires on provenance rather than on a command pattern. Both score 2/4 because this repo's cron already runs `--dangerously-skip-permissions` by deliberate choice; the guard that matters here is the one that checks the *output* afterwards, not the one that argues with the agent at 01:00.
- **skilldiff is yesterday's project as a 168-byte README.** *"A zero-dependency, production-grade Python CLI named `skilldiff` for A/B testing AI agent skills, prompts, and tool definitions using LLM-as-a-Judge."* No code, no `pyproject.toml`, no `src/`. It is worth noting for two reasons: it is the second A/B-testing-your-instructions repo in three days, which confirms [ablate](../projects/2026-08-16-ablate.md) was aimed at a real hole; and it picked LLM-as-a-judge, which is exactly the loop ablate refuses on purpose. A model grading whether a model followed an instruction is unverifiable in the same direction as the thing it is measuring.
- **The Claude system prompts went public and it does not help here, which is worth writing down before someone spends a weekend on it.** *Claude: System Prompts* took **394 points and 168 comments** — full prompt text for Opus 5, Fable 5, Opus 4.8, 4.7 and Sonnet 4.6, organised by release date with the deltas bolded. The obvious project is a watcher that diffs releases and flags the lines in your own `CLAUDE.md` that the vendor default now covers. It does not work: the page states plainly that **these prompts do not apply to the Claude API**, and Claude Code is an API client. The published text governs claude.ai and the mobile apps, not the harness running on this box. Genuinely interesting reading, wrong input for the tool, `fills_gap = 0`.
