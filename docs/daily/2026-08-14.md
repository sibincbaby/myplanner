## Screening Notes

- **codex-structured-steering is the exact project yesterday's screening asked for, shipped by someone else, for the wrong agent.** The 08-13 note on aakit read: *"The version worth building is a `PreToolUse` check that blocks the edit contradicting a recorded assumption, and that is not what shipped."* This is what shipped today. It does not write a report — a cheap watcher subagent reads the session as it goes, turns each *implicit* decision the agent made into a YES/NO toggle or a dropdown, and injects any change back as steering context via `additionalContext` so the correction never enters the visible history. The detail that proves the author has actually lived this: it also surfaces a control when your own guidance has flip-flopped three times, because at that point *you* are the ambiguity. Two things stop it being installable here — it is `Structured Steering.app`, a macOS overlay, and it is wired to Codex — but the mechanism is four hooks and a schema, and Claude Code has hooks. See [steer](../projects/2026-08-14-steer.md).
- **skilldoctor is the first tool in six weeks aimed at the skills rather than made of them.** The backlog has thirty-two skill entries — book-to-skill, reverse-skill, evidence-to-skill, awesome-claude-code-toolkit (135 agents, 176 plugins), flutter-llm-toolkit, sub-agents-skills — every one of them a *producer*. Nobody checks the output. This machine loads roughly forty skills at session start and already runs `ccplug` to switch some off for context cost, which is a triage tool for a problem nobody has measured: whether the descriptions collide, whether a `SKILL.md` is even spec-valid, what each one costs to keep loaded. `daily_utility = 0` honestly — you do not lint skills every day — and it still clears the bar at 3/4 because the other three legs are clean. See [skillcheck](../projects/2026-08-14-skillcheck.md).
- **deposition is yesterday's viable project, minus the part that made it work.** `recap` (08-13) compiles a work log from commits and sessions; deposition extracts *decisions* from agent sessions with deterministic rules and zero API calls. Same primitive, narrower output, and the backlog already holds brain0 (07-05, decision graph from agent prompts), claude-journal-mcp, private-journal-mcp and memory-journal-mcp. `fills_gap = 0` because the plan is already written and one layer up; `novel = 1` for the zero-inference extraction, which is a genuinely good idea worth stealing into recap's parser rather than building beside it. Zero stars, published today, no license file — read it for the heuristics, not the install.
- **mcp-memory is the fifteenth memory project and the best-argued of them.** SQLite FTS5 instead of embeddings means no model to load, no index to rebuild, and search that costs a millisecond — the same bet deja-vu (08-02) and remembrane (08-09) made. 87★ in a day says the category still sells. `fills_gap = 0` regardless: memory here is a directory of markdown files with an index, currently two entries, and the constraint on it is not retrieval speed. Revisit when recall actually misses something.
- **Three more usage meters in two days.** tare (13★, session-log forensics, "where did my limit go"), cookbook-meter (`npx`, one command), and Agent-Dashboard (Rust, centralized token dashboard) join tokentab, tokenBar-companion, aiusage, pandev-cli and cc-probeline. That is eight tools rendering the same number for a human. Yesterday's viable pick in this category — [fuelgauge](../projects/2026-08-13-fuelgauge.md) — was the one handing the number to the *model*, and nothing shipped today changes that split. tare keeps `daily_utility = 1` only because limit diagnosis is a real 5pm question on this machine.
- **speak-ez is a good build on the wrong OS and a saturated shelf.** Thirty-eight voice entries precede it, including SpeakoFlow (08-08) which is explicitly cross-platform, offline Whisper, fully local — the same product without the macOS lock-in. Swift, `NSEvent` key monitoring, Accessibility-API text insertion; none of that ports. On Linux the whole thing is `whisper.cpp` plus `xdotool type`, which is a shell script, not a project.
- **linear-claude-bridge points at a real hole and covers the wrong tracker.** The backlog has *zero* issue-tracker bridges across 401 entries, and daily work on this machine is Redmine tickets — the `lwr` CLI and the `lw-bugfix-lifecycle` skill already drive that loop end to end, including the QA release and the Chat notify. So the category is empty and the need is already met by something better-fitted. `novel = 1`, `fills_gap = 0`, and the interesting half is the direction of travel: it runs the agent *as* the tracker's agent, so the ticket thread is the transcript. Worth remembering if Redmine ever grows a webhook.
- **Varavu.Selavu is the seventeenth personal-finance entry and the first one whose shape is right.** Single `app.py`, SQLite, stdlib-only unless you want PDF statement parsing, and the README's stance is correct ("Real financial data should stay off GitHub. Boring rule, but important"). It is a household ledger with statement import that an agent maintains, which is roughly what accountant24 (07-11) and WiseCashAI (07-13) already specify. `fills_gap = 0` for the same reason as every finance entry since July: sixteen plans exist and none has been built, which is information about the interest, not the tools.
- **prompt-contribution-graph is a green square grid for prompts.** Genuinely novel framing, zero decisions change because of it. `daily_utility = 0`.
- **book-to-skill got 882★ in two days and is the second one of its name in this backlog** — `virgiliojr94/book-to-skill` was screened on 08-04 doing PDFs and EPUBs. When two independent implementations and a four-figure star count arrive inside ten days, `novel = 0` is not a judgement about the idea.
- **chatlens is a single HTML file, which is the right build,** and Hindcast (08-12) plus mirror (08-10) already cover browsing and replaying sessions here — as does the `csess` skill installed on this machine, which reads any session transcript as JSON.
