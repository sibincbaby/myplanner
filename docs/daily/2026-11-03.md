## Why each scored the way it did

- **lightpanda (not viable, use-as-infra):** Architecturally novel (Zig from scratch, CDP-compatible, native MCP + LLM control via PandaScript) but this is infrastructure you plug in, not a weekend build. FG=1 (faster/lighter than Chrome for agent web automation), N=1, but WB=0 (building a headless browser is not a 1-2 session task) and DU=0 (background infra). 2/4.
- **worktrunk (viable, install + extend):** Strongest productivity fit. Parallel agent development — two Claude Code sessions in worktrees, then merge — is the exact workflow the user already attempts with manual worktrees. worktrunk automates the whole lifecycle: create, launch, commit (via LLM), merge, remove. WB=1 (configure in one session, could extend the Claude Code plugin), FG=1 (parallel agents without collision), N=1 (purpose-built for agent dev), DU=1.
- **agent-beacon (viable, install-first, top score):** Cross-harness memory fills the single biggest daily friction: every new agent session starts cold. The pattern "agent works, makes a correction, improvement is forgotten next session" is the exact gap. Generates reusable skills from real workflows. WB=1 (integrate in one session), FG=1, N=1 (cross-harness, not locked to Claude Code), DU=1. 4/4 alongside worktrunk.
- **agent-desktop (viable, build-first):** Accessibility-tree computer use is architecturally different from screenshot-based computer use (BrowserUse, Claude computer-use). Stable refs + structured JSON means scripts don't break when UI pixels shift. WB=1 (write a useful automation script in one session), FG=1, N=1. DU=0 — desktop automation is task-specific. 3/4. Best used as foundation for a specific automation project.
- **opcode (viable, install-first):** Fills the "I want a proper UI for Claude Code" gap without requiring a terminal. Custom agent creation + background agents + session tracking are features that make multi-session work sustainable. WB=0 (existing full app), FG=1, N=1 (Tauri 2 + comprehensive feature set), DU=1. 3/4.
- **lumma (viable, build-first, strongest for journaling):** Voice → Obsidian Markdown is a niche but well-defined gap. The Flutter architecture makes a cross-platform MVP realistic. WB=1 (voice capture + LLM transcription + Markdown export in 1-2 sessions), FG=1 (no existing tool in the toolkit does voice-to-Obsidian), N=1 (AI-native from the start, not a voice-recording app with AI bolted on), DU=1 (daily journaling). 4/4.
- **VoiceStudio (not viable, use-as-library):** Local voice cloning has clear value but daily utility is low. WB=0, DU=0. The gap it fills (no ElevenLabs subscription) is real but not in the top-priority interest areas. 2/4.
- **t3-code (viable, install + configure):** Unified multi-agent control plane from Theo Browne, MIT. The "I have Claude Code, Codex, and Gemini CLI and they're all separate terminals" friction is real. Desktop + web + mobile companion is the right form factor. WB=0 (existing full app), FG=1 (one interface for all agent CLIs with own subscriptions), N=1, DU=1. 3/4.
