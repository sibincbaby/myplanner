## 1. Most interesting discoveries

### M-VAVE FM-1: a cheap synth turned open firmware platform (SDK 2026-10-13; ecosystem still accelerating)
- **What happened:** M-VAVE published [m-vave/fm1_open](https://github.com/m-vave/fm1_open) (390★, created 2026-10-13, last push 2026-10-21). The community hub [aroum/fm1-custom-fw](https://github.com/aroum/fm1-custom-fw) (432★, pushed 2026-11-21) calls it a GPL-3.0 SDK, but GitHub's license field reads NOASSERTION. The hub says the FM-1 runs on a **JieLi AC791N** and lists "270+ community firmwares".
- **Leading firmwares (stars and pushes checked today):**
  - [isod89/sloop-fm1](https://github.com/isod89/sloop-fm1) (851★, live groovebox)
  - [hugelton/Felucca](https://github.com/hugelton/Felucca) (763★, a base that dozens of forks build on)
  - [charlesvestal/fm1-x0x](https://github.com/charlesvestal/fm1-x0x) (246★: 909, 808, two 303s)
  - [illuminus5/skiff](https://github.com/illuminus5/skiff) (198★)
  - [keremimo/melodee](https://github.com/keremimo/melodee) (219★)
- **Tooling:**
  - [joakimeriksson/fm1-emu](https://github.com/joakimeriksson/fm1-emu) (304★) runs FM-1 firmwares unchanged in a browser.
  - [jvitkauskas/m-bootloader](https://github.com/jvitkauskas/m-bootloader) (60★, MIT, pushed 2026-11-21) replaces the stock bootloader. Per its README, the stock one "starts it unchecked". The replacement adds a REC-at-power-on download mode and reinstall over USB MIDI, so a bad flash can be recovered without opening the unit.
  - Firmware is being ported across to the SMK-37 Pro/Elite keyboard ([genkigenki/fm1-to-smk37](https://github.com/genkigenki/fm1-to-smk37)).
- **AI angle:** the Felucca README says it "is developed with the assistance of AI coding agents (code, tests, documentation, translation, maintenance)". Trade-press summaries describe a wider wave of hobbyists using AI tools to write music-gear firmware ([Synthtopia, 2026-10-28](https://www.synthtopia.com/content/2026/10/28/will-open-firmware-become-the-next-big-trend-in-electronic-music-gear/), search summary only; the page was blocked).
- **Limits (hub README):**
  - Newer FM-1 units with a **UC25HQ80 flash chip** (JEDEC `0xB36014`) may be incompatible with some firmwares.
  - One user reported an apparent brick, with only the red charging LED left. The cause is unconfirmed.
  - The community advises returning to stock V15/V16 before switching from one custom firmware to another.
- **Score:** 8/10 · **Confidence:** high (vendor SDK plus many independent working firmwares)

### H713 Linux: mainline Linux 6.18 on cheap MagCubic projectors, written entirely by an AI agent (v0.97-beta 2026-10-22; last push 2026-11-17)
- **What it is:** [well0nez/allwinner-h713-linux](https://github.com/well0nez/allwinner-h713-linux) (35★) replaces the projector's Android. It installs an open boot chain (U-Boot SPL, TF-A, U-Boot) and **mainline Linux 6.18 with Debian 13**.
- **What works:** the README lists each item as measured on a device and dated:
  - HDMI input with HDCP 1.4 and 2.2, using the device's own keys;
  - Kodi, a labwc desktop and Firefox;
  - hardware video decode;
  - keystone on the Mali GPU, and autofocus rebuilt from the built-in camera and focus motor;
  - both stock remotes;
  - a web settings panel;
  - recovery through FEL, with stock Android restorable byte for byte from your own dump.
- **Verified boards:**
  - **Verified:** HY310, HY300PRO-G-EU and L018 (the L018 since v0.97.1-beta, 2026-10-26).
  - **Partial:** HY320, where Linux boots but the video plane stays dark, and LOSEI X9.
  - **Profile only:** HY300 T08, HY350 and "HY300 Pro+" LPDDR3.
  - The rule: "no image for a board nobody has tested."
- **AI angle:** the README opens with "Everything in this project … was **generated by AI** (Claude, in sessions directed by the maintainer)". It has "not yet been reviewed line by line by a human". The repo ships an `AGENTS.md`.
- **Known problems (README):**
  - There is no standby. "Off" draws 2.9 W, and the open ARISC firmware's 0.3 W mode makes the power supply whine.
  - The picture flickers faintly at each key press.
  - One tester's older HY300 Pro ignores its IR remote.
  - These projectors have no HDMI output.
- **Revision trap:** many "HY300" units are **not** H713 boards (see the next item).
- Related: [shift/sun50iw12p1-research](https://github.com/shift/sun50iw12p1-research) (42★, stalled since 2025-10-28) and [minpeter/h713-map](https://github.com/minpeter/h713-map) (projection mapping on top of this port, created 2026-10-31).
- **Score:** 8/10 · **Confidence:** medium (one maintainer plus named testers; AI-written code not yet reviewed)

### Quest 1 bootloader unlock, and Quest 2 support creeping in (QuestStack 2026-08; darknight1050 commit 2026-11-20)
- **QuestStack:** [starseed12345/QuestStack](https://github.com/starseed12345/QuestStack) (232★, GPL-3.0, created 2026-07-31, last push 2026-08-28). It chains the GhostLock privilege escalation with **CVE-2021-1931** (a buffer overflow in the ABL fastboot code). That gives root on the **latest Quest 1 firmware** (`49845030443200410`) and unlocks the bootloader, with backups and slot handling. The full process factory-resets the headset.
- **Quest 2:** on 2026-08-28 the README changed "❌ Quest 2" to "✅ Quest 2 (Website version Only)", but only on firmware `50670960048600150`, which you must sideload first from a third-party file host. Coverage summarised by search in August still said the Quest 2 was unsupported, so treat this as **experimental**.
- **New this week:** darknight1050's original [quest-bootloader-unlocker](https://github.com/darknight1050/quest-bootloader-unlocker) (108★) got its first code commit since 2024 on **2026-11-20**. It adds patch offsets for Quest 2 build `12018400103000000`, plus a CI release workflow. **The commit carries a `Co-Authored-By: Claude` trailer** (checked in the diff today). The README still says "PATCHED ON LATEST FIRMWARE": it works only on the old builds it lists.
- **Why it matters:** used Quest 1s are cheap, discontinued and tied to Meta accounts. An unlocked Snapdragon 835 headset with displays, tracking cameras and a battery is a good platform. **But** no alternative OS exists yet ([Hackaday, 2026-08-25](https://hackaday.com/2026/08/25/quest-vr-headset-becomes-unlocked-hardware/), search summary only).
- **Score:** 6/10 · **Confidence:** medium (Quest 1) / low (Quest 2)

### MousePods: AirPods head-tracking sensors on Linux, with no Apple device (created 2026-11-04; 558★)
- [starman-tech/mousepods](https://github.com/starman-tech/mousepods) is Apache-2.0, with docs under CC BY 4.0, and was last pushed 2026-11-17. It claims "the first public documentation of Apple's **RemoteHID** protocol, the way AirPods 3 expose their sensors".
- **Uses:** a head mouse, plus a Proton game integration that drops in a TrackIR/FreeTrack DLL (tested with AirPods Pro 2 in Assetto Corsa and ETS2). It ships as a Flatpak.
- **AI angle:** press coverage says Claude Code found the blocker, a Bluetooth MTU setting, in an afternoon ([Hackaday](https://hackaday.com/?p=1398217); [GadgetReview](https://www.gadgetreview.com/?p=427467), both search summaries). The README itself does not mention AI.
- Within 12 days, rewrites and forks appeared: [f3nr1l/podtrack](https://github.com/f3nr1l/podtrack) and a Windows port by nathnaelmin27-sudo.
- **Score:** 7/10 · **Confidence:** medium

### Nikon Z 5 "Z5 Extensions": feature firmware for a full-frame camera (release A39, 2026-11-17)
- [WonderLantern/wonder-lantern-z5](https://github.com/WonderLantern/wonder-lantern-z5) (19★, created 2026-11-09) works only on **Z 5 firmware C 1.50**.
- **How it installs:** `patch.py` checks the SHA-256 of your own Nikon `Z_5_0150.bin`, then writes a slightly modified update file. The new features live in a module on the memory card, and the README says the patch "does not touch the boot area".
- **Features tested on the camera:**
  - timed bulb, photo zebras, a level and histogram together, and extra grid styles;
  - battery percentage and focal length for all CPU lenses;
  - custom shutter sounds.
- **Experimental:** faster mechanical burst (233 → ~195 ms/frame, AF-S only) and a portrait-orientation UI.
- **Limits:** "tested on only one camera, the author's", plus a few user reports. No Nikon firmware is redistributed.
- **Score:** 5/10 · **Confidence:** low

### Icom IC-705 / IC-9700 custom firmware (release 20261119v14)
- [sq6emm/icom-custom-firmware](https://github.com/sq6emm/icom-custom-firmware) (37★, created 2026-11-13) is a browser patcher for the official Icom `.dat` files.
- **Features:** transverter support up to 122 GHz display, an **A/B bootloader** that keeps the previous firmware in the radio, FT8/Q65/JT4 decoders, APRS and PSKReporter.
- **Safety check:** the patcher outputs only byte-identical tested builds (MD5 checked on input and output).
- **Caution:** the README notes that the IC-705 build extends TX ranges beyond amateur bands, and that transmitting legally is the operator's responsibility.
- **Score:** 6/10 · **Confidence:** medium

## 3. AI-assisted hardware hacking

- **H713 Linux** (above): the strongest example this week. An AI agent wrote a whole boot chain, kernel bring-up, a display-firmware interface and a UI. The human role was directing the work, testing on hardware and collecting board dumps. The maintainer still asks for human line-by-line review.
- **Chaz Schlarp's peripheral series** (blog dated around 2026-08; [blog](https://schlarp.com/posts/everything-i-own-owned/) blocked, details via [Cybernews](https://cybernews.com/security/hacking-pc-peripherals-with-claude-unveils-lack-of-security/) search summary):
  - He used Claude Opus with his Nix-based [schlarpc/re-shell](https://github.com/schlarpc/re-shell) (541★) to analyse five of his own devices' vendor firmware.
  - Repos verified today: [Insta360 Link](https://github.com/schlarpc/insta360-link-firmware-re), [Elgato Cam Link 4K](https://github.com/schlarpc/elgato-cam-link-4k-firmware-re), [Shure MV7](https://github.com/schlarpc/shure-mv7-firmware-re), [Elgato Key Light Mini](https://github.com/schlarpc/elgato-key-light-mini-firmware-re) and [ASUS PG42UQ](https://github.com/schlarpc/asus-pg42uq-firmware-re).
  - The PG42UQ README identifies a Novatek NT68552 scaler (8051 plus two SPARC Leon2 cores plus Xtensa). It marks inferred findings `[I]` and untested.
  - Manual work remained: hardware validation on the real unit, and judging what is safe to publish (HDCP private keys withheld).
- **darknight1050 Quest unlocker:** an AI-co-authored commit (2026-11-20) adds firmware patch offsets. This is a small, verifiable example of agents helping maintain exploit tooling for old firmware.
- **Felucca (FM-1)** says outright that it is developed with AI coding agents. **Hisense VIDAA Clean Home** ([nineodernein/hisense-vidaa-clean-home](https://github.com/nineodernein/hisense-vidaa-clean-home), 34★, created 2026-11-12) is packaged as a task for a coding agent ("Start with Codex"). Its compatibility page is unusually honest: one reference unit, plus two owner reports (50E6NT, 55U7Q), and native install needs root access.
- **Sector A cross-over, speculative for native installs:** the VIDAA dock is listed here rather than as a discovery because the root step is not public.

## 5. Hidden opportunities

1. **FM-1-class JieLi audio SoCs:**
   - **Opportunity:** JieLi AC79-series chips are everywhere in cheap Chinese audio gear. The FM-1 now gives a documented OTA protocol, an open bootloader and a GPL SDK for one of them. The same work already reaches the SMK-37 keyboard and, per a repo seen today, an M-VAVE/Donner Pocket Amp ([28spawn/Pocket-Onyx](https://github.com/28spawn/Pocket-Onyx), 19★).
   - **Why overlooked:** JieLi parts carry little prestige, and documentation is in Chinese.
   - **What to build:** custom DSP effects on ₹2–5k gadgets.
   - **Validation:** identify the SoC on another M-VAVE or Donner product, then try the FM-1 OTA client read-only. **Speculative.**
2. **H713 projectors as projection-mapping or signage nodes:** with a built-in camera, a focus motor and a tilt sensor, the board already has what calibration needs ([h713-map](https://github.com/minpeter/h713-map) does Gray-code camera calibration).
   - **Why overlooked:** buyers see a toy projector.
   - **Validation:** a verified-board unit running v0.97, measuring a full day of power and heat.
3. **Agent-assisted monitor scaler firmware:** the PG42UQ analysis shows that a Novatek scaler's service escapes reach EEPROM and flash writers over DDC/CI.
   - **Opportunity:** many discarded monitors use the same scaler family. Removing nags such as pixel-cleaning prompts, or unlocking hidden modes, is plausible.
   - **Validation:** static analysis of one cheap monitor's published firmware. **Speculative**, and risky to write to.
4. **Unlocked Quest 1 as a cheap robotics or perception head:** an SD835 with four tracking cameras, IMUs and a battery.
   - **Validation:** after unlocking, boot a custom kernel and read the cameras from userland. **Speculative:** no one has published this.

## 7. Experiments worth attempting

1. **FM-1 custom firmware round trip**
   - **Hardware and budget:** FM-1, about $60–70 per press reports; India price not checked.
   - **Tools:** USB-C cable and a browser.
   - **Steps:** install m-bootloader first for recovery, then Felucca or X0X, then return to stock V16.
   - **Difficulty:** easy.
   - **Expected result:** a working groovebox and confirmed recovery.
   - **Safety:** check which flash chip your unit has before flashing.
2. **H713 projector to Debian**
   - **Hardware:** a verified HY310 or L018 board.
   - **Tools:** USB cable for FEL.
   - **Steps:** take the full dump first, then run the probe, then the installer.
   - **Difficulty:** moderate.
   - **Expected result:** Kodi and HDMI input on Linux.
   - **Recovery:** FEL, and stock Android restored from your own dump.
3. **Quest 1 unlock**
   - **Hardware:** a used Quest 1.
   - **Difficulty:** moderate.
   - **Expected result:** root and an unlocked bootloader.
   - **Risks:** a factory reset and a soft-brick chance. Do it only on a headset you own.
4. **AirPods head tracking on Linux**
   - **Hardware:** existing AirPods 3 or Pro 2. Budget: ₹0.
   - **Tools:** the MousePods Flatpak.
   - **Difficulty:** easy.
   - **Expected result:** head-tracked sim camera.
5. **Agentic RE of your own peripheral's vendor update file**
   - **Tools:** re-shell plus Claude Code, static analysis only.
   - **Difficulty:** moderate.
   - **Expected result:** a documented control protocol.
   - **Safety:** don't write to flash without a dump. Only analyse devices you own.

## 8. Long-term opportunity radar (6–24 months)

- **Vendor-published SDKs for hobbyist music gear.** M-VAVE's fm1_open is real. Reports of Erica Synths opening LXR-02 firmware come from search summaries only. If more cheap vendors follow, "hackable" becomes a selling point.
- **AI-written board bring-up.** H713 Linux shows one person with an agent porting mainline Linux to an obscure Allwinner SoC in about six months. Expect more cheap Allwinner and Rockchip appliances to get ports. The bottleneck shifts to human review and to testers with the hardware.
- **Discontinued VR headsets** (Quest 1 now, Quest 2 partially) are becoming unlockable as Meta's support ends. Watch for the first alternative OS.
- **Camera feature firmware** (Nikon Z 5, plus research repos on Fujifilm, YI M1 and Sony a7R V seen in GitHub search) suggests that card-loaded modules may spread beyond Canon/Magic Lantern. Not verified beyond the Z 5.
