## 1. Most interesting discoveries

### unfr0zen + Fledge: Nest Learning Thermostat 3rd gen rooted over USB, cloud cut, Home Assistant on its screen (created 2026-10-26 / 2026-11-08; pushed 2026-11-23)
- **What it is:** [unfr0zen/unfr0zen](https://github.com/unfr0zen/unfr0zen) (137★, 17 forks, GPL-3.0, latest tag v0.5.4) roots the thermostat "over USB through the i.MX ROM's recovery mode". It leaves Nest's own `nlclient` running the heating and adds `nestlocal`, which "stands in for Google's cloud" and speaks MQTT, Matter (Wi-Fi or Thread) and Zigbee instead.
- **Supported units (README table):**
  - 3rd gen (`diamond3`, NXP **i.MX6SoloX**): MQTT, Matter over Wi-Fi and Thread, Zigbee. Tested on firmware 5.9.4-5, 6.3-5, 6.4-8 and 6.5-14.
  - 2nd gen (`j49`, TI **AM3703**): the same features, firmware 5.9.4-5.
  - 1st gen (`diamond`): has to be opened up to reach USB download mode, and has no Zigbee or Thread.
  - **Not supported:** the Nest Thermostat E and every newer Nest.
- **Why it matters:** Google switched off connected features on Nest 1st and 2nd gen on 2025-10-25 ([9to5google](https://9to5google.com/?p=702534), search summary). The NoLongerEvil project ([Hackaday, 2025-11-11](https://hackaday.com/2025/11/11/nest-thermostat-now-100-less-evil/), search result) answered with the old DFU route for those generations. unfr0zen also covers the **3rd gen**, which is still supported by Google and far more common second-hand.
- **Hidden capability:** the 2nd and 3rd gen have an 802.15.4 radio on SPI (EM357 or EM3581). With unfr0zen it becomes a Zigbee router or Thread device, and "Zigbee needs no Wi-Fi at all", which, per the README, gives "a new life to the many 2nd and 3rd generation units whose Wi-Fi has failed".
- **Fledge** ([sysmoon14/fledge](https://github.com/sysmoon14/fledge), latest tag v0.13.0-rc.10; [Home Assistant integration](https://github.com/sysmoon14/fledge-homeassistant), 6★, created 2026-11-08):
  - A fork that turns the ring and screen into a Home Assistant controller at 60 fps, with cards for lights, speakers, covers, alarms with code entry on the ring, and cameras.
  - Signed over-the-air updates with rollback, and whole-NAND backup and restore.
- **Limits, in the authors' own words:**
  - Fledge "has been tested on exactly one thermostat" (a European 3rd gen on firmware 6.4-8 with a Heat Link).
  - "This rewrites the flash of the device that runs your heating."
  - Matter uses the test vendor ID, so controllers treat the unit as uncertified.
- **AI use (READMEs):** unfr0zen: "Claude Code has been used to speed up the app's GUI, the documentation and the tests". Fledge: "Claude Code has been used throughout Fledge's development".
- **Score:** 8/10 · **Confidence:** medium. Credible code, a NAND-backup safety net and a wider upstream test matrix, but no independent reports were fetched (the German write-up on [simon42.com](https://www.simon42.com/unfr0zen-nest-thermostat-lokal-home-assistant/) was blocked here).

### unfr0zen qemu: the Nest's stock firmware boots in an emulator, with an MCP server for agents (created 2026-10-26; pushed 2026-11-22)
- **What it is:** [unfr0zen/qemu](https://github.com/unfr0zen/qemu) (1★, GPL-2.0) has QEMU machines that boot 2nd and 3rd gen stock firmware "from a dump of their NAND: boot ROM, U-Boot, Linux and the thermostat's own UI, unchanged".
  - It simulates the backplate and a room that warms and cools, Wi-Fi with neighbouring networks, and firmware updates.
  - A `--ui` web page shows the screen and lets you turn the ring.
- **Why it matters:** "An MCP server gives Claude Code, Codex, Cursor and friends screenshots, recordings, inputs…" The README says you can "hand the whole unit to an agent, without a thermostat on the bench."
  - This is the first emulator in this DB that was built so agents can test firmware changes against a whole device.
  - It lowers the brick risk for patch development. Physical flashing is still needed at the end.
- **Score:** 7/10 · **Confidence:** medium (README; not run here).

### Blue Star "smart ready" AC → local Home Assistant for about ₹250 (created 2026-11-02; pushed 2026-11-03)
- **What it is:** [Vikk20/bluestar-ac-esphome](https://github.com/Vikk20/bluestar-ac-esphome) (11★, MIT). Blue Star sells "Wi-Fi ready" inverter split ACs with an **empty 4-pin `R_WIFI T_WIFI GND 5V` header** on the indoor unit's display board, meant for an optional paid Wi-Fi module.
  - An ESP32-C3 SuperMini plugs into that header. With three resistors as a 5 V to 3.3 V divider and a JST-XH plug, it becomes the module.
  - The author calls it "the first public documentation of the Blue Star Wi-Fi port protocol".
- **Protocol:** UART at 9600 8N1, using the standard Tuya MCU framing (`55 AA`), plus a Blue Star string data point (DP101) that carries `*LLKKV…CCCC#` records with a CRC-16/MODBUS. Full reference: [docs/PROTOCOL.md](https://github.com/Vikk20/bluestar-ac-esphome/blob/main/docs/PROTOCOL.md).
- **Gains over the remote:**
  - A 0.5 °C setpoint and a "Quiet" fan step below the remote's lowest.
  - Convertible-capacity select (100, 80, 60 or 40 %).
  - Lifetime counters for on-time and compressor run-time, compressor speed, and filter-clean flag.
- **Tested:** IE518TNUR and IA318MXU, both "in daily use", both on the Megmeet MD50BS display board. Other "smart ready" models are "very likely" the same but **unverified**.
- **Safety:** mains voltage is present inside the indoor unit, so switch off at the breaker before opening it. Only the low-voltage header is touched.
- **Score:** 7/10 · **Confidence:** medium (one author, two units, detailed protocol doc). For India this is unusually practical: Blue Star is a mass-market Indian AC brand.

### Electronic shelf labels: three new open-firmware routes in seven weeks
- **SES-imagotag HRD3-0210-A** ([georgestephanis/hacking-imagotags](https://github.com/georgestephanis/hacking-imagotags), 11★, created 2026-10-07):
  - The tag: PCB `ContRD010A`, Silicon Labs EFR32FG22 (Cortex-M33, 512 KB flash), a 2.06" 248×128 black/white/red panel, an RGB LED, a button, and **no battery** (rail-powered). Bought in "20-packs on eBay".
  - Unlock: "Ships debug-locked, cleared by a device erase (original firmware is lost)." Flashing uses SWD with a Pico running debugprobe.
  - Status: drawing images works three ways. Receiving images over the rail contact is "not working end to end".
  - The repo has an `AGENTS.md` and an explicit AI-disclosure section (see §3).
- **Solum EL016 / EL022 on EFR32BG22** ([steanlab/pin16](https://github.com/steanlab/pin16), 5★, created 2026-11-16, tag v20):
  - Open firmware with a **Web Bluetooth** page: pictures convert in the browser and upload to 32 slots for a slideshow. It also does OTA updates and NFC writes, and is compatible with OpenDisplay.
  - First install wipes the factory firmware for good: "there is no way to back it up".
- **Solum ZBS243 tags** ([mathiasbk/openESL](https://github.com/mathiasbk/openESL), 2★, 3 forks, created 2026-10-14, tag v0.11.0, pushed 2026-11-23):
  - A from-scratch MIT alternative to OpenEPaperLink for 2.9" and 1.54" tags.
  - The access point runs on an ESP32-C6, ESP32-S3 or Linux, "including recycled ESL gateways". It has an HTTP API, a label designer, a simulator and a [Home Assistant integration](https://github.com/mathiasbk/openesl-homeassistant).
- **Context:** the Troopers 26 talk "Priceless: Hacking Electronic Shelf Labels" covers the Picksmart and ZhSunyco systems used in EU stores ([slides PDF](https://troopers.de/downloads/troopers26/TR26_Priceless_DAARST.pdf), search summary). Only tags you own are in scope here; in-store labels belong to the retailer.
- **Score:** 6/10 · **Confidence:** medium (working hardware claims in all three READMEs, one or two authors each).

### Open Dimmer: replacement firmware for the *second* MCU inside a Tuya Zigbee dimmer, installed over Zigbee (created 2026-11-17; v2.2.8; pushed 2026-11-24)
- **What it is:** [patapovich/open-dimmer](https://github.com/patapovich/open-dimmer) (9★, MIT) targets the **AVATTO ZDMS16-2**, Tuya models `_TZE284_jtbgusdc` and `_TZE204_jtbgusdc`.
  - The module has a Zigbee chip and a separate **PY32** dimmer MCU. Open Dimmer replaces the PY32 firmware.
  - The Zigbee side runs a fork of [romasku/tuya-zigbee-switch](https://github.com/romasku/tuya-zigbee-switch), flashed over the air from Zigbee2MQTT, which then installs and updates Open Dimmer.
- **Install:** two wires are soldered once (mains disconnected). After that, every update arrives over Zigbee.
- **Gains:** dimming curves per channel including a measured custom curve, LED compensation, wall-switch gestures as Zigbee2MQTT actions, a detached mode, and a "failed update reinstalls itself".
- **Tested at:** 230 V/50 Hz, which matches India; 60 Hz is untested.
- **Why it matters:** it is a template for any dual-MCU Tuya device. The Zigbee chip becomes the flasher for the dumb MCU next to it.
- **Score:** 6/10 · **Confidence:** medium.

### ACiQ / Midea TL04-1 thermostat: open ADB on a Linux thermostat becomes a local API (created 2026-10-20; pushed 2026-11-22)
- [oxn0r/ha-aciq-thermostat](https://github.com/oxn0r/ha-aciq-thermostat) (6★, MIT): "the thermostat runs Linux with an open debug port (ADB)". The integration pushes "a tiny local API" onto it.
- It exposes data the cloud app hides: compressor Hz, outdoor temperature from the outdoor unit, coil temperatures and fault codes.
- Also sold as Carrier KSACN1701AAA and under the Midea brand. This is a US-market product, so it has no India relevance; it is listed for the pattern of thermostats that leave ADB open.
- **Score:** 6/10 · **Confidence:** medium.

### UnTuyaOS3 in Home Assistant: a no-solder Wi-Fi exploit for some TuyaOS 3 devices, packaged as an app (created 2026-10-27; v1.0.5)
- The upstream exploit is [tuya-cloudcutter/UnTuyaOS3](https://github.com/tuya-cloudcutter/UnTuyaOS3) (11★, created 2026-02-07, pushed 2026-10-30). It flashes Tuya `UG` images over Wi-Fi to T1, BK7231N and RTL8720CF devices, credited to kuba2k2 of LibreTiny.
- [seb5594/Home-Assistant-UnTuyaOS3-App](https://github.com/seb5594/Home-Assistant-UnTuyaOS3-App) (0★) wraps it as a Home Assistant OS app that borrows a spare AP-mode USB Wi-Fi adapter. Only the Atheros AR9271 has flashed anything so far.
- **Results the author reports honestly:**
  - One lamp "Worked".
  - One "Partly": Kickstart runs but the outputs are not set up, and the author warns that the lamp "went dark after a flash".
  - One "Exploit accepted" with nothing documented after that.
  - One "Not accepted".
- **Score:** 5/10 · **Confidence:** low to medium (four devices, mixed results).

## 3. AI-assisted hardware hacking

- **SES-imagotag ESL, three days with Claude Code** ([hacking-imagotags AI disclosure](https://github.com/georgestephanis/hacking-imagotags#ai-disclosure), 5–7 October 2026):
  - "about 17 hours of wall-clock time", of which "around 10 hours of active hands-on work".
  - **Done by the AI:** "researched, wrote the scripts, firmware and docs, ran the SWD and pyOCD tooling against the real tags, analysed the traced netlist, designed the experiments".
  - **Done by the human:** "sourced the tags, soldered, probed with a multimeter, photographed the boards, traced the PCB pad by pad … and did every physical step".
  - The research log keeps the agent's wrong turns: a wrong QFN32 pin-map assumption, a CS/DC swap and an inverted LED polarity. The author warns: "An AI can be confidently wrong, so check anything that could harm hardware".
  - This is one of the clearest published splits of agent work versus human work in this DB.
- **Meross MSS110 open firmware, "vibe-coded, hardware-verified"** ([catskull/meross-mss110-fw](https://github.com/catskull/meross-mss110-fw), created 2026-11-18): "written almost entirely by an AI assistant (Claude / Claude Code)". The author verified the pin map with a scanner sketch and tested relay, LEDs, button, recovery AP and OTA on a real plug. Download mode needed two test pads tied to 3.3 V, which only a human could find.
- **Nest emulator with an MCP server** ([unfr0zen/qemu](https://github.com/unfr0zen/qemu)): it gives agents screenshots, inputs and serial access to the stock thermostat firmware, so agent-written patches can be tested before a human flashes real hardware. unfr0zen and Fledge both say Claude Code was used. unfr0zen's says it was for the GUI, docs and tests; the exploit and reverse engineering are credited to the human author (@will-tm).
- **Agent-facing directories and MCP servers:**
  - [opendevicedb/opendevicedb](https://github.com/opendevicedb/opendevicedb) (50★, AGPL-3.0 code, CC BY-SA data, created 2026-10-17) aggregates "42 today, 32,110 devices" from OpenWrt, Zigbee2MQTT, tuya-local, Valetudo, thingino, tuya-cloudcutter and others. It ships an MCP server so agents can "claim the device, publish findings when done" before starting work.
  - [qubo-local-bridge](https://github.com/hemantkamalakar/qubo-local-bridge) ships `qubo mcp` and an agent skill.
- **Headwind: AI guardrails on reverse engineering.** Per search summaries of [404 Media](https://404media.co/reverse-engineer-anything-ai-companies-crack-down-on-the-coolest-thing-people-were-doing-with-ai) and [Tom's Hardware](https://tomshardware.com/tech-industry/artificial-intelligence/anthropic-confirms-new-claude-code-limits-to-prevent-game-cloning-users-report-opus-5-5-is-also-actively-blocking-reverse-engineering-tasks) (both blocked here; exact date not confirmed, around mid-November 2026):

## 5. Hidden opportunities

1. **"Smart ready" appliances with empty module headers (India).**
   - *Hardware:* Indian ACs, and possibly geysers and fans, sold "Wi-Fi ready" with an unpopulated module header.
   - *Opportunity:* the Blue Star finding shows that the header speaks plain Tuya MCU UART. Many Indian brands use Tuya-based modules.
   - *Why overlooked:* owners don't open the indoor unit, and vendors sell the module separately.
   - *What could be built:* a documented ESP32-C3 "module" per brand, with a protocol sniffer firmware.
   - *Validation:* check one other brand's indoor-unit wiring diagram for a `WIFI` header, then log handshake traffic with the Blue Star project's sniff mode.
2. **Nest 2nd and 3rd gen as a Zigbee or Thread node with a premium dial.**
   - *Hardware:* used Nests, including units with failed Wi-Fi.
   - *Opportunity:* unfr0zen exposes the 802.15.4 radio, and Fledge turns the ring and screen into a controller.
   - *Why overlooked:* people see a thermostat, not a radio with a screen.
   - *What could be built:* a wall-mounted Home Assistant dial with no HVAC wiring.
   - *Validation:* run a used unit on a bench power supply with "Act as a thermostat" off.
3. **Dual-MCU Tuya modules: the Zigbee chip as the flasher for the other MCU.**
   - *Opportunity:* Open Dimmer shows that an open Zigbee firmware can install firmware on the co-processor over Zigbee.
   - *Candidates (theoretical):* curtain motors and fan controllers that use a separate MCU.
   - *Validation:* list Tuya Zigbee devices with a separate MCU in Zigbee2MQTT's database and check which ones use a SWD-capable PY32 or similar.
4. **Rail-powered ESLs as battery-free signage.**
   - *Opportunity:* the HRD3-0210-A has no battery and takes 3.3 V plus a signal contact. Once rail-signal upload works, a strip of these could run off one bus.
   - *Validation:* finish the PB01 software-UART receiver in hacking-imagotags.

### Speculative
- Other Blue Star models and other Indian AC brands sharing the Tuya-MCU header protocol: **untested hypothesis**. Only IE518TNUR and IA318MXU are proven.
- The Levoit Core 300S Matter firmware ([tadhglewis/levoit-matter](https://github.com/tadhglewis/levoit-matter), created 2026-11-23) "compiles, unit tests pass. Has never run on hardware." It is a **theoretical** route until someone flashes it.
- The Shark Matrix vacuum's local mosquitto broker on port 1883 has "no password, no TLS and no ACL" ([jcpsimmons/sharkboard](https://github.com/jcpsimmons/sharkboard), created 2026-11-07), and that is where telemetry and the LiDAR map appear. It is a local cloud-free hook for your own unit, and also a LAN security exposure. Labels are inferred, and only three command frames were captured.

## 7. Experiments worth attempting

1. **Blue Star AC header sniff and control**
   - *Hardware:* a Blue Star smart-ready AC, an ESP32-C3 SuperMini, 3×10 kΩ resistors and a JST-XH 4-pin plug.
   - *Budget:* ~₹400.
   - *Tools:* a screwdriver and a soldering iron.
   - *Software:* bluestar-ac-esphome.
   - *Difficulty:* easy to medium.
   - *Expected outcome:* a Home Assistant climate entity plus compressor counters.
   - *Safety:* switch off at the breaker before opening the indoor unit, and touch only the low-voltage header. Unplugging the ESP restores stock behaviour.
2. **Flash one Solum or SES-imagotag ESL**
   - *Hardware:* one tag and a Raspberry Pi Pico as SWD probe.
   - *Budget:* ~₹500 plus the tag (price unknown).
   - *Software:* pin16, hacking-imagotags or openESL.
   - *Difficulty:* medium.
   - *Expected outcome:* custom images over BLE or 802.15.4.
   - *Recovery:* none for the factory firmware (it is lost on unlock), so practise on a sacrificial tag.
3. **unfr0zen qemu as an agent test bench**
   - *Hardware:* none, but you need a NAND dump from a unit you own.
   - *Software:* unfr0zen/qemu with its MCP server.
   - *Difficulty:* medium.
   - *Expected outcome:* measure how far an agent gets patching the UI before touching a real thermostat.
   - *Safety:* fully virtual.
4. **Open Dimmer on an AVATTO ZDMS16-2**
   - *Hardware:* the dimmer, a Zigbee coordinator and two thin wires.
   - *Difficulty:* medium.
   - *Expected outcome:* smooth curves and switch gestures.
   - *Safety:* solder with the mains disconnected and close the module before powering. The update path reinstalls itself if it fails.

## 8. Long-term opportunity radar (6–24 months)

- **Agent infrastructure for hardware:** device emulators with MCP servers (unfr0zen/qemu), agent-queryable device directories (OpenDeviceDB) and `AGENTS.md` files in reverse-engineering repos are becoming standard. Expect more whole-device emulators for popular Linux IoT targets.
- **Guardrail risk:** if refusals on reverse-engineering tasks persist at Anthropic or OpenAI, agent-driven hobby work may move to older or local models. Watch the 404 Media and Tom's Hardware follow-ups.
- **TuyaOS 3 exploits** (UnTuyaOS3) reopen cheap Tuya devices that tuya-cloudcutter could no longer reach. Coverage per firmware version is still thin.
- **Thermostats after cloud end-of-life:** Nest 1st and 2nd gen lost their cloud in 2025, and the 3rd gen is next in line in time. unfr0zen has positioned itself ahead of that.
- **ESL secondary market:** retailers refreshing their label fleets keep feeding eBay lots. Open firmware now covers ZBS243, EFR32BG22 and EFR32FG22 tags.
