## 1. Most interesting discoveries

### Stratacache Spectra NG-4-64 signage player is really a Jetson TK1 (field notes, 2026-10-08)
- **What it is:** [arthurotieno/Stratacache-Spectra-NG-4-64](https://github.com/arthurotieno/Stratacache-Spectra-NG-4-64) was created 2026-10-08 and has 0★. It is a set of field notes for turning a surplus Stratacache (Scala) digital-signage player into a Linux box or browser kiosk.
- **Hardware, per the README:**
  - **SoC:** NVIDIA Tegra K1 (T124, marked CD575M-A1), with 4× Cortex-A15 cores and a Kepler GPU.
  - **Memory and storage:** 2 GiB RAM and a 58.2 GiB eMMC, of which only about 15 GB is partitioned from the factory.
  - **I/O:** 2× HDMI, Gigabit Ethernet (RTL8168g), SATA, SD, an RS-232 console and a hardware watchdog.
  - **Boot:** the board reports itself as `jetson-tk1` / PM375 and boots **mainline U-Boot 2018.05** through extlinux.
- **What makes it interesting:** many of these units arrive "bricked", but the problem is fixable. The factory root filesystem is owned by UID 1000 instead of root, so setuid binaries drop privileges and nobody can log in. The fix is to interrupt U-Boot on the serial console, boot a USB stick that carries the board's own kernel and DTB, then `chown` the filesystem and restore the setuid bits. Nothing is signed and no exploit is needed.
- **Why it matters:** this is a cheap, dual-HDMI ARM box with a real GPU and a mainline-supported SoC. The README notes that Tegra124 has mainline GPU support via nouveau (GK20A).
- **Limits:** the README marks its Debian/mainline-kernel path **[unverified]**. The stock OS is Ubuntu 14.04 from 2019 (L4T R21.8), and its package archives have expired. The notes come from one author and one model.
- **Context:** a Screenly white paper ([PDF](https://www.screenly.io/assets/whitepapers/screenly-the-hardware-question.pdf), seen as a search summary only) says that in spring 2026 three Stratacache-owned signage platforms "stopped being the thing they were". Screenly is a competitor selling migration. If that is accurate, more Scala/Stratacache players may reach the surplus market. **Speculative.**
- **Score:** 7/10 · **Confidence:** medium

### VMflow (mdb-esp32-cashless): an open vending-machine stack built to be driven by AI agents (firmware v1.3.9, 2026-11-08)
- [nodestark/mdb-esp32-cashless](https://github.com/nodestark/mdb-esp32-cashless) has 193★ and was last pushed 2026-11-15. It is an ESP32-S3 board and firmware that sits on a vending machine's **MDB bus** as a cashless peripheral. It also reads **EVA-DTS DEX/DDCMP** telemetry and accepts credits over BLE or MQTT. The PCBs are KiCad, the firmware installs from a web installer, and the licence is MIT.
- **Recent activity (from git tags today):** `firmware-v1.3.9` on 2026-11-08, `android-v1.2.7` on 2026-11-15 (the first Play production release), and KiCad fixes on 2026-11-09 matching parts to LCSC stock.
- **AI angle:** the README calls it "the first open-source vending platform designed for AI agents". It ships an `AGENTS.md`, an OpenClaw skill and `vmflow-cli` so that "any coding agent with a shell (Claude Code, Codex, etc.)" can send credits or trigger OTA updates. The hosted dashboard's "AI diagnostics" call OpenAI, which is a cloud dependency. A self-hosted Docker stack was fixed on 2026-11-10.
- **Why it matters:** MDB is the common standard inside coin-op vending machines. That makes this a retrofit path for retired machines, and a reason to keep a used machine's MDB board rather than scrap it.
- **Limits:** I verified no installs on real machines. The project carries a "PCBWay Popular Prize 2026" badge, but I did not verify the award.
- **Score:** 7/10 · **Confidence:** medium

### LemonadeMirror: Debian on the abandoned Lululemon MIRROR, now reproduced by a second owner (2026-10-31 → 2026-11-17)
- [ikiiftekhar2/lemonademirror](https://github.com/ikiiftekhar2/lemonademirror) was created 2026-10-31, has 6★ and was last pushed 2026-11-08. It replaces Android with **Debian and a mainline Linux 6.18 kernel** on the Mirror's NXP i.MX8M Mini (4× A53, 2 GiB RAM, 16 GiB eMMC). The aim is to reuse the hardware already in the box: the 1080p LVDS panel, the stereo TAS5805M amps, the mic, the 5 MP camera, and Wi-Fi/Bluetooth. The README tracks a D1–D10 hardware checklist and says most items work.
- [jmurzy/mirror1.1](https://github.com/jmurzy/mirror1.1) was created 2026-11-08 and last pushed 2026-11-17. It is an **independent second unit** (board `Mirror V1.1 EVT rev A08`, FCC ID `VPYLBEE5HY1MW`). The author reached USB boot "without JTAG or UART", backed up the eMMC, and installed LemonadeMirror. Their `mirror-hwcheck` script reports 20 of 20 checks passing. The README says it is written so that you can "point your AI agent at this repository".
- **Why now:** press reports say Lululemon is exiting Mirror hardware and moving content to Peloton ([The Logic](https://thelogic.co/news/lululemon-lays-off-120-as-it-strikes-deal-with-peloton-and-pulls-the-plug-on-mirror/), [Front Office Sports, 2026-10-18](https://frontofficesports.com/article/lululemon-explores-mirror-sale-in-pivot-from-fitness-hardware/); both seen as search summaries). The dates in those articles were inconsistent.
- **Limits:** the second owner says eMMC restore has "not been verified end to end". The mirror runs on mains power with the board exposed, so their safety warning applies. The device is rare in India.
- **Score:** 7/10 · **Confidence:** medium (two independent units)

### Retired retail tablets: the ex-Deliveroo Sunmi V2 root path (older project, first logged today)
- [dafish7/Sunmi-v2-Firmware-](https://github.com/dafish7/Sunmi-v2-Firmware-) has 73★ and was last pushed **2024-08-03**, so it is old work. The method: flash the stock firmware with SP Flash Tool using a Magisk-patched boot image, which roots the device "without compromising the verification integrity". A TWRP image follows, and it needs root first. The firmware files are hosted off-GitHub on the author's site. I did not download them.
- **Why it is in a sector-E report:** the Sunmi V2/V2 Pro (Android 7.1, with a built-in 58 mm thermal printer) is very common in retail and food delivery, including in India. Esper lists the V2 Pro as no longer supported ([Esper](https://esper.io/devices/sunmi-v2-pro)). This is a candidate for a "dashboard plus receipt printer" appliance.
- **Limits:** the steps are for the **V2**, not a verified V2 Pro method. The MTK auth file comes from an unofficial source. The Android 7.1 WebView is too old for modern dashboards, the same issue found on Frameo frames ([HA community](https://community.home-assistant.io/t/frameo-as-hass-wall-mounted-dashboard/1026111)).
- **Score:** 5/10 · **Confidence:** low

## 3. AI-assisted hardware hacking

- **ZNP-RE (2026-11-17):** [devniz/znp-re](https://github.com/devniz/znp-re) (7★) documents the full BLE protocol of the ZNP Z01 "AI badge", which is really a mic, speaker, round screen and button. The author's "Milo" app replaces the vendor's BagiBagi app and cloud with Claude, running the speech pipeline on the iPhone. **Achieved:** the protocol, animation format and a working app. **Manual work:** none needed on the device side, because no firmware was changed. The README does not say whether AI agents wrote the RE code itself.
- **VMflow (Nov 2026):** this is AI used as an *operator*, not as a reverse engineer. The project ships an `AGENTS.md` and a CLI so that coding agents can run a vending fleet ([repo](https://github.com/nodestark/mdb-esp32-cashless)). **Still manual:** the MDB electrical interface and the opto-isolated board design (the KiCad commits are hand part-matching).
- **MIRROR journal (2026-11-08):** written explicitly as context for "your AI agent", with the warning that the agent must "verify each step rather than assuming your unit is identical" ([jmurzy/mirror1.1](https://github.com/jmurzy/mirror1.1)). Repo-as-agent-context looks like an emerging pattern. VMflow and PicoBrew also ship `AGENTS.md`.
- **HP Laser 1008a SPL3 on macOS (2026-08-17, older but first logged):** [Kuberwastaken/hp-laser-1008a-macos](https://github.com/Kuberwastaken/hp-laser-1008a-macos) has 176★ and was last pushed 2026-10-04. Secondary write-ups say Claude Code decoded the Windows-only SPL3 raster format in about four hours, using the printer's own error pages as feedback ([aitoolly summary](https://aitoolly.com/en/ai-news/article/2026-08-19-claude-code-enables-native-macos-printing-for-hp-laser-1008a-via-spl3-reverse-engineering)). There is a follow-on for the HP Laser 105w: [kvx07/hp105w-macos](https://github.com/kvx07/hp105w-macos), created 2026-11-07 with 0★.
- **ripcord (2026-04 → 2026-05):** [DavidClawson/ripcord](https://github.com/DavidClawson/ripcord) has 2★ and was last pushed 2026-05-30. It is a pipeline of Ghidra, DuckDB (Parquet fact tables) and Renode/Unicorn "execution as verification oracle", driven by Claude Code skills, aimed at the FNIRSI 2C53T scope's undocumented Gowin FPGA. The project is stalled.
- **Guardrails:** 404 Media reports that some users hit Claude Code safety checks that blocked reverse-engineering work, and that these can change without notice ([404 Media](https://www.404media.co/come-and-take-it/), search summary only). This matters for any workflow that depends on agents.

## 4. Interesting community discussions

- **Kaspersky, wireless barcode scanners (2026-10-20):** Kaspersky presented this at SAS 2026. Unnamed "major manufacturer" scanners have **no authentication between handheld and base station**, so keystrokes can be spoofed. Kaspersky says the same pattern may apply to PDTs and thermal printers ([press release](https://www.kaspersky.com/about/press-releases/your-order-is-delayed-kaspersky-identifies-vulnerabilities-in-barcode-scanners-posing-potential-threat-for-the-warehouse-industry)). One outlet's remote-code-execution claim is unconfirmed. For hobbyists, this means the scanner-to-base link is plain and may be easy to interface with. Use it only on your own equipment.
- **Zebra bootloaders (Zebra developer forum):** a moderator says Zebra does "not share anything public on how to unlock the bootloader". Unlock keys go through support for repairs only ([thread](https://developer.zebra.com/content/tc520k-bootloader-unlock-possibility-or-pipe-dream)). **This is a failure report and a reason not to buy these for revival.**
- **BrightSign players:** official docs say firmware must be signed by BrightSign and the filesystem is read-only. A root shell is only available when secure boot is off ([BrightSign shell docs](https://docs.brightsign.biz/develop/brightsign-shell)). A 2023 Reddit question about jailbreaking an LS4 found nothing ([mirror](https://axebps-redlib.hf.space/r/jailbreakdevelopers/comments/17wsvd5/brightsign_ls4)). Contrast this with the unsigned Stratacache box above.
- **OpenWrt forum:** a thread titled "A potentially interesting hardware class: digital signage players" exists ([thread](https://forum.openwrt.org/t/a-potentially-interesting-hardware-class-digital-signage-players/249916)). It was blocked here, so I could not see its date or content.
- **SumUp Solo:** Hackster reports Aaron Christophel got a U-Boot/Linux console over UART and ran Doom ([Hackster](https://hackster.io/news/hacking-a-sumup-solo-payment-terminal-to-run-doom-da953844f910), date not seen). [SumUpSoloExplorer](https://github.com/jssystemcz/SumUpSoloExplorer) (created 2026-07-23, 0★) only enumerates USB. Payment terminals stay out of scope beyond curiosity.
- **PAX terminals:** the best public work is still the 2020–2023 pax-pwn research ([git.lsd.cat](https://git.lsd.cat/g/pax-pwn)). I found no 2026 A920 work.

## 5. Hidden opportunities

1. **Surplus signage players with unsigned mainline boot.**
   - **The hardware:** the Stratacache NG-4-64 class.
   - **The opportunity:** U-Boot and extlinux with no signature checks, on a Tegra K1 with 2× HDMI and SATA.
   - **Why it is overlooked:** the units look bricked, and their brand implies a locked appliance (compare BrightSign).
   - **What could be built:** dual-screen dashboards, a low-power NAS with a GPU, or a CUDA-6-era Jetson for teaching.
   - **Validating experiment:** boot current Debian armhf with a 6.x kernel and the `tegra124-jetson-tk1` DTB from USB, then confirm nouveau acceleration.
2. **The MDB board inside retired vending machines.**
   - **The opportunity:** with VMflow, a used machine plus a roughly ESP32-priced board becomes a locally controlled, UPI/QR-capable kiosk. Indian UPI integration is **my extrapolation, not in the project**.
   - **Why it is overlooked:** operators scrap whole machines.
   - **Validating experiment:** run the three-ESP32 VMC/cashless/bill-reader simulator board the author published on PCBWay before touching a real machine.
3. **Android POS tablets with built-in printers as "physical output" appliances.**
   - **The opportunity:** Sunmi-class devices already pair a screen, Wi-Fi/4G, battery and thermal printer. Printer-art projects such as [matt-w-horn/morningprint](https://github.com/matt-w-horn/morningprint) (19★, pushed 2026-11-16) currently use separate receipt printers.
   - **Why it is overlooked:** POS gear is assumed to be locked to its vendor.
   - **Validating experiment:** on stock firmware, without root, call the Sunmi printer service from a sideloaded app. If that works, root is optional.

### Speculative
- Kaspersky's finding implies some wireless scanner bases accept unauthenticated packets. That could let a hobbyist write a custom base-station receiver that uses cheap used scanners as wireless input devices. This is untested, and the vendor is unnamed.

## 7. Experiments worth attempting

1. **Revive a "bricked" Stratacache NG-4-64.**
   - **Hardware:** the unit, a USB-RS232 cable (with a null-modem adapter if nothing appears) and a USB stick.
   - **Budget:** the cable plus whatever the unit costs; not checked.
   - **Tools and software:** Tera Term with transmit delay, and the repo's procedure.
   - **Difficulty:** medium.
   - **Expected outcome:** a login prompt, then a kiosk.
   - **Recovery and safety:** take the optional eMMC backup in §7d of the notes first. The work is low-voltage and external.
2. **Run a VMflow bench simulator.**
   - **Hardware:** an ESP32-S3 dev board, or the published 3×ESP32 simulator PCB.
   - **Budget:** low.
   - **Software:** the web installer at the project's site and the self-hosted Docker stack.
   - **Difficulty:** easy to medium.
   - **Expected outcome:** simulated vends and DEX telemetry over MQTT with no real machine.
   - **Recovery and safety:** no mains involved.
3. **Drive a Sunmi printer as a home-automation output.**
   - **Hardware:** a used Sunmi V2/V2 Pro.
   - **Software:** stock firmware plus a sideloaded app using Sunmi's printer service. Root via the dafish7 method only if needed.
   - **Difficulty:** easy without root, hard with root.
   - **Expected outcome:** Home Assistant notifications printed on paper.
   - **Recovery and safety:** SP Flash Tool "Format all" wipes the device. Back up first.
4. **Port check on LemonadeMirror (only if a Mirror is available).**
   - **Hardware:** the Mirror and a UART cable.
   - **Difficulty:** medium.
   - **Expected outcome:** reproduce the 20/20 hwcheck.
   - **Recovery and safety:** disconnect mains before opening. eMMC restore is unverified, so keep the image.

## 8. Long-term opportunity radar (6–24 months)

- **Stratacache/Scala platform changes in 2026 (per Screenly)** could release a wave of surplus x86 and Tegra signage players. Watch for model-by-model unlock notes.
- **Clover Gen 1 devices** (Station C010, Mobile C020/C021, Mini C030/C031, Flex C041/C042) reached End-of-App-Update on 2026-03-30 ([Clover docs](https://docs.clover.com/docs/announcement-end-of-app-update-gen-1-devices)). They will reach resellers, but I found no root path. Watch only.
- **Zebra TC52/TC57** support ends 2028-12-31. Without a public bootloader unlock they will most likely become e-waste. Watch for any leaked or official unlock.
- **Repos written for agents to read** (`AGENTS.md`, journals written for AI agents): expect faster spread of device ports from a single proven unit to other owners, as the second MIRROR unit shows. The risk is agents applying one unit's partition GUIDs to another unit.
- **Wireless warehouse peripherals:** the Kaspersky disclosure may push vendors to add pairing authentication in new firmware. That would close any hobby interfacing path on updated units.
