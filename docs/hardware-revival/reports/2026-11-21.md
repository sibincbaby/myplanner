## 1. Most interesting discoveries

### NEMESIS: no-hardware root and a package ecosystem for Hyundai/Kia/Genesis Gen5W head units (repo created 2026-09-27; v1.16.9)
- **What it is:** [xwtk/hmg_nemesis](https://github.com/xwtk/hmg_nemesis) has **729★ and 86 forks**, was created 2026-09-27 and last pushed 2026-11-19, under AGPL-3.0. Its tags run up to `v1.16.9`. The README says it "provides a way to execute software as root" on Android-based Gen5W AVNT head units.
- **Install:** two routes, and neither opens the car.
  - **Option 1:** copy an `ota_package.tar` to a USB stick, then run it from Engineering Mode → USB Copy → Update DSP → Update OTA.
  - **Option 2:** extract a USB package that the unit picks up on boot, then confirm in an on-screen installer. Choosing "Decline" restores the factory state.
- **Compatibility (README):** the version string must contain **S5W_M**, with firmware **250818 or later** confirmed to work. **S5W_L is "fundamentally different hardware" and not supported.**
- **The ecosystem in the 8 weeks since:**
  - [Open-HMG/HMG-API](https://github.com/Open-HMG/HMG-API) is a mod manager (145★, created 2026-10-31). It hooks the car's own software at runtime instead of patching APKs, and puts back what each mod changed when the mod is removed.
  - [Open-HMG/hmgapi-wireless-cp-aa](https://github.com/Open-HMG/hmgapi-wireless-cp-aa) adds wireless CarPlay/Android Auto with turn-by-turn on the cluster/HUD (19★, created 2026-11-07).
  - [StopDragon/korea-projection](https://github.com/StopDragon/korea-projection) adds wireless projection on Korean-market units through a USB Wi-Fi dongle (175★, created 2026-11-05). Its README notes that Korean 5W firmware cannot use the built-in Wi-Fi module. It also carries Coupang affiliate links.
  - More than 25 other NEMESIS packages were pushed in the last 30 days (GitHub search `gen5w`): a cold-start seat heater, a charge-port button, an EQ, a "dog mode", an OTA blocker, Arabic localisation and launchers.
- **Why it matters:** this is a factory OEM head unit on mass-market cars, opened with a USB stick. That is rare.
- **Limits:**
  - Per the HMG-API README, an official firmware update wipes the mod files.
  - The OTA blocker supports only one firmware build (260507).
  - Some mods act on body controls such as door locks. See the AI-generated auto-lock below.
- **Earlier work:** [cantcs/HKG_Gen5W_ReverseEngineer](https://github.com/cantcs/HKG_Gen5W_ReverseEngineer) patched firmware for adb/root (62★, last push 2024-09-23, so stalled).
- **Score:** 8/10 · **Confidence:** medium. Many independent package authors report it working, but this run did not reproduce it.

### xj-scanner: an AI agent reads a 1994 Jeep's engine computer through a $3 Arduino Nano (2026-11-10)
- **What it is:** [MZULALI/xj-scanner](https://github.com/MZULALI/xj-scanner) has 318★ and was created and last pushed on 2026-11-10, under GPL-3.0. Three wires run from the 6-cavity diagnostic plug of a 1991–95 Chrysler/Jeep **SBEC (OBD1)** computer to a Nano. Python on the laptop then reads fault codes and live data, logs drives and runs actuator tests.
- **Built for agents:** the repo ships `AGENTS.md` and `.claude/skills/` playbooks. The README's "easy way" is to open the repo in Claude Code or Codex and say "Help me hook this up to my Jeep."
- **Limits (README):**
  - It was tested on **one car**: a 1994 Cherokee XJ 4.0L with computer 56030117.
  - "Cavity 6 is 12 volts with the key on. Never connect anything to it." On the test car that wire is the same colour as ground.
  - Protocol data comes from [ChryslerScanner](https://github.com/laszlodaniel/ChryslerScanner).
- **Press coverage** (search summaries only): [The Drive](https://www.thedrive.com/news/cant-pass-emissions-with-your-pre-obd-ii-car-have-claude-tune-it-for-you), [HotHardware](https://hothardware.com/news/driver-uses-claude-to-hack-1994-jeep-into-passing-smog-test) and [Cybernews](https://cybernews.com/ai-news/claude-ai-jeep-cherokee-hack/) disagree on the outcome. Some say the car passed smog, others that it "nearly passed". One says Codex wrote to the ECU's EEPROM. **Treat the smog result and the EEPROM tuning as unverified.** The repo itself documents reading and actuator tests.
- **Score:** 7/10 · **Confidence:** medium

### 70mai A800S (DR2800) map firmware: community firmware for a mainstream 4K dashcam (v3.5.1, 2026-11-16)
- **What it is:** [hsnk2011/70mai-a800s-map-firmware](https://github.com/hsnk2011/70mai-a800s-map-firmware) (1★, created 2026-11-05) is built on official firmware **2.2.31ww**. It keeps recording unchanged and adds:
  - an offline full-screen map, with a Windows Map Builder for any country;
  - speed-camera and overspeed alerts;
  - Wi-Fi STA mode, so the camera can join a phone hotspot;
  - a phone web admin page;
  - a master switch for ADAS, which the README says the official firmware ships **off** so its alerts do nothing;
  - adjustable card-space quotas, telnet (off by default) and custom boot logos.
- **Recovery:** the official 2.2.31ww image is published for rollback. Flash it via `FW_DR2800.bin` + `FORCEUPD.txt`.
- **Why it matters:** the 70mai A800S is a common retail dashcam. A modified firmware that flashes from SD suggests that the update path does not enforce signatures. **That is an inference, not tested.**
- **Limits:** single developer, A800S only, and the live-traffic feature targets Iran.
- **Score:** 7/10 · **Confidence:** medium

### Surfsight / Lytx AI-12 fleet dashcam rooted out of an e-waste bin (log updated 2026-10-04)
- **What it is:** [KhanLabs/surfsight-ai12-reverse-engineering](https://github.com/KhanLabs/surfsight-ai12-reverse-engineering) is a CC-BY-4.0 log that tags every claim as CONFIRMED, STRONG, THEORY or REJECTED.
- **Hardware (confirmed in the log):** Qualcomm SDM450 with PMI632, 2 GB LPDDR3, 16 GB eMMC, microSD up to 128 GB, LTE, GPS and dual cameras.
- **Achieved:**
  - The bootloader is already unlocked (`verifiedbootstate=orange`).
  - Root via Magisk LEGACYSAR.
  - The maker's `surfdash2` backdoor was removed.
  - A factory "Enable Root" activity left in the shipping firmware was found and disabled. Any app could launch it, because it is exported.
- **Hard-won lessons:**
  - The unit has **four power sources**, including a hidden 300 mAh LiPo that keeps the EDL flag alive in IMEM. A true cold boot requires unplugging it.
  - USB-C powers only the boot-ROM logic, so the usual D+-to-ground "deep flash" trick is **REJECTED**.
  - One of two units is **bricked**: Firehose is refused at the ABOOT stage.
  - The LTE fault is narrowed to RF hardware.
- **Why it matters:** a Snapdragon Android box with LTE, GPS and two cameras that fleets discard. It is a strong candidate for a local recorder or vehicle telemetry node.
- **Score:** 6/10 · **Confidence:** medium

### OpenAutoLink: Android Auto/CarPlay back on GM's locked AAOS EVs (v0.1.94, pushed 2026-11-17)
- **What it is:** [mossyhub/openautolink](https://github.com/mossyhub/openautolink) has 204★ and was created 2026-04-01. GM's AAOS EVs ship without phone projection. OAL runs as an app on the car's own head unit; it does not replace the OS.
- **How it installs:** sideloading is blocked, so users build a personal AAB on a web builder and install it through **their own Google Play Console internal-test track**. CarPlay additionally needs "your own compatible, authorized authentication pair".
- **Evidence:** the compatibility matrix is **maintainer validated** on a 2024 Chevrolet Blazer EV (AAOS 12L), covering wireless AA, touch, audio, calls and cluster integration. Wireless CarPlay "is not working in the maintainer's vehicle".
- **Why it matters:** a clean, non-root template for restoring features that an OEM removed from a locked AAOS car.
- **Score:** 7/10 · **Confidence:** medium

### DDPAI Z50 local API reverse engineered with AI agents (2026-10-16)
- **What it is:** [JohnKuruvila/ddpai-z50-api](https://github.com/JohnKuruvila/ddpai-z50-api) is an MIT-licensed, stdlib-only Python client and CLI for the camera's Wi-Fi CGI API. It was observed on firmware v7.2.0.24 at `193.168.0.1`.
- **What it exposes:** clip listing and download, live GPS/IMU, RTSP, and settings that the official app hides, including turning ADAS off.
- **Companion app:** [z50-bridge](https://github.com/JohnKuruvila/z50-bridge), for Android.
- **Disclosure:** the README says it was "Built with AI coding agents under human direction".
- **Limits:** this is a cloud-free control path, not a firmware change. 0★.
- **Score:** 5/10 · **Confidence:** medium

### Renault TomTom Carminat LIVE rooted to change the clock (blog 2026-11-02)
- Rasmus Moorats rooted the navigation unit of a 2014 Renault Latitude, which hid its clock setting without the map SD card. Coverage seen only as search summaries: [Tom's Hardware](https://www.tomshardware.com/tech-industry/cyber-security/security-researcher-had-to-jailbreak-their-car-just-to-update-the-clock-missing-tomtom-sd-card-locked-settings-menu-custom-linux-exploit-deployed-to-adjust-daylight-saving-time) and [GBHackers](https://gbhackers.com/renault-navigation-system/amp/). The original blog, blog.nns.ee, was blocked.
- **Reported method:** a path traversal in the script language's LOG command, chained with Linux `core_pattern`, on a Samsung-based unit running kernel 2.6.28.10. It is local only. The fix amounted to changing a stored offset from 180 to 120 minutes.
- **Why it matters:** this is a common failure mode of the 2010s, where head-unit settings are gated behind a paid map card.
- **Score:** 4/10 · **Confidence:** medium

## 3. AI-assisted hardware hacking

- **xj-scanner** ([repo](https://github.com/MZULALI/xj-scanner)) is the strongest evidence today. The agent is part of the product: AGENTS.md and the skills walk a novice through probing a live 12 V connector with a meter.
  - **AI did:** protocol work and the scanner, per press coverage.
  - **Humans still did:** the wiring, the meter checks, and relied on prior community protocol work (ChryslerScanner, disassembled SBEC code from [AR1972/jeep_2.5L](https://github.com/AR1972/jeep_2.5L)).
- **CSS Electronics CAN skills.** [CSS-Electronics/can-bus-reverse-engineering-skills](https://github.com/CSS-Electronics/can-bus-reverse-engineering-skills) has 260★ and was pushed 2026-11-13. It packages three Claude Code skills that turn raw CAN logs into DBC signals: ID, start bit, length, endianness, scale and offset. It is a vendor repo tied to their CANsub hardware, and its README calls it "not a 'polished tool', but an illustration". The companion article was blocked.
- **Agent-first OBD tooling is multiplying.** [october-dev/car-use](https://github.com/october-dev/car-use) (7★, created 2026-11-11) provides `dtcs()`, `freeze_frame()`, `watch()`, a used-car `inspect` and a `can-check` that tests whether raw CAN reaches the OBD port. It also has a cloud upsell. Several read-only OBD MCP servers appeared in the last 30 days, for example [darblinko/q50-obd-scanner](https://github.com/darblinko/q50-obd-scanner) with a KWP2000/UDS read-only gate.
- **Gen5W mods written by AI.** [DVWburner/Gen5WAutoLock](https://github.com/DVWburner/Gen5WAutoLock) states that the whole project is AI-generated. It calls `IBCMService.lockDoor(true)` after a timer and phone-proximity check, and **does not detect a key fob left inside**. The same author has AI-generated launchers and a theme studio. AI is lowering the bar to writing body-control code for real cars faster than testing practice is keeping up.
- **The DDPAI Z50 API** was built "with AI coding agents under human direction" (see §1).
- **Outside sector F:** [DrivingBench](https://github.com/aditya-ramabadran/drivingbench_harness_code) (63★) lets MCP clients steer a real car at parking-lot speed through comma/openpilot, with a human on the brake. It is research, not revival, and logged only for context. Per Nintendo Life and Wccftech search summaries, the Switch 2 ns2jb exploit was reportedly built with Codex help (see §4).

## 5. Hidden opportunities

1. **Discarded fleet dashcams as LTE + GPS + camera Android nodes.** The AI-12 shows that the bootloader can ship unlocked and that factory root hooks remain. Fleets refresh these units in bulk, and the cloud lock is the only thing making them e-waste. **Build:** an open local recorder plus MQTT telemetry. **Validate:** get one unit and check `ro.boot.verifiedbootstate`, then whether `adb` is reachable on its stock image.
2. **The dashcam firmware update path as a platform.** The A800S mod suggests that modified images flash from SD. Indian dashcam buyers lack local speed-camera maps, and the Windows Map Builder builds them from OpenStreetMap. **Validate:** build an India map and check how many cameras OSM actually has for one city. **Speculative:** the project has not tested India coverage.
3. **Gen5W as an in-car data logger.** HMG-API already hooks vehicle services (door, IBCM, climate). Nobody appears to export EV battery and trip data locally to Home Assistant. **Validate:** check whether HMG-API's Car Report already includes readable SoC/charging fields. **Speculative.**
4. **Pre-OBD2 ECUs plus agent playbooks.** The xj-scanner pattern (cheap MCU + documented protocol + AGENTS.md) could transfer to other 1980s–90s ECUs that have community protocol notes, such as Maruti 800/Gypsy-era carburettor or MPFI systems. **Speculative:** no protocol work was verified today.

## 7. Experiments worth attempting

1. **Read-only CAN survey of your own car.** You need any ELM327-class or CAN adapter; the budget is not checked. Run [car-use](https://github.com/october-dev/car-use) `can-check`, or log raw frames and try the [CSS skills](https://github.com/CSS-Electronics/can-bus-reverse-engineering-skills) on them. Difficulty: low. Expected outcome: learn whether a gateway silences the port. **Safety: read-only only. Do not transmit on a moving vehicle's bus.**
2. **A800S India map build.** Use an A800S, an SD card and the Windows Map Builder. Difficulty: low to medium. Back up and keep the official 2.2.31ww recovery image first.
3. **Fleet dashcam triage.** Hardware is any surplus AI-12-class unit. Tools are a USB-C cable, a separate 5 V/2 A supply and adb. Difficulty: medium. Never write `aboot`; that is what bricked one unit. Note the hidden LiPo before any EDL work.
4. **Gen5W package dev in an emulator before the car.** HMG-API targets Android 4.4 / API 19, so prototype APKs on an API 19 emulator. Difficulty: medium. Never deploy body-control mods without a physical key fallback.
