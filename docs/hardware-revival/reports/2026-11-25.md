_This is the first sector-C run. One pattern stands out: **NAS boxes whose makers have gone away are getting second lives, and AI coding agents are doing much of the software work.** A Drobo 5N (Drobo the company is gone) now boots plain Debian 13 from its own U-Boot. The project's disclosure is unusually exact: Claude Code wrote the scripts and boot stub in about 24 active hours, and the human did every hardware step ([drobo-5n](https://github.com/georgestephanis/drobo-5n)). On networking, [unifi-openwrt](https://github.com/antoniocosta/unifi-openwrt) (154★ in 12 days) lets a UniFi controller adopt OpenWrt access points as if they were Ubiquiti APs. And surplus Lenovo ThinkSmart View meeting-room displays keep turning into local voice assistants._

## 1. Most interesting discoveries

### drobo-5n: Debian 13 on an orphaned Drobo 5N, built with Claude Code (created 2026-11-11; pushed 2026-11-12)
- **What it is:** [georgestephanis/drobo-5n](https://github.com/georgestephanis/drobo-5n) (5★, GPL-2.0) replaces Drobo OS with "plain Debian 13 that boots by itself, from the Drobo's own U-Boot, with no flashing of the bootloader".
- **Hardware (README):** Marvell Armada XP MV78460, 2 GB RAM, Debian on the internal 1 GB eUSB stick, five SATA bays and an mSATA slot.
- **What works:**
  - All five bays as ordinary SATA disks, with staggered power-up.
  - A fan controlled by SoC and disk temperature, plus the bay and capacity lights.
  - Samba, HTTPS, a web dashboard, and a rescue boot from the pinhole button.
  - Kernel updates rebuild the boot files, and U-Boot falls back to the last set that booted.
- **How:** solder three wires to the unpopulated **J2** UART (3.3 V), stop U-Boot (`bootdelay` is 0, so tap space), network-boot the Debian installer, back up the stick, then set a few U-Boot variables. SPI and NOR flash are untouched.
- **Limits (README §10):**
  - The first 16 MB of RAM is unused ("writes below 16 MB hang this board early in boot").
  - Hardware crypto (CESA) is off because its self-tests fail on Debian's 6.12 kernel.
  - Booting from the eUSB stick takes about 2½ minutes, or about 80 s with an mSATA SSD.
  - "Tested on one Drobo 5N… has not yet been repeated on a second, fresh Drobo."
- **Why it matters:** Drobo units have been orphaned since the company stopped trading (not re-verified today). They are 5-bay boxes with a quad-core ARM and 2 GB of RAM. This is the first route to a maintained OS on them that keeps the bootloader intact.
- **Score:** 8/10 · **Confidence:** medium (detailed, honest docs; one unit).

### unifi-openwrt: a UniFi controller adopts OpenWrt access points (created 2026-11-13; pushed 2026-11-24)
- **What it is:** [antoniocosta/unifi-openwrt](https://github.com/antoniocosta/unifi-openwrt) (154★, 13 forks, GPL-2.0). A daemon on the AP "speaks the UniFi inform protocol, so a UniFi controller adopts the AP as a UniFi model of your choice". The controller then pushes settings and shows clients, radios and stats.
- **Tested devices (README table, five units by four people):**
  - Google OnHub TGR1900 (IPQ8064): everything works. This was the author's motivation, because Google ended OnHub support in January 2023.
  - Linksys MX4300 (IPQ8174, adopted as U6-IW).
  - Linksys E4200 v2 (Kirkwood). Mesh uplink to a U7 Lite works.
  - TP-Link Archer BE800 (IPQ9574, Wi-Fi 7). Mesh uplink "joins but does not pass traffic".
  - D-Link DIR-878 A1 (MT7621).
- **Safety design:** it "never applies Ubiquiti firmware": upgrade requests are answered and ignored. A failed Wi-Fi bring-up or a lost controller triggers an automatic rollback.
- **Why it matters:** earlier attempts (openUF, unifi-gateway) are described as stale in [OpenWrt forum threads](https://forum.openwrt.org/t/openwrt-with-the-unifi-controller/128789) (search summary; forum blocked here). This one has a protocol write-up ([docs/internals.md](https://github.com/antoniocosta/unifi-openwrt/blob/main/docs/internals.md)) and a growing compatibility table. Any router OpenWrt supports can now join a UniFi network instead of becoming e-waste.
- **Score:** 8/10 · **Confidence:** medium.

### ShareOS: alternative firmware for D-Link DNS-320L family NAS boxes, "built by an AI" (created 2026-10-16; pushed 2026-11-24)
- **What it is:** [UniqueDroid/ShareOS](https://github.com/UniqueDroid/ShareOS) (18★) is a fork of the long-running [Alt-F](http://sourceforge.net/projects/alt-f) firmware. It runs from flash (UBI with a persistent overlay), keeps the stock U-Boot, and updates itself from GitHub Releases.
- **Install:** flash the `.bin` from the D-Link or Alt-F firmware page. "No serial console, no soldering; the data on the disks is not touched."
- **Models:**
  - DNS-320L: tested with every release. The DNS-320LW is the same box.
  - DNS-325 rev A1: boots from flash.
  - DNS-320 rev A1: first test report in [#185](https://github.com/UniqueDroid/ShareOS/issues/185).
  - DNS-320 rev B: built, not tested.
- **AI claim:** "Apart from importing Alt-F, ShareOS was developed by Claude (Anthropic): architecture, all code, builds, tests and docs. Jan started the project, made the decisions and tested on the real box."
- **Score:** 7/10 · **Confidence:** medium (beta; pre-releases labelled "for test devices only").

### Four more dead-or-dated NAS platforms revived this month
- **Seagate NAS 2-Bay SRPD20** ([laserbirdx/seagate-nas2bay-omv](https://github.com/laserbirdx/seagate-nas2bay-omv), 10★, created 2026-11-03):
  - Hardware: Armada 370, 512 MB.
  - Installs Debian 12 + OpenMediaVault 7 from the factory OS over SSH, with "no NAND flashing, no wipe, and an automatic fallback to the factory firmware". OMV plugins drive the fan, all six LEDs and the buttons.
  - Tested on **one** unit, and only Debian 12's 6.1 kernel is packed.
- **Zyxel NAS326** ([laserbirdx/zyxel-nas326-openwrt](https://github.com/laserbirdx/zyxel-nas326-openwrt)):
  - Hardware: Armada 380, 512 MB, 2× SATA III.
  - An install guide for an **upstream** OpenWrt 25.12.6 target ([commit 471dd1b](https://github.com/openwrt/openwrt/commit/471dd1ba15bf13f57fa1c935f8766e520daabfdd)). Fan control and the buzzer do not work.
- **NETGEAR ReadyNAS Duo v1** ([beudbeud/ReadyNasNextGen](https://github.com/beudbeud/ReadyNasNextGen), 0★, created 2026-11-16):
  - Hardware: Infrant SPARC.
  - A RAIDiator add-on "relay" hands the box to Linux 6.18 on a USB stick, which serves SMB 3 and NFS with a web UI. Existing X-RAID disks are read-only by default.
  - Measured: SMB reads 28–39 MiB/s, but only about 4 MiB/s once SMB signing is on, which Windows and macOS use by default. Validated on one NAS.
- **Cubbit Cell → ESPRESSObin V7 NAS** ([pieroantonio/espressobin-v7-nas-case](https://github.com/pieroantonio/espressobin-v7-nas-case), created 2026-11-15):
  - "Once our Cells were deactivated", the boards got TF-A 2.9 + U-Boot 2024.10 and Debian 13 on eMMC.
  - Done on one board and passed a 40-minute stress test. Needs `cpufreq.off=1`. The 3D-printed case is an unprinted draft.
- **Score (group):** 6/10 · **Confidence:** medium.

### ZTE CloudBook Air: a cloud-desktop laptop runs mainline Linux (created 2026-11-16; pushed 2026-11-21)
- **What it is:** [eastwoodnet/cloudbook-air-mainline-linux](https://github.com/eastwoodnet/cloudbook-air-mainline-linux) (35★, 11 forks). The laptop is the China Mobile / ZTE "cloud computer" CT2000-24RTW: Rockchip RK3568B2, 4 GB, 32 GB eMMC, 1920×1200 eDP, MT7663S Wi-Fi.
- **Status (README):** Linux 6.12.117 LTS + Armbian Debian 13 on the internal eMMC. Desktop, Wi-Fi/BT, PD charging, suspend on lid close and H.264 hardware decode all work. Panfrost and Mesa 25.0.7 run the GPU.
- **The interesting part:**
  - The device has fused secure boot (`fuse.programmed=1`), and its bootloader stages are RSA-2048 signed. But the stock U-Boot "does not intercept unsigned kernels" in `boot_a`/`boot_b`.
  - So Linux goes in slot A and Android 11 stays in slot B.
  - The README's hard rule: never write unsigned code to the first 8 MiB, `uboot_a/b`, `trust_a/b` or `security`.
- **Why it matters:** operator-subsidised "cloud PC" laptops are cheap thin clients with real ARM SoCs. If the kernel slot is unchecked on one model, sister models may share the gap (**unverified**).
- **Score:** 7/10 · **Confidence:** medium.

### ThinkSmart View becomes an off-the-shelf local voice terminal (created 2026-11-01)
- **What it is:** [justhalfbit/thinksmart-ubuntu-image](https://github.com/justhalfbit/thinksmart-ubuntu-image) (103★, 28 forks). It flashes a Lenovo ThinkSmart View CD-18781Y with Ubuntu 24.04 on a postmarketOS 6.19 kernel, booting straight into a wake-word voice UI ([xiaozhi-thinksmart-client](https://github.com/justhalfbit/xiaozhi-thinksmart-client), 35★).
  - Local wake word (sherpa-onnx) and WebRTC echo cancellation.
  - Claude (the default) or DeepSeek as the back-end LLM.
  - Fixes for both microphones, the speaker, proximity wake, Wi-Fi stability and a GPU hang.
- **Agent-first docs:** the README opens with a section addressed to "the AI assistant (Agent) called in to help flash", with a step-by-step EDL procedure.
- **Parallel effort:** [jethac/lenovo-thinksmart-view](https://github.com/jethac/lenovo-thinksmart-view) (9★, created 2026-10-30) targets mainline Linux 7.x + Arch Linux ARM via lk2nd.
- **Limits:**
  - UI and wake word are Chinese only.
  - Flashing wipes Teams/Android, and a full eMMC backup "is the only way back to stock".
  - The [HA community thread](https://community.home-assistant.io/t/lenovo-thinksmart-view-rom-os-development/676324) (search summary) reports gaps on some postmarketOS builds: audio, touch-wake and volume keys.
- **Score:** 7/10 · **Confidence:** medium.

### IPQ50XX-Uboot: a web-rescue U-Boot for cheap Qualcomm Wi-Fi 6 routers (created 2026-11-08; pushed 2026-11-17)
- **What it is:** [FlyFish-go/IPQ50XX-Uboot](https://github.com/FlyFish-go/IPQ50XX-Uboot) (13★, GPL-2.0). It adds a web recovery page and vendor-style dual boot, and checks each item before writing.
- **Models:**
  - H3C NX30 / RT3000 / RC3000 / RW3000: installable from a **browser tool, no disassembly**.
  - Xiaomi CR8806, TCL T30 Pro, Ruijie RG-MA3063, China Mobile RAX3000Q(Y) and others: verified via TTL.
  - The README warns: **do not flash** the PZ-L8 or the RG-MA3063 V3.
  - Xiaomi AX6000 and Redmi AX5400: "planned".
- **Score:** 5/10 · **Confidence:** medium.

## 3. AI-assisted hardware hacking

- **Drobo 5N, the best-documented split of work so far** ([README disclosure](https://github.com/georgestephanis/drobo-5n)):
  - **What Claude Code did:** wrote "most of the scripts, the boot stub and this guide". It also ran commands on the Drobo "over its serial console and SSH", through a Raspberry Pi Pico serial bridge.
  - **What needed human hands:** "opening the case, wiring the serial consoles… power-cycling and recovering the board, swapping fans, and checking results by eye and ear."
  - **Effort:** about **24 h of active time over 9–12 Nov 2026**, about 300 human messages, about 2,870 model calls and about 2.35 M output tokens.
  - **Agent-ready:** the repo ships an Agent Skill (`skills/drobo5n-debian/SKILL.md`) with checkpoints and a list of "the commands that hang or brick this board".
  - This is the same author as the SES-imagotag shelf-label work in the 2026-11-24 report.
- **ShareOS** ([README](https://github.com/UniqueDroid/ShareOS)): the author says Claude wrote the architecture, all code, builds, tests and docs, and the human tested on the real box. A dated timeline is in `docs/DEVELOPMENT.md` (not reviewed today).
- **cros-sofaudio** ([isaiahscape/cros-sofaudio](https://github.com/isaiahscape/cros-sofaudio), 5★, created 2026-10-20): Windows 11 KMDF audio drivers for SOF Chromebooks (MAX98373 amps, NAU88L25 codec). The credits thank Claude "for diagnosing and fixing the sound output drivers".
  - **Caveat:** installing it requires Windows test-signing mode and **disabling the vulnerable-driver blocklist**, which is a real security trade-off.
- **Agent skills shipped with firmware repos are becoming normal:**
  - CLX-S20P router ([clx-s20p-firmware](https://github.com/LucxXxifer/clx-s20p-firmware)): a provisioning skill written for Codex, Claude Code, Gemini CLI, Cursor and others.
  - Xiaomi BE6500 Pro root guide ([skill/SKILL.md](https://github.com/TongenShen/Xiaomi-BE6500Pro-SSH-Guide)).
  - The ThinkSmart Ubuntu image's agent-facing README.
  - Already in the DB: [android-mainline-port](https://github.com/yzddmr6/android-mainline-port), now at 131★.
- **Security research with agents** (search summaries only; the sites were not fetched):
  - Bishop Fox gave Claude Code (with Binary Ninja over MCP) an encrypted SonicWall NSv image. Its own attempts at the vendor encryption kept failing, and it succeeded only when told to run the vendor's tool: "senior-level skill, junior-level autonomy" ([Bishop Fox](https://bishopfox.com/blog/cracking-firmware-with-claude-senior-level-skill-junior-level-autonomy)).
  - SoftwareSecured ran Claude Code against Tenda router firmware through an MCP server ([write-up](https://www.softwaresecured.com/post/ai-firmware-analysis-tenda-router-vulnerabilities)).
  - An [OpenWrt forum thread](https://forum.openwrt.org/t/ai-agent-for-development/254846) from October 2026 shares a Claude instruction set for getting U-Boot running via TFTP (forum blocked; summary only).
- **What still needs a human:** soldering and wiring UARTs, power-cycling bricked boards, judging physical outputs (LEDs, fan noise), and buying the hardware. Every project above is validated on **one** unit.

## 5. Hidden opportunities

1. **Orphaned-service storage boxes (Drobo, Cubbit Cell, older WD and Seagate consumer NAS)**
   - *Opportunity:* ARM SoCs with SATA, Gigabit Ethernet and 512 MB–2 GB RAM, whose vendor service is gone, often with interruptible U-Boot.
   - *Why overlooked:* each one needs serial work and a custom boot chain, and the user base is small.
   - *What could be built:* one Debian/OMV kit per family, each with an agent skill, so the next model takes days rather than weeks.
   - *Validation:* repeat the Drobo 5N guide on a second unit and on a Drobo 5N2 (the 5N2 is not covered by the repo).
2. **Operator "cloud PC" laptops and IPTV boxes (ZTE CloudBook, ZTE B860AV5.2)**
   - *Opportunity:* RK3568-class laptops and Amlogic/HiSilicon-class IPTV boxes that ISPs hand out or dump in bulk. On the CloudBook the kernel slot is not signature-checked.
   - *Why overlooked:* mostly sold in China, documented in Chinese, and buyers think of them as thin clients.
   - *What could be built:* Armbian images for sister CloudBook models, and cheap fnOS/OMV NAS boxes.
   - *Validation:* on another cloud-PC model, read the GPT and test whether stock U-Boot boots an unsigned `boot_a`. Read only; do not write bootloader partitions.
3. **OpenWrt APs as UniFi devices, with ISP-supplied routers as the hardware pool**
   - *Opportunity:* unifi-openwrt turns any OpenWrt-capable router into a managed AP for anyone already on UniFi.
   - *Why overlooked:* it launched 12 days ago.
   - *What could be built:* a curated list of cheap supported routers, and a Wi-Fi 7 mesh fix.
   - *Validation:* adopt an MT7621 router (as on the DIR-878 A1) and test roaming between a real UniFi AP and the OpenWrt AP.
4. **Meeting-room displays (ThinkSmart View) as English Home Assistant voice satellites**
   - *Opportunity:* the Ubuntu image already fixes the two microphones and echo cancellation, which are the hard parts. Swap the xiaozhi client for Wyoming/Assist.
   - *Why overlooked:* the image is Chinese-only, and HA users mostly try postmarketOS.
   - *Validation:* flash the image, then run `wyoming-satellite` against HA and measure wake-word false accepts.

## 7. Experiments worth attempting

1. **Drobo 5N → Debian 13**
   - *Hardware:* a Drobo 5N and its own 12 V 8.33 A PSU.
   - *Budget:* the cost of a used unit, plus about ₹300 for a 3.3 V USB-UART adapter.
   - *Tools:* soldering iron, a TFTP-capable PC, `dtc`.
   - *Software:* [drobo-5n kit](https://github.com/georgestephanis/drobo-5n).
   - *Difficulty:* medium-hard.
   - *Expected outcome:* a 5-bay Debian NAS.
   - *Recovery:* step 5 backs up the eUSB stick, and SPI/NOR flash is never written.
   - *Safety:* use a 3.3 V adapter, not 5 V. Keep a fan on the heatsink while the case is open. A weak PSU browns out when a third disk spins up.
2. **unifi-openwrt on an old router**
   - *Hardware:* any OpenWrt 25.12 router (e.g. DIR-878 A1, MT7621) plus an existing UniFi controller.
   - *Budget:* a spare router you already own.
   - *Difficulty:* easy-medium.
   - *Expected outcome:* the router is adopted as a UAP-AC-Pro, with SSIDs and VLANs pushed from the controller.
   - *Recovery:* automatic rollback on failure. Ubiquiti firmware is never applied.
3. **ThinkSmart View → local voice terminal**
   - *Hardware:* a CD-18781Y and a USB cable.
   - *Tools:* the `edl` tool.
   - *Software:* [thinksmart-ubuntu-image](https://github.com/justhalfbit/thinksmart-ubuntu-image).
   - *Difficulty:* medium.
   - *Expected outcome:* a wake-word assistant, which could then be re-pointed at Home Assistant.
   - *Recovery:* a **full eMMC backup before anything else**. It is the only way back to Teams/Android.
4. **D-Link DNS-320L → ShareOS**
   - *Software:* [ShareOS releases](https://github.com/UniqueDroid/ShareOS/releases).
   - *Difficulty:* easy (web flash).
   - *Expected outcome:* a maintained NAS OS on 2012-era hardware.
   - *Recovery:* keep the current firmware `.bin`. Beta-quality, so use a box without irreplaceable data.
5. **Acer Chromebook 311 (MT8183) → Debian 13**
   - *Software:* [chromebook-311-linux](https://github.com/olamellberg/chromebook-311-linux).
   - *Difficulty:* easy.
   - *Expected outcome:* an XFCE laptop with Panfrost acceleration, which could also serve as a low-power ARM server.
   - *Recovery:* a ChromeOS recovery USB. Developer mode wipes local data.

## 8. Long-term opportunity radar (6–24 months)

- **The Googlebook OS transition:** Google says many recent Chromebooks will be eligible for Googlebook OS (search summary). Chromebooks left out of that migration are the next wave of cheap, Linux-capable laptops, especially ARM MediaTek models like the 311.
- **OpenWrt 24.10 reached end of security support** in about September 2026, six months after 25.12.0 (per [Help Net Security](https://www.helpnetsecurity.com/2026/03/09/openwrt-25-12-0-released/), search summary). Devices that only reached 24.10 should be avoided for new buys. 25.12 supports 2,200+ devices.
- **Marvell mvebu NAS boards (Armada 370/380/XP)** are having a revival: Drobo, Seagate, Zyxel and Cubbit all appeared this month. Mainline support for these SoCs is mature, so the work is per-board boot glue, which suits agents.
- **Agent skills bundled with hardware repos:** at least five new repos this month ship `SKILL.md` or agent-facing READMEs. Expect "one person + agent + one board in a long weekend" to become the normal pace for revivals like these.
- **Wi-Fi 7 OpenWrt APs (IPQ9574)** are already adoptable into UniFi, with mesh limited by the ath12k driver. Watch for driver maturity.
